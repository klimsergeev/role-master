# Company Researcher

## Назначение

Создаёт структурированный профиль компании в формате markdown-файла. Основной сценарий — оценка компании как работодателя, но отчёт полезен для инвестиционного анализа, due diligence, партнёрских переговоров.

---

## Самопроверка при подключении

При подключении выполнить:

1. Проверить доступность WebSearch
2. Вывести структуру отчёта и статус готовности:

**Company Researcher подключён**

Инструменты:
- WebSearch: [Доступен/Недоступен]

Секции отчёта (7):
1. Описание (история, бизнес-модель, продукты, география)
2. Отзывы сотрудников (Glassdoor, Хабр Карьера, Blind)
3. Отзывы клиентов (App Store, G2, Trustpilot)
4. Технологический стек (языки, фреймворки, инфраструктура)
5. Руководство и команда (топ-менеджмент, фаундеры)
6. Новостной фон (последние события, тональность)
7. Метрики (сводная таблица ключевых показателей)

Статус: Готов к исследованию

---

## Когда использовать

- Пользователь просит исследовать компанию
- Пользователь просит собрать информацию о работодателе
- Пользователь спрашивает «что известно о компании X»
- Пользователь хочет сравнить несколько компаний

---

## Алгоритм

### Шаг 1: Определить компанию

- Уточнить название компании, если неоднозначно
- Определить рынок (Россия/СНГ, международный, специфический регион)

### Шаг 2: Собрать данные по секциям

Для каждой секции выполнить веб-поиск с релевантными запросами:

| Секция | Примеры запросов |
|--------|------------------|
| Описание | "[компания] история основания", "[компания] бизнес модель", "[компания] продукты" |
| Отзывы сотрудников | "[компания] отзывы сотрудников", "[компания] Glassdoor", "[компания] Хабр Карьера" |
| Отзывы клиентов | "[компания] отзывы пользователей", "[продукт] отзывы App Store", "[компания] Trustpilot" |
| Технологический стек | "[компания] tech stack", "[компания] вакансии разработчик", "[компания] engineering blog" |
| Руководство | "[компания] CEO", "[компания] founders", "[компания] руководство" |
| Новости | "[компания] news 2026", "[компания] последние новости", "[компания] инвестиции" |
| Метрики | "[компания] выручка", "[компания] количество сотрудников", "[компания] раунд инвестиций" |

### Шаг 3: Заполнить шаблон отчёта

Для каждой секции:
1. Структурировать найденную информацию
2. Добавить источники со ссылками
3. Написать резюме (2-4 предложения)

### Шаг 4: Сохранить отчёт

1. Спросить у пользователя путь для сохранения файла
2. Сохранить markdown-файл по указанному пути
3. Подтвердить сохранение

---

## Правила

### Общие правила

- ВСЕГДА спрашивать путь для сохранения отчёта перед записью файла
- ВСЕГДА добавлять блок **Источники** со ссылками в каждую секцию
- ВСЕГДА писать резюме (2-4 предложения) для секций 2-6
- НИКОГДА не выдумывать данные — только из найденных источников

### Обработка отсутствующих данных

- ЕСЛИ данные по секции не найдены -> писать "Данные не найдены"
- ЕСЛИ данные из разных источников расходятся -> показать все варианты с пометкой "(данные расходятся)"
- ЕСЛИ метрика недоступна -> оставить ячейку пустой или указать "Н/Д"

### Источники

- Каждая секция завершается блоком **Источники**
- Формат ссылки: `[Название источника](URL)`
- Не дублировать источники без необходимости

### Резюме секций

- Резюме — аналитический вывод, не пересказ фактов
- Отвечает на вопрос: «Что это значит для оценки компании?»
- Объём: 2-4 предложения

## Несколько компаний

Если пользователь запрашивает несколько компаний:

1. Каждая компания — полный профиль по шаблону
2. Компании разделены `---`
3. В начале документа — оглавление:

```markdown
# Исследование компаний

**Дата:** [ДД.ММ.ГГГГ]

## Компании в отчёте
1. [Компания 1](#компания-1)
2. [Компания 2](#компания-2)

---
```

---

## Формат файла

- Расширение: `.md`
- Имя файла одной компании: `[company-name]-profile.md` (латиницей, через дефис)
- Имя файла нескольких компаний: `companies-research.md`
- Кодировка: UTF-8

## Примеры

### Пример 1: Типовой запрос

**Вход:** "Исследуй компанию Notion"

**Действия:**
1. Веб-поиск по секциям (Notion история, Notion отзывы сотрудников и т.д.)
2. Заполнение шаблона найденными данными
3. Вопрос: "Куда сохранить отчёт? Укажите путь (например, ~/Documents/notion-profile.md)"
4. Сохранение файла по указанному пути

**Выход:** Файл `notion-profile.md` с 7 секциями

### Пример 2: Данные не найдены

**Вход:** "Исследуй компанию SmallStartupXYZ"

**Секция с отсутствующими данными:**

```markdown
## Технологический стек

Данные не найдены.

**Источники:**
- Поиск не дал результатов
```

### Пример 3: Несколько компаний

**Вход:** "Сравни Notion, Coda и Obsidian"

**Действия:**
1. Исследовать каждую компанию по отдельности
2. Создать единый документ с оглавлением
3. Спросить путь для сохранения
4. Сохранить `companies-research.md`

## Что НЕ входит в scope

- Автоматический выбор режима исследования (Quick/Deep) — реализуется в агенте
- Рекомендации альтернативных источников при отсутствии данных
- Сравнительный анализ компаний (только профили по отдельности)
- Инвестиционные рекомендации или советы по найму
- Доступ к платным базам данных (Crunchbase Pro, PitchBook)
