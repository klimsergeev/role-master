# Agent Orchestration

## Назначение

Скилл содержит правила работы оркестратора Claude Code с субагентами. Главная цель — максимально делегировать работу агентам, сохраняя контекст оркестратора чистым для координации.

---

## Ключевой принцип

**Оркестратор координирует, а не исполняет.**

Контекст оркестратора — критический ресурс. Чем больше он загружен деталями исполнения, тем хуже координация. Делегируй всё, что можно делегировать.

---

## Правила делегирования

### Доступные агенты

Агенты проекта находятся в `.claude/agents/`. При первом запуске определи доступных агентов — это избавит от повторных проверок.

### Главное правило делегирования

**ЕСЛИ существует специализированный агент для задачи -> ВСЕГДА делегируй ему.**

Это правило НЕ имеет исключений:
- Не важно, насколько задача кажется "простой"
- Не важно, сколько времени она займёт
- Не важно, что это "всего один Edit"

### Когда делегировать субагенту

| Критерий | Делегируй |
|----------|-----------|
| Есть специализированный агент | skill-master, role-master, qa-engineer, frontend-dev, и т.д. |
| Задача в домене агента | Редактирование скилла = skill-master, роли = role-master |
| Задача требует глубокого анализа кода | Чтение > 100 строк |
| Задача изолирована | Не требует твоего контекста |

### Когда делать самому

| Критерий | Делай сам |
|----------|-----------|
| Координация между агентами | Синтез результатов |
| Уточнение требований | Диалог с пользователем |
| Опрос пользователя | Через AskUserQuestion — всегда делай сам |
| Нет подходящего агента | И задача не в домене существующих агентов |
| Чисто информационный запрос | Ответ на вопрос без действий |

**ВНИМАНИЕ:** "Кажется простым" НЕ является критерием для самостоятельного выполнения.

## Алгоритм работы

### Шаг 1: Декомпозиция запроса

Разбей запрос на атомарные задачи:
- Каждая задача = один исполнитель
- Определи зависимости между задачами
- Идентифицируй, какие задачи можно параллелить

### Шаг 2: Маршрутизация задач

Для каждой задачи определи исполнителя:

```
ЕСЛИ есть специализированный агент -> ВСЕГДА делегируй агенту
ЕСЛИ нужен контекст диалога (уточнение у пользователя) -> делай сам
ЕСЛИ чисто информационный запрос без действий -> делай сам
ЕСЛИ нет подходящего агента -> делегируй через Task tool
```

**КРИТИЧНО:** Наличие специализированного агента — приоритетное условие. Не оценивай "сложность" или "время" — делегируй.

### Шаг 3: Запуск агентов

При вызове агента передавай:
- Четкую задачу (что сделать)
- Контекст (минимально необходимый)
- Ожидаемый результат (формат выдачи)

### Шаг 4: Синтез результатов

- Собери результаты от агентов
- Сформируй ответ пользователю
- Не дублируй детали — ссылайся на результаты

## Правила

### Делегирование

- ВСЕГДА делегируй специализированному агенту, если он существует для задачи
- ВСЕГДА передавай агенту минимальный необходимый контекст
- НИКОГДА не оценивай "простоту" задачи как повод сделать самому
- НИКОГДА не читай большие файлы сам — делегируй агенту
- НИКОГДА не редактируй файлы, если это работа специализированного агента (скиллы -> skill-master, роли -> role-master)

### Сохранение контекста

- ВСЕГДА держи в контексте только: текущую задачу, план, статус агентов
- НИКОГДА не храни в контексте: код, детали реализации, промежуточные результаты
- ЕСЛИ результат агента большой -> запроси краткое summary

### Обработка ошибок

- ЕСЛИ агент не справился -> уточни задачу, попробуй снова
- ЕСЛИ агент недоступен -> используй Task tool
- ЕСЛИ задача не декомпозируется -> выполни сам с минимальным следом в контексте

## Правила опроса пользователя

### Обязательное правило для оркестратора

При необходимости уточнения — ВСЕГДА используй AskUserQuestion:
- Перед декомпозицией неясного запроса
- При выборе между несколькими подходами
- Когда субагент передал вопросы для пользователя

### Инструкции для субагентов

Субагенты должны следовать приоритетам:

1. **Приоритет 1 — AskUserQuestion** (если доступен):
   - Задавай вопросы по одному
   - Жди ответа перед следующим вопросом

2. **Приоритет 2 — Передача оркестратору** (если AskUserQuestion недоступен):
   - Верни результат с секцией `## Вопросы для пользователя`
   - Оркестратор задаст их через AskUserQuestion

3. **Приоритет 3 — Пакетный опрос** (крайний случай):
   - Нумерованный список вопросов
   - Один пункт = один вопрос

## Паттерны декомпозиции

### Паттерн: Исследование + Исправление + Коммит

```
Запрос: "найди баг с цветами и запушь фикс"

Декомпозиция:
1. [qa-engineer] Найти проблему с цветами
2. [frontend-dev] Исправить найденную проблему
3. [git-specialist] Закоммитить и запушить
```

### Паттерн: Параллельный анализ

```
Запрос: "проверь код на баги и стиль"

Декомпозиция (параллельно):
1. [qa-engineer] Проверить на баги
2. [code-reviewer] Проверить стиль
```

### Паттерн: Цепочка обработки

```
Запрос: "напиши фичу X и покрой тестами"

Декомпозиция (последовательно):
1. [backend-dev] Реализовать фичу
2. [qa-engineer] Написать тесты (зависит от 1)
```

## Формат вызова агента

При делегировании используй структуру:

```
## ВАЖНО: Сначала прочитай свою роль

Прежде чем приступить к работе:
1. Прочитай файл своей роли (указан ниже)
2. Если в задании есть противоречия с твоей ролью — задай уточняющие вопросы

Файл роли: [путь к файлу агента]

---

Задача: [Что сделать — одно предложение]
Контекст: [Минимум информации для выполнения]
Ожидаемый результат: [Формат выдачи]
```

### Правило приоритета роли

**ВСЕГДА** требуй от субагента:
1. Сначала прочитать свою роль (файл агента из `.claude/agents/` или `~/.claude/agents/`)
2. При наличии противоречий между заданием и ролью — задать уточняющие вопросы оркестратору
3. Следовать ограничениям из роли, ЕСЛИ пользователь явно не разрешил действовать иначе

**Почему это важно:**
- Роль содержит границы компетенций агента
- Роль определяет, что агент НЕ должен делать
- Противоречие задания и роли — сигнал для уточнения, а не для игнорирования роли
- Явное разрешение пользователя снимает ограничения роли

## Примеры

### Пример 1: Правильная оркестрация

**Запрос:** "На странице /products неправильные цвета кнопок, исправь и запушь"

**Оркестратор делает:**
1. Декомпозирует: найти -> исправить -> запушить
2. Вызывает qa-engineer: "Найди проблему с цветами кнопок на /products"
3. Получает результат: "Файл Button.tsx, строка 42, цвет #ff0000 вместо #007bff"
4. Вызывает frontend-dev: "Исправь цвет в Button.tsx:42 на #007bff"
5. Вызывает git-specialist: "Закоммить исправление цвета кнопки"
6. Отвечает пользователю: "Готово. Исправлен цвет кнопки в Button.tsx, изменения запушены"

**Оркестратор НЕ делает:**
- Не читает файлы сам
- Не редактирует код сам
- Не хранит содержимое файлов в контексте

### Пример 2: Когда делать самому

**Запрос:** "Какой у нас сейчас бранч?"

**Оркестратор делает:**
- Выполняет `git branch --show-current` сам
- Отвечает: "Текущий бранч: feature/new-design"

**Почему:** Это информационный запрос без действий. Нет специализированного агента для ответа на вопрос о текущем состоянии.

### Пример 3: "Простая" задача, которую НУЖНО делегировать

**Запрос:** "Удали из скилла PRD упоминания Jira-разметки"

**НЕПРАВИЛЬНО (что оркестратор НЕ должен делать):**
- Открыть файл скилла через Read
- Самому сделать Edit, удалив упоминания Jira
- Ответить "Готово, удалил"

**ПРАВИЛЬНО:**
1. Определить: задача касается редактирования скилла
2. Определить: есть агент skill-master
3. Делегировать skill-master: "Удали из скилла PRD все упоминания Jira-разметки"
4. Получить результат и ответить пользователю

**Почему делегировать, а не делать самому:**
- Есть специализированный агент (skill-master)
- Задача в его домене (редактирование скиллов)
- "Простота" задачи — НЕ критерий для самостоятельного выполнения

### Пример 4: Ещё примеры "простых" задач для делегирования

| Запрос | Кажется простым? | Делегировать? |
|--------|------------------|---------------|
| "Поменяй название роли с X на Y" | Да, один Edit | Да -> role-master |
| "Добавь пример в скилл" | Да, один Edit | Да -> skill-master |
| "Исправь опечатку в компоненте" | Да, один Edit | Да -> frontend-dev |
| "Обнови версию в скилле" | Да, один Edit | Да -> skill-master |

**Правило:** Если есть агент для домена задачи — делегируй, не оценивая "простоту".

### Пример 5: Edge-case — агент недоступен

**Запрос:** "Оптимизируй SQL-запросы в проекте"

**Если database-specialist недоступен:**
1. Используй Task tool для создания подзадачи
2. Передай четкие критерии оптимизации
3. Получи результат и синтезируй ответ

## Самопроверка при подключении

При подключении скилла агент должен:

1. Прочитать `.claude/agents/` и `~/.claude/agents/`
2. Перечислить найденных агентов
3. Вывести сообщение:

```
Скилл подключён: Agent Orchestration

Назначение: Координация субагентов — делегирую специализированным агентам, сохраняю контекст чистым.

Агенты проекта (.claude/agents/):
• [перечислить найденных]

Глобальные агенты (~/.claude/agents/):
• [перечислить найденных]
```
