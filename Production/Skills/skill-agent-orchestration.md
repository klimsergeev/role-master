# Agent Orchestration

## Назначение

Скилл содержит правила работы оркестратора Claude Code с субагентами. Главная цель — максимально делегировать работу агентам, сохраняя контекст оркестратора чистым для координации.

---

## Ключевой принцип

**Оркестратор координирует, а не исполняет.**

Контекст оркестратора — критический ресурс. Чем больше он загружен деталями исполнения, тем хуже координация. Делегируй всё, что можно делегировать.

---

## Правила делегирования

### Доступные агенты

Агенты проекта находятся в `.claude/agents/`. При первом запуске определи доступных агентов — это избавит от повторных проверок.

### Когда делегировать субагенту

| Критерий | Делегируй |
|----------|-----------|
| Задача требует специализации | QA, Frontend, Backend, Git |
| Задача требует глубокого анализа кода | Чтение > 100 строк |
| Задача изолирована | Не требует твоего контекста |

### Когда делать самому

| Критерий | Делай сам |
|----------|-----------|
| Быстрый ответ пользователю | < 30 сек работы |
| Координация между агентами | Синтез результатов |
| Уточнение требований | Диалог с пользователем |
| Нет подходящего агента | Простая задача без специализации |

## Алгоритм работы

### Шаг 1: Декомпозиция запроса

Разбей запрос на атомарные задачи:
- Каждая задача = один исполнитель
- Определи зависимости между задачами
- Идентифицируй, какие задачи можно параллелить

### Шаг 2: Маршрутизация задач

Для каждой задачи определи исполнителя:

```
ЕСЛИ есть специализированный агент -> делегируй агенту
ЕСЛИ задача тривиальная (< 30 сек) -> делай сам
ЕСЛИ нужен контекст диалога -> делай сам
ИНАЧЕ -> делегируй через Task tool
```

### Шаг 3: Запуск агентов

При вызове агента передавай:
- Четкую задачу (что сделать)
- Контекст (минимально необходимый)
- Ожидаемый результат (формат выдачи)

### Шаг 4: Синтез результатов

- Собери результаты от агентов
- Сформируй ответ пользователю
- Не дублируй детали — ссылайся на результаты

## Правила

### Делегирование

- ВСЕГДА передавай агенту минимальный необходимый контекст
- НИКОГДА не читай большие файлы сам — делегируй агенту
- НИКОГДА не делай работу агента, если агент доступен

### Сохранение контекста

- ВСЕГДА держи в контексте только: текущую задачу, план, статус агентов
- НИКОГДА не храни в контексте: код, детали реализации, промежуточные результаты
- ЕСЛИ результат агента большой -> запроси краткое summary

### Обработка ошибок

- ЕСЛИ агент не справился -> уточни задачу, попробуй снова
- ЕСЛИ агент недоступен -> используй Task tool
- ЕСЛИ задача не декомпозируется -> выполни сам с минимальным следом в контексте

## Паттерны декомпозиции

### Паттерн: Исследование + Исправление + Коммит

```
Запрос: "найди баг с цветами и запушь фикс"

Декомпозиция:
1. [qa-engineer] Найти проблему с цветами
2. [frontend-dev] Исправить найденную проблему
3. [git-specialist] Закоммитить и запушить
```

### Паттерн: Параллельный анализ

```
Запрос: "проверь код на баги и стиль"

Декомпозиция (параллельно):
1. [qa-engineer] Проверить на баги
2. [code-reviewer] Проверить стиль
```

### Паттерн: Цепочка обработки

```
Запрос: "напиши фичу X и покрой тестами"

Декомпозиция (последовательно):
1. [backend-dev] Реализовать фичу
2. [qa-engineer] Написать тесты (зависит от 1)
```

## Формат вызова агента

При делегировании используй структуру:

```
Задача: [Что сделать — одно предложение]
Контекст: [Минимум информации для выполнения]
Ожидаемый результат: [Формат выдачи]
```

## Примеры

### Пример 1: Правильная оркестрация

**Запрос:** "На странице /products неправильные цвета кнопок, исправь и запушь"

**Оркестратор делает:**
1. Декомпозирует: найти -> исправить -> запушить
2. Вызывает qa-engineer: "Найди проблему с цветами кнопок на /products"
3. Получает результат: "Файл Button.tsx, строка 42, цвет #ff0000 вместо #007bff"
4. Вызывает frontend-dev: "Исправь цвет в Button.tsx:42 на #007bff"
5. Вызывает git-specialist: "Закоммить исправление цвета кнопки"
6. Отвечает пользователю: "Готово. Исправлен цвет кнопки в Button.tsx, изменения запушены"

**Оркестратор НЕ делает:**
- Не читает файлы сам
- Не редактирует код сам
- Не хранит содержимое файлов в контексте

### Пример 2: Когда делать самому

**Запрос:** "Какой у нас сейчас бранч?"

**Оркестратор делает:**
- Выполняет `git branch --show-current` сам
- Отвечает: "Текущий бранч: feature/new-design"

**Почему:** Задача тривиальная (< 30 сек), не требует специализации.

### Пример 3: Edge-case — агент недоступен

**Запрос:** "Оптимизируй SQL-запросы в проекте"

**Если database-specialist недоступен:**
1. Используй Task tool для создания подзадачи
2. Передай четкие критерии оптимизации
3. Получи результат и синтезируй ответ
