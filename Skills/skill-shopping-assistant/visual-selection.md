# Визуальный отбор (Фазы 4-5)

## Назначение

Процедура визуального отбора моделей: показ по одной, сбор реакций "да/нет/возможно", дожим всех "возможно" до бинарного решения.

## Условие выполнения

ТОЛЬКО для товаров с `has_visual_component = true` (определяется в [task-intake.md](task-intake.md)).

Для товаров без визуального компонента -- пропустить, перейти к [buying-guide.md](buying-guide.md).

---

## Фаза 4: Визуальный отбор

### Формат показа (для каждой модели)

1. **Название + бренд**
2. **3-5 изображений модели** (запрос: `[модель] [пол] [цвет] side view`)
3. **Краткое описание** (1-2 предложения о стилевом профиле силуэта и особенностях/предупреждениях)
4. **Оценка на маркетплейсах** (рейтинг, количество отзывов)
5. **Цитаты из отзывов** (1-2 самые показательные)
6. **Вопрос:** "Да / Нет / Возможно" (через AskUserQuestion)

### Пример показа

```
**Hoka Clifton 9**

[3-5 изображений]

Толстая "облачная" подошва, узнаваемый Hoka-силуэт. Текстильный верх,
без замши. Предупреждение: массивный вид, не всем подходит.

Ozon: 4.7/5 (1 200 отзывов) | WB: 4.6/5 (800 отзывов)

"Мягчайшие кроссовки, как ходить по облакам" (Ozon, муж. 43)
"Широкая колодка, подошва не скользит" (WB, муж. 44)

Да / Нет / Возможно?
```

### Правила фазы 4

- По одной модели за раз -- не показывать сетки или галереи
- Показывать в том числе модели, которых нет в промежуточном документе (расширение выборки)
- Показывать "провальные" гипотезы -- они калибруют стилевой профиль
- НЕ адаптировать выборку по ходу -- показывать все запланированные модели
- Сухое подтверждение: "Записал: [Модель] -- [ответ]." и сразу следующая модель
- БЕЗ паузы "продолжаем?" -- пользователь сам остановит, если устанет
- БЕЗ комментариев к выбору -- не обсуждать, не оправдывать, не давить

### Обработка ответов

| Ответ | Действие |
|---|---|
| Да | Записать, показать следующую |
| Нет | Записать, показать следующую |
| Возможно | Записать, показать следующую (обработать в фазе 5) |

---

## Фаза 5: Дожим "возможно"

После показа всех моделей -- вернуться к каждой, отмеченной "возможно".

### Формат дожима

1. Счётчик прогресса: "N1 из N"
2. Те же фото, что в фазе 4 (не искать новые)
3. Название + бренд
4. Вопрос: "Да или нет?" (ТОЛЬКО бинарный, без третьего варианта)

### Пример дожима

```
№1 из 8

**Hoka Clifton 9**
[те же фото]

Да или нет?
```

### Правила фазы 5

- Те же фото, что в первый раз -- не искать новые, не добавлять контекст
- ТОЛЬКО бинарный вопрос -- "Да или нет?" без "возможно"
- Счётчик прогресса -- "N1 из N" для каждой модели
- БЕЗ подсказок -- не говорить "эту мы обсуждали как комфортную, может да?"
- БЕЗ давления -- пользователь принимает решение на том же сигнале, на котором сомневался

---

## Edge-cases

- ЕСЛИ не удалось найти изображения модели -> описать текстово + спросить "продолжить без визуала?"
- ЕСЛИ пользователь устал от отбора -> предложить остановиться, перейти к руководству с уже собранными данными
- ЕСЛИ все модели получили "нет" -> сообщить результат, предложить расширить критерии и повторить ресёрч
- ЕСЛИ "возможно" нет (все ответы бинарные) -> пропустить фазу 5

## Примеры

### Пример 1: Полный цикл визуального отбора

**Вход:** 18 моделей после ресёрча

**Фаза 4:** Показано 18 моделей -> 4 "да", 6 "нет", 8 "возможно"

**Фаза 5:** Дожим 8 "возможно" -> 6 стали "да", 2 стали "нет"

**Результат:** 10 моделей "да", 8 моделей "нет"

### Пример 2: Пользователь устал

**Вход:** 18 моделей, после 12 показанных пользователь говорит "хватит"

**Результат:** Остановить показ. Перейти к buying-guide.md с 12 показанными моделями (4 "да", 3 "нет", 5 "возможно"). Провести дожим 5 "возможно", затем руководство.
