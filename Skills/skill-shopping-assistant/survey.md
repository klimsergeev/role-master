# Опрос (Фаза 1)

## Назначение

Структурированный опрос для сбора недостающих параметров, которые отсеют 70% нерелевантной выдачи.

## Принципы опроса

1. **Не более 3 вопросов на экран** -- снижает нагрузку на пользователя
2. **Конкретные примеры в вариантах** -- помогают "отрезонировать", даже без знания терминологии
3. **Multi-select только где нужен** -- для приоритетов, не для простых выборов
4. **Опция "не важно" в каждом вопросе** -- пользователь не обязан иметь мнение
5. **Обязательно один пункт со свободным текстом** или "что-то ещё?" -- критичные ограничения всплывают именно там
6. **Фундаментальные величины** (размер, вес, объём) -- из [product-parameters.md](product-parameters.md)

## Приоритет способа опроса

1. **Интерактивный** (AskUserQuestion) -- задавать по одному вопросу, ждать ответ
2. **Пакетный** -- нумерованный список, каждый вопрос на отдельной строке (крайний случай)

## Структура вопросов

### Блок 1: Стиль/направление (если has_visual_component = true)

Вопрос с вариантами, включающими конкретные примеры моделей или образов.

Формат:
```
Какой стиль ближе?
1. [Направление A] (примеры: Модель X, Модель Y)
2. [Направление B] (примеры: Модель Z, Модель W)
3. [Направление C] (примеры: Модель V, Модель U)
4. Не важно
```

### Блок 2: Фундаментальные параметры

Параметры зависят от категории товара. Загрузить из [product-parameters.md](product-parameters.md).

### Блок 3: Приоритеты (multi-select + свободный текст)

```
Что критично? (можно выбрать несколько)
1. [Приоритет A]
2. [Приоритет B]
3. [Приоритет C]
4. Что-то ещё? (свободный текст)
```

## Правила

- ЕСЛИ маркетплейс не указан в task-intake -> спросить, предлагая варианты из `recommended_marketplaces` (список формируется динамически через WebSearch в task-intake.md, НЕ захардкоженный)
- ЕСЛИ пользователь добавляет критичное ограничение в свободном тексте -> зафиксировать как приоритетное
- ЕСЛИ пользователь отвечает "не важно" на все вопросы -> не переспрашивать, перейти к ресёрчу с широким покрытием
- НИКОГДА не задавать подвопросы (1.1, 1.2) -- усложняют ответы
- НИКОГДА не объединять два вопроса в один

## Обработка свободного текста

Свободный текст из блока 3 может содержать критичные ограничения, которые перекрывают выбор из блока 1.

Пример: пользователь выбрал "Классические/минималистичные (Samba, Gazelle)", но в свободном тексте написал "без замши, тёмный цвет". Это отвергает Samba и Gazelle (замша), хотя они были выбраны.

- ВСЕГДА проверять свободный текст на конфликты с предыдущими ответами
- ЕСЛИ конфликт найден -> уточнить у пользователя

## Примеры

### Пример 1: Кроссовки (has_visual_component = true)

```
1. Какой стиль кроссовок ближе?
   a) Классические/минималистичные (Samba, Gazelle, 574)
   b) Спортивные ретро (Air Max, 990, Dunk)
   c) Современные технологичные (Ultraboost, 1080, NMD)
   d) Не важно

2. Размер и пол?
   a) Мужские 41-43
   b) Мужские 44+
   c) Женские 36-38
   d) Женские 39+

3. Что критично? (можно несколько)
   a) Комфорт для долгой ходьбы
   b) Внешний вид
   c) Износостойкость
   d) Совместимость с любой одеждой
   e) Что-то ещё?
```

### Пример 2: Батарейки (has_visual_component = false)

Варианты маркетплейсов формируются из `recommended_marketplaces` (определены в task-intake через WebSearch).
Например, WebSearch по "батарейки купить лучшие магазины 2026" вернул: Ozon, Wildberries, Яндекс Маркет, DNS, "Всеинструменты.ру".

```
1. Какой тип батареек?
   a) AA (пальчиковые)
   b) AAA (мизинчиковые)
   c) Другой (укажите)

2. Что важнее?
   a) Самая низкая цена за штуку
   b) Долгий срок службы
   c) Конкретный бренд (укажите)
   d) Не важно

3. Где планируете покупать?
   a) Ozon
   b) Wildberries
   c) Яндекс Маркет
   d) DNS
   e) Всеинструменты.ру
   f) Другой (укажите)
```

> Варианты a)-e) -- из результатов WebSearch, адаптированы под категорию "батарейки". Для другого товара список будет другим.
