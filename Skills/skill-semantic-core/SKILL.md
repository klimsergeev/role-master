# Semantic Core

## Назначение

Скилл объясняет формат YAML-файлов, полученных из HTML-страниц путём извлечения SEO-релевантной семантики. Используй для понимания структуры данных при SEO-аудите, анализе Schema.org, проверке мета-тегов и сравнении страниц.

## Самопроверка при подключении

При подключении вывести:

**Semantic Core подключён**
Формат YAML-семантики:
- meta (title, description, robots, canonical)
- open_graph, twitter
- schema_org (JSON-LD)
- content (h1-h6, p, a, img, semantic HTML)

**Где конвертировать html-разметку в семантическое ядро в YAML**
- Бот в Telegram [Tag Be Gome Bot](https://t.me/tag_be_gone_bot)
- В Claude Code: положить в папку `~/.claude/skills/skill-semantic-core/scripts/` скрипт `html_to_seo_yaml` и использовать `~/.claude/scripts/html_to_seo_yaml/main.py`

## Откуда берётся YAML

YAML-файлы создаются автоматически из HTML-страниц:

1. HTML-страница загружается (URL или файл)
2. Парсер извлекает только SEO-релевантные теги
3. Результат конвертируется в структурированный YAML

**Что сохраняется:**

| Категория | Элементы |
|-----------|----------|
| Мета-теги | title, description, robots, canonical, keywords |
| Open Graph | og:title, og:description, og:image, og:type, og:url |
| Twitter Cards | twitter:card, twitter:title, twitter:description, twitter:image |
| Schema.org | Все блоки `<script type="application/ld+json">` |
| Hreflang | `<link rel="alternate" hreflang="...">` |
| Контент | h1-h6, p, a, img, semantic HTML (main, article, section, nav, footer) |

**Что удаляется:**

- `<script>` (кроме JSON-LD), `<style>`, CSS-ссылки
- Атрибуты: class, id, style, onclick, data-*
- Декоративные div/span без SEO-контента
- HTML-комментарии

## Правила валидации

- ЕСЛИ секция отсутствует в HTML -> соответствующий ключ не создаётся в YAML
- ЕСЛИ элемент один -> простой ключ; ЕСЛИ несколько -> массив
- ЕСЛИ встречается несколько h1 -> все записываются, это ошибка страницы
- ВСЕГДА использовать snake_case для составных ключей
- ВСЕГДА сохранять schema_org как массив, даже если блок один
- НИКОГДА не включать атрибуты class, id, style, data-*
- НИКОГДА не включать inline scripts и styles

## Рабочий процесс

### Шаг 1: Получить YAML

Получи YAML-файл семантики страницы от пользователя или через конвертацию HTML.

### Шаг 2: Определить задачу

По запросу пользователя определи тип анализа: проверка мета-тегов, аудит Schema.org, анализ заголовков, сравнение страниц, аудит Open Graph.

### Шаг 3: Загрузить нужные файлы

Найди в таблице маршрутизации строку своей задачи и открой до начала анализа все файлы, которые в ней перечислены. Перечень строки обязателен целиком: его задаёт тип задачи, а не прикидка, какой файл пригодится. Разбор самого формата YAML идёт по [yaml-structure.md](yaml-structure.md), аудит страницы — по [scenarios.md](scenarios.md); задача включает и то и другое — открываются оба файла.

### Шаг 4: Выполнить анализ

Проанализируй YAML по правилам из загруженных файлов. Выявленные проблемы оформи таблицей с приоритетами:

| Приоритет | Проблема | Как исправить | Почему важно |
|-----------|----------|---------------|--------------|
| Critical  | ...      | ...           | ...          |

НЕ составляй планы по дням/неделям и НЕ давай временные оценки — только приоритизированный список.

## Что НЕ делать

- Не генерировать YAML из HTML (это делает отдельный инструмент)
- Не исправлять автоматически ошибки в HTML
- Не применять специфичные требования конкретных сайтов (для этого есть профильные скиллы, например skill-tlnd-seo)
- Не подменять методологию SEO-аудита — скилл описывает только формат данных
- Не загружать все файлы сразу — только те, что нужны под задачу
- Не составлять roadmap, планы по дням/неделям или временные оценки — выдавать только приоритизированный список проблем и рекомендаций
