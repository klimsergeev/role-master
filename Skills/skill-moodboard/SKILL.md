# Moodboard

## Назначение

Процедура сборки мудборда из настоящих картинок-референсов для двух задач: визуальное направление проекта и коллекция паттернов интерфейса. Картинки собираются из открытых источников, отбираются глазами, раскладываются кладкой на доске в Figma с подписями и источниками; палитра, шрифты и слова настроения идут сводкой поверх картинок.

## Принципы

- **Мудборд — не код.** Результат — доска в Figma (или копия вне Figma) и манифест. Генерация Tailwind config, CSS-переменных, компонентов — задача других инструментов
- **Картинка прежде описания.** Основа мудборда — реальные изображения. Параметры (hex, шрифты, приёмы) — сводка поверх картинок, а не замена им, и у каждого параметра метод: точно, приблизительно (по изображению), визуально
- **Источники прежде всего, агент не рисует.** Палитры и шрифты не выдумываются — извлекаются из источников. Мокапы, паттерны и схемы не рисуются ни в Figma, ни в HTML: нет реального примера — нет карточки, пробел записывается в блок «Чего не нашлось»
- **Внутреннее использование.** Референсы — внутренний материал для поиска направления: не публикуются, не идут в продукт и в материалы для клиентов. Источник — на каждой карточке, водяные знаки и подписи авторов остаются как есть
- **Итеративность.** Доска собирается циклом «собрать -> показать -> уточнить по номерам карточек». Не угадывать идеальный результат с первого раза

## Самопроверка при подключении

При активации скилла, когда задача — мудборд или коллекция паттернов:

1. **Манифест.** ЕСЛИ пользователь указал папку мудборда -> искать в ней `moodboard-*.json`. Найден -> показать тему, число карточек, ссылку на доску и предложить продолжить с ним. Не найден или папка не указана -> спросить, в какую папку сохранять манифест
2. **Chrome.** ЕСЛИ картинки будут собираться в Chrome (поиск картинок, витрины, живые сайты) -> вызвать `tabs_context_mcp` расширения Claude in Chrome. Ответ с вкладками — канал есть; ошибка подключения -> сообщить пользователю, настройка — в skill-chrome-mcp
3. **Figma.** ЕСЛИ доска строится в Figma -> вызвать `whoami`. Ответ с планом и местом — канал есть; нет Remote MCP или права редактирования -> предложить копию вне Figma
4. **Скрипты.** Выполнить `python3 -c "import PIL"` и `python3 -c "import playwright"`. Результат определяет путь: с Pillow — контактный лист и квантование цветов скриптами, без него — запасные пути; с Playwright — мобильный вид и снимок всей страницы, без него — снимки в Chrome

## Рабочий процесс

### Шаг 1: Определить тип, режим и назначение

- **Тип:** визуальное направление или коллекция паттернов — по таблице выбора в [moodboard-templates.md](moodboard-templates.md)
- **Режим:** по ссылкам, поисковый, по описанию настроения — по таблице в [moodboard-workflow.md](moodboard-workflow.md); настроение тоже переводится в поисковые запросы
- **Назначение:** страница Figma Design по умолчанию — нужна ссылка на страницу; FigJam — если пользователь попросил; копия вне Figma — по запросу или если Figma недоступна
- **Папка манифеста** — из самопроверки

ЕСЛИ пользователь явно указал назначение («сделай доску в Figma на странице X», «мудборд в FigJam») -> принять, НЕ переспрашивать.

### Шаг 2: Собрать кандидатов

Источник — по типу задачи, если пользователь его не назвал (таблица в [moodboard-workflow.md](moodboard-workflow.md)). Способы — в [reference-capture.md](reference-capture.md): поиск картинок Google, Pinterest, Google Lens, витрины, снимки живых сайтов и живые корзины в Chrome, Playwright, узлы Figma, файлы пользователя.

### Шаг 3: Отобрать по контактному листу

Скачать исходники кандидатов во временную папку сессии и отобрать глазами по контактному листу или снимкам Chrome: отсев рекламы, логотипов, чужих шагов сценария, дублей; проверка маленьких картинок и перекоса в один продукт. Процедура — [reference-capture.md](reference-capture.md).

### Шаг 4: Показать список кандидатов

Одно сообщение со списком до снимков и раскладки. Подтверждение списка покрывает скачивание и живые корзины — отдельного вопроса не нужно.

### Шаг 5: Захватить и скачать

Снимки живых сайтов и корзин в Chrome, картинки узлов Figma, файлы пользователя; размеры — из файлов; запись в манифест. Сводка — по [element-extraction.md](element-extraction.md).

### Шаг 6: Каркас и загрузка в Figma

Каркас доски шаблоном каркаса из папки скриптов, `upload_assets` с `nodeIds`, отправка `curl` с явным типом каждого файла. Процедура — [figma-output.md](figma-output.md). ЕСЛИ доска строится без Figma -> копия вне Figma по шаблону из [moodboard-templates.md](moodboard-templates.md).

### Шаг 7: Проверить доску

Чтение заливок через `use_figma`, перезаливка пустых, блок «Чего не нашлось», `get_screenshot`. После проверки — удаление локальных картинок; манифест остаётся.

### Шаг 8: Ревью по номерам карточек

Показать скриншот доски и сообщение ревью из [moodboard-workflow.md](moodboard-workflow.md): оставить, убрать, «ещё таких, как N», уточнить подпись, пересобрать группу.

### Шаг 9: Итерировать

Точечные правки по номерам, объяснение изменений, рост версии; не больше 3–4 кругов, затем синтез и финальное предложение. «Ещё таких, как N» — через Google Lens и новые запросы.

### Шаг 10: Финализировать

Проверка по чек-листу готовности из [moodboard-templates.md](moodboard-templates.md), обновление шапки и сводки на доске. Markdown с картинками — только по запросу или если Figma недоступна.

ЕСЛИ пользователь просит использовать skill-figma-mcp или skill-chrome-mcp — загрузить их для справки по инструментам. Порядок шагов мудборда берётся из этого скилла.

## Что НЕ делать

- НЕ рисовать мокапы, паттерны, бейджи, схемы — ни в Figma, ни в HTML. Нет реального примера — пункт в «Чего не нашлось»
- НЕ отбирать кандидатов вслепую — по подписям и адресам выдачи без контактного листа или снимков
- НЕ публиковать референсы и НЕ использовать их в продукте, в презентациях и материалах для клиентов
- НЕ удалять водяные знаки, подписи авторов, стрелки и выделения авторов статей
- НЕ обходить вход, капчу, «необычный трафик», платный доступ — источник пропускается, пользователю сообщается
- НЕ нажимать согласие в баннерах cookie — баннеры скрываются стилями
- НЕ снимать вкладки, кроме вкладки источника, и НЕ оставлять в кадре личные данные
- НЕ оформлять заказ, НЕ платить и НЕ вводить данные в живой корзине; НЕ оставлять добавленный товар в корзине после снимка
- НЕ выгружать каталоги сайтов массово
- НЕ отправлять файлы в Figma без явного типа и НЕ отправлять их через Python `urllib`
- НЕ оставлять картинки на диске после загрузки доски (кроме копии вне Figma) и НЕ класть их в проект
- НЕ генерировать код (Tailwind config, CSS, компоненты)
- НЕ выдумывать hex-коды и названия шрифтов — извлекать с методом или явно помечать «предложение»
- НЕ пропускать ревью с пользователем — даже если «очевидно, что подходит»
- НЕ перезаписывать предыдущие версии доски без подтверждения; отклонённые карточки НЕ удалять из манифеста
- НЕ делать больше 4 итераций без синтеза
- НЕ ссылаться на внешние скиллы design-wizard, color-curator, typography-selector — скилл автономный
- НЕ вызывать `use_figma` без предварительной загрузки `/figma-use`
- НЕ строить доску через Desktop MCP — запись только через Remote

## Примеры

### Пример: Мудборд по ссылкам на сайты (типовой сценарий)

**Запрос:** "Собери мудборд для лендинга. Вдохновение: notion.so, linear.app. Доска — в Figma на странице figma.com/design/xyz789/..."

**Маршрут:** строка «Собрать мудборд визуального направления на доске в Figma Design или FigJam» — [moodboard-workflow.md](moodboard-workflow.md), [reference-capture.md](reference-capture.md), [element-extraction.md](element-extraction.md), [moodboard-templates.md](moodboard-templates.md), [figma-output.md](figma-output.md).

**Результат:**
- Самопроверка: манифеста нет — агент спрашивает папку; `tabs_context_mcp` и `whoami` отвечают
- Сбор: окно Chrome проверено на ширину 1440; первые экраны и фрагменты обоих сайтов сняты в Chrome, стили — скриптом вычисленных стилей через `javascript_tool` (метод «точно»); снимков двух сайтов меньше объёма — агент добирает поиском картинок Google и витринами по словам настроения, которые видны на сайтах
- Отбор: контактный лист, отсев дублей и рекламы; список кандидатов одним сообщением
- Раскладка: доска 4 колонки по 300, группы по смыслу, сводка — палитра плашками с hex, источником и методом, шрифты; «Чего не нашлось»; проверка заливок, скриншот, удаление локальных файлов
- Ревью по номерам, итерации до одобрения

### Пример: Мудборд из поиска картинок Google

**Запрос:** "Нужен мудборд для кофейни в скандинавском стиле, картинки из гугла"

**Маршрут:** строка «Собрать мудборд визуального направления на доске в Figma Design или FigJam» — те же пять файлов.

**Результат:**
- Источник — поиск картинок (атмосфера, фотостиль, фактуры): несколько запросов с разных сторон — интерьер, посуда, свет, вывески
- Кандидаты собраны без кликов скриптом кандидатов из выдачи частями по 25; около 60 исходников скачаны `curl` в 8 потоков, файлы с HTML вместо картинки выпали
- Пины Pinterest из выдачи: для каждого прошедшего — Google Lens по исходнику; у одного первоисточник не найден — пометка и ссылка на пин; стоковые картинки с водяным знаком — как есть
- Отбор по контактным листам: 42 картинки в 5 группах; список одним сообщением
- Доска 4 колонки по 300, палитра — квантованием цветов скриптом с пометкой «приблизительно»
- Ревью: «убрать 3, 7; ещё таких, как 12» — карточки 3 и 7 удалены с доски и отклонены в манифесте; для 12 — Lens, вкладка «Visual matches», плюс новые запросы; новые кандидаты — снова списком до захвата

### Пример: Мудборд по описанию настроения (edge-case)

**Запрос:** "Нужен мудборд для приложения трекера привычек. Хочу минимализм, спокойные тона, ощущение порядка."

**Маршрут:** строка «Собрать мудборд визуального направления на доске в Figma Design или FigJam» — режим «по описанию настроения» в [moodboard-workflow.md](moodboard-workflow.md).

**Результат:**
- Ссылок и темы нет, но картинки всё равно ищутся: настроение переведено в запросы для поиска картинок и витрин («calm minimal habit tracker app UI», «спокойный минималистичный интерфейс, много воздуха»)
- Отбор, список, доска — как в типовом сценарии
- ЕСЛИ поиск ничего не дал бы -> текстовые значения из таблиц «Значения по настроению» с пометкой «предложено на основе описания» и пункт в «Чего не нашлось»; нарисованных карточек нет в любом случае

### Пример: Мудборд из Figma-макета

**Запрос:** "Вот ссылка на макет в Figma: figma.com/design/abc123/... — собери мудборд на основе этого"

**Маршрут:** строка «Собрать мудборд визуального направления на доске в Figma Design или FigJam»; сводка из макета — раздел «Из Figma-макета» в [element-extraction.md](element-extraction.md).

**Результат:**
- Узлы макета: картинки и рендеры — `download_assets`, стили — `get_design_context` (метод «точно»), метка «макет»
- Агент спрашивает, куда класть доску, если в запросе нет страницы; добирает к макету референсы поиском картинок под его настроение
- Отбор добранных кандидатов — по контактному листу; узлы макета в отбор не идут, они заданы пользователем; список — одним сообщением
- Раскладка: узлы макета — отдельной группой с меткой «макет», добранные — по смысловым группам; проверка заливок, скриншот, ревью — как в типовом сценарии

### Пример: Коллекция FOMO-плашек на реальных снимках

**Запрос:** "Создай мудборд с примерами FOMO-плашек. Делай борд в Figma на странице figma.com/design/xyz789/...?node-id=123-456"

**Маршрут:** строка «Собрать коллекцию паттернов интерфейса на доске в Figma Design или FigJam» — пять файлов.

**Результат:**
- Тип — коллекция паттернов, назначение — Figma (указано явно, не переспрашивается)
- Сбор: поиск картинок по запросам «осталось мало товара плашка», «таймер до конца акции на карточке товара», «сейчас смотрят N человек отель»; снимки живых сайтов маркетплейсов и бронирования в Chrome — фрагменты карточки товара и выдачи через `zoom`
- Отбор по контактному листу: отсеяны рекламные баннеры и статьи без экранов
- Группы — по месту в сценарии: «на карточке товара», «в выдаче каталога», «в корзине», «на странице бронирования»; 3 колонки по 360
- Плашки не рисуются: группа «в корзине» набрала 3 примера — недобор записан в «Чего не нашлось»
- Визуальные константы и «делай / не делай» — с номерами карточек

### Пример: Коллекция паттернов интерфейса «оплата частями в корзине»

**Запрос:** "Собери полноценный мудборд на 20–30 примеров: как российский e-commerce показывает оплату частями на первых шагах оформления, сфера любая"

**Маршрут:** строка «Собрать коллекцию паттернов интерфейса на доске в Figma Design или FigJam» — пять файлов; раздел «Живые экраны корзины и оформления» в [reference-capture.md](reference-capture.md).

**Результат:**
- Сбор: пять запросов в поиске картинок — «Яндекс Сплит в корзине», «Долями в корзине», «Ozon Рассрочка в корзине», «Подели на оформлении», «Wildberries рассрочка в корзине»; около 100 кандидатов со страницами-источниками
- Отбор по контактным листам: отсеяны реклама сервисов, логотипы, карточки товаров, экраны после оплаты и личные кабинеты
- Перекос: один сервис занял больше трети отобранного — агент добирает живыми корзинами: на нескольких сайтах кладёт по товару в корзину, снимает корзину и первый шаг оформления, убирает товар; сайты, где корзина требует входа, пропущены и названы
- Две картинки короче 500 px оставлены с пометкой «маленькое разрешение» — других источников этих экранов нет; снимки из статей со стрелками авторов — как есть, видно по источнику
- Доска: 4 группы по месту в сценарии — «Частями в итоге корзины», «выбор срока на шаге оформления», «среди способов оплаты», «виджет графика платежей у магазина»; 3 колонки по 360; 24 карточки; «Чего не нашлось» — что не удалось выровнять

### Пример: Figma недоступна и Pillow не установлен (edge-case)

**Запрос:** "Собери референсы картинками для страницы тарифов, Figma у меня сейчас не подключена"

**Маршрут:** строка «Собрать мудборд или коллекцию без Figma» — [moodboard-workflow.md](moodboard-workflow.md), [reference-capture.md](reference-capture.md), [element-extraction.md](element-extraction.md), [moodboard-templates.md](moodboard-templates.md).

**Результат:**
- Самопроверка: `python3 -c "import PIL"` падает — контактный лист и квантование недоступны
- Отбор — запасным путём: выдача и страницы просматриваются снимками Chrome; скачивание — после подтверждения списка; размеры — `sips`
- Палитра — визуально, с пометкой метода
- Выдача — копия вне Figma: markdown по шаблону, картинки в `refs/` и манифест в папке пользователя; временная папка сессии удалена

## Формат выдачи

После каждого шага — краткий статус:

```
Мудборд v[N]: [тема] — [визуальное направление / коллекция паттернов]
Доска: [ссылка на страницу Figma / FigJam / копия вне Figma: путь]
Референсы на доске: [N] — поиск картинок [a], продукт [b], концепт [c], библиотека [d], макет [e], файл пользователя [f]
Отклонено: [K] (номера)
Чего не нашлось: [кратко / всё нашлось]
Манифест: [путь]
Статус: [кандидаты / на ревью / финализирован]
```

После финализации:

```
Мудборд финализирован: [ссылка на доску]
Референсы: [N] по меткам; отклонено [K]
Сводка: палитра [N цветов, методы], шрифты [N], слова настроения [N] — или визуальные константы и делай/не делай для коллекции
Чего не нашлось: [пункты]
Манифест: [путь]; локальные картинки удалены: [да / копия вне Figma: путь]
Пользователь одобрил: [да/нет]
```
