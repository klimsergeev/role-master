# Шаблоны мудборда

## Назначение

Готовые markdown-шаблоны для чернового и финального мудборда. Используются агентом при генерации документа — заполняются реальными данными из этапа извлечения элементов.

## Выбор шаблона

| Запрос пользователя | Какой шаблон | Критерий |
|---|---|---|
| «Создай мудборд для лендинга», «подбери палитру и стиль» | **Стандартный мудборд** | Визуальное направление для проекта: палитра, типографика, лейаут, настроение |
| «Собери примеры FOMO-плашек», «покажи паттерны онбординга» | **Тематическая коллекция паттернов** | Коллекция примеров одного типа: категории, вариации, do/don't |
| «Мудборд с вдохновением для кнопок и форм» | **Тематическая коллекция** | Конкретный UI-элемент, а не весь проект |
| «Визуальное направление + примеры карточек» | **Стандартный + секция паттернов** | Гибрид: основной мудборд проекта, но одна секция развёрнута как коллекция |

ЕСЛИ непонятно -> спросить пользователя: «Нужно общее визуальное направление или коллекция конкретных паттернов?»

## Черновая тематическая коллекция паттернов

Используется, когда задача — собрать примеры конкретного типа UI-паттернов (FOMO, онбординг, empty states, pricing и т.п.), а не визуальное направление для проекта.

```markdown

## Тема и контекст

[Описание темы: что за паттерны, где применяются, зачем нужны]

## Источники

| Источник | Что берём | Тип |
|---|---|---|
| [URL или имя] | [Конкретный паттерн/приём] | [статья / реальный продукт / дизайн-площадка] |
| [URL или имя] | [Конкретный паттерн/приём] | [тип] |

## Категория: [Название подтипа]

### [Название паттерна]

- **Описание:** [Что делает, как работает, какую задачу решает]
- **Визуальные характеристики:**
  - Цвета: [hex-коды, если извлечены] — [роль: фон бейджа, цвет текста, акцент]
```

## Правила заполнения шаблонов

### Цвета

- Каждый hex-код — реальный, извлечённый из источника, или явно помеченный как «предложение»
- Минимум 5 ролей: primary, secondary/accent, background, text primary, text secondary
- Дополнительные роли (surface, border, success, error) — по необходимости

### Типографика

- Указывать конкретные названия шрифтов (Inter, не «гротеск»)
- ЕСЛИ шрифт не удалось идентифицировать -> описать стиль и предложить ближайший аналог с пометкой «предложение»
- Пара headline + body обязательна; monospace — если проект технический

### UI-паттерны

- Описывать конкретно: «горизонтальная навигация с прозрачным фоном, фиксированная при скролле» вместо «современная навигация»
- Для каждого паттерна — заметки для имплементации (как реализовать)

### Лейаут

- Указать тип сетки, философию spacing, структуру секций
- ЕСЛИ из источников не ясно -> предложить на основе типа продукта с пометкой

### Ключевые слова настроения

- Минимум 4, максимум 6 слов
- Без противоречий (не «минималистичный» и «избыточный» одновременно)
- Слова из описания пользователя имеют приоритет

### Чего избегать

- Минимум 2 антипаттерна
- Конкретно: «тёмный фон с неоновыми акцентами» вместо «слишком яркое»

## Правила заполнения тематической коллекции

### Категории

- Минимум 2 категории (подтипа паттернов)
- Категории должны быть взаимоисключающими — один паттерн не попадает в две категории
- Название категории = тип приёма, а не источник: «Scarcity — ограниченный запас», а не «Паттерны с Booking.com»

### Паттерны внутри категорий

- Минимум 2 паттерна на категорию
- Каждый паттерн — конкретный: «Бейдж "Осталось N штук" с иконкой fire» вместо «Индикатор ограниченности»
- Визуальные характеристики обязательны: цвета (hex, если извлечены), типографика, форма, расположение
- Источник обязателен для каждого паттерна
- Пример реального текста (с сайта-источника) — если удалось извлечь

### Визуальные константы

- Обобщить повторяющиеся визуальные решения из всех паттернов
- Цвета — hex-коды с наблюдением, почему именно эти (например, красный для urgency — конвенция)
- Типографика — общие черты (bold, uppercase, compact)
- Иконография — типичные иконки для этой темы

### Do / Don't

- Минимум 2 пункта в каждой секции
- Конкретно: «Показывать реальное количество оставшихся товаров, а не всегда "Осталось 2"» вместо «Быть честным»
- Don't — с объяснением последствий: «Не показывать 5 FOMO-элементов одновременно — эффект ослабевает, пользователь перестаёт верить»
