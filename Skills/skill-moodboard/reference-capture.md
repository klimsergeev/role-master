# Захват картинок-референсов

## Назначение

Процедура получения настоящих картинок для мудборда: где искать кандидатов, как их скачать и отобрать, как снять живой сайт и корзину, как вести манифест и добирать «ещё таких, как N». Читается при любом создании мудборда или коллекции паттернов, при доборе референсов и при итерациях, которые меняют состав доски.

Агент по этой процедуре ничего не рисует: на доску идут только картинки, полученные одним из способов ниже. Нет реального примера — нет карточки, пробел записывается в блок «Чего не нашлось».

---

## Правила использования

- Референсы — материал только для внутренней доски: не публиковать, не использовать в продукте, в презентациях и материалах для клиентов, в маркетинге
- Источник на каждой карточке: домен со ссылкой на страницу, где опубликована картинка; для витрин — автор; для пина без найденного первоисточника — пометка «первоисточник не найден» и ссылка на пин
- Водяные знаки, подписи авторов, стрелки и выделения авторов статей не удаляются; стоковые картинки с водяным знаком берутся как есть
- Вход, капча, «необычный трафик», платный доступ не обходятся: источник пропускается, пользователю сообщается, какой и почему. Входит в учётные записи только сам пользователь — агент пароли не вводит
- Баннеры cookie скрываются стилями (шаг 3 процедуры снимка), кнопка согласия не нажимается
- В Chrome снимается только вкладка источника; личные данные в кадре (аватар, имя, почта в шапке сайта, адрес в корзине) обрезаются
- Нагрузка на сайты: без массовой выгрузки каталогов — только кандидаты под эту доску
- Живая корзина — только добавление товара; оформление заказа, оплата и ввод данных не выполняются, товар после снимка убирается (раздел «Живые экраны корзины и оформления»)
- Картинки лежат во временной папке сессии, не в проекте, и удаляются после проверки доски (раздел «Удаление локальных файлов»)

## Подготовка

### Временная папка сессии

- Все скачанные исходники, снимки, контактные листы и результаты скриптов складываются во временную папку сессии: папка для временных файлов, которую даёт среда, а если её нет — новая папка из `mktemp -d`
- Внутри: `img/` — картинки-кандидаты, имя файла = номер кандидата без расширения (`01`, `02`, …); контактные листы и рабочие списки (`cand.tsv`, `up.txt`) — в корне папки
- В папку проекта и в документы проекта картинки не кладутся

### Окно Chrome

Окно, которое расширение Claude in Chrome создаёт для своей группы вкладок, может открыться узким (360×800) и за краем экрана. В таком окне `resize_window` отвечает «успешно», ничего не меняя, а сайт отдаёт мобильную вёрстку.

1. Через `javascript_tool` прочитать `innerWidth`, `innerHeight`, `screenY`, `screen.availHeight`
2. ЕСЛИ ширина не 1440 -> `resize_window` на 1440×900 и прочитать `innerWidth` ещё раз
3. ЕСЛИ ширина не изменилась -> попросить пользователя вынести окно с вкладкой на экран (перетащить вкладку в обычное окно), затем повторить `resize_window` — после переноса он срабатывает
4. Ширина окна для снимков — 1440: при ширине до 1440 снимок сохраняется без уменьшения, шире — уменьшается до размера изображения в ответе инструмента

### Правила `javascript_tool`

- Из скриптов возвращать только `origin + pathname` ссылок: значение со строкой запроса или похожее на токен расширение блокирует целиком (`[BLOCKED: …]`)
- Длинный ответ обрезается (`[TRUNCATED]`): результат складывать в переменную окна (`window.__q`) и забирать частями (`window.__q.slice(25, 50)`)
- Имя автора из DOM витрины может прийти как `[BLOCKED: Sensitive key]` — автора брать из заголовка вкладки

## Поиск картинок Google

Основной источник для атмосферы, фотостиля, фактур, иллюстраций и для экранов продуктов, опубликованных в статьях и обзорах. Работает в Chrome пользователя, без входа.

1. Составить несколько запросов по одной теме с разных сторон: сервис, продукт, место в сценарии пользователя. Язык запросов — язык рынка задачи. Пример для оплаты частями в российской рознице: «Яндекс Сплит в корзине», «Долями в корзине», «Ozon Рассрочка в корзине», «Подели на оформлении», «Wildberries рассрочка в корзине»
2. Открыть выдачу отдельным вызовом `navigate`: `https://www.google.com/search?q=<запрос>&udm=2`. Подождать около 2 секунд и проверить адрес вкладки, а не ответ `navigate`. ЕСЛИ открылась капча или «необычный трафик» -> не обходить, сообщить пользователю, перейти к другим источникам
3. Собрать кандидатов скриптом [scripts/google-candidates.js](scripts/google-candidates.js) через `javascript_tool`, без кликов. Условие применимости: Chrome на связи, открыта страница выдачи картинок. Скрипт возвращает первые 25 пар «исходник, страница-источник» и кладёт весь список в `window.__q`; следующие части — `window.__q.slice(25, 50)` и далее. Запасной путь, если скрипт вернул пустой список: кликать по результатам по одному — справа открывается панель предпросмотра с `img` исходного файла и ссылкой «Visit» на страницу-источник; исходник в панели загружается не сразу, читать через 1,5–3 секунды после клика; аватар пользователя Google (`lh3.google.com`, 32×32) отбрасывать
4. Записать кандидатов в манифест со статусом `candidate` (исходник, страница-источник, запрос) и в `cand.tsv` строками «номер<TAB>исходник» для скачивания
5. Повторить для каждого запроса, продолжая сквозную нумерацию

Правила:
- Превью выдачи (`encrypted-tbn0.gstatic.com`, около 600 px по длинной стороне) на доску не идут — скрипт их уже отбрасывает
- Размеры картинки из данных выдачи ненадёжны (высота и ширина бывают перепутаны) — размеры брать из скачанного файла
- Источник на карточке — страница, где картинка опубликована, а не адрес файла
- Подписи и тексты в коде выдачи для отбора ненадёжны: отбор — только глазами (раздел «Отбор по контактному листу»)
- Метка карточки — «поиск картинок»

## Pinterest

- Прямой поиск Pinterest без входа закрыт окном входа — не обходится. Он работает, только если пользователь сам вошёл в Pinterest в этом Chrome
- Пины приходят и через поиск картинок Google: исходники вида `i.pinimg.com/736x/…` со ссылкой на пин скачиваются без входа
- У каждого пина, который проходит на доску, искать первоисточник через Google Lens (раздел ниже). Нашёлся — на карточке источник и автор первоисточника. Не нашёлся — пометка «первоисточник не найден» и ссылка на пин
- Метка — «поиск картинок»; ЕСЛИ первоисточник — работа на витрине -> «концепт»

---

## Google Lens

Адрес: `https://lens.google.com/uploadbyurl?url=<ссылка на исходник без строки запроса>`. Открывает поиск по картинке без загрузки файла (переадресация на выдачу Google с `udm=26`).

Две задачи:
- **Первоисточник картинки,** найденной на странице-пересказе или на Pinterest: обзор ИИ сверху и ряд точных совпадений называют сайт и автора (так находится, например, автор работы на Behance для картинки, которую поиск привёл с сайта-подборки). Первоисточник найден -> на карточке его страница и автор
- **«Ещё таких, как N»:** вкладка «Visual matches» показывает похожие картинки с разных сайтов; клик по результату открывает ту же панель предпросмотра, что в поиске картинок, — с исходником и ссылкой «Visit». Используется вместе с новыми текстовыми запросами (раздел «Добор "ещё таких, как N"»)

## Витрины

Dribbble, Behance и похожие — источник интерфейсных концептов. Метка — «концепт».

- Исходник — `img` самой работы на её странице, ссылка без строки запроса
- Dribbble: исходник — `cdn.dribbble.com/userupload/<id>/file/<hash>.png`; в `srcset` тот же путь с разными строками запроса, а путь без строки запроса отдаёт исходник крупнее наибольшего размера в `srcset`
- Dribbble: `og:image` ведёт не на работу, а на общую картинку площадки — не использовать
- Автор — из заголовка вкладки («… by <автор> on Dribbble»)
- Для Behance и других витрин действует то же общее правило (исходник — `img` работы без строки запроса); особенности выше подтверждены только для Dribbble
- ЕСЛИ витрина требует вход, а пользователь не вошёл -> источник пропускается, пользователю сообщается

## Живые сайты в Chrome

Основной способ для конкретных продуктов и конкурентов: снимок первого экрана или фрагмента живого сайта в Chrome пользователя. Метка — «продукт»; экраны из библиотек паттернов (Mobbin, Page Flows и похожих) снимаются так же и получают метку «библиотека».

### Процедура снимка

1. Проверить окно Chrome (раздел «Окно Chrome»): ширина 1440
2. Открыть страницу отдельным вызовом `navigate`, подождать около 2 секунд, проверить адрес вкладки. Внутри пакета `browser_batch` переход может ответить «Navigated», не сменив страницу
3. Скрыть баннеры cookie и всплывающие окна стилями через `javascript_tool`: вставить на страницу элемент `style` с набором селекторов из константы `HIDE_OVERLAYS_CSS` в [scripts/capture.py](scripts/capture.py). Кнопку согласия не нажимать
4. Прокрутить страницу вниз и вернуться наверх, чтобы подгрузились отложенные картинки
5. Увести курсор за пределы содержимого (`hover` в угол окна): курсор попадает в снимок
6. Снять `computer` → `screenshot` с `save_to_disk`, без `scale` (`scale` уменьшает и сохранённый файл). Снимок делать отдельным вызовом: снимок внутри пакета `browser_batch`, который завершился ошибкой, на диск не сохраняется. Фрагмент вместо первого экрана — действие `zoom` с областью в координатах последнего снимка; область не может выходить за видимую часть окна даже на пиксель; `zoom` сохраняет PNG
7. Взять путь файла из ответа: файл лежит во временной папке системы `…/T/claude-chrome-screenshots-<суффикс>/` (JPEG). Скопировать его в `img/` временной папки сессии под номером карточки и запомнить путь папки снимков — она удаляется в конце
8. ЕСЛИ в кадр попали личные данные -> переснять фрагментом без них
9. Снять стили страницы, пока она открыта: процедура — раздел «Со страницы в Chrome» в [element-extraction.md](element-extraction.md)

### Живые экраны корзины и оформления

Для коллекций паттернов интерфейса корзины, оформления и оплаты. Свежие экраны с живых сайтов дополняют снимки из статей и обзоров, у которых неизвестна дата и бывают стрелки авторов.

Агент может положить товар в корзину на сайте в Chrome пользователя, чтобы снять настоящую корзину и первый шаг оформления. Сайты для этого перечисляются в списке кандидатов (раздел «Список кандидатов для пользователя»), подтверждение списка покрывает и этот шаг.

1. Открыть карточку любого товара на сайте. ЕСЛИ для корзины нужен вход, а пользователь не вошёл -> сайт пропускается, пользователю сообщается
2. Запомнить, что уже лежит в корзине пользователя: эти товары не трогать
3. Добавить один товар в корзину — только это действие
4. Снять корзину по процедуре снимка; ЕСЛИ первый шаг оформления открывается без ввода данных -> снять и его
5. Убрать из корзины добавленный товар и проверить, что корзина вернулась к прежнему составу
6. ЕСЛИ на экране видны адрес, имя, телефон пользователя -> снять фрагментом без них

НИКОГДА: оформлять заказ, нажимать оплату, вводить данные, применять промокоды, оставлять добавленный товар в корзине.

### Снимок через Playwright, если установлен

Необязательное улучшение: даёт мобильный вид шириной 390 с двойной плотностью и снимок всей страницы. Без него скилл полностью рабочий.

1. Проверить условие применимости: `python3 -c "import playwright"` завершается без ошибки. Устанавливать Playwright не нужно
2. ЕСЛИ условие выполнено -> запустить [scripts/capture.py](scripts/capture.py): `python3 "<папка скилла>/scripts/capture.py" --url <адрес> --out "<временная папка>/shots" --id <номер>-<домен> --preset desktop|mobile --mode viewport|full|element`; для фрагмента — `--mode element --selector "<селектор>"`; для тёмной темы — `--scheme dark`; для фото и крупных кадров — `--jpeg`. Результат — картинка и JSON с вычисленными стилями (метод «точно»)
3. ЕСЛИ модуль не найден или запуск упал (нет браузера для Playwright, сайт не пускает) -> запасной путь: процедура снимка в Chrome выше
4. Мобильный вид живого сайта без Playwright не снимается: мобильные паттерны берутся из поиска картинок, библиотек паттернов и витрин

## Скачивание

Исходники кандидатов скачиваются во временную папку сессии сразу после сбора — для контактного листа. Отдельного вопроса скачивание не требует: подтверждение списка кандидатов покрывает и остальное — снимки сайтов, живые корзины, загрузку на доску.

1. `cand.tsv` — строки «номер<TAB>исходник»; `DIR` — папка `img/` во временной папке сессии. Путь `DIR` — без пробелов: `xargs -n 2` делит строку по пробелам, и путь с пробелом ломает пары «адрес, файл»
2. Скачать параллельно в 8 потоков, с заголовком `User-Agent` браузера:

```bash
while IFS=$'\t' read -r n url; do echo "$url $DIR/$n"; done < cand.tsv \
  | xargs -P 8 -n 2 sh -c 'curl -sS -L --max-time 40 -A "Mozilla/5.0" -o "$1" "$0"'
for f in "$DIR"/*; do case "$(file -b --mime-type "$f")" in image/*) ;; *) rm "$f";; esac; done
```

3. Проверять тип каждого файла по содержимому (`file --mime-type`, вторая строка команды), а не код ответа: часть сайтов отдаёт 403 или 404 с HTML вместо картинки. Такие файлы удаляются, кандидаты выпадают — в манифесте у них статус `rejected` с причиной
4. Размеры каждого файла — из самого файла: Pillow (`Image.open(f).size`), ЕСЛИ Pillow не установлен -> на macOS `sips -g pixelWidth -g pixelHeight <файл>` (читает JPEG, PNG и WebP). Записать размер в манифест

## Отбор по контактному листу

Шаг обязательный: подписи в данных выдачи ненадёжны, а большая часть выдачи по интерфейсной теме — реклама сервисов. Отбор вслепую, по одним адресам и подписям, не делается.

1. Проверить условие применимости: `python3 -c "import PIL"` завершается без ошибки
2. ЕСЛИ Pillow установлен -> запустить [scripts/contact_sheet.py](scripts/contact_sheet.py): `python3 "<папка скилла>/scripts/contact_sheet.py" "<временная папка>"`. Скрипт берёт файлы из `img/` и кладёт в корень папки листы `sheet1.jpg`, `sheet2.jpg`, … — миниатюры по 24 на лист с крупными номерами. Просмотреть каждый лист через Read
3. ЕСЛИ Pillow не установлен -> запасной путь: просматривать выдачу и страницы-источники снимками Chrome (без `save_to_disk`), сверяя кандидатов по порядку в выдаче; скачивание в этом случае идёт после подтверждения списка
4. Отсеять: рекламу и баннеры сервисов, логотипы, экраны не того шага сценария, дубли
5. Картинки из статей и обзоров допустимы: на карточке это видно по источнику, стрелки и выделения авторов статей не убираются
6. Картинки короче 500 px по длинной стороне — только если другого источника этого экрана нет, с пометкой «маленькое разрешение» в подписи
7. Проверить перекос: ЕСЛИ один продукт или сервис занял больше трети отобранного -> добрать примеры других новыми запросами, через Google Lens и снимками живых сайтов. Не нашлось -> записать в «Чего не нашлось»
8. Сверить объём с моделью доски из [moodboard-workflow.md](moodboard-workflow.md): ЕСЛИ отобранного меньше половины нужного -> сказать пользователю, предложить другие запросы или попросить ссылки
9. Квот на доли источников и типов нет: состав задаёт задача

Показывается одним сообщением до снимков и загрузки на доску:

```
Кандидатов: [N] (из [M] найденных). Группы: [перечень].

№  | Что                                   | Откуда                    | Метка           | Способ
01 | Блок «Частями» в итоге корзины        | review.example            | поиск картинок  | исходник из выдачи
07 | Корзина с выбором срока               | shop.example              | продукт         | живая корзина в Chrome
12 | Онбординг из трёх экранов, автор X    | dribbble.com/shots/…      | концепт         | исходник с витрины

Пропущены: [источник — причина: вход, капча, платный доступ]
Живые корзины: положу по одному товару на [сайты], сниму корзину и первый шаг оформления, уберу товар.
Подтверждаешь список? Можно убрать номера или добавить источники.
```

- ЕСЛИ пользователь подтвердил -> снимки, живые корзины, раскладка; отдельного вопроса про скачивание не задаётся
- ЕСЛИ скорректировал -> обновить список и манифест, показать снова одним сообщением
- Отклонённые кандидаты удаляются из `img/`, в манифесте остаются со статусом `rejected`

## Манифест

Небольшой JSON без картинок. Хранится в папке, которую указал пользователь, под именем `moodboard-<тема>.json`, и остаётся после загрузки доски: по нему идут итерации «убрать N», «ещё таких, как N» и повторное скачивание для копии вне Figma.

```json
{
  "board": { "title": "Moodboard — Трекер привычек", "version": 1, "type": "direction", "figma": { "fileKey": "…", "pageId": "…", "boardId": "…" } },
  "items": [
    {
      "n": 1,
      "group": "Атмосфера",
      "label": "продукт",
      "source_url": "https://linear.app",
      "image_url": null,
      "author": null,
      "capture": "снимок живого сайта в Chrome, первый экран, 1440",
      "size": [1440, 723],
      "take": "Тёмный фон без чистого чёрного, приглушённый акцент",
      "notes": [],
      "extracted": {
        "colors": { "method": "computed-styles", "values": ["#08090A", "#0F1011", "#5E6AD2"] },
        "fonts": { "method": "computed-styles", "values": ["Inter Variable 400", "Inter Variable 510"] }
      },
      "status": "approved",
      "figma_node_id": "123:456",
      "file": null
    }
  ]
}
```

| Поле | Что в нём |
|---|---|
| `board.type` | `direction` — визуальное направление, `patterns` — коллекция паттернов |
| `board.version` | Номер круга ревью; растёт на каждой итерации |
| `group` | Смысловая группа; для коллекции — место в сценарии пользователя |
| `label` | Метка типа: «поиск картинок», «продукт», «концепт», «библиотека», «макет», «файл пользователя» |
| `source_url` | Страница, где картинка опубликована (для пина без первоисточника — пин) |
| `image_url` | Адрес исходного файла без строки запроса; для снимков — `null`. Нужен для Google Lens и повторного скачивания |
| `author` | Автор для витрин и найденных первоисточников |
| `capture` | Способ получения словами: исходник из выдачи, исходник с витрины, снимок живого сайта в Chrome, живая корзина в Chrome, снимок через Playwright, узел Figma, файл пользователя |
| `size` | Ширина и высота из скачанного файла |
| `take` | «Что взять» одной строкой |
| `notes` | Пометки: «маленькое разрешение», «первоисточник не найден», «снимок из статьи» |
| `extracted` | Параметры с методом у каждого: раздел «Извлечение параметров» |
| `status` | `candidate` → `captured` → `approved` / `rejected`; отклонённые не удаляются — это история ревью, у них в `notes` причина |
| `figma_node_id` | id прямоугольника карточки на доске |
| `file` | Имя файла в копии вне Figma (`refs/…`); `null`, если копии нет |

---

## Извлечение параметров

Метод зависит от того, как получена картинка, и всегда записывается в манифест у каждого параметра:

| Метод в манифесте | Как называется на доске | Когда |
|---|---|---|
| `computed-styles` | точно | Снимок живого сайта в Chrome со стилями через `javascript_tool`, снимок через Playwright |
| `figma` | точно | Узел Figma, `get_design_context` |
| `image-quantize` | приблизительно, по изображению | Исходники из выдачи и с витрин, файлы пользователя, снимки без доступа к стилям |
| `visual` | визуально | Шрифт по картинке, композиция, настроение |

Процедуры извлечения и скрипты — в [element-extraction.md](element-extraction.md).

## Добор «ещё таких, как N»

1. Взять из манифеста карточку N: исходник, страницу-источник, продукт или автора, группу
2. ЕСЛИ у карточки есть `image_url` -> открыть Google Lens по исходнику, вкладку «Visual matches»; кандидатов читать из панели предпросмотра (исходник и ссылка «Visit»). ЕСЛИ это снимок без `image_url` -> перейти к шагу 3
3. Добавить новые текстовые запросы в поиске картинок: тот же сервис у других продуктов, то же место в сценарии, конкуренты продукта с карточки N; для витрины — другие работы автора и связанные работы
4. Скачать, отобрать по контактному листу по тем же правилам, включая проверку перекоса
5. Показать новых кандидатов списком одним сообщением; после подтверждения — добавить на доску в группу карточки N (продолжение группы — в [figma-output.md](figma-output.md)) и записать в манифест

## Удаление локальных файлов

После проверки доски (все прямоугольники с заливкой-картинкой, `get_screenshot` принят):

1. ЕСЛИ пользователь попросил копию вне Figma или Figma недоступна -> сначала переложить одобренные картинки в папку `refs/` рядом с манифестом в папке пользователя, с именами `NN-домен-что.ext` (расширение — по `file --mime-type`), и записать имена в поле `file`
2. Удалить временную папку сессии целиком: скачанные исходники, копии снимков, контактные листы, результаты `capture.py`
3. Удалить папки снимков Chrome `…/T/claude-chrome-screenshots-<суффикс>/` — только те, чьи пути пришли в ответах инструмента в этой сессии
4. Манифест остаётся

ЕСЛИ копию вне Figma попросили после удаления -> скачать одобренные картинки заново по `image_url` из манифеста, снимки переснять.
