# Извлечение дизайн-элементов

## Назначение

Процедура получения сводки поверх картинок мудборда — палитры, шрифтов, приёмов и слов настроения — из живых страниц, узлов Figma и самих картинок. Сводка дополняет референсы на доске, а не заменяет их; у каждого элемента записывается метод, которым он получен.

## Метод извлечения — обязательное поле

Каждый извлечённый элемент (цвет, шрифт, приём) записывается вместе с методом. Без метода элемент в сводку не попадает.

| Метод | Как называется на доске | Точность | Откуда |
|---|---|---|---|
| `computed-styles` | точно | Точная | Вычисленные стили живой страницы: Chrome через `javascript_tool` или Playwright |
| `figma` | точно | Точная | `get_design_context` узла Figma |
| `image-quantize` | приблизительно, по изображению | Приблизительная | Квантование цветов картинки скриптом |
| `visual` | визуально | Оценка | Взгляд на картинку: цвет без скрипта, шрифт по картинке, композиция, настроение |

Метод пишется в манифест у каждого параметра (схема — в [reference-capture.md](reference-capture.md), раздел «Манифест») и показывается на доске рядом со значением.

## Категории элементов

### Цвета

Что извлекать:
- **Primary** — основной цвет бренда или интерфейса (кнопки, ссылки, акценты)
- **Secondary** — дополнительный цвет (состояния наведения, иконки, второстепенные элементы)
- **Accent** — яркий акцент для призывов к действию и выделения
- **Background** — фон страницы
- **Surface** — фон карточек, модальных окон, приподнятых элементов
- **Text Primary** — основной текст и заголовки
- **Text Secondary** — подписи, мета-информация, приглушённый текст

Формат: hex-код (#RRGGBB) + роль + источник (номер карточки) + метод.

### Типографика

Что извлекать:
- **Headline font** — шрифт заголовков
- **Body font** — шрифт основного текста
- **Weight** — используемые начертания
- **Размерные наблюдения** — крупные или мелкие заголовки, плотный или свободный текст
- **Spacing/tracking** — межстрочный интервал, трекинг

Формат: название шрифта + вес + наблюдения + источник + метод. Шрифт по картинке названием не угадывается: описывается класс («геометрический гротеск, крупный кегль, плотный трекинг») и предлагается аналог с пометкой «предложение», метод — визуально.

### UI-паттерны и приёмы

Что извлекать:
- **Навигация** — тип, фиксированная или нет, фон
- **Карточки** — скругление, тень, рамка, отступы
- **Кнопки** — форма, стиль, размеры
- **Секции лейаута** — во всю ширину или в контейнере, чередование фонов, первый экран
- **Декоративные элементы** — градиенты, фактуры, иллюстрации
- **Формы** — стиль полей, подписей, ошибок

Формат: название приёма + конкретное описание + номера карточек, где он виден. Приём описывается словами и номерами карточек — не перерисовывается.

### Настроение / атмосфера

- **Ключевые слова** — 4–6 слов, описывающих ощущение
- **Эмоциональный отклик** — какое чувство вызывает подборка
- **Черты характера бренда** — если просматриваются

Формат: список слов + краткое описание. Метод — визуально.

## Методы извлечения по типу источника

### Со страницы в Chrome

Для живых сайтов, которые снимаются в Chrome пользователя. Метод — точно.

1. Условие применимости: Chrome на связи, страница источника открыта, баннеры скрыты, страница прокручена (процедура снимка — в [reference-capture.md](reference-capture.md), раздел «Живые сайты в Chrome»)
2. Выполнить [scripts/styles.js](scripts/styles.js) через `javascript_tool`. Скрипт обходит видимые элементы и возвращает фоны, взвешенные по площади, цвета текста и шрифты, взвешенные по числу текстовых узлов, цвета рамок и заголовок страницы
3. Роли: фон и поверхности — фоны с наибольшей площадью; основной и второстепенный текст — самые частые цвета текста; шрифты заголовков и текста — по весам и частоте
4. Акцент скрипт автоматически не выделяет: найти на снимке кнопки и ссылки и сверить их цвет с цветами из ответа; ЕСЛИ цвета акцента в ответе нет -> взять его с картинки по разделу «Из изображения» с методом «приблизительно»
5. Поле `og_image` в ответе может прийти как `[BLOCKED: …]` — для сводки и поиска исходников оно не нужно
6. Запасной путь, ЕСЛИ Chrome недоступен или скрипт вернул ошибку: снимок через Playwright (раздел ниже), а без него — извлечение из снимка по разделу «Из изображения»

### Со страницы через Playwright, если установлен

1. Условие применимости: `python3 -c "import playwright"` завершается без ошибки
2. [scripts/capture.py](scripts/capture.py) вместе со снимком пишет рядом `<id>.json` с теми же вычисленными стилями (поле `extracted`) — запуск описан в [reference-capture.md](reference-capture.md), раздел «Снимок через Playwright, если установлен»
3. Роли и акцент — по шагам 3–4 раздела «Со страницы в Chrome». Метод — точно
4. Запасной путь, ЕСЛИ условие не выполнено: раздел «Со страницы в Chrome»

### Из Figma-макета

1. `get_design_context` узла — цвета, шрифты, размеры, отступы. Метод — figma (точно)
2. `get_screenshot` узла — общее впечатление и проверка ролей цветов
3. Картинка узла для доски — `download_assets` (раздел «Узел Figma и файлы пользователя» в [reference-capture.md](reference-capture.md))

Ограничения: нужна ссылка с fileKey и nodeId; лимиты вызовов — в skill-figma-mcp.

### Из изображения

Для исходников из выдачи и с витрин, файлов пользователя и снимков, у которых нет доступа к стилям.

1. Условие применимости скрипта: `python3 -c "import PIL"` завершается без ошибки
2. ЕСЛИ Pillow установлен -> запустить [scripts/palette.py](scripts/palette.py): `python3 "<папка скилла>/scripts/palette.py" <файл> --colors 6`. Ответ — список `{hex, share_%}`, доли площади. Метод — приблизительно, по изображению
3. ЕСЛИ Pillow не установлен -> запасной путь: просмотреть картинку через Read и описать доминирующие цвета глазами. Метод — визуально, hex помечается как приблизительный
4. Роли цветов: доли площади описывают фон, а не акцент. Фон и поверхности берутся из крупных долей. Акцент ищется среди насыщенных цветов с малой долей — по насыщенности, а не по площади. Роль каждого цвета подтверждается взглядом на картинку
5. Шрифт — описывается классом, аналог помечается «предложение» (раздел «Типографика»)

### Из текстового описания

Только когда поиск картинок по описанию настроения ничего не дал (режимы — в [moodboard-workflow.md](moodboard-workflow.md)).

1. Извлечь ключевые слова настроения из описания пользователя
2. Подобрать элементы по таблицам раздела «Значения по настроению»
3. Каждый элемент маркировать «предложено на основе описания», метод — визуально; на доске эти значения стоят в сводке без карточек-картинок, а в «Чего не нашлось» записывается, что картинок по описанию не нашлось

## Правила извлечения

- **Метод у каждого элемента.** Без метода элемент в сводку не идёт
- **Конкретность.** Не «синий» — а `#2563EB`. Не «гротеск» — а «Inter» (если получен точно) или «геометрический гротеск, аналог — Inter, предложение» (если визуально). Не «карточки» — а «карточки с радиусом 12px, тенью и внутренним отступом 24px»
- **Источник обязателен.** Для каждого элемента — номер карточки или узел Figma, откуда он взят
- **Честность при неопределённости.** Приблизительный hex помечается методом; неопознанный шрифт описывается классом с аналогом
- **Не додумывать.** Если из источника видны только цвета — записать цвета, а для типографики указать «не извлечено из этого источника»
