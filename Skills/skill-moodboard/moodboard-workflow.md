# Рабочий процесс создания мудборда

## Назначение

Пошаговая процедура мудборда из реальных картинок: модель доски, выбор режима и источников, сбор и отбор кандидатов, сводка, раскладка, ревью по номерам карточек, итерации и финализация. Подробности получения картинок — в [reference-capture.md](reference-capture.md), раскладки в Figma — в [figma-output.md](figma-output.md).

---

## Модель доски

Действует для обоих типов результата — визуального направления и коллекции паттернов.

### Карточка

- Основа мудборда — реальные картинки, сгруппированные по смыслу
- У каждой карточки: номер, «что взять» одной строкой, продукт или автор, источник (домен со ссылкой на страницу, где опубликована картинка), метка типа; ЕСЛИ картинка короче 500 px по длинной стороне или у пина не найден первоисточник -> пометка («маленькое разрешение», «первоисточник не найден»)
- Нет реального примера — нет карточки. Пробел называется явно в блоке «Чего не нашлось» на доске, а не закрывается нарисованным мокапом

### Метки типа

| Метка | Что значит |
|---|---|
| поиск картинок | Картинка из поиска картинок Google (включая пины Pinterest и снимки из статей) |
| продукт | Снимок работающего сайта или приложения, включая живую корзину |
| концепт | Работа с витрины (Dribbble, Behance и похожих), не обязательно реализованная |
| библиотека | Экран из библиотеки паттернов (Mobbin, Page Flows и похожих) |
| макет | Узел из Figma-файла |
| файл пользователя | Картинка, которую дал пользователь |

### Сводка поверх картинок

- Визуальное направление — палитра, шрифты, слова настроения
- Коллекция паттернов — визуальные константы и «делай / не делай»
- У каждого параметра — метод получения: точно (вычисленные стили, Figma), приблизительно (по изображению), визуально. Методы — в [element-extraction.md](element-extraction.md)
- Палитра на доске — плашки с hex и источником: это сводка, а не мокап

### Назначение, объём, раскладка

| Параметр | По умолчанию | Иначе |
|---|---|---|
| Где доска | Страница Figma Design | FigJam — если пользователь попросил |
| Копия вне Figma | Нет | Markdown с папкой картинок и манифестом — по запросу или если Figma недоступна |
| Объём: визуальное направление | 30–50 картинок | Другой — если пользователь назвал |
| Объём: коллекция паттернов | 20–30 примеров, 6–10 на группу | Другой — если пользователь назвал |
| Раскладка | Кладка колонками одинаковой ширины, картинки не обрезаются | Сетка или коллаж — по запросу |
| Колонки | Направление — 4 колонки шириной 300; коллекция — 3 колонки шириной 360 | — |
| Группы коллекции | По месту, где паттерн появляется в сценарии пользователя | — |

Группы коллекции паттернов строятся по месту в сценарии, а не по источнику. Пример для оплаты частями: «в итоге корзины», «выбор срока на шаге оформления», «среди способов оплаты», «виджет у магазина».

### Ревью и манифест

- Ревью — по номерам карточек: оставить, убрать, «ещё таких, как N», уточнить подпись, пересобрать группу
- Манифест — небольшой JSON без картинок в папке, которую указал пользователь; остаётся после загрузки доски и ведёт все итерации. Схема — в [reference-capture.md](reference-capture.md), раздел «Манифест»

## Определение режима работы

| Что дал пользователь | Режим | Откуда картинки |
|---|---|---|
| Ссылки на сайты, Figma, файлы | **По ссылкам** | Снимки указанных страниц в Chrome, узлы Figma, файлы пользователя; добор — поиском, если ссылок меньше объёма |
| Тему или тип паттернов без ссылок («собери примеры X») | **Поисковый** | Источник по типу задачи (таблица ниже) |
| Только описание настроения | **По описанию настроения** | Тоже поиск: настроение переводится в поисковые запросы для поиска картинок Google и витрин («calm minimal wellness app UI», «спокойный минималистичный интерьер, много воздуха») |

- ЕСЛИ непонятно, тема это или настроение -> поисковый режим
- Текстовые значения без картинок (таблицы «Значения по настроению» в [element-extraction.md](element-extraction.md)) — только если поиск по настроению ничего не дал; тогда в «Чего не нашлось» записывается, что картинок не нашлось

### Источник по типу задачи

Если пользователь источник не назвал, он выбирается по типу задачи:

| Задача | Источник | Метка |
|---|---|---|
| Атмосфера, фотостиль, фактуры, иллюстрации | Поиск картинок Google (с пинами Pinterest из выдачи) | поиск картинок |
| Интерфейсные концепты | Витрины: Dribbble, Behance и похожие | концепт |
| Конкретные продукты и конкуренты | Снимки живых сайтов в Chrome | продукт |
| Паттерны корзины, оформления, оплаты | Поиск картинок Google + живые экраны корзины и оформления | поиск картинок, продукт |
| Мобильные паттерны | Поиск картинок, библиотеки паттернов, витрины; снимок через Playwright — если установлен | поиск картинок, библиотека, концепт |

Квот на состав доски нет: доли источников и типов задаёт задача. Единственное ограничение состава — правило против перекоса: один продукт или сервис не больше трети доски (раздел «Отбор»).

### Тип источника → что делать

| Тип источника | Что делать |
|---|---|
| Ссылка на сайт | Снимок живого сайта в Chrome; стили — `javascript_tool` |
| Ссылка на работу на витрине | Исходник работы со страницы; автор — из заголовка вкладки |
| Ссылка на пин | Исходник пина; первоисточник — через Google Lens |
| Ссылка на Figma | `download_assets` — картинка узла, `get_design_context` — стили |
| Файл или папка пользователя | Копия во временную папку сессии |
| Тема | Запросы в поиске картинок Google и на витринах |
| Описание настроения | Поисковые запросы из слов настроения |

## Сбор кандидатов

Кандидаты собираются способами из [reference-capture.md](reference-capture.md): поиск картинок Google, Pinterest, Google Lens, витрины, живые сайты и корзины в Chrome, Playwright, узлы Figma, файлы пользователя. Несколько запросов по одной теме с разных сторон — сервис, продукт, место в сценарии. Кандидатов собирается больше нужного объёма: часть отсеется при скачивании и отборе.

## Отбор

Отбор — глазами, по контактному листу или снимкам Chrome; отсев рекламы, логотипов, чужих шагов сценария, дублей; правило маленьких картинок; правило против перекоса. Процедура — разделы «Скачивание» и «Отбор по контактному листу» в [reference-capture.md](reference-capture.md).

## Показ списка кандидатов

Список отобранных кандидатов показывается пользователю одним сообщением до снимков и раскладки (формат — раздел «Список кандидатов для пользователя» в [reference-capture.md](reference-capture.md)). Скачивание исходников отдельного вопроса не требует — подтверждение списка его покрывает.

- ЕСЛИ пользователь подтвердил -> захват и раскладка
- ЕСЛИ скорректировал -> обновить список, показать снова
- ЕСЛИ кандидатов меньше половины нужного объёма -> сказать, предложить другие запросы или попросить ссылки

## Захват и скачивание

Снимки живых сайтов и корзин в Chrome, окно 1440, снимок без `scale`, проверка типа каждого скачанного файла, временная папка сессии вне проекта. Процедура — [reference-capture.md](reference-capture.md).

## Сводка

Для каждого источника извлечь параметры с методом по [element-extraction.md](element-extraction.md). Затем свести их по разделу «Работа с несколькими источниками» ниже.

ЕСЛИ из нескольких источников получены конфликтующие данные (например, разные палитры) -> показать пользователю оба варианта с номерами карточек и спросить, что ближе. НЕ выбирать молча.

## Раскладка

- Доска в Figma (по умолчанию) — по [figma-output.md](figma-output.md): каркас, загрузка картинок, проверка, блок «Чего не нашлось», удаление локальных файлов
- Копия вне Figma (по запросу или если Figma недоступна) — markdown по шаблону из [moodboard-templates.md](moodboard-templates.md) с папкой `refs/` и манифестом в папке пользователя

## Ревью с пользователем

Ревью идёт по номерам карточек. Сообщение после первой версии доски:

```
Доска v1: [N] референсов в [K] группах. Скриншот выше.
Метки: поиск картинок [a], продукт [b], концепт [c], …
Чего не нашлось: [кратко или «всё нашлось»].
Как удобнее дать обратную связь:
— «оставить 2, 5, 9» / «убрать 3, 7»
— «ещё таких, как 5» — найду похожие
— «5 — только цвет, не композицию» — уточню подпись
— «группа "Виджет у магазина" не та» — пересоберу группу
```

| Реакция | Действие |
|---|---|
| Оставить N | `status: approved` в манифесте |
| Убрать N | Удалить карточку с доски, `status: rejected` в манифесте с причиной; карточка из манифеста не удаляется |
| Ещё таких, как N | Добор через Google Lens и новые запросы — раздел «Добор "ещё таких, как N"» в [reference-capture.md](reference-capture.md); новые кандидаты снова показываются списком до захвата |
| Уточнить «что взять» у N | Правка подписи без замены картинки; правка `take` в манифесте |
| Группа не та | Пересобрать одну группу, остальное не трогать |
| Цвета, шрифты, слова настроения | Правка сводки; при конфликте источников — показать варианты с номерами карточек |

ЕСЛИ пользователь доволен всем -> финализация. ЕСЛИ есть замечания -> итерация.

## Итерация

- **Фокусные изменения.** Менять только то, что назвал пользователь, по номерам карточек
- **Объяснять изменения.** Кратко: что добавлено, что убрано, почему
- **Версии.** Каждый круг — новая версия (v1 -> v2 -> v3): растёт `board.version` в манифесте и номер в названии доски. Отклонённые карточки остаются в манифесте как история
- **Лимит.** Максимум 3–4 круга. Если после четвёртого нет консенсуса: свести всю обратную связь, предложить финальный вариант с обоснованием, спросить, можно ли финализировать

## Финализация

При одобрении пользователя:
- Проверить доску по чек-листу готовности из [moodboard-templates.md](moodboard-templates.md)
- ЕСЛИ доска в Figma -> обновить шапку и сводку по финальным данным (процедура — [figma-output.md](figma-output.md))
- ЕСЛИ пользователь попросил копию вне Figma или Figma недоступна -> оформить финальный markdown по шаблону из [moodboard-templates.md](moodboard-templates.md) с папкой `refs/` и манифестом
- Убедиться, что локальные картинки удалены, а манифест сохранён (раздел «Удаление локальных файлов» в [reference-capture.md](reference-capture.md))
- Вывести формат выдачи (финализация)

## Работа с несколькими источниками

### Синтез палитры

- Выписать все извлечённые цвета с номером карточки и методом
- Найти общие тона и направление
- Предложить единую палитру (5–7 цветов), указав для каждого карточку-источник и метод
- ЕСЛИ один и тот же цвет получен разными методами и значения расходятся -> приоритет у точного (вычисленные стили, Figma) перед приблизительным (по изображению), у приблизительного — перед визуальным
- Конфликтующие варианты одного уровня точности — показать пользователю

### Синтез типографики

- Перечислить шрифты из всех источников с методом
- Предложить пару (заголовки + основной текст), указав источник выбора; шрифт, определённый визуально, — с пометкой «предложение»
- ЕСЛИ шрифты из разных источников не сочетаются -> предложить альтернативу с объяснением

### Синтез приёмов

- Выписать приёмы с номерами карточек, где они видны
- Выделить повторяющиеся в нескольких источниках
- Конфликтующие приёмы — показать пользователю с рекомендацией

### Синтез настроения

- Объединить ключевые слова из всех источников и описания пользователя
- Убрать противоречивые (например, «минимализм» и «избыточность»)
- Предложить 4–6 финальных ключевых слов
