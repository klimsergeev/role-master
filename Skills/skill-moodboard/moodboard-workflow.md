# Рабочий процесс создания мудборда

## Назначение

Пошаговая процедура создания мудборда от сбора источников до финализации. Включает основной поток, поисковый режим (агент сам находит источники по теме), fallback-режим (без визуальных источников) и ветку для Figma-выдачи.

## Определение режима работы

Перед сбором источников — определить режим:

| Что дал пользователь | Режим | Куда идти |
|---|---|---|
| Конкретные URL, Figma-ссылки, скриншоты | **Основной поток** | Сбор источников ниже |
| Тему / тип паттернов / описание «собери примеры X» без конкретных URL | **Поисковый режим** | Секция «Поисковый режим» |
| Только текстовое описание настроения, без темы для поиска | **Fallback-режим** | Секция «Fallback-режим» |

**Как отличить поисковый режим от fallback:**
- Поисковый — пользователь описывает ТЕМУ или ПАТТЕРН, по которому можно искать реальные примеры: «собери примеры FOMO-плашек», «найди референсы онбординга», «покажи лучшие empty states»
- Fallback — пользователь описывает НАСТРОЕНИЕ или ХАРАКТЕР без конкретной темы для поиска: «хочу минимализм и спокойные тона», «что-то технологичное и строгое»
- ЕСЛИ непонятно -> предпочитать поисковый режим (реальные данные лучше предположений)

## Основной поток

### Сбор источников

Запросить у пользователя источники вдохновения. Принимаемые типы:

| Тип источника | Что делать |
|---|---|
| URL сайта | WebFetch -> извлечь CSS/HTML, проанализировать визуальные решения |
| Figma-ссылка | Figma MCP: get_screenshot + get_design_context -> цвета, стили, компоненты |
| Скриншот / изображение | Визуальный анализ: описать цвета, типографику, паттерны |
| Dribbble / Behance URL | WebFetch -> извлечь визуальные решения из страницы |
| Текстовое описание | Записать как ключевые слова настроения, перейти к fallback-элементам |

Для каждого источника зафиксировать:
- Откуда (URL, имя файла, описание)
- Что берём (какие именно элементы вдохновляют)
- Почему релевантно (связь с задачей пользователя)

ЕСЛИ пользователь не предоставил ни одного визуального источника -> определить режим по таблице выше (поисковый или fallback).

### Извлечение элементов

Для каждого источника извлечь дизайн-элементы по справочнику [element-extraction.md](element-extraction.md).

Результат извлечения — структурированный набор:
- **Цвета:** hex-коды с описанием роли (primary, secondary, accent, background, text)
- **Типографика:** названия шрифтов, веса, наблюдения о размерах и межстрочном интервале
- **UI-паттерны:** конкретные решения (тип навигации, стиль карточек, форма кнопок, декоративные элементы)
- **Настроение:** ключевые слова, эмоциональный отклик, черты характера бренда

ЕСЛИ из нескольких источников получены конфликтующие данные (например, разные палитры):
- Показать пользователю оба варианта
- Спросить, что ближе к желаемому результату
- НЕ выбирать молча

### Создание чернового мудборда

Сгенерировать markdown-документ по шаблону «Черновой мудборд» из [moodboard-templates.md](moodboard-templates.md).

Правила заполнения:
- Каждый hex-код должен иметь реальный источник (URL, Figma-нода) или явную пометку «предложение»
- Каждый шрифт — либо извлечён из источника, либо помечен как «подобран по описанию»
- Паттерны описываются конкретно: «горизонтальная навигация с выпадающими меню» вместо «современная навигация»
- Ключевые слова настроения — из пользовательского описания или синтезированы из визуального анализа

Сохранить файл по указанному пользователем пути.

ЕСЛИ пользователь выбрал Figma-выдачу -> после создания markdown-черновика (или вместо него, если выбран только Figma) создать мудборд-фрейм в Figma. Процедура — в [figma-output.md](figma-output.md).

### Ревью с пользователем

Показать созданный мудборд и задать вопросы:

- Направление в целом — чувствуется правильным?
- Цвета — что скорректировать? (показать конкретные hex)
- Типографика — есть предпочтения по шрифтам?
- Паттерны — что добавить, что убрать?
- Ключевые слова — какие не подходят?

ЕСЛИ пользователь доволен всем -> перейти к финализации.
ЕСЛИ есть замечания -> перейти к итерации.

### Итерация

Правила итерации:

- **Фокусные изменения.** Не переделывать весь мудборд — менять только то, что просил пользователь
- **Объяснять изменения.** При каждой итерации кратко описать, что изменилось и почему
- **Before/after для крупных сдвигов.** Если меняется палитра или типографика целиком — показать было/стало
- **Версионирование.** Каждая итерация — новая версия (v1 -> v2 -> v3). Предыдущие версии не удалять без подтверждения пользователя
- **Лимит итераций.** Максимум 3-4 итерации. Если после четвёртой нет консенсуса:
  - Синтезировать всю обратную связь
  - Предложить финальный вариант с обоснованием каждого решения
  - Спросить, можно ли финализировать

### Figma-выдача (если выбрана)

ЕСЛИ пользователь выбрал Figma-формат — после одобрения чернового мудборда (или параллельно) создать мудборд-фрейм в Figma.

Полная процедура создания Figma-фрейма описана в [figma-output.md](figma-output.md). Здесь — ключевые точки интеграции с основным потоком:

- **Когда создавать:** после того, как данные мудборда сформированы и базово одобрены (не нужно ждать полной финализации markdown)
- **Тип фрейма:** для стандартного мудборда — структура «палитра / типографика / паттерны / ключевые слова / источники». Для тематической коллекции — структура «категории / визуальные мокапы / do-don't / источники» (секция «Визуальные мокапы» и «Структура фрейма для тематической коллекции» в [figma-output.md](figma-output.md))
- **Мокапы:** для тематических коллекций создавать визуальные мокапы (бейджи, таймеры, нотификации) через `use_figma`, а не только текстовые описания
- **Итерация:** при изменениях в markdown-мудборде обновлять Figma-фрейм через `use_figma`. НЕ пересоздавать фрейм целиком — менять конкретные элементы
- **Проверка:** после каждого создания/обновления фрейма — `get_screenshot` для визуальной проверки и показа пользователю
- **Данные берутся из того же набора:** палитра, типографика, паттерны, ключевые слова — общие для markdown и Figma

### Финализация

При одобрении пользователя:
- Оформить мудборд по шаблону «Финальный мудборд» из [moodboard-templates.md](moodboard-templates.md)
- ЕСЛИ есть Figma-выдача -> обновить фрейм финальными данными (процедура в [figma-output.md](figma-output.md))
- Проверить чеклист готовности (все обязательные элементы заполнены)
- Сохранить файл
- Вывести формат выдачи (финализация)

## Поисковый режим

Используется, когда пользователь описывает тему или тип паттернов, но не даёт конкретные URL. Агент самостоятельно находит реальные источники через WebSearch. Это НЕ fallback — результат основан на реальных данных, а не на предположениях.

**Примеры запросов, активирующих поисковый режим:**
- «Собери примеры FOMO-плашек»
- «Найди референсы онбординга для SaaS»
- «Покажи лучшие empty states»
- «Мудборд с примерами pricing page»
- «Собери коллекцию паттернов геймификации»

### Формирование поисковых запросов

На основе темы пользователя сформировать 3-5 поисковых запросов через WebSearch. Стратегия:

| Тип запроса | Пример (для FOMO-плашек) | Цель |
|---|---|---|
| Обзорная статья | "FOMO UI patterns best examples" | Найти статьи с подборками и классификацией |
| Дизайн-площадки | "urgency scarcity ecommerce design dribbble" | Визуальные примеры на Dribbble, Behance |
| Реальные продукты | "booking.com amazon urgency design patterns" | Живые примеры на реальных сайтах |
| UX-анализ | "FOMO notification design psychology UX" | Исследования, best practices, do/don't |
| Конкретный подтип (при необходимости) | "countdown timer low stock badge UI" | Углубление по конкретной категории |

### Отбор и показ источников

Из результатов WebSearch отобрать 5-10 качественных источников. Критерии отбора:
- Содержит визуальные примеры (скриншоты, макеты), а не только текст
- Релевантен теме пользователя
- Источник авторитетный (UX-блоги, дизайн-площадки, реальные продукты)
- Разнообразие: статьи + дизайн-площадки + реальные сайты

**Показать список найденных источников пользователю перед извлечением:**

```
Нашёл [N] источников по теме "[тема]":

- [URL] — [краткое описание: что ценного]
- [URL] — [краткое описание]
- [URL] — [краткое описание]
...

Начинаю извлечение из всех? Или убрать/добавить какие-то?
```

ЕСЛИ пользователь подтвердил -> перейти к извлечению по основному потоку (WebFetch для каждого URL)
ЕСЛИ пользователь скорректировал список -> обновить и продолжить
ЕСЛИ WebSearch не дал качественных результатов -> сообщить пользователю, предложить альтернативные поисковые запросы или запросить URL вручную

### Далее — основной поток

После подтверждения источников процесс идёт по основному потоку: извлечение элементов -> создание чернового мудборда -> ревью -> итерация -> финализация.

**Особенность для тематических коллекций:** ЕСЛИ пользователь просит коллекцию паттернов (а не визуальное направление для проекта) -> использовать шаблон «Тематическая коллекция паттернов» из [moodboard-templates.md](moodboard-templates.md) вместо стандартного.

## Fallback-режим

Используется, когда у пользователя нет визуальных источников и нет конкретной темы для поиска — только описание настроения и желаемого результата.

### Сбор описания

Запросить у пользователя:
- Тип продукта (лендинг, приложение, дашборд, блог, e-commerce)
- Желаемое настроение (ключевые слова: минимализм, яркость, строгость, игривость и т.д.)
- Целевая аудитория (кто будет пользоваться)
- Референсы «по ощущению» (необязательно: «что-то вроде Apple» или «как в Notion»)

### Формирование элементов

На основе описания сформировать предложения для каждой категории. Детали извлечения — в [element-extraction.md](element-extraction.md), секция «Fallback-значения».

**Все элементы в fallback-режиме явно маркируются:**
- «Предложено на основе описания: [ключевые слова]»
- НЕ выдавать за извлечённые из реального источника

### Далее — основной поток

После формирования элементов процесс идёт по основному потоку: создание чернового мудборда -> ревью -> итерация -> финализация.

## Работа с несколькими источниками

Когда источников больше одного, элементы извлекаются из каждого отдельно, затем синтезируются:

### Синтез палитры

- Выписать все извлечённые цвета с указанием источника
- Найти общие тона и направление
- Предложить единую палитру (5-7 цветов), указав, из какого источника взят каждый
- Конфликтующие варианты — показать пользователю

### Синтез типографики

- Перечислить шрифты из всех источников
- Предложить пару (headline + body), указав источник выбора
- ЕСЛИ шрифты из разных источников не сочетаются -> предложить альтернативу с объяснением

### Синтез паттернов

- Выписать все UI-паттерны с указанием источника
- Выделить непротиворечивые (используются в нескольких источниках)
- Конфликтующие паттерны — показать пользователю с рекомендацией

### Синтез настроения

- Объединить ключевые слова из всех источников
- Убрать противоречивые (например, «минимализм» и «избыточность»)
- Предложить 4-6 финальных ключевых слов
