# Жесты и пружины

## Назначение

Процедура и значения для жестового движения в вебе: отклик, прямое манипулирование, прерываемость, пружины, передача скорости, проекция импульса, резиновые границы.

Основа — доклады Apple о плавных интерфейсах, прежде всего *Designing Fluid Interfaces* (WWDC 2018), переложенные на веб-платформу (CSS, Pointer Events, `requestAnimationFrame`, пружины Motion), и правила жестов Эмиля Ковальски.

Сквозная мысль: интерфейс ощущается живым, когда движение стартует от текущего значения на экране, наследует скорость пользователя, проецирует импульс вперёд и в любой момент может быть схвачено и развёрнуто.

## Отклик

- Отклик — на pointer-down, а не на отпускание: кнопка подсвечивается в момент нажатия.
- Аудит задержек на пути ввода: debounce, искусственные таймеры, ожидание переходов. Всё, что на пути ввода не обязательно, — регрессия.
- Задержка касания 300–350ms снята на страницах с `<meta name="viewport" content="width=device-width">` (Chrome 32, iOS 9.3) или с `touch-action: manipulation`; при аудите задержек проверяется, что одно из них есть.

  Расхождение с первоисточником: у Эмиля — «and the ~300ms tap delay» (skills/apple-design/SKILL.md); по Chrome for Developers, https://developer.chrome.com/blog/300ms-tap-delay-gone-away — задержки нет на страницах с `width=device-width` или `touch-action: manipulation`.
- Обратная связь непрерывна во время взаимодействия, а не только в конце: при перетаскивании, слайдере, шторке интерфейс обновляется 1:1 с указателем всю дорогу.

```css
/* Feedback lives on the press, and it's instant */
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## Прямое манипулирование 1:1

Перетаскиваемый элемент держится за пальцем и учитывает точку, за которую его взяли: прыжок к центру элемента при захвате ломает иллюзию.

- Pointer Events с `setPointerCapture`: после начала перетаскивания все события указателя идут захватившему элементу, поэтому перетаскивание продолжается, даже когда указатель выходит за его границы.
- Короткая история положения и скорости (несколько последних `pointermove`), а не только текущая точка — скорость понадобится при отпускании.

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // respect where they grabbed
  // ...track position + timestamp history for velocity
});
```

## Прерываемость

- Ввод не блокируется во время перехода: движущийся элемент можно схватить и развернуть, не дожидаясь конца анимации. Закрывающуюся модалку, которую снова схватили, ведёт палец, а не завершение закрытия.
- Анимация стартует от текущего (видимого) значения, а не от целевого: при прерывании читается живая трансформация на экране.
- При развороте жеста скорость смешивается, а не обрывается: замена одной анимации другой в момент разворота даёт разрыв скорости — «кирпичную стену».
- Аддитивные анимации iOS делают это сами; в вебе выбирается пружинная библиотека, которая перенацеливается с текущей скоростью.
- 2D-движение раскладывается на независимые пружины по X и по Y: одна пружина на 2D-расстоянии рассинхронизируется, когда скорости по осям разные.
- `@keyframes` для жестов не годятся — начинаются с первого кадра. CSS-переход при прерывании стартует с текущего значения и умеет ускоренный разворот, но скорость пальца не переносит. Всё, что ведёт палец, анимируется физической пружиной, которая скорость учитывает. Любая анимация Motion стартует с текущего значения.

  Расхождение с первоисточником: у Эмиля — «**Avoid CSS transitions and `@keyframes` for anything gesture-driven** — they can't be smoothly grabbed and reversed mid-flight. Springs animate from the current value by default» (skills/apple-design/SKILL.md); по CSS Transitions Level 1, https://drafts.csswg.org/css-transitions-1/#reversing — прерванный переход стартует с текущего значения и умеет ускоренный разворот, не сохраняется только скорость.
- Выбор между CSS-переходом и пружиной — по правилу раздела «Прерывание и выход» [motion-values.md](motion-values.md).

## Пружины

Apple в 2018 году свела массу, жёсткость и демпфирование к двум параметрам:

- **Демпфирование** (damping ratio) — управляет перелётом. `1.0` — критическое демпфирование, без отскока, плавная остановка. Меньше `1.0` — перелёт и колебания; чем меньше, тем больше отскока.
- **Отклик** (response) — как быстро значение стремится к цели, в секундах. Это не длительность: у физической пружины нет фиксированной длительности.

Умолчания:

- Большая часть интерфейса — демпфирование `1.0`.
- Отскок (демпфирование около `0.8`) — только когда сам жест нёс импульс: бросок, щелчок, отпускание после перетаскивания. Перелёт у меню, которое просто появилось, ощущается неправильно; у карточки, которую бросили, — правильно.

Значения из реконструкции Nathan Gitter (Building Fluid Interfaces, 2018):

| Взаимодействие | Демпфирование | Отклик |
| --- | --- | --- |
| Перемещение (например, PiP) | `1.0` | `0.4` |
| Поворот | `0.8` | `0.4` |
| Шторка | `0.8` | `0.3` |

Сама Apple в докладе назвала только 100% демпфирования при касании и 80% при смахивании в мини-плеере «Музыки».

Расхождение с первоисточником: у Эмиля — «**Concrete values Apple ships:**» (skills/apple-design/SKILL.md); по докладу Apple, https://developer.apple.com/videos/play/wwdc2018/803/ — этих пар в докладе нет, они совпадают с реконструкцией Nathan Gitter.

Перевод на Motion: с 2023 года Apple использует ту же пару, что Motion, — длительность и отскок (0 — критическое демпфирование, без отскока; положительные значения — больше отскока; отрицательные — передемпфированная пружина). Пара «демпфирование + отклик» — параметризация Apple 2018 года (`Spring(response:dampingRatio:)` в SwiftUI).

Расхождение с первоисточником: у Эмиля — «the `bounce` + `duration` spring API maps closely to Apple's damping + response.» (skills/apple-design/SKILL.md); по докладу Apple «Animate with springs», https://developer.apple.com/videos/play/wwdc2023/10158/ — с Motion совпадает пара Apple «длительность + отскок», а «демпфирование + отклик» — её прежняя параметризация.

```js
import { animate } from 'motion';

// Critically damped default (no overshoot)
animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });

// Momentum interaction — a little bounce, only because a flick preceded it
animate(el, { y: target }, { type: 'spring', mass: 1, stiffness: 100, damping: 16, velocity: releaseVelocity });
```

Значение второй пружины расчётное: коэффициент демпфирования ζ = damping / (2 · √(stiffness · mass)) = 16 / (2 · √100) = 0.8.

Расхождение с первоисточником: у Эмиля — «animate(el, { y: target }, { type: 'spring', bounce: 0.2, duration: 0.4 });» (skills/apple-design/SKILL.md); по документации Motion, https://motion.dev/docs/react-transitions — пружина на `duration` + `bounce` скорость броска не принимает, принимает только физическая пружина.

Пружина по умолчанию и правило её выбора — раздел «Пружины» [motion-values.md](motion-values.md).

## Передача скорости

Когда жест заканчивается, анимация продолжается с точной скоростью пальца, чтобы между перетаскиванием и анимацией не было шва. Скорость отпускания передаётся пружине как начальная. Некоторые API пружин ждут относительную скорость — нормированную на оставшееся до цели расстояние:

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

Пример: элемент на `y=50`, цель `y=150` (осталось 100px), палец движется со скоростью 50px/s → начальная скорость пружины `50 / 100 = 0.5`.

Опция `velocity` в Motion задаётся в единицах значения в секунду (px/s для `y`) и работает только с физическими пружинами (`stiffness`, `damping`, `mass`); с `duration` или `bounce` переданная скорость обнуляется.

Расхождение с первоисточником: у Эмиля — «Framer Motion / Motion take absolute px/s velocity directly (`velocity` option), so you usually hand it the raw value.» (skills/apple-design/SKILL.md); по документации Motion, https://motion.dev/docs/react-transitions — с пружинами на `duration` + `bounce` опция `velocity` не работает.

## Проекция импульса

Цель выбирается не от точки отпускания, а от спроецированной точки остановки — как при замедлении скролла: по скорости вычисляется, где элемент остановился бы, и берётся ближайшая к этой точке точка привязки. Так щелчок «бросает» элемент.

```js
// decelerationRate ≈ 0.998 for normal scroll feel; 0.99 for snappier
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);   // choose target from the projection
animateSpringTo(target, { velocity: releaseVelocity }); // then hand off velocity (§5)
```

Ссылка «(§5)» в комментарии ведёт к разделу «Передача скорости» этого файла.

Функцию проекции показывали в докладе Apple «Designing Fluid Interfaces» (WWDC 2018); её текст — по реконструкции Nathan Gitter, отдельного образца кода у Apple нет, коэффициент 0.998 в документации Apple не назван. Формула — экспоненциальное убывание (сумма геометрического ряда при умножении скорости на коэффициент каждую миллисекунду), а не `v²/(2·decel)`. Vaul закрывает шторку по порогу скорости 0.4, Embla гасит скорость трением на каждом кадре — эту формулу они не используют.

Расхождение с первоисточником: у Эмиля — «This is the standard behavior in good bottom-sheets and carousels (Vaul, Embla).» (skills/apple-design/SKILL.md); по докладу Apple, https://developer.apple.com/videos/play/wwdc2018/803/ и исходному коду Vaul и Embla — образца кода к докладу нет, а Vaul и Embla эту проекцию не используют.

## Резиновые границы и детали перетаскивания

У края элемент сопротивляется постепенно, а не останавливается жёстко: жёсткая остановка читается как «зависло», постепенное сопротивление — как «отзывается, но дальше ничего нет».

```js
// The further past the bound, the less the element follows — real things slow before they stop
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

- **Закрытие по импульсу.** Не требовать перетаскивания за порог расстояния: считать скорость `Math.abs(dragDistance) / elapsedTime`; ЕСЛИ скорость больше ~0.11 → закрывать независимо от расстояния. Короткого щелчка достаточно.

```js
const timeTaken = new Date().getTime() - dragStartTime.current.getTime();
const velocity = Math.abs(swipeAmount) / timeTaken;

if (Math.abs(swipeAmount) >= SWIPE_THRESHOLD || velocity > 0.11) {
  dismiss();
}
```

- **Демпфирование на границах.** За естественной границей (шторку тянут вверх, когда она уже наверху) чем дальше тянут, тем меньше движется элемент.
- **Трение вместо жёсткой остановки.** Перетягивание вверх не запрещается, а идёт с растущим трением.
- **Защита от мультитача.** После начала перетаскивания дополнительные точки касания игнорируются; иначе смена пальца посреди перетаскивания заставляет элемент прыгнуть к новой точке.

```js
function onPress() {
  if (isDragging) return;
  // Start drag...
}
```

## Детали жестов

- **Касание:** подсветка на касание (мгновенно), действие на отпускание. ~10px гистерезиса и запаса вокруг цели; отмена уводом пальца и возврат.
- **Перетаскивание и смахивание:** небольшой порог движения (гистерезис ~10px) до выбора направления, затем отслеживание 1:1.
- **Все вероятные жесты распознаются параллельно с первого движения**, проигравшие отменяются, когда намерение ясно. Распознаватели, которые сообщают только финальное состояние (события вида `swipeleft`), теряют непрерывное отслеживание, нужное для обратной связи.
- **Задержки на различение — минимальные.** Распознавание двойного касания неизбежно задерживает одиночное; эта цена платится только там, где двойное касание действительно есть.

## Пространственная согласованность и направление

- **Вход и выход по одному пути.** Панель, въехавшая справа, уходит вправо.
- **Привязка к источнику.** Меню, поповер или шторка выходят из вызвавшего их элемента: `transform-origin` — у триггера.
- **Зеркальная кривая для обратного направления.** Обращённая во времени кривая `cubic-bezier(x1, y1, x2, y2)` — это `cubic-bezier(1 − x2, 1 − y2, 1 − x1, 1 − y1)`; браузер сам её не зеркалит — при развороте прерванного перехода используется та же кривая, поэтому зеркальная задаётся вручную.
- **Подсказка направлением жеста.** Промежуточные кадры указывают на исход: модули Пункта управления «растут вверх и наружу к пальцу».

## Покадровая плавность

- Изменение положения за кадр держится ниже порога восприятия, чтобы не было стробоскопа.
- Для очень быстрого движения лёгкое размытие или растяжение в направлении движения кодирует скорость лучше резкого следа.
- `requestAnimationFrame` — часы веба, синхронные с дисплеем (у Apple — `CADisplayLink`). Анимируются только свойства, дружественные компоновщику, — `transform` и `opacity`; `will-change` подсказывается там, где движение вот-вот начнётся.

Расхождение внутри набора: apple-design — подсказывать `will-change` там, где движение близко; animation-performance — добавлять `will-change` только после замеченного сдвига на 1px или замеренной потери кадров.

Правило: ЕСЛИ решается, ставить ли `will-change` → по разделу «`will-change`» [performance.md](performance.md).

## Мультимодальная обратная связь

- **Причинность** — понятно, что вызвало отклик: он срабатывает на настоящем причинном событии (переключатель щёлкнул, элемент встал на место) и по характеру соответствует физике действия.
- **Гармония** — визуал, звук и тактильный отклик срабатывают в одном кадре; задержка между ними разрушает иллюзию.
- **Полезность** — отклик только там, где он оправдан: успех, ошибка, фиксация, защёлкивание. Избыток приучает игнорировать весь отклик.

Vibration API (`navigator.vibrate`) работает в Chrome для Android (с версии 60 — только после жеста пользователя); в Safari, Safari на iOS и Firefox его нет или вызов ничего не делает. Тактильная отдача в вебе не бывает единственной обратной связью.

Расхождение с первоисточником: у Эмиля — «Don't let a CSS transition lag the audio/haptic (Vibration API).» (skills/apple-design/SKILL.md); по данным совместимости MDN, https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate — в Safari и Firefox Vibration API не работает.

## Reduced motion для жестов

Reduced motion не означает отсутствия отклика — это мягкий эквивалент без вестибулярной нагрузки. При `prefers-reduced-motion: reduce` слайды, пружины и параллакс заменяются коротким затуханием или статичным переходом, отскок и перелёт убираются, изменения прозрачности и цвета, помогающие понять происходящее, сохраняются.

Apple в HIG для visionOS советует избегать длительных колебаний около 0.2 Гц, движения всей окружающей области и резкой разницы яркости движущегося объекта на периферии; перенос этих правил на веб и совет плавно менять светлую и тёмную тему — рекомендация Эмиля. Общий раздел HIG Accessibility при Reduce Motion просит сокращать автоматические и повторяющиеся анимации, приближение, масштабирование и движение на периферии. Крупные движущиеся объекты во время движения делаются полупрозрачными; большие поверхности при крупном перемещении гаснут и появляются, когда встали на место.

Расхождение с первоисточником: у Эмиля — «slow looping oscillations (near 0.2 Hz / one cycle per 5s)» (skills/apple-design/SKILL.md); по Apple Human Interface Guidelines, https://developer.apple.com/design/human-interface-guidelines/motion — правило о 0.2 Гц и движении окружения записано для visionOS.

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
```

## Краткая таблица значений

| Задача | Приём | Значение |
| --- | --- | --- |
| Пружина интерфейса по умолчанию | Критическое демпфирование, без перелёта | демпфирование `1.0`, отклик `0.3–0.4` |
| Пружина после броска или щелчка | Недодемпфированная, лёгкий отскок | демпфирование `~0.8`, отклик `0.3–0.4` |
| Скорость жеста → пружина | Передать скорость отпускания | `gestureVelocity / (target − current)`, если API ждёт нормированную |
| Точка остановки броска | Проекция импульса | `current + (v/1000)·d/(1−d)`, `d ≈ 0.998` |
| Чистое прерывание | Старт от видимого значения | читать трансформацию на экране |
| Без «кирпичной стены» при развороте | Перенос скорости через перенацеливание | пружина, которая смешивает скорость |
| Обратимый переход | Зеркальная кривая | `cubic-bezier(1 − x2, 1 − y2, 1 − x1, 1 − y1)` |
| Развернуть или завершить | По знаку скорости, а не по положению | в момент отпускания |
| Перетаскивание 1:1 | Pointer Events + захват | учитывать точку захвата |
| Обратная связь | На pointer-down, непрерывно | никогда только в конце |
| Граница | Резиновое сопротивление, не жёсткая остановка | постепенное сопротивление |
| Reduced motion | Затухание вместо слайда и пружины | `@media (prefers-reduced-motion)` |
