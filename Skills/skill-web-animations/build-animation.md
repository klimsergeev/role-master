# Построить анимацию

## Назначение

Процедура превращает запрос на движение в реализацию, которая проходит проверку по [review-motion.md](review-motion.md).

## Жёсткие правила

1. Шаги идут по порядку; шаги 1 и 2 — ворота. Кривая не выбирается, пока не решено, анимировать ли вообще.
2. Значения не выдумываются и не приближаются: значения скилла — в [motion-values.md](motion-values.md) и [recipes.md](recipes.md), у каждого другого значения есть свой источник (макет, прототип, токены проекта).
3. Параллельная система токенов не заводится: если в кодовой базе уже есть `--ease-out` или шкала длительностей, новое значение встаёт в неё.
4. Reduced motion и ограничение hover входят в тот же шаг, что и анимация.
5. Самый дешёвый работающий инструмент: библиотека движения не ставится ради затухания.

## Шаг 1: Анимировать ли вообще

Частота — по разделу «Частота → решение» [motion-values.md](motion-values.md). Действия, запущенные с клавиатуры, — дисквалификация.

ЕСЛИ запрос не проходит ворота → анимация не строится; результат шага — немоторная замена: мгновенная смена состояния или статичная подсказка.

## Шаг 2: Цель

Цель называется одним словом из раздела «Цель» [motion-values.md](motion-values.md). ЕСЛИ цель не называется → не строить. Там же — проверка функции: данные, которые читают или с которыми действуют, не двигаются ради стиля.

## Шаг 3: Инструмент — самый дешёвый работающий

Таблица проходится сверху вниз; берётся первый подходящий инструмент.

| Что нужно | Инструмент |
| --- | --- |
| Hover, нажатие, цвет, переключение состояния через класс или атрибут | **CSS transition** |
| Анимация входа при монтировании без JS-состояния | **CSS `@starting-style`** |
| Заранее заданное движение, которое должно оставаться плавным, пока страница занята загрузкой | **CSS animation** |
| Программное управление с производительностью CSS, без библиотеки | **WAAPI** (`element.animate()`) |
| Пружины, layout-анимации, анимации выхода, значения от жеста | **Motion** (`motion.dev`) |

Вне главного потока работают CSS-анимации и переходы тех свойств, которые браузер выносит на компоновщик (надёжно — `transform` и `opacity`). Анимации на `requestAnimationFrame`, включая layout-анимации Motion, при занятом главном потоке теряют кадры. Поэтому CSS — для заранее заданного движения, JS — для динамического и прерываемого.

Расхождение с первоисточником: у Эмиля — «CSS animations run off the main thread.» (skills/emil-design-eng/SKILL.md); по документации Motion, https://motion.dev/docs/performance — вне главного потока работают только анимации свойств, которые браузер выносит на компоновщик.

ЕСЛИ задаче нужен компонент, а не анимация (тост, шторка, командное меню, выпадающий список) → компонент не собирается вручную, берётся готовый примитив из стека проекта: самописный компонент даёт `<div>` вместо выпадающего списка и нет управления фокусом. ЕСЛИ готового примитива в проекте нет → процедура останавливается до решения пользователя, какую библиотеку-примитив подключить.

## Шаг 4: Свойства

- Только `transform` и `opacity`; `clip-path` — разрешённое четвёртое; `height` — только для аккордеона. Подробнее — раздел «Свойства» [motion-values.md](motion-values.md).
- Никогда `scale(0)`: старт с `scale(0.9–0.97)` + `opacity: 0`.
- `transform-origin` — у триггера для поповеров, выпадающих списков, меню, подсказок; модалки — исключение.
- Проценты в `translate()` вместо жёстких пикселей.
- В Motion новые версии аппаратно ускоряют независимые трансформации `x`/`y`/`scale`/`rotate`:

```jsx
<motion.div animate={{ x: 100 }} />                          // motion 14.2+: hardware accelerated
<motion.div animate={{ transform: "translateX(100px)" }} />  // hardware accelerated in every version
```

- `transform` детей не управляется через CSS-переменную на родителе.

## Шаг 5: Кривая и длительность — или пружина

Кривая — по разделу «Кривая», длительность — по разделу «Длительность», пружина и правило её выбора — по разделу «Пружины» [motion-values.md](motion-values.md). Пружина вместо кривой — для перетаскивания с импульсом, «живого» элемента, прерываемого жеста, декоративного следования за курсором.

## Шаг 6: Прерывание и выход

По разделу «Прерывание и выход» [motion-values.md](motion-values.md): переходы, а не keyframes, для всего, что срабатывает часто; пружины для жестов; выход тем же путём, что вход; асимметричный тайминг там, где пользователь решает.

## Шаг 7: Reduced motion и ограничение hover

По разделу «Доступность» [motion-values.md](motion-values.md): мягкий вариант под `prefers-reduced-motion` и hover под `@media (hover: hover) and (pointer: fine)` входят в этот же шаг.

## Маршруты внутри процедуры

- ЕСЛИ запрос совпадает с компонентом каталога → начинать с рецепта из [recipes.md](recipes.md), а не с пустого файла.
- ЕСЛИ движение ведёт жест → [gestures-and-springs.md](gestures-and-springs.md).
- ЕСЛИ на одно событие движутся два и более элемента → [choreography.md](choreography.md).

## Последние шаги

1. Сверить код с таблицей запретов из [motion-values.md](motion-values.md).
2. Выполнить проверку на ощупь по [feel-check.md](feel-check.md).

Результат процедуры — код анимации или, если ворота не пройдены, немоторная замена.
