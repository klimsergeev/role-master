# Система значений движения

## Назначение

Справочник частот, целей, кривых, длительностей, пружин и запретов, на который опираются все процедуры скилла.

## Частота → решение

| Как часто пользователь видит движение | Решение |
| --- | --- |
| 100+ раз в день (горячие клавиши, переключение командной палитры) | Никакой анимации. Никогда. На этом остановиться |
| Десятки раз в день (hover-эффекты, навигация по списку) | Только почти незаметное — быстро и тонко, или ничего |
| Изредка (модалки, шторки, тосты) | Стандартная анимация |
| Редко или впервые (онбординг, успех, праздничный момент) | Здесь живёт бюджет «восторга» |

Действия, запущенные с клавиатуры, — дисквалификация, а не вопрос суждения: они повторяются сотни раз в день, и анимация делает их медленными, запаздывающими и оторванными от действия пользователя.

## Цель

Цель называется одним из этих слов до продолжения работы:

- **Feedback** (обратная связь) — подтвердить, что интерфейс услышал пользователя.
- **Spatial consistency** (пространственная согласованность) — показать, откуда элемент пришёл или куда ушёл.
- **State indication** (индикация состояния) — сделать смену состояния читаемой.
- **Preventing a jarring change** (предотвращение резкой смены) — связать содержимое, которое иначе «телепортируется».
- **Explanation** (объяснение) — показать, как что-то работает; только маркетинг и онбординг.
- **Delight** (восторг) — только на уровне «редко или впервые».

ЕСЛИ цель не называется одним из этих слов → не строить. «Выглядит круто» на часто видимом элементе — повод остановиться.

Проверка функции: данные, которые пользователь читает или с которыми действует, не двигаются ради стиля. Декоративное следование за курсором уместно на маркетинговой странице, а не на графике в банковском приложении.

## Кривая

| Ситуация | Кривая |
| --- | --- |
| Вход или выход | `ease-out` |
| Движение или морф на экране | `ease-in-out` |
| Hover, смена цвета | `ease` |
| Постоянное движение (бегущая строка, прогресс) | `linear` |
| По умолчанию | `ease-out` |

НИКОГДА `ease-in` на интерфейсе: кривая стартует медленно и задерживает начальное движение — тот самый момент, на который пользователь смотрит внимательнее всего. Выпадающий список с `ease-in` за 300ms ощущается медленнее, чем с `ease-out` за те же 300ms.

Встроенные кривые CSS слишком слабые; используются сильные кастомные кривые. Третья кривая — кривая шторки как в iOS из Ionic Framework.

```css
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);        /* strong ease-out for UI */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);    /* strong ease-in-out for on-screen movement */
--ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);     /* iOS-like drawer curve (Ionic) */
```

Кривую, которой нет ни в одном источнике задачи, брать с [easing.dev](https://easing.dev/) или [easings.co](https://easings.co/), а не рисовать самому.

## Длительность

| Элемент | Длительность |
| --- | --- |
| Отклик на нажатие кнопки | 100–160ms |
| Подсказки, маленькие поповеры | 125–200ms |
| Выпадающие списки, select | 150–250ms |
| Модалки, шторки | 200–500ms |
| Маркетинг, объясняющие анимации | Может быть дольше |

Правило: анимации интерфейса укладываются в 300ms. Выпадающий список за 180ms ощущается отзывчивее, чем за 400ms.

Воспринимаемая скорость:

- Быстро вращающийся спиннер делает загрузку на ощупь быстрее при том же времени загрузки.
- Select с анимацией 180ms ощущается отзывчивее, чем с 400ms.
- Мгновенные подсказки после первой открытой (без задержки и без анимации) делают всю панель инструментов на ощупь быстрее.

## Пружины

Пружина вместо кривой — когда движение:

- перетаскивание с импульсом;
- элемент, который должен ощущаться «живым» (как Dynamic Island у Apple);
- жест, который пользователь может прервать или развернуть;
- декоративное следование за курсором.

```js
{ type: "spring", duration: 0.5, bounce: 0.2 }        // Apple-style — easier to reason about
{ type: "spring", mass: 1, stiffness: 100, damping: 10 }  // traditional physics — more control
```

Отскок держать в пределах 0.1–0.3 и избегать его в большей части интерфейса — он для смахивания с закрытием и игривых взаимодействий.

Физическая пружина (`stiffness`, `damping`, `mass`) не имеет фиксированной длительности и останавливается по порогам `restSpeed` и `restDelta`; у Motion есть и пружины, заданные длительностью (`duration` + `bounce`, `visualDuration`).

Расхождение с первоисточником: у Эмиля — «They don't have fixed durations — they settle based on physical parameters.» (skills/emil-design-eng/SKILL.md); по документации Motion, https://motion.dev/docs/react-transitions — пружины Motion бывают и физическими, и заданными длительностью (`duration` + `bounce`, `visualDuration`).

Пружины на `duration` + `bounce` скорость не учитывают — ни унаследованную от прерванной анимации, ни переданную в `velocity` (подробнее — раздел «Прерывание и выход»).

Расхождение внутри набора: emil-design-eng — `{ type: "spring", duration: 0.5, bounce: 0.2 }` как рекомендуемая; apple-design — `bounce: 0, duration: 0.4` по умолчанию и `bounce: 0.2` только после жеста с импульсом.

Правило выбора пружины:

- ЕСЛИ пружина должна принять скорость (отпускание после перетаскивания, смахивания, броска; прерывание идущего движения) → физическая пружина `{ type: "spring", mass: 1, stiffness: 100, damping: 16 }`, скорость жеста — в опции `velocity`. Значение расчётное: коэффициент демпфирования ζ = damping / (2 · √(stiffness · mass)) = 16 / (2 · √100) = 0.8 — около 0.8, как у Apple для отпускания после жеста с импульсом. У Эмиля такой конфигурации нет: его физическая пружина `damping: 10` даёт ζ = 0.5.
- ЕСЛИ скорость принимать не нужно и взаимодействие игривое → `{ type: "spring", duration: 0.5, bounce: 0.2 }`.
- Иначе → `{ type: "spring", bounce: 0, duration: 0.4 }`.

Расхождение с первоисточником: у Эмиля — «Settle with a spring so an interrupted drag keeps its velocity» (skills/animate/RECIPES.md) с пружиной `{ type: "spring", duration: 0.5, bounce: 0.2 }`; по документации Motion, https://motion.dev/docs/react-transitions — пружина на `duration` + `bounce` скорость не переносит, переносит только физическая пружина.

## Физичность

- НИКОГДА `scale(0)`: в реальном мире ничто не появляется из ничего. Старт — `scale(0.9–0.97)` вместе с `opacity: 0`.
- Поповеры, выпадающие списки, меню и подсказки масштабируются из триггера, а не из центра. Переменную `--transform-origin` выставляет Base UI:

  ```css
  .popover { transform-origin: var(--transform-origin); } /* Base UI */
  ```

  Модалки — исключение: они не привязаны к триггеру и остаются по центру, `transform-origin: center` для них верен.
- Точка трансформации по умолчанию — центр (`50% 50%`); у SVG-элементов без CSS-раскладки — `0 0`, левый верхний угол.

  Расхождение с первоисточником: у Эмиля — «Every element has an anchor point from which transforms execute. The default is center.» (skills/emil-design-eng/SKILL.md); по спецификации CSS Transforms Level 1, https://drafts.csswg.org/css-transforms-1/#transform-origin-property — для SVG-элементов без CSS-раскладки начальное значение `0 0`.
- Проценты в `translate()` отсчитываются от размера самого элемента: `translateY(100%)` сдвигает на собственную высоту при любом содержимом. Так Sonner ставит тосты и Vaul прячет шторку. Проценты предпочтительнее жёстких пикселей.
- `scale()` масштабирует и детей — текст, иконки и содержимое; для отклика на нажатие это свойство, а не ошибка.
- Отклик на нажатие: `transform: scale(0.97)` на `:active`, `transition: transform 160ms ease-out`; масштаб тонкий, 0.95–0.98; относится к любому нажимаемому элементу.

## Свойства

- Анимируются только `transform` и `opacity`: они не запускают раскладку и отрисовку. `padding`, `margin`, `height`, `width` запускают все три этапа отрисовки.
- `clip-path` — разрешённое четвёртое свойство (рецепты — в [recipes.md](recipes.md)). `height` терпим только для аккордеона, где нет эквивалента на `transform`.
- Сокращения Motion `x`/`y`/`scale`/`rotate` с версии `motion` 14.2 аппаратно ускоряются на HTML-элементах, в более ранних версиях работают на главном потоке; подробности и блок кода — в [performance.md](performance.md).
- `transform` детей не управляется через CSS-переменную на родителе — `transform` ставится прямо на элемент. Пользовательские CSS-свойства наследуются, поэтому смена переменной на родителе затрагивает стили всех потомков, которые её наследуют; объём пересчёта зависит от движка. Наследование отключает регистрация через `@property` с `inherits: false`.

  Расхождение с первоисточником: у Эмиля — «Changing a CSS variable on a parent recalculates styles for all children.» (skills/emil-design-eng/SKILL.md); по CSS Properties and Values API Level 1, https://drafts.css-houdini.org/css-properties-values-api-1/#inherits-descriptor — наследование подтверждено, объём пересчёта спецификация не описывает, а зарегистрированное свойство с `inherits: false` не наследуется.

## Прерывание и выход

- Переходы, а не keyframes, для всего, что срабатывает часто: тосты, переключатели, всё, что пользователь может запустить дважды за секунду.
- Пружины — для жестов.
- Выход тем же путём, что вход: тост, въехавший снизу, уходит вниз. Симметричный путь делает смахивание с закрытием очевидным.
- Асимметрия там, где пользователь решает: медленно в намеренной фазе (удержание для подтверждения — 2s `linear`), быстро в ответе системы (отпускание — 200ms `ease-out`).

```css
.overlay { transition: clip-path 200ms ease-out; }            /* release: fast */
.button:active .overlay { transition: clip-path 2s linear; }  /* press: slow, deliberate */
```

Что происходит при прерывании:

- Физические пружины Motion (`stiffness`, `damping`, `mass`) при прерывании сохраняют скорость; пружины на `duration` + `bounce` скорость не учитывают — ни унаследованную, ни переданную в `velocity`. CSS-переход при прерывании стартует с текущего значения, но без скорости; с первого кадра начинаются только `@keyframes`.

  Расхождение с первоисточником: у Эмиля — «Springs maintain velocity when interrupted — CSS animations and keyframes restart from zero.» (skills/emil-design-eng/SKILL.md); по документации Motion, https://motion.dev/docs/react-transitions — скорость сохраняют только физические пружины, пружины на `duration` + `bounce` её не учитывают; CSS-переход стартует с текущего значения.
- `@keyframes` для жестов не годятся — начинаются с первого кадра. CSS-переход при прерывании стартует с текущего значения и умеет ускоренный разворот, но скорость пальца не переносит. Всё, что ведёт палец, анимируется физической пружиной, которая скорость учитывает. Любая анимация Motion стартует с текущего значения.

  Расхождение с первоисточником: у Эмиля — «**Avoid CSS transitions and `@keyframes` for anything gesture-driven** — they can't be smoothly grabbed and reversed mid-flight. Springs animate from the current value by default» (skills/apple-design/SKILL.md); по CSS Transitions Level 1, https://drafts.csswg.org/css-transitions-1/#reversing — прерванный переход стартует с текущего значения и умеет ускоренный разворот, не сохраняется только скорость.

Правило:

- ЕСЛИ движение ведёт палец или жест → физическая пружина по разделу «Пружины».
- ЕСЛИ движение часто запускается, но без жеста → CSS-переход.
- `@keyframes` — только для того, что не прерывается.

## Стаггер

Когда несколько элементов входят вместе, их появление сдвигается: 30–80ms между элементами. Длинные задержки делают интерфейс медленным. Стаггер декоративен и никогда не блокирует взаимодействие, пока играет. Отношения внутри группы — в [choreography.md](choreography.md).

## Маскировка кроссфейда

ЕСЛИ при кроссфейде видны два наложенных состояния, а подбор кривой и длительности не помогает → на время перехода добавить `filter: blur(2px)`: размытие сливает два состояния в одно воспринимаемое превращение. Размытие держать меньше 20px. По наблюдению Эмиля Ковальски, тяжёлое размытие дорого, особенно в Safari.

## Доступность

`prefers-reduced-motion` означает «меньше и мягче», а не ноль: сохраняются переходы прозрачности и цвета, которые помогают понять происходящее; убираются перемещение и смена положения.

На сенсорных экранах `:hover`, в зависимости от браузера, не срабатывает, срабатывает на мгновение после касания или остаётся активным до касания другого элемента. Медиазапрос `(hover: hover) and (pointer: fine)` отсекает такие устройства, но спецификация предупреждает, что `:hover` может сработать и при `hover: none`.

Расхождение с первоисточником: у Эмиля — «Touch devices trigger hover on tap, causing false positives.» (skills/emil-design-eng/SKILL.md); по MDN, https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/:hover — поведение `:hover` при касании зависит от браузера.

```css
@media (prefers-reduced-motion: reduce) {
  .element { animation: fade 0.2s ease; } /* keep opacity/color, drop transform-based motion */
}

@media (hover: hover) and (pointer: fine) {
  .element:hover { transform: scale(1.05); } /* touch fires false hovers on tap */
}
```

```jsx
const reduce = useReducedMotion();
const closedX = reduce ? 0 : '-100%';
```

## Связность

- Значения движения подбираются по характеру компонента: игривый компонент может пружинить, рабочая панель — чёткая и быстрая.
- Пример Sonner: анимация тоста 400ms с `ease`, а не `ease-out`, немного медленнее типичной анимации интерфейса — кривая и длительность подобраны под характер библиотеки, дизайн тоста и название.
- Пара `opacity` и `height` во входящем и уходящем списке подбирается на ощупь: формулы нет, значения двигают, пока не станет правильно.

## Таблица запретов и замен

| Никогда | Вместо |
| --- | --- |
| `transition: all` | Назвать точные свойства: `transition: transform 200ms ease-out` |
| Вход с `transform: scale(0)` | `scale(0.95)` + `opacity: 0` |
| Вход чистым затуханием без начальной трансформации | Старт `scale(0.9–0.97)` + `opacity: 0` (раздел «Физичность») |
| `ease-in` на элементе интерфейса | `ease-out` или сильная кастомная кривая |
| Слабая встроенная кривая (встроенный `ease-out`) на намеренной анимации | `cubic-bezier(0.23, 1, 0.32, 1)` |
| Анимация на горячей клавише, переключении командной палитры или действии 100+ раз в день | Без анимации |
| Длительность интерфейса больше 300ms без причины | 150–250ms |
| `transform-origin: center` у поповера, выпадающего списка или подсказки, привязанных к триггеру | Положение триггера или `var(--transform-origin)` у Base UI (модалки — исключение, остаются по центру) |
| Keyframes на тостах, переключателях и всём, что срабатывает часто | CSS-переходы |
| Анимация `width`/`height`/`margin`/`padding`/`top`/`left` | `transform` / `opacity` |
| Сокращения Motion `x`/`y`/`scale` под нагрузкой в версиях до 14.2 | Обновиться до 14.2+ или полная строка `transform` |
| Layout-анимации Motion на движении, которое играет при занятой странице | CSS-анимация или WAAPI ([performance.md](performance.md)) |
| Обновление CSS-переменной на родителе ради `transform` детей | `transform` прямо на элементе |
| `:hover`-движение без медиазапроса | `@media (hover: hover) and (pointer: fine)` |
| Движение без обработки `prefers-reduced-motion` | Мягкий вариант, не ноль |
| Симметричный тайминг входа и выхода на нажатии или удержании | Выход быстрее входа (удержание 2s `linear`, отпускание 200ms `ease-out`) |
| Всё появляется разом там, где нужен стаггер | Стаггер 30–80ms между элементами |
