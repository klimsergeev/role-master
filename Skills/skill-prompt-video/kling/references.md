# Kling: входные материалы

## Назначение

Как подавать Kling изображения, видео, элементы и голоса: элементы и их имена, ссылки на материалы по поверхностям, поля элементов `contents`, роли материалов, видео-референс и видео для правки, первый, последний и промежуточные кадры, раскадровка как референс и лимиты по моделям и поверхностям.

Состояние на 2026-11-16.

## Элементы

- Элемент — персонаж или предмет, который модель удерживает одинаковым. Создаётся из видео персонажа 3–8 с (модель извлекает внешность и исходный голос; голос можно заменить чистой записью) или из 2–4 изображений; персонажу можно добавить запись голоса или выбрать голос.
- VIDEO 3.0: элемент привязывается к загруженному изображению, чтобы персонаж оставался стабильным при приближении, панорамировании и наклоне камеры; до 3 элементов; элементы должны присутствовать в кадре-референсе.
- ЕСЛИ у элемента уже привязан голос -> голос в промпте повторно не задаётся.
- Запись голоса для элемента из изображений у VIDEO 3.0 Omni: источники расходятся — одна позиция: от 3 с; другая: 5–30 с.
- Имена элементов: имя не должно содержаться в другом имени (`@Mira` и `@Miranda` в одной задаче нельзя) и не должно совпадать с частью текста промпта (`@port` в промпте о морском порте нельзя). Имя элемента — до 20 символов.
- В API элемент передаётся идентификатором `element_id` из API элементов.

## Ссылки на материалы

| Поверхность | Запись ссылки |
|---|---|
| Приложение, VIDEO 3.0 и 3.0 Omni | `@` и имя элемента; изображение — `@Image`; запись ссылки на видео у 3.0 Omni не установлена — рядом с промптом предупредить |
| Приложение, Kling 4.0 | по порядку загрузки: `@Image1`, `@Image2`, `@Video1` |
| Новые адреса API, Kling 4.0 и 4.0 Flash | каждому материалу в `contents` задаётся `id`, в промпте — `@` и этот `id` (`@image_1`); `id` уникальны в пределах задачи |
| Новые адреса API, VIDEO 3.0 и 3.0 Omni | `@xxx`; чему он равен — расхождение ниже |
| Старый адрес `/v1/videos/omni-video` | `<<<element_1>>>`, `<<<image_1>>>`, `<<<video_1>>>` — номер по порядку в своём списке |
| Старый адрес `/v1/videos/image2video` | голос — `<<<voice_1>>>`, номер по порядку в `voice_list` |

### Ссылка `@xxx` у VIDEO 3.0 и 3.0 Omni в новых адресах

- Источники расходятся: одна позиция — `@xxx` равен значению поля `id` элемента `contents`; другая — `@xxx` у элемента равен имени элемента.
- Процедура: каждому изображению и видео задаётся `id` (`image_1`, `video_1`), в промпте — `@image_1`, `@video_1`; элементу задаётся `id`, равный его имени, если имя известно и удовлетворяет правилам имён, и в промпте пишется `@` с этим именем — тогда обе позиции указывают на один и тот же текст.
- Рядом с промптом — предупреждение: чему соответствует `@xxx` у этих адресов, не установлено.

## Поля элементов `contents`

| Тип | Поля | Значение | `id` | Адреса |
|---|---|---|---|---|
| `prompt` | `type`, `text` | текст промпта | нет | все адреса с `contents` |
| `first_frame`, `middle_frame`, `last_frame` | `type`, `url`, `id` | URL или Base64 | Kling 4.0: для ссылки `@id`, уникален; в адресе Omni при нескольких `middle_frame` обязателен; VIDEO 3.0 Omni: необязателен, задаётся для ссылки `@`; VIDEO 3.0 из изображения и первый кадр 4.0 Flash из изображения: поля `id` нет | `middle_frame` — только Kling 4.0 |
| `refer_image` | `type`, `url`, `id` | URL или Base64 | для ссылки `@id`; при нескольких `refer_image` у Kling 4.0 обязателен; у VIDEO 3.0 Omni необязателен | Omni |
| `feature_video`, `base_video` | `type`, `url`, `id` | только URL | необязателен | Omni |
| `element` | `type`, `element_id`, `id` | `element_id` из API элементов | обязателен | Omni всех версий, VIDEO 3.0 из изображения |
| `voice` | `type`, `voice_id`, `id` | `voice_id` из API пользовательских голосов или системный голос | обязателен | только `/omni-video/kling-4.0` |

## Роли материалов

- Kling 4.0: роль каждого материала называется явно отдельной фразой в блоке `[Asset Roles]`. Без ролей модель сама решает, как использовать материал, и результат менее предсказуем.
- ЕСЛИ материалы несут разную информацию -> указать границы роли каждого и прямо исключить то, что переносить не надо.

| Тип референса | Что сказать в роли |
|---|---|
| Персонаж | черты лица и внешность держать строго по изображению |
| Действие | движения и тайминг — из видео, внешность — из изображений |
| Камера | траектория и темп камеры — из видео, субъект и фон — из изображений |
| Композиция | сохранить композицию изображения |
| Раскадровка | изображение персонажа задаёт внешность, раскадровка — порядок планов, кадрирование, траектории камеры, направление движения и развитие эмоций; прямо попросить готовые кадры, иначе в видео попадут сетка, плашки заголовков и пометки с листа |

- VIDEO 3.0 Omni: порядок описания при нескольких референсах — в [prompt-anatomy.md](prompt-anatomy.md).

## Видео-референс и видео для правки

- `feature_video` — референс для новой генерации: камера, действие, стиль. `base_video` — видео, которое нужно изменить. Модель определяет назначение видео по адресу и объявленному типу.
- Тайминг видео-референса модель воспроизводит очень буквально (наблюдение пользователя модели, опубликованное разработчиком).
- Правка — в [editing.md](editing.md).

## Первый и последний кадр

- VIDEO 3.0 и 3.0 Omni: только первый кадр или первый и последний; последний кадр без первого не поддерживается.
- VIDEO 3.0: первый кадр и до 3 элементов; привязываются элементы, которые есть в первом кадре.
- Kling 4.0, только первый кадр: `@Image1` — первый кадр, дальше описывается, что происходит после него.
- Kling 4.0, первый и последний кадр: `@Image1` — первый кадр, `@Image2` — последний, между ними описывается процесс. Подходящие задачи — превращение, ремесленный процесс, сравнение «до и после».
- Kling 4.0, только последний кадр: описывается то, что происходит до него.
- Kling 4.0 Flash: только первый кадр; описывается, что происходит после него, движение камеры и что должно оставаться неизменным.
- В API ссылки на кадры — через `id` (`@frame_1`); в приложении — по порядку загрузки.

## Промежуточные ключевые кадры

- Только Kling 4.0, у 4.0 Flash нет.
- Шаблон: отрезки времени с номерами кадров — `X–Y sec | Keyframe 1: [what happens]`, `Y–Z sec | Keyframe 2: [what happens]`. Для каждого кадра описывается, что в нём происходит и как камера в него приходит.
- Без ключевых кадров порядок и время изменений решает модель, с ними — пользователь.
- API: до 10 изображений; порядок в `contents` — первый кадр, промежуточные в порядке появления, последний; каждому кадру задаётся `id`, в промпте — `@id` с ролью кадра; порядок передачи кадров совпадает с порядком ссылок в промпте.
- Приложение: вход Keyframes не принимает референсы, соотношение сторон берётся с первого ключевого кадра, совместить Keyframes и Omni Reference в одной задаче нельзя. В API ключевые кадры и референсы совмещаются в адресе Omni.

## Лимиты

### Kling 4.0

- Адрес Omni, изображения: `.jpg`, `.jpeg`, `.png`; до 30 МБ; стороны от 300 px; соотношение от 2:5 до 5:2; до 10 изображений; URL или Base64.
- Адрес Omni, видео: `.mp4`, `.mov`; до 300 МБ; длительность каждого и общая — от 3 до 30 с (в общую входят `feature_video`, `base_video` и видеоэлементы персонажей); стороны 700–4553 px, площадь до 8 294 400 px; соотношение от 2:5 до 5:2; вход 24–60 кадров/с, выход 24 кадра/с. Без видеоэлементов — до 5 видео-референсов; с видеоэлементами — в сумме до 5; `base_video` — не больше одного.
- Адрес Omni: элементы — до 7, из них видеоэлементов персонажей до 3; голоса — до 3; изображения, видео, элементы и голоса вместе — до 15.
- Адрес image-to-video: до 10 изображений-кадров.
- Приложение, правка: до 5 клипов, из них 1 основной; каждый 3–30 с, всего до 30 с. После пяти видео-референсов видеоэлемент не добавить: у видео-референсов, видео для правки и видеоэлементов общий лимит — 5 клипов и 30 с.

### Kling 4.0 Flash

- Адрес Omni: изображения, видео и элементы вместе — до 15; изображений — до 10; общая длительность видео на входе — до 20 с; голосов, последнего и промежуточных кадров нет.
- Адрес image-to-video: только первый кадр.

### Kling VIDEO 3.0

- Новый адрес image-to-video: изображения `.jpg`, `.jpeg`, `.png`; до 50 МБ; стороны от 300 px; соотношение от 1:2.5 до 2.5:1; `first_frame` обязателен, `last_frame` необязателен; элементы — до 3.
- Старый адрес `/v1/videos/image2video`: изображение `image` и последний кадр `image_tail` — строки (URL или Base64 без префикса `data:`), хотя бы одно обязательно; `element_list` — до 3, `voice_list` — до 2, они взаимоисключающие; при голосе `sound` — `on`.

### Kling VIDEO 3.0 Omni

Лимиты разделены по поверхности: приложение и API различаются.

- Новый адрес, изображения: до 50 МБ, стороны от 300 px, соотношение от 1:2.5 до 2.5:1.
- Новый адрес, сочетания: без видео-референса и только с элементами из изображений — изображения и элементы вместе до 7; без видео-референса, но с видеоэлементами персонажей — до 4; с видео-референсом и только с элементами из изображений — до 4; с видео-референсом нельзя одновременно видеоэлемент персонажа и изображения-референсы.
- Новый адрес, видео: `.mp4`, `.mov`; до 200 МБ; 3–15,5 с; стороны 700–4553 px, площадь до 8 294 400 px; соотношение 0,4–2; вход 24–60 кадров/с, выход 24 кадра/с; не больше одного видео-референса, после него — не больше одного видеоэлемента персонажа.
- Новый адрес, элементы: при генерации по первому или первому и последнему кадру — до 3; без видео-референса и только видеоэлементы персонажей — до 3; с видео-референсом и только видеоэлементы — до 1.
- Новый адрес: с `feature_video` звук только `off`; мультикадровые видео-референсы поддерживаются, и тогда `multi_shot` только `true`. С `base_video` нельзя первый и последний кадр, мультикадровость и `audio: native`; `multi_shot: false` передаётся явно, потому что по умолчанию он `true` (в [editing.md](editing.md)).
- Приложение: одно видео 3–10 с, до 200 МБ, до 2K; изображения до 10 МБ; до 7 изображений или элементов, при видео на входе — до 4.
- Старый адрес `/v1/videos/omni-video`: изображения до 10 МБ; `image_list` с `type` `first_frame` или `end_frame` только у первого и последнего кадров, у референсов `type` не задаётся; `video_list` — не больше одного видео; голосов нет, голос — только через привязку к элементу.

## Примеры

### Пример 1: два изображения в Kling 4.0 Omni Reference

**Вход:** «Kling 4.0: фото воздушного змея и фото девочки, змей должен быть точно как на фото, девочка — героиня».

**Результат** (иллюстрация скилла): в `contents` — `refer_image` с `"id": "image_1"` (змей) и `"id": "image_2"` (девочка); блок `[Asset Roles]`: `@image_1 is the kite: keep its shape, colors and ribbon tail exactly. @image_2 is the girl: keep her face, hair and raincoat exactly, take nothing else from this image.`

### Пример 2: элемент в VIDEO 3.0 Omni через новый адрес

**Вход:** «Kling Omni 3 через API, мой элемент из библиотеки с именем Mira и фото оранжереи».

**Результат:** `{"type": "element", "element_id": "<ID>", "id": "Mira"}` и `{"type": "refer_image", "url": "<URL>", "id": "image_1"}`; в промпте — `@Mira` и `@image_1`; рядом с промптом — предупреждение, что соответствие ссылки `@xxx` у этого адреса не установлено.
