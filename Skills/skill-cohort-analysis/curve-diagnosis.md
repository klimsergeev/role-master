# Диагностика retention-кривых

## Назначение

Алгоритм диагностики формы retention-кривой (healthy/declining/dying), процедура activation analysis для поиска "aha moment", формат продуктовых рекомендаций.

## Формы retention-кривых

### Healthy (выход на плато)

```
     |########
     |        ##
     |          ####
     |              ################  <- плато, удержание стабилизируется
     +-------------------------------- время
```

- Кривая выравнивается на некотором проценте и не падает дальше
- Означает: есть ядро пользователей, для которых продукт создаёт устойчивую ценность
- Продукт имеет product-market fit (как минимум для части аудитории)
- **Действие:** оптимизировать ранние периоды (Day 1->7), чтобы больше пользователей доходили до плато

### Declining (медленное снижение)

```
     |########
     |        ###
     |           ###
     |              ###
     |                 ###           <- медленно, но снижается
     +-------------------------------- время
```

- Кривая снижается, но медленнее, чем dying
- Означает: продукт даёт ценность, но она уменьшается со временем или есть лучшие альтернативы
- Может перейти в healthy при продуктовых улучшениях
- **Действие:** найти точку перелома (где ускоряется падение), проработать activation и re-engagement

### Dying (стремится к нулю)

```
     |########
     |        ####
     |            ####
     |                ####
     |                    ####       <- стремится к 0%
     +-------------------------------- время
```

- Кривая непрерывно падает к нулю без признаков выравнивания
- Означает: **отсутствие product-market fit** -- продукт не решает проблему или решает её для слишком узкой аудитории
- Больше привлечения НЕ поможет -- новые пользователи тоже уйдут
- **Действие:** остановить growth-инвестиции, сфокусироваться на PMF -- исследовать, почему пользователи уходят

## Алгоритм диагностики

### Шаг 1: Визуализировать кривую

Построить retention по периодам для каждой когорты. Минимум 6 точек на кривой для надёжной диагностики.

### Шаг 2: Определить форму

| Признак | Healthy | Declining | Dying |
|---|---|---|---|
| Последние 3 точки | Разброс < 3 п.п. | Падение 1-3 п.п. между точками | Падение > 3 п.п. между точками |
| Наклон к концу | ~0 (горизонтальный) | Слабо отрицательный | Сильно отрицательный |
| Экстраполяция | Плато на N% | Выход к 0% через долгое время | Выход к 0% в обозримом будущем |

### Шаг 3: Найти точку максимального drop-off

Вычислить разницу retention между последовательными периодами:

```
Drop-off(N) = Retention(N-1) - Retention(N)
```

Точка с максимальным drop-off -- приоритет для продуктовой работы.

| Точка drop-off | Типичная причина | Типичное решение |
|---|---|---|
| Day 0 -> Day 1 | Плохой onboarding, непонятна ценность | Улучшить first-time experience |
| Day 1 -> Day 7 | Не сформирована привычка | Триггеры возврата, уведомления, activation |
| Day 7 -> Day 14 | Исчерпание первичной ценности | Deeper engagement, расширение функций |
| Day 14 -> Day 30 | Конкуренция, потеря интереса | Re-engagement, новые use cases |
| Day 30+ | Естественный churn | Lifecycle marketing, loyalty programs |

### Шаг 4: Сравнить когорты

Если доступно несколько когорт -- сравнить столбцы таблицы:

- ЕСЛИ более новые когорты лучше -> продуктовые изменения работают, продолжать
- ЕСЛИ более новые когорты хуже -> регрессия: изменения в продукте или трафике ухудшают retention
- ЕСЛИ когорты одинаковы -> продуктовые изменения не влияют на retention

## Activation Analysis

Процедура поиска "aha moment" -- действия, которое предсказывает долгосрочное удержание.

### Алгоритм

**Шаг 1:** Разделить пользователей на 2 группы:
- Retained: активны через 30+ дней
- Churned: не возвращались после первой недели

**Шаг 2:** Сравнить поведение групп в первые 7 дней:
- Какие действия совершали retained, но не churned?
- Какова частота этих действий в каждой группе?

**Шаг 3:** Для каждого действия-кандидата рассчитать:

```
Lift = Retention(выполнившие действие) / Retention(не выполнившие)
```

**Шаг 4:** Ранжировать кандидатов по:
1. Lift (чем выше, тем сильнее предсказательная сила)
2. % пользователей, выполняющих действие (слишком редкое действие бесполезно как activation metric)
3. Управляемость -- можно ли продуктово подтолкнуть к этому действию?

### Классические примеры activation metrics

| Продукт | Activation Metric | Таймфрейм |
|---|---|---|
| Facebook | Добавить 7 друзей | 10 дней |
| Slack | Отправить 2000 сообщений командой | 30 дней |
| Twitter | Подписаться на 30 аккаунтов | 7 дней |
| Dropbox | Положить файл в 1 папку на 1 устройстве | 1 час |
| Zoom | Провести первый звонок | 1 день |

### Ловушки activation analysis

- **Корреляция != причинность** -- "активные пользователи делают X" может означать, что X -- следствие активности, а не причина
- **Survivorship bias** -- анализируются только дожившие до 30 дня; проверяй, что действие доступно всем
- **Размер выборки** -- обе группы (retained и churned) должны быть > 100 пользователей
- **Множественное тестирование** -- при проверке 20 действий одно будет значимым случайно; приоритизируй по бизнес-логике

## Формат рекомендаций

Финальный отчёт когортного анализа должен содержать следующие компоненты:

### 1. Retention-таблица

Заполненная таблица из [retention-metrics.md](retention-metrics.md) с аннотациями трендов.

### 2. Диагноз кривой

```
Форма кривой: [Healthy / Declining / Dying]
Плато (если есть): [N]% на [Period X]+
Тренд между когортами: [Улучшение / Стабильность / Деградация]
```

### 3. Ключевые drop-off точки

```
Критическая точка: [Period A] -> [Period B]
Потеря: [X]% пользователей ([абсолютное число])
Вероятная причина: [гипотеза]
```

### 4. Activation Metric (если проводился analysis)

```
Кандидат: [действие]
Lift: [X]x (retained [Y]% vs non-retained [Z]%)
Охват: [N]% пользователей выполняют это действие
Управляемость: [высокая / средняя / низкая]
```

### 5. Рекомендации

Ранжированный список, каждая рекомендация содержит:

```
[Приоритет: высокий/средний/низкий]
Что: [конкретное действие]
Почему: [какой drop-off или паттерн адресует]
Ожидаемый эффект: [какой retention-показатель и на сколько может улучшиться]
```

### Правила формулирования рекомендаций

- ВСЕГДА привязывай рекомендацию к конкретной точке данных (drop-off, сравнение когорт, activation lift)
- НИКОГДА не рекомендуй "увеличить привлечение" при dying curve
- ЕСЛИ данных недостаточно для рекомендации -> явно укажи, какие данные нужны
- Максимум 5 рекомендаций, ранжированных по ожидаемому влиянию
- Каждая рекомендация должна быть actionable -- команда должна понимать, что делать
