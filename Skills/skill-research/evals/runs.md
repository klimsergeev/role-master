# Журнал прогонов

Записи о том, как проверялась активация скилла. Новая запись добавляется сверху, прежние не переписываются. Набор кейсов — в [triggers.md](triggers.md).

## 2026-10-07 — активационный прокси на Haiku, проза 1.0.0

- **Дата:** 2026-10-07.
- **Модель судьи:** `claude-haiku-4-5-20251001` — значение поля `model` в транскрипте каждого из 48 субагентов. Вызов через Agent tool, `subagent_type: general-purpose`, `model: haiku`, без роли и без скиллов.
- **Версия прозы:** `description` и `when_to_use` из `SKILL.md` версии 1.0.0, без правок. Длина после `yaml.safe_load` и `strip()`: `description` 593 + `when_to_use` 634 = 1227 символов при лимите 1536.
- **Тип оценки:** реальный прогон на отдельной модели, не самооценка. Метод одиночный: в промпте судьи только этот скилл.
- **Голоса:** 16 кейсов × 3 голоса = 48 субагентов, каждый голос — отдельный субагент с одним сообщением. Три раунда запускались последовательно, внутри раунда — 16 субагентов параллельно.

### Промпт судьи

Один и тот же для всех голосов, менялась только строка сообщения:

```
Ты — классификатор активации скиллов. Ниже описание одного скилла (поля name, description, when_to_use) и одно сообщение пользователя. Реши, должен ли агент, получивший это сообщение, активировать этот скилл. Не вызывай никаких инструментов и не читай файлов — решай только по переданному тексту. Ответь ровно одной строкой: TRIGGER или ABSTAIN, затем через тире причина одним предложением.

=== СКИЛЛ ===
name: skill-research
description: <description из SKILL.md 1.0.0 дословно>
when_to_use: <when_to_use из SKILL.md 1.0.0 дословно>

=== СООБЩЕНИЕ ПОЛЬЗОВАТЕЛЯ ===
<запрос из triggers.md>
```

### Валидность стенда

- Счётчик `tool_uses` у каждого из 48 субагентов равен 1, а не 0. Единственный вызов в каждом транскрипте — `SubagentHandback`: это обязательный в этом харнессе канал, по которому субагент сдаёт ответ вызывающему. Проверено разбором JSONL-транскриптов: в списке вызовов каждого субагента ровно `['SubagentHandback']`, ни одного `Read`, `Skill`, `Bash` или поиска. Классификация шла по переданному тексту; условие плана «`tool_uses: 0`» в этом харнессе буквально невыполнимо, и в отчёте это названо отклонением, а не закрыто молча.
- Независимость голосов: тексты причин сравнены скриптом попарно внутри каждого кейса. Дословных совпадений нет ни в одном из 16 кейсов, то есть 48 голосов — 48 отдельных выходов модели, а не повтор одного ответа.

### Наблюдения по причинам

- N7 («вытащи товары со страницы в JSON»): в двух голосах из трёх (первый и второй раунды) судья обосновал воздержание исключением «не для подбора товара», то есть сработал антипример про шопинг, а не граница «извлечение данных — не ресёрч». В третьем раунде причина — «спарсить каталог, а не провести ресёрч». Вердикт верный во всех трёх голосах, но держится частично на смежном исключении. Если в наборе появится извлечение данных не о товарах (например, таблица расписания со страницы), этот кейс стоит проверить отдельно.
- N8 («код по документации Stripe»): упоминание документации не потянуло на срабатывание, все три причины — «задача разработки, а не ресёрч».
- S3 и S6: судья опирался на близкие примеры из `when_to_use` («быстро найди статистику по X», «найди первоисточник этой цифры»).

### Что не покрыто

- Живой харнесс Claude Code с полным реестром установленных скиллов: прокси одиночный, конкуренция с соседями (`skill-report-company`, `skill-shopping-assistant`, `skill-product-strategy`) не мерилась.
- Сценарии в работе (преднагрузка через `skills:` роли `research-analyst`, дочитывание файлов-процедур) — это этап «Проверка роли в работе» в плане, он идёт после публикации.
- Вторая формулировка промпта судьи (семантическая, как в образце `skill-session-harvest`) не гонялась.
