# aiogram 3

## Назначение

Скилл описывает, как устроен код Telegram-бота на aiogram 3 с приёмом обновлений через long polling и как писать его под актуальный выпуск линии 3. Применяется, когда агент пишет, правит или проверяет Python-код бота.

## Принципы

1. Базовая версия — aiogram 3.32.0 (выпущена 2026-11-15): Python 3.11 и новее, Telegram Bot API 10.4, типы на pydantic 2. ЕСЛИ в проекте закреплена версия ниже 3.32.0 → сверяться с [versions.md](versions.md): часть приёмов в более ранних выпусках записывается иначе.
2. Обновления приходят только через long polling. Код webhook, внешние хранилища FSM, деплой и тесты ботов скилл не описывает.
3. Обработчики, фильтры, middleware и вызовы методов API пишутся асинхронно: все вызовы идут через `await`.
4. Аргументы вызовов методов API и сокращённых методов передаются по ключевым словам: Telegram добавляет параметры, и позиционные аргументы после обновления aiogram сдвигаются.

## Рабочий процесс

### Шаг 1: Определить версию aiogram в проекте

Найти версию aiogram в файле зависимостей проекта. ЕСЛИ версия ниже 3.32.0 → в шаге 2 добавить [versions.md](versions.md) к файлам строки. ЕСЛИ проект на aiogram версии 2 → сообщить пользователю, что скилл описывает только линию 3, и остановиться до его решения. ЕСЛИ aiogram в проекте ещё нет → писать под 3.32.0.

### Шаг 2: Выбрать строку и открыть файлы

Найти в таблице маршрутизации строку по задаче, открыть файлы колонки «Обязательно» и проверить условия колонки «Читать, если». ЕСЛИ задача состоит из нескольких → пройти строки по очереди.

### Шаг 3: Написать или изменить код

Строить код по правилам открытых файлов. Каркас нового бота: по роутеру на модуль, роутеры подключаются к `Dispatcher` через `include_routers`, универсальный обработчик подключается последним, запуск — `start_polling` или `run_polling`.

### Шаг 4: Сверить код перед ответом

Пройти список по каждому обработчику и вызову:

- обработчик объявлен через `async def`, а все вызовы методов внутри — через `await`
- фильтры переданы позиционно, не именованными аргументами
- роутер подключён ровно к одному родителю
- обработчик без фильтров или с широким фильтром (например, `F.text`) зарегистрирован после всех специфичных обработчиков того же события, а его роутер подключён после их роутеров
- на нажатие inline-кнопки есть ответ `callback.answer()` либо включён `CallbackAnswerMiddleware`
- аргументы вызовов API переданы по ключевым словам
- в коде нет webhook и внешних хранилищ FSM

### Шаг 5: Выдать результат

Код. ЕСЛИ пришлось сделать предположение о версии aiogram → назвать его.

## Что НЕ делать

- Не выдавать код вне охвата (webhook, Redis и подобные хранилища, развёртывание, тесты, aiogram 2, сторонние библиотеки вокруг aiogram) за проверенный по скиллу: сказать, что скилл эти темы не описывает.
- Не переносить в код линии 3 приёмы aiogram 2: скилл описывает только линию 3.
- Не добавлять в бот сторонние библиотеки вокруг aiogram, если пользователь о них не просил.
- Не писать позиционные аргументы в вызовах методов API и сокращённых методов.

## Примеры

### Пример 1: Каркас бота с командой и эхо-ответом

**Запрос:** «Напиши бота на aiogram: на `/start` приветствие, на остальной текст — эхо».

**Маршрут:** строка «Собрать каркас бота»: [dispatching.md](dispatching.md), [polling.md](polling.md), [bot-client.md](bot-client.md); условия колонки «Читать, если» не выполнены — версия в проекте не закреплена, диалога из нескольких шагов нет.

**Результат:** пакет `handlers` с роутером приветствия и роутером эха, `include_routers` с приветствием раньше эха, `Bot` с токеном из переменной окружения, запуск через `start_polling`; в сверке — `async def` у обоих обработчиков и фильтр `F.text` у эха.

### Пример 2: Проект на более раннем выпуске линии 3

**Запрос:** «В проекте закреплён aiogram 3.6. Добавь HTML-разметку для всех сообщений бота».

**Маршрут:** строка «Вызвать метод API, отправить или изменить сообщение»: [bot-client.md](bot-client.md); плюс [versions.md](versions.md), потому что версия в проекте ниже текущей; плюс [text-formatting.md](text-formatting.md), потому что текст с форматированием.

**Результат:** `Bot(token=..., default=DefaultBotProperties(parse_mode=ParseMode.HTML))`: передача `parse_mode` прямо в `Bot` объявлена устаревшей в 3.4.0 и убрана в 3.7.0, поэтому код записан способом, который переживёт обновление.

### Пример 3: Запрос вне охвата

**Запрос:** «Переведи бота на webhook и храни состояния диалога в Redis».

**Маршрут:** строки таблицы не подходят: приём обновлений через webhook и внешние хранилища FSM вне охвата скилла.

**Результат:** ответ, что скилл описывает только long polling и хранилище FSM в памяти, поэтому проверенных по скиллу шагов для webhook и Redis нет; предложение оставить polling или продолжить без опоры на скилл по решению пользователя.
