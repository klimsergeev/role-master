# Agent Teams — Диагностика

Справочник нестандартных ситуаций Agent Teams: тиммейты не появляются, «пропавший» тиммейт, ошибки API, осиротевшие tmux-сессии, сбои mailbox. Version-маркеры приведены как в официальной доке — поведение зависит от версии Claude Code.

## Mailbox (механика доставки)

- Inbox каждого агента — JSON-файл: `~/.claude/teams/{team-name}/inboxes/{agent-name}.json`.
- Claude Code **валидирует каждую запись** при чтении mailbox-файла. Записи, не совпадающие с форматом сообщения, репортятся как ошибки и удаляются из файла; валидные сообщения при этом всё равно доставляются.
- **До v2.1.207:** одна битая запись в mailbox вызывала повторяющуюся ошибку каждую секунду и **блокировала доставку** для этого mailbox, пока файл не удалить вручную.
  - Обходной путь на старых версиях: удалить проблемный `~/.claude/teams/{team-name}/inboxes/{agent-name}.json` вручную.

## Тиммейты не появляются

Проверить по порядку:

1. **«Пропавший» тиммейт — это скрытие строки, а не остановка.** Idle-строка панели скрывается, но тиммейт остаётся запущен и адресуем. Чтобы вернуть строку — отправить тиммейту сообщение по имени (`SendMessage`); строка вернётся на его следующем turn.
2. **Достаточно ли сложна задача.** Claude сам решает, спавнить ли команду, исходя из задачи. Простую задачу он команду не образует.
3. **Split-panes: установлен ли tmux** (если режим запрошен явно):
   ```bash
   which tmux
   ```
4. **iTerm2:** проверить, что установлен CLI `it2` и включён Python API в настройках iTerm2.

## Скрытие и сворачивание idle-строк (version-зависимо)

Точная механика зависит от версии Claude Code:

| Версия | Поведение idle-строки |
|---|---|
| до v2.1.181 | Idle-строки **не прячутся**. |
| v2.1.181 – v2.1.198 | Idle-строка прячется через **30 с после окончания собственного turn** — даже если другие тиммейты ещё работают. |
| с v2.1.199 | Idle-строка **остаётся** в панели, пока хоть один тиммейт или субагент работает (можно выбрать её и посмотреть транскрипт / дослать работу). Когда **вся** панель ушла в idle — строки прячутся через **30 с** и возвращаются на следующем turn тиммейта. Пока строка скрыта, тиммейт остаётся запущен и адресуем. |

**Сворачивание при >3 idle:** когда одновременно в idle больше трёх тиммейтов, строки сверх первых трёх сворачиваются в одну строку-счётчик, например `2 idle agents` (когда в idle пятеро). Выбрать её и нажать Enter — развернуть; Esc — свернуть обратно. Работающие, упавшие и просматриваемый сейчас тиммейты всегда сохраняют свои строки.

## Слишком много permission-промптов

Пермишен-запросы тиммейтов всплывают у лида, что создаёт трение. **Пре-одобрить типовые операции** в permission settings ДО спавна тиммейтов — тогда прерываний меньше.

## Тиммейт остановился на ошибке

- Тиммейт может остановиться после ошибки вместо восстановления. Открыть его вывод: выбрать тиммейта в agent panel и нажать Enter (in-process) либо кликнуть в его pane (split). Дальше — либо дать доп. инструкции напрямую, либо заспавнить замену.
- **С v2.1.198:** тиммейт, чей turn завершился на **ошибке API**, уведомляет лида, что он упал, и включает текст ошибки — вместо того чтобы выглядеть завершившимся нормально.
- **С v2.1.198:** сообщение от лида или другого тиммейта **будит** in-process тиммейта, ждущего retry упавшего API-запроса, — он повторяет запрос немедленно, не дожидаясь полной задержки retry.

## Лид завершился раньше времени

Лид может решить, что команда закончила, до фактического завершения всех задач. Если так — сказать ему продолжить. Если лид начал делать работу сам вместо делегирования — сказать «дождись, пока тиммейты завершат свои задачи».

## Осиротевшие tmux-сессии

Если tmux-сессия сохраняется после завершения сессии Claude Code — вероятно, она не была полностью очищена. Посмотреть список и завершить нужную:

```bash
tmux ls
tmux kill-session -t <session-name>
```
