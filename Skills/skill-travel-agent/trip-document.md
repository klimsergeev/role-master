# Итоговый документ поездки

## Назначение

Шаблон-образец итогового документа поездки: таблицы (маршрут по дням, бюджет, экстренные номера, обычаи/безопасность), цены с провенансом — из travel-API или со страницы поставщика, каждая в своей форме — и, где уместно, ссылка «где смотреть». Грузится на финальной упаковке. Бронирование не описывается — процесс брони вне роли.

## Структура документа

### 1. Шапка

Направление, даты, число путешественников, ключевые ограничения (например, «без музеев»).

### 2. Маршрут по дням

| День | Город/зона | Активности | Часы/примечания (с источником) |
|---|---|---|---|
| 1 | … | … | часы — веб-поиск, дата |
| 2 | … | … | … |

Времязависимые факты (часы, дни закрытия) — со ссылкой и датой (протокол — в [verification.md](verification.md)).

### 3. Бюджет

| Статья | Сумма | Класс источника | Источник (вендор или адрес) | Снимок | Пометка |
|---|---|---|---|---|---|
| Перелёт | … | API | Travelpayouts Data API | ГГГГ-ММ-ДД | «ориентировочно, по кэшу, проверить актуальную» |
| Перелёт (альт.) | … | Страница | `https://…` — сайт перевозчика | ГГГГ-ММ-ДД ЧЧ:ММ TZ | «цена этой сессии, до сборов и багажа» |
| Жильё | … | Страница | `https://…` — сайт отеля | ГГГГ-ММ-ДД ЧЧ:ММ TZ | «цена этой сессии, до курортного сбора» |

**Цены — только от первоисточника: travel-API или страница поставщика; каждая с провенансом своей формы** (см. [price-sources.md](price-sources.md), [verification.md](verification.md)).

- **Колонка «Класс источника» обязательна и заполняется одним из двух значений: `API` или `Страница`.** Она делает видимым, какая цена откуда, — смешивать обе формы в одну строку без пометки нельзя. Значения вроде «интернет», «нашёл в браузере», «источник указан выше» не годятся.
- **Колонка «Снимок» несёт разную точность для разных классов.** У API — дата (`expires_at`, где есть — `actual`, у v3 — `search_date`). У страницы — дата **и время** с часовым поясом: страница живая, число меняется в течение дня, и одна дата провенанс не закрывает.
- **Колонка «Источник» у страницы содержит полный адрес,** а не название сайта: по названию цену не перепроверить.
- Кэш-цена — с пометкой «ориентировочно, проверить актуальную». Браузерная — с пометкой персональной и предварительной: она зависит от сессии, региона и валюты профиля и может вырасти на оформлении за счёт сборов и налогов.
- Без провенанса цена в документ не попадает. Нет ни API, ни доступной страницы поставщика → в бюджете честно «цену дать не могу», а не выдуманное число и не число с агрегатора.

### 4. Экстренные номера

| Служба | Номер | Примечание |
|---|---|---|
| Полиция / скорая / пожарные | … | местные, проверить веб-поиском |
| Консульство/посольство | … | ИИ не заменяет консульство (см. [risk-practices.md](risk-practices.md)) |

### 5. Обычаи и безопасность

| Тема | Что учесть |
|---|---|
| Местные нормы | чаевые, дресс-код, этикет |
| Безопасность | районы, риски, сезонные факторы |

### 6. Где смотреть (не бронь)

Где уместно — ссылка «где смотреть цену / купить». Это указатель, а НЕ бронирование: процесс брони роль не выполняет и не описывает как флоу. Довести пользователя до страницы в браузере и оставить отобранное в корзине или в избранном можно — оформляет он сам (граница — в [browser-use.md](browser-use.md)).

Раздел не отменяется тем, что цена уже стоит в бюджете, и не дублирует её: в бюджете — число с провенансом, здесь — куда пойти оформлять. Витрина агрегатора как указатель «где смотреть» допустима, хотя её цена в бюджет не идёт: показать, где искать, и взять оттуда число — разные вещи.

## Что НЕ включать

- НЕ описывать процесс бронирования (book/prebook/order, хендофф брони).
- НЕ ставить цену без провенанса; у браузерной цены — без времени и часового пояса.
- НЕ ставить цену из памяти, из сниппета веб-поиска или с витрины агрегатора.
- НЕ оставлять строку бюджета без класса источника — «API» или «Страница» проставляется всегда.
- НЕ подавать браузерную цену как окончательную сумму: она персональная и до сборов.

## Примеры

### Пример 1: Готовый документ

**Вход:** проверенный план на 7 дней; перелёт взят из travel-API, жильё — со страницы отеля в браузере.

**Результат:** документ с таблицей дней (часы со ссылками), таблицей бюджета, экстренными номерами, обычаями; где уместно — «где смотреть». В бюджете две строки с разным классом источника: перелёт — `API`, вендор и дата снимка, пометка «по кэшу»; жильё — `Страница`, полный адрес сайта отеля, дата и время просмотра с поясом, пометка «цена этой сессии, до курортного сбора». Итог по бюджету сопровождается оговоркой, что часть сумм персональная и предварительная. Брони нет.

### Пример 2: Смешанный бюджет без API (edge-case)

**Вход:** ценовой API не подключён; браузер есть, сайт перевозчика найден, сайт нужного гестхауса — нет, зато его цена видна на витрине агрегатора.

**Результат:** строка «Перелёт» заполняется — класс `Страница`, адрес сайта перевозчика, дата и время, пометка «до сборов и багажа». Строка «Жильё» НЕ заполняется числом с витрины: вместо суммы — честная пометка «цену дать не могу, нужен сайт поставщика или подключённый источник», рядом ссылка «где смотреть» на ту же витрину для самостоятельной проверки. Единый прочерк по всему бюджету при этом не ставится: отсутствие API больше не обнуляет бюджет целиком, недостающей остаётся только та строка, у которой нет первоисточника.
