# Product Strategy

## Назначение

Процедура построения полной продуктовой стратегии для любого digital-продукта (мобильное приложение, web-сервис, SaaS) — от исследования рынка до дорожной карты и метрик. Результат по умолчанию — структурированный Markdown-документ; опционально по запросу выгружается в интерактивный HTML с боковой навигацией. Роутер с ленивой загрузкой: под конкретную задачу грузится только нужный reference-файл.

## Принципы

- **Каждая цифра = свежий источник + дата.** Любая рыночная, конкурентная или бенчмарк-цифра берётся через веб-поиск в момент использования и сопровождается пометкой `(Источник, месяц год)`. Числа НЕ хардкодятся в скилл — в reference-файлах только методология и что искать (согласуется с anti-bias: версии, метрики, цены, статистику всегда проверять поиском).
- **Данные не старше 2 лет.** Для рынка и конкурентов ищи самые свежие доступные данные; устаревшие цифры помечай датой явно.
- **Синтетика тегируется `[AI-симуляция]`.** Любые сгенерированные персоны, цитаты, ответы интервью — креатив, а не факт. Помечаются жёстко, чтобы выдумка не выдавалась за реальные данные пользователей. Реальные данные — `[Первичные данные]`. Смешивать в одной ячейке нельзя.
- **JTBD — от первого лица и результат-ориентированно.** Формулировка «Когда я..., я хочу..., чтобы...», без упоминания конкретного продукта или решения.
- **Касдев ≠ конкурентная аналитика.** Первичные наблюдения не смешиваются с анализом конкурентов.
- **Вижины — реальный выбор.** Каждое стратегическое направление имеет обоснованные плюсы, не «хороший vs плохой».
- **Мостики, а не копирование.** За количественной аналитикой метрик — `skill-product-analytics-methods`, `skill-cohort-analysis`, `skill-ab-test-analysis`; за спецификацией конкретной фичи — `skill-prd-writing`. Ссылайся, не переписывай их фреймворки.
- **Универсальность.** Скилл применим к любому digital-продукту. Бенчмарки монетизации/retention даются в общем виде, не привязаны жёстко к мобайлу.
- **Ленивая загрузка.** Читай только файлы под задачу из таблицы маршрутизации.

## Рабочий процесс

### Шаг 1: Собрать входные данные

Задать пользователю вопросы. Приоритет — интерактивный опрос (AskUserQuestion) по одному вопросу; fallback — пакетный нумерованный список:

```
1. Название и описание продукта (что делает, платформа: mobile / web / SaaS)
2. Целевые географические рынки (страны, регионы)
3. Основные сегменты пользователей или ниши
4. Горизонт стратегии (6 / 12 / 18 месяцев)
5. Есть ли данные из касдева, отзывы, личные наблюдения?
6. Какие конкуренты уже известны?
7. Формат вывода: Markdown (по умолчанию) или Markdown + HTML-выгрузка?
8. Язык документа (по умолчанию: русский)
```

### Шаг 2: Исследование рынка и конкурентов

Веб-поиск по рынку, трендам, конкурентам, AI-новичкам. Каждая цифра — со свежим источником и датой. Методология и что искать — в [research-blocks.md](research-blocks.md).

### Шаг 3: Персоны и JTBD

Построить эволюцию JTBD, 5 ключевых JTBD, 5 персон, симулятор интервью. Детали — в [users-and-jtbd.md](users-and-jtbd.md).

### Шаг 4: AI-касдев (при необходимости)

Если реальных интервью нет или есть сырые данные (отзывы, транскрипты) — запустить один из 4 режимов. Любая синтетика тегируется `[AI-симуляция]`. Детали — в [ai-customer-dev.md](ai-customer-dev.md).

### Шаг 5: Продукт сегодня (as-is)

Сильные стороны, аудит монетизации/paywall, placeholder под касдев. Детали — в [product-as-is.md](product-as-is.md).

### Шаг 6: Стратегия

Сформулировать видение и ставку, два вижина ([vision.md](vision.md)); стратегические фокусы и дорожную карту ([roadmap.md](roadmap.md)); продуктовые метрики и риски ([metrics.md](metrics.md)).

### Шаг 7: Сборка документа

Собрать разделы в Markdown-документ по структуре из [document-format.md](document-format.md). При запросе HTML — выгрузить в интерактивный формат (тот же файл описывает CSS/JS).

### Шаг 8: Дозаполнение касдева

Когда пользователь предоставит первичные наблюдения — дописать раздел касдева и связать с приоритетами. См. [product-as-is.md](product-as-is.md), [ai-customer-dev.md](ai-customer-dev.md).

## Что НЕ делать

- Не выдумывать цифры, источники, ARR/загрузки, цитаты (anti-bias). Нет данных — искать или писать «не нашёл».
- Не хардкодить конкретные бенчмарки как вечную истину — брать свежие через поиск с источником.
- Не выдавать синтетические персоны/цитаты за реальные данные — обязателен тег `[AI-симуляция]`.
- Не смешивать первичные данные касдева с аналитикой конкурентов.
- Не делать финальную приоритизацию и дедлайны за продакт-менеджера — предлагать, обосновывать.
- Не копировать фреймворки смежных скиллов — ссылаться на них.
- Не выводить в HTML без запроса — дефолт Markdown.

## Примеры

### Пример 1: Полная стратегия с нуля

**Запрос:** «Построй продуктовую стратегию для нашего SaaS-сервиса аналитики на 12 месяцев, рынки — РФ и СНГ.»

**Маршрут:** Шаг 1 (опрос) → [research-blocks.md](research-blocks.md), [users-and-jtbd.md](users-and-jtbd.md), [vision.md](vision.md), [roadmap.md](roadmap.md), [metrics.md](metrics.md), [document-format.md](document-format.md)

**Результат:** Markdown-документ со всеми разделами; цифры со свежими источниками; при запросе — HTML-выгрузка.

### Пример 2: Edge-case — только AI-касдев по отзывам

**Запрос:** «Вот 40 отзывов из стора, найди паттерны боли и незакрытые jobs.»

**Маршрут:** [ai-customer-dev.md](ai-customer-dev.md) (Режим 2: анализ отзывов)

**Результат:** Кластеры боли с частотой, дословные цитаты `[Первичные данные]`, незакрытые JTBD. Без построения полного документа.
