# Журнал прогонов

Свидетельство, что скилл проверяется на слабейшем вероятном потребителе, плюс
провенанс прогонов. Метод и набор запросов — в [triggers.md](triggers.md).

## 2026-07-14 — реальный активационный прокси на модели (v1.0.0)

Первый **реальный прогон на отдельной модели** (не self-assessment) под нашу версию. Честно: это прокси **не-CC прозового слоя** (модель классифицирует по переданному `name`+`description`), а НЕ живой харнесс Claude Code. Раздел «Статус» и исторический провенанс оригинала ниже остаются как есть.

- **Дата:** 2026-07-14.
- **Модель судьи:** Haiku-класс (`haiku` = claude-haiku-4-5) через Agent tool, субагент general-purpose (без роли/skills). **Референс:** Sonnet (`sonnet` = claude-sonnet-4-6).
- **Версии прозы:** `description` v1.0.0 (659 символов) + `when_to_use` (604 символа).
- **Тип оценки:** реальный активационный прокси на модели (в отличие от прежнего self-assessment). Прогнаны **оба метода** — A (одиночный скилл) и B (коллизия, меню `skill-skill-refine` + `skill-session-harvest`).
- **GATE валидности стенда:** **пройден**. Контроль-проба чистая: у классификаций Haiku `tool_uses: 0` — субагент классифицирует по тексту, не вызывает скилл и не реагирует на реестр.

### Метод A (одиночный скилл)

- **should-trigger — recall 7/7 (оба написания имени):** S1 «запусти skill-refine» 3/3 TRIGGER; S2 «run skill refine» 3/3; S3 «skill-refine» (оригинальное имя) 3/3; S4 «skill-skill-refine» (наше имя) 3/3; S5 наше имя+команда 3/3; S6 имя+глагол 3/3; S7 имя+глагол 3/3. **Двойное имя работает: оба написания 3/3.**
- **listed should-not — 4/4 ABSTAIN** (1 голос): N1 улучши этот скилл → ABSTAIN; N2 посмотри что поправить → ABSTAIN; N3 обнови скилл email-draft → ABSTAIN; N4 примени находку → ABSTAIN.
- **novel-adjacency — 0 ложных под ОБЕИМИ формулировками** (форм. A дословная, B семантическая):

  | Кейс | Фраза | Форм. A | Форм. B |
  |---|---|---|---|
  | N5 | сверь уроки из этой выжимки… предложи правки (зеркало функции) | 5/5 ABSTAIN | 5/5 ABSTAIN |
  | N6 | apply the session lessons to our skill and suggest edits (EN) | 5/5 ABSTAIN | 3/3 ABSTAIN |
  | N7 | проаудируй этот скилл (аудит) | 3/3 ABSTAIN | 3/3 ABSTAIN |
  | N8 | собери уроки из этой сессии в файл (функция harvest) | 3/3 ABSTAIN | 3/3 ABSTAIN |
  | N9 | refine this skill based on what we learned (слово «refine») | 5/5 ABSTAIN | 5/5 ABSTAIN |

  N9 «refine this skill» держится и под семантической формулировкой B.

### Метод B (коллизия, меню = skill-skill-refine + skill-session-harvest)

- **should-trigger — recall 7/7, БЕЗ просадки от коллизии:** S1 3/3 → skill-skill-refine; S2 3/3; S3 (skill-refine ориг.) 3/3; S4 (skill-skill-refine) 3/3; S5 3/3; S6 3/3; S7 3/3. Все 21/21 корректно выбрали skill-skill-refine. **Оригинал давал 8/18 методом B — наша проза заметно устойчивее, предсказанной просадки recall нет.**

- **should-not (novel N5–N9 ×3) — НАХОДКА: под коллизией name-gate ТЕЧЁТ на Haiku.** Обнаружены ложные срабатывания, которых метод A не показывал:

  | Кейс | Метод B (Haiku) выбрал | Ложно для skill-skill-refine? |
  |---|---|---|
  | N5 сверь уроки… предложи правки | skill-skill-refine 3/3 | **ДА, 3/3** |
  | N6 apply lessons… suggest edits (EN) | skill-skill-refine 3/3 | **ДА, 3/3** |
  | N7 проаудируй этот скилл | NONE 3/3 | нет |
  | N8 собери уроки в файл | skill-session-harvest 3/3 | нет (ушло в соседа) |
  | N9 refine this skill (слово refine) | skill-skill-refine 2/3, NONE 1/3 | **ДА, 2/3** |

  Обнаружено: name-gate держится при **одиночной** классификации (метод A: 0 ложных под обеими формулировками), но **течёт при мультискилл-роутинге** (метод B): 3 из 5 смежных-без-имени (N5, N6, N9) ложно тянут skill-skill-refine по совпадению функции, игнорируя правило «без имени не реагирую». N5 при этом дословно присутствует в exclusion-списке `when_to_use`.

- **Sonnet-референс на протёкших кейсах — артефакт слабой модели, НЕ дефект прозы:**
  - N5 Sonnet метод B ×3 → NONE, NONE, NONE (**0 ложных**; Haiku давал 3/3).
  - N6 Sonnet метод B ×3 → NONE, NONE, NONE (**0 ложных**; Haiku давал 3/3).
  - N9 Sonnet метод B ×3 → сломал фрейм классификатора (`tool_uses:1`, обратился к реально установленному skill-skill-refine, обсуждал `disable-model-invocation`); чистого ложного выбора нет, но и чистой классификации нет — **неоднозначно**.

  **Вывод:** протечка метода B на N5/N6 — **артефакт слабой модели Haiku, не дефект прозы**: Sonnet на тех же кейсах даёт 0 ложных. Подтверждает предсказание плана/оригинала о потолке мультискилл-роутинга слабой модели. На Claude Code снято полем `disable-model-invocation` (слой A). Для не-CC переносимости — задокументированное известное ограничение: на слабых моделях в мультискилл-меню name-gate может течь на смежные-по-функции просьбы без имени.

### Слой A (Claude Code, наше окружение)

Скиллы установлены глобально (`~/.claude/skills/skill-skill-refine`), в frontmatter присутствует `disable-model-invocation: true` (проверено). Слой A: скилл корректно установлен и вызываем по имени, контракт `disable-model-invocation` присутствует. **Реальное исполнение скилла не запускалось.**

### Что НЕ покрыто / артефакт стенда (честно)

- **E2e-качество** вердиктов на полной сессии (выжимка/вердикты, гейт записи, дисциплина «не менять») — **не измерено:** session-фикстуры нет.
- **Blind adversarial-набор** — отложен.
- **Полный Sonnet-референс метода A** (recall на сильной модели) — не гнался (метод B recall 7/7 на Haiku — уже сильный сигнал).
- **Артефакт стенда:** Sonnet-субагенты на N9 (фраза со словом «refine») ломали фрейм судьи и обращались к реальному реестру скиллов (`tool_uses:1`) — на capable-модели контроль чистоты стенда для name-содержащих фраз не идеален. На основном (Haiku) прогоне стенд остался чист (`tool_uses:0` везде).

## Потолок и что НЕ покрыто (относится и к нашей версии)

- Trigger-eval — **активационный прокси** (модель видит `name`+`description` или меню),
  не прогон в живом харнессе. Спот-чек в реальной сессии остаётся желательным.
- **Недо-срабатывание под коллизией на слабой модели прозой `description` не лечится.**
  Поэтому на Claude Code добавлено поле **`disable-model-invocation: true` поверх прозы**:
  вызов становится детерминированным (только пользователь/харнесс), оба режима отказа —
  ложное авто-срабатывание и недо-триггер под коллизией — на CC снимаются разом, а
  `description` уходит из always-loaded контекста. Поле — расширение Claude Code, не часть
  открытого стандарта, но **аддитивно и безопасно**: прочие харнессы незнакомый ключ
  игнорируют и продолжают грузить скилл, а прозовый гейт остаётся их floor'ом.
- **End-to-end (L2) под слабой моделью** — качество самих вердиктов на полной сессии,
  соблюдение гейта одобрения, дисциплина «не менять». В оригинале это измерялось только
  **в аудите скилла** (4/4 matchedGold, гейт записи удержан 4/4); отдельной
  session-фикстуры не было — «открытый пункт на следующий цикл». **В нашей версии
  session-фикстуры тоже нет, e2e-эвал НЕ покрыт** — результаты не выдумываем, помечаем
  честно как открытый пункт.
