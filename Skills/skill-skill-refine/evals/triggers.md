# Trigger eval — should / should-not set

`skill-skill-refine` запускается **строго по явному называнию скилла по имени**. Гейт
**двухуровневый**: на **Claude Code** — жёстко полем `disable-model-invocation: true`
(модель не видит `description` и не может выбрать скилл сама; вызывает только
пользователь/харнесс). На **прочих харнессах** поле игнорируется → гейт держится на
прозе `description`. Активационный прокси меряет именно **прозовый, не-CC слой**
(переносимый floor); на CC поведение детерминировано полем. Точность прозы должна
**перепрогоняться после каждой правки `description`**.

**Особенность нашей версии — двойное имя.** Скилл называется `skill-skill-refine`
(наш префикс `skill-` + оригинальное `skill-refine`). Пользователь и харнесс могут
звать его обоими написаниями — оба перечислены в `description`/`when_to_use` как
should-trigger. Набор ниже проверяет оба.

## Статус этого прогона

- **Это self-assessment автора скилла, НЕ прогон на модели.** Ниже — разметка
  should/should-not по нашему новому `description` v1.0.0 и разумная оценка ожидаемого
  поведения, а не результат запуска свежих агентов. Колонки с числами намеренно
  оставлены как «ожидание», без выдуманных счётчиков вроде «3/3».
- **Прогоны оригинала непереносимы.** Оригинальный `skill-refine` мерялся на своём
  `description` (v1.1.0, 686 символов, только имя «skill-refine»). Наш `description`
  переписан (658 символов, добавлено второе имя `skill-skill-refine` и мостик к
  session-harvest), поэтому прежние результаты оригинала (метод A 18/18, метод B 8/18,
  should-not 27/27) **к нашей версии не относятся** и здесь не воспроизводятся.
- **Требуется реальный перепрогон** обоими методами под слабейшего потребителя
  (Haiku-класс), 3 свежих агента на запрос — открытый пункт (см. `runs.md`).

## Два метода (конвенция репо)

- **A. Активационный прокси (одиночный скилл).** Свежему агенту дают ТОЛЬКО
  `name`+`description` скилла `skill-skill-refine` и одно сообщение; решение «вызвать /
  нет». Дёшево, воспроизводимо, сравнимо между скиллами.
- **B. Коллизия (меню из нескольких скиллов).** Агенту дают описания
  `skill-skill-refine` + семантически близких соседей и одно сообщение; решение «какие
  активировать». Жёстче: проверяет, не теряется ли явный вызов среди соседей.
  **Про соседа `skill-audit`:** в оригинале метод B строился на меню
  `skill-refine + skill-audit + session-harvest`. **В нашем окружении `skill-audit`
  НЕ существует.** Поэтому меню коллизии строим из реально существующих скиллов —
  как минимум `skill-skill-refine + skill-session-harvest` (реальный сосед). Кейс N7
  «проаудируй этот скилл» сохранён в should-not ниже как проверка подавления (он про
  «активироваться только по имени», а не про существование соседа-аудитора).

Набор делит should-not на **перечисленные** в exclusion и **неперечисленные смежные**
(novel-adjacency, RU+EN, в т.ч. зеркалящие функцию скилла и слово «refine») — последние
проверяют, что подавление обобщается за пределы дословного списка.

## Заметки к self-assessment

- **Двойное имя (S3/S4):** оба написания перечислены в прозе `description`. Ожидание —
  оба триггерят; при реальном перепрогоне проверить, не путает ли второе написание
  слабую модель и какое написание надёжнее (возможно, стоит front-load'ить одно).
- **should-not про функцию без имени (N5, N9):** N5 зеркалит саму работу скилла
  («сверь уроки… предложи правки»), N9 несёт слово «refine» — оба **без имени**.
  Ожидание — воздержаться: правило «активирую только при назывании по имени» должно
  обобщаться за пределы дословного exclusion.
- **N7 (аудит) и N8 (сбор уроков):** запросы на смежные функции. У нас `skill-audit`
  не существует, `skill-session-harvest` существует — но ни один из этих запросов не
  называет `skill-skill-refine` по имени, поэтому ожидание — воздержаться.
- **Потолок под коллизией (из оригинала):** на слабой модели среди близких соседей
  вероятно недо-срабатывание на явный вызов (в оригинале Haiku давал 8/18 методом B
  при 18/18 методом A; Sonnet — идеально). Это **потолок мультискилл-роутинга слабой
  модели, а не дефект прозы** — прозой не лечится, лечится полем
  `disable-model-invocation: true` на Claude Code. Ожидаем то же поведение и у нас;
  подтвердить перепрогоном.

## Перепрогон (когда будет проводиться)

На каждую правку `description`: по 3 свежих Haiku-агента на запрос **обоими методами**;
вход — `name`+`description` (метод A) или меню из реально существующих скиллов
(метод B) и сообщение; решение строго по описанию. Счёт: should = вызвал,
should-not = воздержался. Записать дату, модель, версию `description` и итоги сюда и в
`runs.md`. До проведения — таблицы выше остаются self-assessment, не измерением.
