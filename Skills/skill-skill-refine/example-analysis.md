# Пример анализа

Образец **тона и формы** вердикта первой фазы — не схема для заполнения и не жёсткий формат. Показано, как выглядят все исходы (применить с правкой «было → стало», не применять с конкретной причиной, проверить вручную), как обоснование опирается на реальный код скилла и как анализ останавливается перед применением, ожидая одобрения. Пример нейтральный, на простом скилле черновика письма.

---

**Контекст для примера.** Целевой скилл — `email-draft` (черновик письма: задаёт тон, структуру, обязательно тему). Выжимка из сессии содержит четыре урока.

**Итог: к применению — один урок из четырёх. Жду одобрения, в файлы пока ничего не вношу.**

**Урок 1 — тон по умолчанию формальный, но для внутренних писем команде раз за разом просили проще.**
Вердикт: **применить (обновить).** Релевантно скиллу (это про его инструкцию о тоне), переносимо, в скилле сейчас задан единый формальный тон без различения адресата, уверенность в выжимке высокая.
Предлагаемая правка, `email-draft/SKILL.md`, раздел «Тон»:
- было: «Пиши в формальном, профессиональном тоне.»
- стало: «По умолчанию пиши в формальном тоне; для внутренних писем коллегам — проще и короче, если контекст не требует формальности.»

**Урок 2 — пользователь хотел, чтобы была тема письма.**
Вердикт: **не применять (новизна).** Проверка по скиллу: раздел «Структура» уже требует тему первой строкой. Урок уже покрыт — добавлять нечего.

**Урок 3 — письмо в этой сессии было про бюджет Q3, и пользователь уточнял цифры.**
Вердикт: **не применять (переносимость).** Это частность конкретной задачи (содержание одного письма), а не урок про работу скилла. За пределы сессии не переносится.

**Урок 4 — возможно, скилл слишком длинно раскрывает приветствия; пользователь один раз сократил, но явно об этом не говорил.**
Вердикт: **проверить вручную (уверенность).** В выжимке помечено низкой уверенностью — это разовое молчаливое сокращение, паттерна не видно. В код не вношу; стоит понаблюдать в следующих сессиях, прежде чем что-то менять.
