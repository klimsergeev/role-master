# Trigger eval — should / should-not set

`skill-session-harvest` активируется **строго по явному вызову**. Гейт **двухуровневый**: на **Claude Code** — жёстко полем `disable-model-invocation: true` (модель не видит `description` и не выбирает скилл сама; вызывает только пользователь/харнесс). На **прочих харнессах** поле игнорируется → гейт держится на прозе `description` + `when_to_use`. Этот eval меряет именно **прозовый, не-CC слой** (переносимый floor); на CC поведение детерминировано полем и здесь не отражается.

Точность прозы **перепроверяется после каждой правки `description`/`when_to_use`**.

## Статус этого прогона (ЧЕСТНО)

> **Обновление 2026-07-14:** реальный активационный прокси на модели (Haiku-класс через Agent tool) выполнен — recall 4/4, listed 6/6 ABSTAIN, novel 0 ложных под обеими формулировками (40/40 ABSTAIN). Числа и провенанс — в [runs.md](runs.md). Таблицы ниже остаются как **self-assessment** (разметка ожиданий), не переписываются как «доказанные».

Это **self-assessment** — самооценка соответствия набора и текущей прозы `description`+`when_to_use`, а НЕ прогон на отдельной модели (не давали свежему Haiku-агенту `name`+`description` с одним сообщением, как в оригинале). Оценка сделана рассуждением о том, что говорит проза и как на неё должен реагировать классификатор активации. Это слабее реального прогона: полноценный активационный прокси на отдельной модели остаётся **желательным** и не выполнен.

Причина: набор и проза переписаны под нашу версию (`description` 570 + `when_to_use` 519 = 1089 символов), поэтому прежний результат оригинала (14/14 на v1.1.0, 572 символа) **не переносится** — он был на другом тексте.

## Метод (целевой, при реальном прогоне)

Симуляция активации под слабейшего потребителя: свежему агенту Haiku-класса дают ТОЛЬКО `name` + `description` (+ `when_to_use`) и одно пользовательское сообщение; агент решает, вызвать скилл или нет. Один голос на запрос. Это *прокси* активации в реальном харнессе — дёшево и воспроизводимо, но не заменяет спот-чек в живой сессии. Поскольку активация name-gated, коллизии с соседними скиллами второстепенны; главный риск — ложное срабатывание на смежную NL-просьбу без имени.

Набор намеренно делит should-not на две группы: **перечисленные** в прозе (лёгкие) и **неперечисленные смежные** (novel-adjacency, RU+EN, в т.ч. зеркалящие лексику скилла и слово «harvest») — последние проверяют, что подавление обобщается за пределы дословного списка.

## Набор (self-assessment под нашу прозу)

- **Версия:** `description` v1.0.0 (570 символов) + `when_to_use` (519 символов)
- **Тип оценки:** self-assessment (не прогон на отдельной модели)
- **Ожидаемый счёт:** should-trigger **4/4**, should-NOT-trigger **10/10** (overall **14/14**)

### should-trigger (ожидаем активацию)

| # | Запрос | Тип | Ожидание |
|---|---|---|---|
| S1 | запусти Session Harvest | имя (RU) | ✅ активация |
| S2 | run session harvest please | имя (EN) | ✅ активация |
| S3 | session-harvest | голое имя | ✅ активация |
| S4 | выполни скилл session-harvest по этому диалогу | имя + команда | ✅ активация |

Все четыре несут имя скилла дословно → проза `description`/`when_to_use` прямо предписывает активацию по имени. S1, S3, S4 присутствуют в `when_to_use` как примеры-срабатывания; S2 — вариант S1 на EN, покрыт правилом «run session harvest».

### should-NOT-trigger (ожидаем воздержание)

| # | Запрос | Тип | Ожидание |
|---|---|---|---|
| N1 | собери итоги сессии | перечислено в прозе | ✅ воздержание |
| N2 | сохрани заметки | перечислено | ✅ воздержание |
| N3 | подведи итоги | перечислено | ✅ воздержание |
| N4 | законспектируй наш диалог | перечислено (в description) | ✅ воздержание |
| N5 | что важного было в сессии? | перечислено (в when_to_use) | ✅ воздержание |
| N6 | запиши уроки из этой сессии в отдельный файл | перечислено (в when_to_use) | ✅ воздержание |
| N7 | extract the transferable lessons from this session into a markdown file | novel-adjacency (EN) | ✅ воздержание |
| N8 | сделай плотную выжимку переносимого знания из сессии | novel-adjacency (зеркалит лексику) | ✅ воздержание |
| N9 | harvest the key takeaways from this chat | novel-adjacency (слово «harvest») | ✅ воздержание |
| N10 | summarize what we learned and save it to a file | novel-adjacency (EN) | ✅ воздержание |

### Обоснование ожиданий по should-not

- N1–N6 дословно перечислены в `description`/`when_to_use` как «НЕ реагирует / НЕ срабатывает» → воздержание прямо предписано прозой.
- N7–N10 не перечислены, но проза даёт **общее правило**: «активируется ТОЛЬКО при явном вызове по имени», «НЕ реагирует на смежные просьбы без имени». Ни один из N7–N10 не называет скилл по имени → корректное воздержание должно обобщиться. Особенно проверочны N8 (зеркалит лексику самого скилла — «плотную выжимку переносимого знания») и N9 (несёт слово «harvest»): оба НЕ должны срабатывать, потому что имени скилла в них нет.
