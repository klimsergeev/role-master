# Claude: тексты для Claude Code

## Назначение

Официальные правила и значения для текстов Claude Code: CLAUDE.md, правил `.claude/rules/`, определений субагентов и SKILL.md. Общие техники текста — в [principles.md](principles.md); задание, которое агент передаёт субагенту, — в [delegation-task.md](delegation-task.md).

Значения сверены 2026-11-09; номера версий Claude Code и лимиты меняются — перед опорой на число в важном решении перепроверь его.

## Общее для всех артефактов

- Промпт, CLAUDE.md и скиллы — недетерминированные инструкции: модель читает и решает, следовать ли. Хуки, правила запрета и управляемые настройки — детерминированные: их исполняет харнесс. Правило, которое должно выполняться всегда, — в хук или правило запрета, потому что CLAUDE.md задаёт ориентиры, а Claude вправе решить, что ориентир к случаю не подходит.
- Записывать только то, чего Claude не найдёт, читая репозиторий, или что иначе будет заново выяснять каждую сессию. Тест перед записью: может ли модель найти это, читая код, и пойдёт ли искать; если оба ответа «да» — не записывать. Правило относится и к скиллам.
- Строку, которую модель продолжает пропускать, выделение не спасает: либо файл слишком длинный, либо это правило без исключений и ему место в хуке.

## CLAUDE.md

- Содержимое CLAUDE.md приходит пользовательским сообщением после системного промпта, а не частью системного промпта; строгого соблюдения нет, особенно у расплывчатых и противоречивых инструкций.
- Цель — меньше 200 строк на файл: длинные файлы занимают больше контекста и хуже соблюдаются.
- Инструкции конкретные настолько, чтобы их можно было проверить: «Run `npm test` before committing» вместо «Test your changes», «Use 2-space indentation» вместо «Format code properly».
- Связанные инструкции — под заголовками и в списках; организованные разделы соблюдаются легче плотных абзацев.
- Из двух противоречащих инструкций Claude может выбрать любую; периодически убирать устаревшее и противоречащее.
- Что держать: команды проверки работы (тесты, типы, линтер, запуск одного теста), места, где код вводит в заблуждение, решения, которых нет в репозитории, то, что приходилось поправлять дважды.
- Многошаговая процедура или правило для части кодовой базы — в скилл или правило с ограничением по путям.
- Описание архитектуры и структуры файлов не писать: Claude читает репозиторий сам, записывать нужно только то, чего в нём нет.
- Импорты `@path` помогают организации, но не уменьшают стоимость контекста: импортированные файлы грузятся вместе с CLAUDE.md.
- Блочные HTML-комментарии `<!-- ... -->` вырезаются перед попаданием в контекст; заметки для людей можно оставлять в них.
- CLAUDE.md подкаталога и правила, загружаемые по требованию, сверх лимита на файл приходят только началом: 40 000 символов при окне 200K; при окне 1M — 200 000 у Opus 4.6 и Sonnet 4.6 и 150 000 у более поздних моделей.
- Личные предпочтения — в `CLAUDE.local.md`, добавленный в `.gitignore`.
- Инструменты: `/init` создаёт стартовый вариант; `/doctor` предлагает сокращения; `/doctor prompt-audit` ищет инструкции, написанные для старых моделей, ссылки на несуществующие файлы и команды и файлы, противоречащие друг другу, в CLAUDE.md, CLAUDE.local.md, AGENTS.md, правилах, скиллах, командах, субагентах и стилях вывода; требует Claude Code v2.1.283 или новее; файлы не меняет, пока не попросят применить правки. Это отдельный инструмент; процедура аудита скилла от него не зависит.

## Правила `.claude/rules/`

- Один файл — одна тема, с описательным именем; все `.md` ищутся рекурсивно.
- Правило без `paths` грузится при старте с тем же приоритетом, что `.claude/CLAUDE.md`.
- Правило с `paths` грузится, когда Claude читает, пишет или правит подходящий файл.
- `paths` — единственное поле фронтматтера, которое читает Claude Code; остальные молча игнорируются; фронтматтер вырезается перед загрузкой.
- Фронтматтер, который не разбирается как YAML, игнорируется, и правило грузится как без `paths`.
- Правила пользователя (`~/.claude/rules/`) грузятся раньше правил проекта; при конфликте Claude может последовать любому.
- Задачам, которым не нужно быть в контексте постоянно, — скиллы, а не правила.

## Определение субагента (`.claude/agents/*.md`)

- Обязательны только `name` и `description`; `description` говорит, когда Claude делегировать этому субагенту.
- Claude делегирует по описанию задачи, полю `description` и текущему контексту; для проактивного делегирования добавлять в `description` фразы вроде «use proactively».
- Описания короткие: при суммарном объёме описаний субагентов больше 15 000 токенов Claude Code предупреждает при старте.
- Описание выделяет одного субагента среди прочих: оно достаточно конкретно, чтобы направить к нужному.
- Тело файла — системный промпт субагента; субагент получает его и сведения об окружении, но не системный промпт Claude Code.
- В начальном контексте субагента: его системный промпт, сообщение-задание, файлы CLAUDE.md всех уровней (кроме Explore, Plan и субагентов с `omitClaudeMd`), снимок git status, предзагруженные скиллы. Истории разговора, уже вызванных скиллов и прочитанных файлов нет.
- Правило, которое обязано дойти до субагента, повторить в задании при делегировании.
- Поле `skills` внедряет полное содержимое скиллов при старте, не больше 32 различных имён; скилл с `disable-model-invocation: true` предзагрузить нельзя.
- Пример хорошей практики: сфокусированный субагент с ограниченными инструментами и подробным промптом, который точно говорит, что искать и как оформить результат.

Отдельной официальной инструкции по написанию тела субагента нет; к телу применяются общие техники системного промпта из [principles.md](principles.md) и [../write-prompt.md](../write-prompt.md).

Внедряются ли при предзагрузке файлы рядом со SKILL.md, официально не уточнено. Замер 2026-08-20: внедряется только SKILL.md, файлы-процедуры субагент дочитывает сам.

## SKILL.md

- Все поля фронтматтера необязательны; рекомендовано `description`, чтобы Claude знал, когда применять скилл; неизвестное поле молча игнорируется.
- `description` — что делает скилл и когда его применять; ключевой сценарий — первым: суммарный текст `description` и `when_to_use` в списке скиллов обрезается на 1 536 символах.
- `when_to_use` — дополнительные триггеры: фразы, примеры запросов; дописывается к `description` и входит в те же 1 536 символов.
- Угловые скобки в `description` и `when_to_use` показываются как `&lt;` и `&gt;`; для плейсхолдеров — квадратные скобки.
- При сломанном YAML скилл грузится без полей: `/имя` работает, но по описанию скилл не находится.
- Тело — коротко: после вызова содержимое остаётся в контексте на все ходы, каждая строка — постоянная плата; писать, что делать, а не рассказывать, как и почему (расхождение — [principles.md](principles.md), раздел «Причина инструкции»).
- SKILL.md — меньше 500 строк; подробные справочные материалы — в отдельные файлы.
- Дополнительные файлы перечисляются в SKILL.md с указанием, что в каждом и когда его читать; скрипты исполняются, а не грузятся в контекст.
- Claude Code не перечитывает файл скилла на следующих ходах: указания на всю задачу пишутся как постоянные («Run the tests after every edit», а не «Run the tests»).
- После компакции от каждого вызванного скилла остаются первые 5 000 токенов, на все скиллы — 25 000; самое важное — в начало SKILL.md.
- `context: fork` — только для скиллов с явной задачей: субагент не видит истории разговора, инструкции должны быть самодостаточными; набор правил без задачи вернёт пустой результат.
- Скилл не срабатывает — проверить, есть ли в описании слова, которые скажет пользователь.
- Скилл срабатывает слишком часто — сделать описание конкретнее или запретить автовызов.
- Скилл, просящий модель выписать мышление или рассуждение, может получить отказ `reasoning_extraction` (Opus 5, Fable 5.1).
- Скиллы, написанные для прежних моделей, часто слишком предписывающие для Fable 5 и могут ухудшать результат.

Источники расходятся о длине описания:

- Одна позиция — в Claude Code `description` и `when_to_use` вместе обрезаются на 1 536 символах в списке скиллов; лимит настраивается параметром `skillListingMaxDescChars`.
- Другая — открытый стандарт скиллов задаёт жёсткий лимит в 1024 символа. При загрузке скилла на claude.ai, через Skills API и упаковке `package_skill.py` допустимы только поля стандарта: `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`.

## Проверка срабатывания

Срабатывание скилла и делегирование субагенту проверяются на тестах — раздел «Скиллы и субагенты Claude Code» в [prompt-debugging.md](prompt-debugging.md).
