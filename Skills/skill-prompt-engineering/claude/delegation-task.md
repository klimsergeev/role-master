# Claude: задание субагенту Claude Code

## Назначение

Техника текста задания, которое агент Claude Code передаёт субагенту: что в нём должно быть, чтобы субагент без истории разговора сделал нужную работу.

Файл не задаёт рамку вызова инструмента делегирования — какого субагента вызвать и какие поля вызова заполнить; он о содержании текста задания.

Сверено 2026-11-09.

## Что субагент знает

- Единственное, что родитель передаёт субагенту, — строка prompt инструмента Agent, поэтому пути к файлам, тексты ошибок и решения, которые нужны субагенту, вписываются прямо в неё.
- Субагент начинает с чистого контекста и не видит истории разговора, уже вызванных скиллов и прочитанных файлов; CLAUDE.md проекта у него есть (кроме Explore, Plan и субагентов с `omitClaudeMd`). Правило, которое обязано до него дойти, повторяется в задании.
- Значит, задание читает тот самый «коллега с минимальным контекстом» из ключевого теста ([principles.md](principles.md), раздел «Ясность и прямота»).

## Что должно быть в задании

Каждому субагенту нужны цель, формат результата, указания по инструментам и источникам и чёткие границы задачи; без подробного описания задачи агенты дублируют работу, оставляют пробелы или не находят нужных сведений. Пример: короткие указания вроде «research the semiconductor shortage» субагенты понимали неверно или повторяли поиски друг друга.

| Часть задания | Что в ней |
|---|---|
| Цель | Что сделать и зачем, для кого результат: намерение за запросом (блок «Цель запроса» в [official-blocks.md](official-blocks.md)) |
| Вводные | Пути к файлам, тексты ошибок, принятые решения, установленные факты |
| Инструменты и источники | Чем пользоваться и где искать |
| Границы | Что не входит в задачу и чего не делать |
| Формат результата | Что вернуть и в каком виде |

## Как писать текст задания

- Повелительной формой, с явным охватом: модели понимают инструкции буквально ([principles.md](principles.md), разделы «Ясность и прямота» и «Буквальность и охват»).
- Не просить выписать рассуждение в ответ; просить короткое объяснение или сводку действий ([principles.md](principles.md), раздел «Рассуждение»).
- Для задания проверяющему — формулировать, что сверять и что пропускать. Пример: «use a subagent to review the rate limiter diff against SPEC.md, check every requirement is implemented and the listed edge cases have tests, report gaps that affect correctness and skip style». Часть `skip style` из такого промпта не убирать, потому что проверяющий, которому велели искать проблемы, всегда что-нибудь найдёт.
- Использовать ли субагента для проверки собственной работы — источники расходятся ([models.md](models.md), раздел о расхождениях, пункт «Самопроверка»).

## Проверка задания перед отправкой

- [ ] Субагент выполнит задание, не зная ничего, кроме его текста и CLAUDE.md проекта.
- [ ] Есть цель, вводные, инструменты и источники, границы, формат результата.
- [ ] Пути, ошибки и решения вписаны в текст, а не упомянуты как «см. выше».
- [ ] Правила, которые субагент обязан соблюдать и которых нет в CLAUDE.md, повторены.
- [ ] Нет просьбы выписать рассуждение.

## Пример

**Плохо:**

```text
Look into why the auth tests fail and fix it.
```

**Лучше:**

```text
Goal: find why the auth tests fail after the session-timeout change and fix the cause. The fix ships in today's release, so keep it to the auth module.

Inputs:
- Failing tests: tests/auth/test_refresh.py::test_expired_session, tests/auth/test_refresh.py::test_refresh_rotation
- Error output: "AssertionError: expected 401, got 200" in both.
- Decision already made: refresh tokens rotate on every use; don't change that.

Tools and sources: read src/auth/ and tests/auth/; run the tests with `pytest tests/auth -q`.

Boundaries: change only files under src/auth/; don't edit the tests.

Result: the root cause in two or three sentences, the diff, and the test command output after the fix.
```

Пример иллюстративный: пути и ошибки условные.
