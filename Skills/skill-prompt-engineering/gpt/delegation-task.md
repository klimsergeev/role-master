# GPT: задание субагенту Codex

## Назначение

Техника текста задания, которое главный агент Codex передаёт субагенту: как задание доходит до субагента, что субагент знает и что должно быть в самом задании. Официальных правил оформления задания в документации Codex немного; файл опирается на то, как Codex передаёт задание, на описание полей, которое видит модель, и на советы о промпте для субагентов.

Файл не задаёт рамку вызова инструмента делегирования — какого субагента вызвать и какие поля вызова заполнить; он о содержании текста задания. Определение субагента — в [codex-artifacts.md](codex-artifacts.md).

Сверено 2026-11-11.

## Как задание доходит до субагента

- Главный агент запускает субагента инструментом `spawn_agent` с обязательными полями: `task_name` — имя задачи (строчные латинские буквы, цифры и подчёркивания) и `message` — начальное задание обычным текстом. Имя задачи передаётся субагенту вместе с заданием.
- Поле `fork_turns` по умолчанию `all`: субагент наследует всю историю родителя; при `none` окружающий контекст ему не передаётся. Модель и уровень рассуждения, если их не задать, наследуются от родителя.
- Новую задачу уже запущенному агенту дают отдельным инструментом; сообщение субагенту без новой задачи нового хода у него не запускает.
- Хороший промпт на работу с субагентами объясняет, как делить работу, ждать ли всех агентов перед продолжением и какую сводку или результат вернуть.

## Что субагент знает

- Те же инструменты, что у главного агента, и возможность запускать своих субагентов.
- Скиллы родителя; права, песочницу и серверы MCP родителя.
- Историю родителя — если запущен с ней; без неё — только текст задания, имя задачи и собственные инструкции.
- Свою роль: он агент в команде агентов, совместно выполняющих задачу; входящие сообщения помечены типом (новая задача, сообщение, итоговый ответ), именем задачи и отправителем.
- Итог, отправленный в финальный канал, сразу уходит родителю; его может прочитать и человек, поэтому итог должен быть читаемым.

## Что должно быть в задании

| Часть задания | Что в ней |
|---|---|
| Цель | Что сделать и зачем |
| Вводные | Пути к файлам, тексты ошибок, принятые решения — если субагент запускается без истории родителя, всё нужное вписывается сюда |
| Границы | Та же область автономии, что у главного агента: какие действия допустимы, какие требуют подтверждения, когда остановиться |
| «Готово» | Что считается выполненным и как субагент проверяет свою работу |
| Итог | Что вернуть и в каком виде: сводка, а не сырой промежуточный вывод |

## Как писать текст задания

- Задание, отправляемое без истории родителя, самодостаточно: пути, ошибки и решения вписываются прямо в текст, а не упоминаются как «см. выше».
- Задание и итог могут читать люди: текст читаемый, с нормальными пробелами между словами и числами (блок «Читаемость сообщений между агентами» в [official-blocks.md](official-blocks.md) — для инструкций субагента).
- Не требовать от субагента отчитываться по счётчику шагов и не расписывать маршрут по шагам: цель, ограничения и порог завершения ([principles.md](principles.md), разделы «Ясность и прямота» и «Автономия, вопросы и остановка»).
- Общие техники текста — [principles.md](principles.md).

## Когда главный агент делегирует

- Текущие выпуски Codex запускают субагентов по прямой просьбе пользователя или по применимой инструкции проекта или скилла.
- GPT-6 Astra делегирует реже, чем нужно процессу; если нужно больше параллельной работы — блок «Делегирование субагентам» в инструкциях главного агента.
- Независимые чтения можно распараллеливать; если один результат определяет следующий шаг, работа идёт последовательно ([agents-and-tools.md](agents-and-tools.md), раздел «Результаты инструментов»).

## Проверка задания перед отправкой

- [ ] Если субагент запускается без истории родителя — он выполнит задание, не зная ничего, кроме его текста, своих инструкций и `AGENTS.md`.
- [ ] Есть цель, вводные, границы, «готово» и вид итога.
- [ ] Границы автономии субагента не шире, чем у главного агента.
- [ ] Итог запрошен сводкой, а не сырым промежуточным выводом.
- [ ] Если запускается несколько субагентов — сказано, как поделена работа и ждать ли всех.

## Пример

**Плохо:**

```text
Look into why the auth tests fail.
```

**Лучше** (субагент запускается без истории родителя):

```text
Goal: find why the auth tests fail after the session-timeout change. Do not fix anything; the main agent will apply the fix.

Inputs:
- Failing tests: tests/auth/test_refresh.py::test_expired_session, tests/auth/test_refresh.py::test_refresh_rotation
- Error output in both: "AssertionError: expected 401, got 200".
- Decision already made: refresh tokens rotate on every use.
- Relevant code: src/auth/

Boundaries: read files and run the auth tests; do not edit files or touch git.

Done when: you can point to the code path that returns 200 for an expired session and the commit that introduced it.

Result: a short summary — the root cause in two or three sentences, the file and line numbers involved, and the commit hash. No raw logs.
```

Пример иллюстративный: пути и ошибки условные.
