# GPT: переходы между версиями

## Назначение

Порядок переноса промпта по официальной методике и таблица переходов между версиями моделей GPT: что меняется в тексте промпта и в связанных с ним параметрах при переносе на покрываемую модель. Используется на шаге поиска перехода в [../migrate-prompt.md](../migrate-prompt.md); поведение целевой модели — в [models.md](models.md), устаревшие приёмы — в [legacy-patterns.md](legacy-patterns.md), параметры — в [parameters.md](parameters.md) (справочник).

Целевая модель перехода — всегда из [models.md](models.md). Исходная модель может быть вне охвата: тогда она названа только в колонке «Переход», раздела о ней в [models.md](models.md) нет.

Сверено 2026-11-11.

## Порядок переноса

Шаги идут до строки таблицы и применяются к любому переходу:

1. Сменить модель, сохранив текущий уровень рассуждения.
2. Прогнать представительные оценки до правки промпта — это база для сравнения.
3. Начать с чистой базы, а не переносить каждую инструкцию из старого набора: убрать устаревшие подпорки, повторы и инструменты, не относящиеся к задаче ([legacy-patterns.md](legacy-patterns.md)).
4. Добавлять только минимальную точечную инструкцию, которая исправляет измеренную регрессию.
5. Перезапускать оценки после каждой правки.
6. Не переписывать рабочий набор промптов целиком за один раз.
7. Поправки под ошибки конкретной модели пересматривать с каждым выпуском: новая модель может сделать их ненужными.

Платформа оценок OpenAI отключается 30.11.2026; для оценок OpenAI предлагает внешний инструмент Promptfoo. Это отдельный инструмент; процедура переноса скилла от него не зависит, а методики отладки на тестах для GPT в скилле нет.

## Обе модели в охвате

| Переход | Что меняется в тексте |
|---|---|
| GPT-6 Sol → GPT-6.1 Sol | Уровень `none` у GPT-6.1 Sol не поддерживается — вместо него `low` ([parameters.md](parameters.md)). Блоки рекомендаций по GPT-6 остаются отправной точкой. Дальше — строки раздела GPT-6.1 Sol в [models.md](models.md) |
| Между линиями (Astra, Sol, Terra, Luna; например, GPT-6 Astra → GPT-6.1 Sol) | Отдельных официальных правил о тексте промпта для такого перехода нет. Убрать блоки и формулировки, написанные под поведение исходной модели, которого у целевой не описано; применить раздел целевой модели в [models.md](models.md) и правило шага 2 процедуры переноса о приёмах, измеренных на конкретной модели. Указания, которые помогают моделям Sol и Luna, могут чрезмерно ограничивать GPT-6 Astra. При переходе с Astra на более дешёвую модель найденные закономерности ошибок (у GPT-6.1 Sol — пропуск зависимостей) закрывать явной инструкцией под задачу. Инструменты у Astra, 6.1 Sol и 6.1 Terra — только через Responses API, у 6 Sol и Luna в Chat Completions — только при `none` ([parameters.md](parameters.md), раздел «Поверхности») |
| GPT-5.3-Codex → семейство GPT-6 | Официальная замена в API — GPT-6 Sol. Советов о тексте промпта для этого перехода нет — не установлено. Блоки рекомендаций по GPT-6 к исходной модели не относились — на целевой проверить их по условиям. `phase` у сообщений ассистента сохранять и дальше. Дальше — раздел целевой модели в [models.md](models.md) |

## Исходная модель вне охвата

| Переход | Что меняется в тексте |
|---|---|
| GPT-5.6 Sol, Terra, Luna → семейство GPT-6 | Если модель лишний раз просит одобрения — блоки «Намерение и доведение до конца», «Просьба — это поручение», «Сначала работа, потом вопрос»; повторы «сначала спроси» заменить границами решений (блок «Политика автономии»). Напоминания запускать тесты и проверять работу убрать (GPT-6 Astra). Проверить скиллы и `AGENTS.md` на скрытые и противоречивые указания, задать приоритет пользователя над скиллом. Если нужна проза — блоки «Проза вместо списков» и «Стоп-лист оборотов». В многоагентной обвязке — блок «Делегирование субагентам». Параметры: `none` у Astra и 6.1 Sol не поддерживается — `low`; с `minimal` — начать с `low` и сравнить; при уровне выше `none` убрать `temperature`, `top_p`, `top_logprobs`; инструменты у Astra, 6.1 Sol и 6.1 Terra — только через Responses API ([parameters.md](parameters.md)). GPT-5.6 Terra → GPT-6.1 Terra: сравнить обе модели на представительных задачах при одинаковом уровне рассуждения. Дальше — строки раздела целевой модели в [models.md](models.md) |
| GPT-5.5, GPT-5.4, GPT-5.4 Mini, GPT-5.2 → семейство GPT-6 | Начать с чистой базы, а не переносить каждую инструкцию. У GPT-5.4, GPT-5.4 Mini и GPT-5.2 уровень рассуждения по умолчанию `none`, у GPT-5.5 — `medium`; у целевых моделей по умолчанию `medium`, у GPT-6 Astra в API — не установлено: инструкции, добавленные, чтобы побудить модель подумать при `none`, пересмотреть при уровне целевой модели. Схему вывода из текста перенести в структурированный вывод. Дальше — строка GPT-5.6 выше |
| Отключённые и отключаемые модели: o-серия, GPT-5, GPT-5 mini, GPT-5 nano, GPT-5.1, GPT-5.4 nano, GPT-4o, GPT-4o mini, GPT-4.1, GPT-4.1 mini | Официальные замены из числа покрываемых: для GPT-4o, GPT-4o mini, GPT-4.1, GPT-4.1 mini и GPT-5.4 nano — GPT-6 Luna, для GPT-5.1 — GPT-6 Sol; для o-серии и GPT-5 замены — модели GPT-5.6 вне охвата. Советов о тексте промпта для этих моделей в скилле нет. Перенос — по разделу «Порядок переноса», каталогу [legacy-patterns.md](legacy-patterns.md) и разделу целевой модели в [models.md](models.md) |
