# GPT: тексты для Codex

## Назначение

Официальные правила и значения для текстов Codex: файлов инструкций `AGENTS.md`, замены базовых инструкций модели, скиллов (SKILL.md) и определений субагентов. Общие техники текста — в [principles.md](principles.md); задание, которое главный агент передаёт субагенту, — в [delegation-task.md](delegation-task.md).

Значения сверены 2026-11-11; Codex обновляется часто — перед опорой на конкретное значение в важном решении перепроверь его.

## Общее для всех артефактов

- Рекомендованные модели в Codex — GPT-6 Astra, GPT-6.1 Sol, GPT-6.1 Terra, GPT-6 Luna; в пресетах приложения есть и GPT-6 Sol. GPT-5.3-Codex при входе через ChatGPT в Codex уже выведена; с ключом API доступность моделей следует организации API.
- Умолчания Codex, которые влияют на текст: уровень рассуждения `low` у GPT-6 Astra, GPT-6.1 Sol и GPT-6.1 Terra и `medium` у GPT-6 Sol и GPT-6 Luna; подробность ответа `low` у всех моделей GPT-6. Это настройки клиента, а не умолчания API ([parameters.md](parameters.md)).
- GPT-6 Astra сильнее следует инструкциям и чувствительнее к инструкциям в скиллах и `AGENTS.md`: проверять их на скрытые и противоречивые указания, влияющие на поведение ([models.md](models.md), раздел GPT-6 Astra).
- Модель-программист действует по инструкциям `AGENTS.md`, README и комментариев кода; файл `AGENTS.md` в текущем каталоге надёжнее случайного файла в загрузках.
- Пишется ли текст под одну модель или под несколько, учитывать, что указания, которые помогают моделям Sol и Luna, могут чрезмерно ограничивать GPT-6 Astra.

## AGENTS.md

- Цепочка инструкций строится при запуске — один раз за прогон, в TUI обычно один раз за сессию.
- Глобальный уровень: в домашнем каталоге Codex (`~/.codex` или `CODEX_HOME`) читается `AGENTS.override.md`, если он есть, иначе `AGENTS.md`; берётся только первый непустой файл.
- Проектный уровень: от корня проекта (обычно корня Git) вниз до текущего каталога; в каждом каталоге проверяются `AGENTS.override.md`, затем `AGENTS.md`, затем имена из `project_doc_fallback_filenames`; берётся не больше одного файла на каталог. Без корня проекта — только текущий каталог. `AGENTS.override.md` вытесняет `AGENTS.md` того же каталога; глобальный `~/.codex/AGENTS.override.md` — временная замена без удаления основного файла.
- Своё имя файла: список `project_doc_fallback_filenames` в `~/.codex/config.toml` (например, `["TEAM_GUIDE.md", ".agents.md"]`); имена не из списка при поиске инструкций игнорируются.
- Файлы склеиваются от корня вниз через пустые строки; файл ближе к текущему каталогу стоит позже и переопределяет более ранние указания. Пустые файлы пропускаются.
- Предел — `project_doc_max_bytes`, по умолчанию 32 КиБ. Источники расходятся: одна позиция — предел суммарный, добавление файлов прекращается, когда общий размер его достигает, файл, не влезающий в остаток, обрезается с предупреждением; другая — предел на каждый файл. При недоверенном проекте или `project_doc_max_bytes = 0` проектные инструкции не загружаются.
- Текст приходит модели ролью `user` с заголовком `# AGENTS.md instructions`, до промпта пользователя. Источники расходятся: одна позиция — каждый найденный файл приходит отдельным сообщением, от корня к листьям; другая — весь склеенный текст приходит одним фрагментом, глобальные и проектные инструкции разделены отдельной строкой-разделителем. Если инструкции меняются по ходу сессии, новые объявляются заменой всех прежних.
- Что писать:
  - когда нужны какие документы и тесты: какой документ для какой работы, а не требование читать все документы перед каждой правкой;
  - явное разрешение безопасных рутинных действий — например, запуск локальных тестов на одноразовых данных без доступа к рабочей среде;
  - что входит в «готово»: внести изменение, запустить, проверить результат, устранить сбои, — и какие решения требуют проверки человеком;
  - чёткие границы решений вместо общего правила «всегда спрашивай»;
  - без напоминаний запускать тесты и проверять работу для GPT-6 Astra ([legacy-patterns.md](legacy-patterns.md)).
- Личные инструкции пользователя Codex хранятся в глобальном `AGENTS.md`; то, что должно действовать всегда, держать в `AGENTS.md` или документации проекта, а не в памяти ([principles.md](principles.md), раздел «Инструкции ChatGPT»).

## Замена базовых инструкций

- `model_instructions_file` — путь к файлу, который заменяет встроенные базовые инструкции модели (прежнее имя ключа `experimental_instructions_file` устарело). Источники расходятся в описании: одна позиция — файл заменяет встроенные инструкции вместо `AGENTS.md`; другая — по устройству Codex он заменяет базовые инструкции, а `AGENTS.md` продолжает загружаться отдельным фрагментом.
- `developer_instructions` — дополнительные developer-инструкции, вставляемые в сессию отдельным сообщением.
- `instructions` — зарезервировано; вместо него — `model_instructions_file` или `AGENTS.md`.
- `personality` — устаревшая настройка совместимости: значения `friendly` и `pragmatic` стиль больше не выбирают; `none` убирает встроенный раздел о личности из инструкций модели.
- `skills.include_instructions` — включать ли автоматические инструкции о скиллах в контекст модели; по умолчанию `true`.
- Управляемые администратором `additional_developer_instructions` приходят отдельным developer-сообщением; инструкции больше примерно 10 000 токенов с маркерами контекста отклоняются.

## Скилл (SKILL.md)

- Скилл — каталог с файлом `SKILL.md` и необязательными `scripts/`, `references/`, `assets/` и `agents/openai.yaml`; устроен по открытому стандарту скиллов агентов.
- Фронтматтер: обязательны `name` и `description`; `name` — не длиннее 64 символов, пустое `description` — ошибка разбора. В `agents/openai.yaml` — интерфейс (отображаемое имя, короткое описание, промпт по умолчанию) и политика: `policy.allow_implicit_invocation: false` запрещает Codex вызывать скилл неявно.
- Места поиска: `.agents/skills` в каждом каталоге от текущего до корня репозитория; `$HOME/.agents/skills`; `/etc/codex/skills`; встроенные скиллы. Скиллы с одинаковым `name` не сливаются: в выборе видны оба. Отключение — записи `[[skills.config]]` по `path` или `name`; при нескольких подходящих записях действует последняя.
- До выбора модель видит имя, описание и путь каждого скилла. Если пользователь назвал скилл (`$SkillName` или словами) или задача явно подходит под описание — модель обязана использовать скилл в этом ходе и прочитать `SKILL.md` целиком до действий; чтение и толкование скилла не поручается субагенту.
- Бюджет списка скиллов — по умолчанию не больше 2 % окна контекста модели или 8 000 символов, если окно неизвестно; настройка `skills.max_context_tokens` — до 10 000 токенов. Каждое описание в списке обрезается до 1 024 символов. Если полный список не влезает, сначала укорачиваются описания — оставшийся бюджет раздаётся им по кругу по одному символу, чтобы ни одно описание не заняло весь остаток; если не влезают даже строки без описаний, описания убираются все, а лишние скиллы выпадают из списка с предупреждением.
- Главный случай применения и слова-триггеры — в начале описания, чтобы скилл находился и при укороченном описании. Остальные правила описаний и тела — [agents-and-tools.md](agents-and-tools.md), раздел «Скиллы».
- Субагенты наследуют скиллы родителя.

## Определение субагента

- Встроенные агенты: `default`, `worker`, `explorer`. Свои — TOML-файлы в `~/.codex/agents/` (личные) или `.codex/agents/` (проектные), один файл — один агент.
- Обязательные поля: `name`; `description` — указание для людей, когда Codex использовать этого агента; `developer_instructions` — основные инструкции, задающие поведение агента.
- Необязательные поля: `model`, `model_reasoning_effort`, `model_reasoning_summary`, `model_verbosity`, отключение возможностей `features.*`, `skills.config`, `skills.include_instructions`.
- Права, песочница, провайдер и серверы MCP наследуются от родителя; файл агента их не переопределяет.
- Глобальные настройки `[agents]`: `enabled`, `max_concurrent_threads_per_session`, `default_subagent_model`, `default_subagent_reasoning_effort`, `interrupt_message`.
- Текущие локальные выпуски Codex запускают субагентов по прямой просьбе или по применимой инструкции проекта или скилла. Текст `developer_instructions` пишется по общим техникам системного промпта ([principles.md](principles.md), [../write-prompt.md](../write-prompt.md)).

## Проверка срабатывания

- `codex debug prompt-input` — выводит в JSON точный вход, видимый модели (экспериментальная команда): так разбирают, какие инструкции и скиллы получила модель.
- `codex debug models` — каталог моделей, который видит Codex, вместе с базовыми инструкциями моделей.
- Проверка `AGENTS.md`: `codex --ask-for-approval never "Summarize the current instructions."`; для подкаталога — `codex --cd subdir --ask-for-approval never "Show which instruction files are active."`. Какие файлы загружены — по текстовому журналу TUI: `codex -c log_dir=./.codex-log`, затем `./.codex-log/codex-tui.log`, или по последнему файлу `session-*.jsonl`, если включено журналирование сессий.
- `/status` — модель, политика одобрений, корни для записи, расход токенов; `/debug-config` — слои конфигурации; `/skills` — просмотр и выбор скиллов; `/mcp` — подключённые инструменты MCP.
- При переполнении бюджета `AGENTS.md` или списка скиллов Codex выводит предупреждения: это повод сократить файлы или описания.
