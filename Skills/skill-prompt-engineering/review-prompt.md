# Проверить или улучшить готовый промпт

## Назначение

Процедура проверки готового текста для текущей модели Claude, Gemini, GPT или Grok по официальным техникам и особенностям модели, с таблицей находок и исправленной версией.

Файлы семейства лежат в папке `claude/`, `gemini/`, `gpt/` или `grok/`; ниже они названы по имени файла, папку задаёт семейство целевой модели.

## Шаг 1. Собрать вводные

- Текст промпта целиком, включая официальные блоки и примеры.
- Целевая модель и её семейство. ЕСЛИ не названа → запросить. ЕСЛИ модель из покрываемого семейства, но её нет в `models.md` → правило ближайшей покрываемой версии из первого шага рабочего процесса `SKILL.md`. ЕСЛИ промпт переносится с другой модели → это задача переноса, процедура в [migrate-prompt.md](migrate-prompt.md).
- Назначение промпта и для кого результат.
- Известные сбои: что модель делает не так. ЕСЛИ сбои названы → каждый сбой сопоставить со строками `models.md` и индексом `official-blocks.md` семейства в шаге 3.
- Вид текста: системный промпт или developer-сообщение; текст агентной среды — файл текстов агентной среды семейства ([claude/claude-code-artifacts.md](claude/claude-code-artifacts.md), [gemini/gemini-cli-artifacts.md](gemini/gemini-cli-artifacts.md), [gpt/codex-artifacts.md](gpt/codex-artifacts.md) или [grok/grok-build-artifacts.md](grok/grok-build-artifacts.md)); инструкции ChatGPT — раздел «Инструкции ChatGPT» в [gpt/principles.md](gpt/principles.md); задание субагенту — `delegation-task.md` семейства.
- Для Gemini: передаётся ли текст через API (тогда [gemini/parameters.md](gemini/parameters.md)) и есть ли функции, встроенные инструменты или структурированный вывод (тогда [gemini/agents-and-tools.md](gemini/agents-and-tools.md)).
- Для GPT: передаётся ли текст через API OpenAI (тогда [gpt/parameters.md](gpt/parameters.md)) и есть ли функции, скиллы или структурированный вывод (тогда [gpt/agents-and-tools.md](gpt/agents-and-tools.md)).
- Для Grok: передаётся ли текст через API xAI (тогда [grok/parameters.md](grok/parameters.md)) и есть ли функции, серверные инструменты или структурированный вывод (тогда [grok/agents-and-tools.md](grok/agents-and-tools.md)).

## Шаг 2. Прочитать текст целиком

Прочитать весь текст до первой находки: противоречие и повтор видны только при полном чтении.

## Шаг 3. Пройти чеклист

Каждый пункт проверяется по тексту; правило лежит в указанном разделе `principles.md` семейства или в названном файле семейства.

| Пункт | Что проверить | Раздел скилла |
|---|---|---|
| Ясность | Человек без контекста задачи выполнил бы промпт без вопросов | «Ясность и прямота» |
| Цель и причина | Сказано, зачем задача и для кого результат; причины инструкций — по правилу семейства | «Ясность и прямота», «Причина инструкции» |
| Формат и ограничения | Формат ответа и ограничения названы конкретно | «Ясность и прямота», «Формат ответа» |
| Охват | Инструкции, которые должны распространяться шире одного элемента, говорят об этом явно | «Буквальность и охват» |
| Формулировка запретов | Запреты сформулированы так, как предписывает семейство | «Ясность и прямота», «Формат ответа» |
| Примеры | Есть, если формат или тон нестандартный; число, разнообразие и оформление — по правилу семейства | «Примеры» |
| Структура | Разделы отделены тегами или заголовками; порядок данных и запроса — по правилу семейства | «Структура промпта», «Длинные документы» |
| Роль | Место и объём роли соответствуют разделу семейства | «Роль» |
| Рассуждение | Просьбы о рассуждении соответствуют разделу семейства | «Рассуждение» |
| Выделение | Нет нагромождения капса и нагнетания в собственном тексте | «Выделение и капс» |
| Инструменты | Для каждого инструмента сказано, когда он применяется; нет перетриггеров | «Инструменты в тексте промпта» |
| Противоречия и повторы | Нет двух инструкций, противоречащих друг другу; одно правило не повторено разными словами | «Противоречия внутри промпта» |
| Объём | Каждая строка задаёт поведение | «Объём и плотность» |
| Устаревшие приёмы | Нет строк `legacy-patterns.md` семейства, относящихся к целевой модели | `legacy-patterns.md` |
| Поведение модели | Для поведения целевой модели, относящегося к задаче, есть нужный блок или формулировка | `models.md` |
| Официальные блоки | Вставлены дословно; условие блока выполнено; место вставки соответствует строке «Куда»; блоков другого семейства нет | `official-blocks.md` |
| Параметры | ЕСЛИ у семейства есть `parameters.md` и текст передаётся через API → текст не опирается на параметр, который модель не принимает или игнорирует, и не дублирует то, что задаёт параметр | `parameters.md` |
| Стиль промпта | Стиль текста соответствует нужному стилю ответа | «Формат ответа» |

ЕСЛИ в `principles.md` семейства раздел содержит строку «Официальных сведений нет» → пункт не проверяется и в находки не идёт.

ЕСЛИ в `principles.md` семейства есть раздел «Чеклист проблем промпта» → после таблицы пройти каждый его пункт. Находка, уже записанная по строке таблицы, второй раз не записывается.

## Шаг 4. Записать находки

Каждая находка — строка таблицы:

| Место | Проблема | Правило скилла | Правка |
|---|---|---|---|
| Цитата или номер строки | Что не так | Раздел файла скилла | Конкретный новый текст |

ЕСЛИ пункт чеклиста выполнен → в таблицу не идёт. ЕСЛИ пункт зависит от расхождения источников в файлах семейства → находка записывается всеми позициями, а не как нарушение.

## Шаг 5. Собрать исправленную версию

- Внести правки из таблицы.
- Официальные блоки — посимвольно как в `official-blocks.md` семейства, кроме плейсхолдеров.
- Не менять то, что находкой не является: стиль автора, порядок разделов, формулировки, к которым нет замечаний.

## Шаг 6. Результат

- Таблица находок.
- Исправленный текст.
- Перечень добавленных и удалённых официальных блоков с местом вставки.
- Предупреждение, если правила взяты у ближайшей покрываемой версии.

Для моделей Claude что правка улучшила поведение модели, подтверждает только прогон на тестах — процедура в [claude/prompt-debugging.md](claude/prompt-debugging.md). Для Gemini, GPT и Grok методики отладки на тестах в скилле нет.

## Пример (Claude)

**Вход:** промпт агента-ревьюера кода для Sonnet 5.5: «You are a senior code reviewer. IMPORTANT: Only report high-severity issues. Think step by step and explain your reasoning in `<thinking>` tags before giving findings. Be conservative.»

**Находки:**

| Место | Проблема | Правило скилла | Правка |
|---|---|---|---|
| «Only report high-severity issues», «Be conservative» | Модель исполнит буквально и сообщит меньше находок | claude/legacy-patterns.md, строка «Фильтрующие формулировки в ревью» | Блок «Ревью кода без фильтрации»; фильтрация — отдельным шагом |
| «IMPORTANT:» | Нагнетание в собственном тексте | claude/principles.md, раздел «Выделение и капс» | Убрать слово |
| «Think step by step and explain your reasoning in `<thinking>` tags» | Просьба выписать рассуждение; на Sonnet 5.5 — риск отказа `reasoning_extraction` | claude/legacy-patterns.md, строка «Просьба выписать рассуждение в ответ» | Просить уверенность и серьёзность у каждой находки — это входит в блок ревью |

**Исправленный текст:**

```text
You are a senior code reviewer.

Report every issue you find, including ones you are uncertain about or consider low-severity. Do not filter for importance or confidence at this stage - a separate verification step will do that. Your goal here is coverage: it is better to surface a finding that later gets filtered out than to silently drop a real bug. For each finding, include your confidence level and an estimated severity so a downstream filter can rank them.
```
