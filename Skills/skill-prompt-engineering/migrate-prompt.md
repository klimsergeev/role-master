# Перенести промпт на другую версию модели

## Назначение

Процедура переноса текста промпта на текущую модель Claude с другой версии: что убрать, что заменить и что добавить в тексте. Изменения параметров запроса к API в процедуру не входят: их перечисляют страницы migration guide и what's new каждой модели.

## Шаг 1. Определить исходную и целевую модель

- Исходная модель — та, под которую писался промпт. ЕСЛИ неизвестна → запросить; ЕСЛИ так и не выяснено → пройти в шаге 3 все строки, ведущие к целевой модели, и записать это допущение в результат.
- Целевая модель — одна из текущих: Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5. ЕСЛИ целевая не текущая → вне охвата скилла.

## Шаг 2. Прочитать раздел целевой модели

Открыть раздел целевой модели в [models.md](models.md), включая строку таблицы «Текущие модели» о промптах предыдущей версии. Официальное правило переноса — best practices: «Where a technique names a specific model, treat it as measured on that model and re-check it against your own evals before applying it to another» (приём, названный для модели, считать измеренным на ней и перепроверять на своих тестах перед применением к другой).

## Шаг 3. Найти переход в таблице

| Переход | Что меняется в тексте | Источник |
|---|---|---|
| Opus 5 → Opus 5.5 | Промпты работают без изменений, паттерны гайда Opus 5 остаются отправной точкой. ЕСЛИ промпт писался под выключенное мышление → убрать инструкции, заменявшие мышление записью рассуждения в ответе; убрать правило «не думай»; перепроверить, нужен ли блок «Промпты под отключённое мышление». Перепроверить обходные приёмы для зрения. Дальше — строки раздела Opus 5.5 в models.md по задаче | Гайд Opus 5.5; what's new Opus 5.5; migration guide Opus 5.5, раздел Recommended changes: «Instructions tuned for Claude Opus 5's behavior might no longer be needed» (инструкции, настроенные под поведение Opus 5, могут быть уже не нужны) |
| Opus 4.8 и старше → Opus 5.5 | Всё из строки Opus 5 → Opus 5.5, плюс строки «из гайда Opus 5» раздела Opus 5.5 в models.md: краткость, длина документов, удаление инструкций перепроверки, ограничение объёма, делегирование, поправки, ревью кода. С Opus 4.6 и старше — убрать каркас принудительных статусов (Opus 4.7 даёт сообщения о ходе работы сам). С Opus 4.5 и старше — убрать опору на заданное начало ответа (не поддерживается с моделей 4.6; текстовые замены в legacy-patterns.md). Для промптов, писавшихся под модели до Opus 4.5 и 4.6, — смягчить «CRITICAL / MUST» и подстёгивание «не ленись» (Opus 4.5 и 4.6 чувствительнее к системному промпту, модели 4.6 проактивнее) | Гайд Opus 5; migration guide Opus 5.5, разделы для Opus 4.8, 4.7, 4.6 и старше; best practices, разделы Tool use и Migration considerations |
| Fable 5 → Fable 5.1 | Промпты работают без изменений. Проверить по поведению, изменившемуся с Fable 5: пакетные вызовы, прогресс-сообщения (убрать «hold all findings»), поиск на низком уровне усилия, плотность прозы, форматирование в чате (убрать антиформатирование), цитаты без пометки, переписывание файлов целиком | Гайд Fable 5.1; what's new Fable 5.1, раздел Changed from Claude Fable 5 |
| Opus 5, Opus 4.8 и старше → Fable 5.1 | Всё из строки Fable 5 → Fable 5.1, плюс: найти и убрать просьбы выписать рассуждение («show-your-thinking»), сократить слишком предписывающие инструкции и скиллы; строки раздела Fable 5.1 в models.md по задаче | Migration guide Fable 5.1; гайд Fable 5, раздел Recommended scaffolding changes |
| Sonnet 5 → Sonnet 5.5 | Промпты работают без изменений, паттерны гайда Sonnet 5 остаются отправной точкой. Убрать правила «не думай». Проверить размещение сообщений пользователя посреди хода. Дальше — строки раздела Sonnet 5.5 в models.md по задаче | Гайд Sonnet 5.5 |
| Sonnet 4.6 и старше → Sonnet 5.5 | Всё из строки Sonnet 5 → Sonnet 5.5, плюс строки «из гайда Sonnet 5»: явный охват инструкций (буквальное следование), краткость, удаление каркаса принудительных статусов, тон и разнообразие инструкциями вместо параметра, дизайн, ревью кода. С Sonnet 4.5 и старше — убрать опору на заданное начало ответа (migration guide Sonnet 5.5: Sonnet 4.5, Haiku 4.5 и старше его принимают, Sonnet 4.6 и новее — нет) | Гайд Sonnet 5; migration guide Sonnet 5.5 |
| Haiku 4.5 → Haiku 5.5 | Промпты работают без изменений. С инструментом поиска — дать дату и при длинном промпте подсказку искать; не ставить общей инструкции искать всегда. Строки раздела Haiku 5.5 в models.md по задаче. Убрать опору на заданное начало ответа и на встроенный счётчик контекста | Гайд Haiku 5.5; what's new Haiku 5.5 |
| Между линиями (например, Opus → Sonnet, Sonnet → Haiku) | Отдельного гайда о тексте промпта для такого перехода на официальных страницах нет. Убрать блоки и формулировки, написанные под поведение исходной модели, которого у целевой не описано; применить раздел целевой модели в models.md | Best practices, правило о приёмах, измеренных на конкретной модели |

## Шаг 4. Убрать компенсации исходной модели

Для каждой инструкции и каждого официального блока в тексте ответить: какое поведение он исправлял и описано ли это поведение у целевой модели в models.md.

- ЕСЛИ блок взят из гайда исходной модели и у целевой модели такого поведения не описано → удалить или пометить для проверки на тестах.
- ЕСЛИ поведение у целевой модели описано обратным (например, антиформатирование при переносе на Fable 5.1, которая форматирует меньше) → удалить.
- Гайд Fable 5: «Review and consider removing older instructions if default performance is better» (пересмотри и подумай об удалении старых инструкций, если поведение по умолчанию лучше).

## Шаг 5. Проверить на устаревшие приёмы

Пройти [legacy-patterns.md](legacy-patterns.md) по строкам, где в колонке «Модели» есть целевая модель или «все текущие модели».

## Шаг 6. Добавить блоки целевой модели

По строкам раздела целевой модели в models.md, относящимся к задаче, найти блоки в [official-blocks.md](official-blocks.md) и вставить те, чьё условие выполнено, дословно и в указанное место.

## Шаг 7. Результат

- Новый текст промпта.
- Перечень изменений: удалено (с основанием), заменено (было → стало, с основанием), добавлено (блок и источник).
- Допущения шага 1.
- Отметка, что параметры запроса меняются отдельно, по migration guide целевой модели: https://platform.claude.com/docs/en/models/fable-5-1/migration-guide, https://platform.claude.com/docs/en/models/opus-5-5/migration-guide, https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide, https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide.

Сравнение старой и новой версии на одном наборе тестов — процедура в [prompt-debugging.md](prompt-debugging.md).

## Пример

**Вход:** системный промпт агента-исследователя, написанный под Opus 4.6, переносится на Fable 5.1. В тексте: «CRITICAL: You MUST use the search tool for every question», «Explain your reasoning step by step in `<thinking>` tags before answering», «Do not use bullet points or headers», блок `avoid_excessive_markdown_and_bullet_points`.

**Изменения:**

- Удалено «Explain your reasoning step by step in `<thinking>` tags before answering» — legacy-patterns.md, строка «Просьба выписать рассуждение в ответ»: на Fable 5.1 риск отказа `reasoning_extraction`.
- Удалены «Do not use bullet points or headers» и блок `avoid_excessive_markdown_and_bullet_points` — гайд Fable 5.1, раздел Formatting in chat; на место — блок «Форматирование в чате».
- «CRITICAL: You MUST use the search tool for every question» заменено на «Use the search tool when a question depends on facts that may have changed since your training.» — legacy-patterns.md, строки «Капс и нагнетание» и «Перетриггер инструментов».
- Блок «Поиск по незнакомым именам» отмечен как кандидат — models.md, раздел Fable 5.1, строка о поиске на низком уровне усилия; добавляется, если на тестах агент отвечает по памяти там, где нужен поиск.
