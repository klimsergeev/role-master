# Каталог устаревших приёмов

## Назначение

Справочник приёмов, устаревших, вредных или ненужных для текущих моделей Claude: по какому признаку их найти, почему приём устарел и чем его заменить. Используется при аудите, проверке готового промпта и переносе на другую версию модели.

## Как читать таблицу

- «Что искать» — примеры формулировок для поиска (`grep -n -i`, `rg -i`). Совпадение — повод прочитать место целиком, а не вывод: та же фраза может стоять внутри официального блока, вставленного дословно, или в цитате.
- «Модели» — для каких моделей это установлено. Строка, относящаяся к одной модели, на другой переносится только с проверкой на тестах ([prompt-debugging.md](prompt-debugging.md)).
- «Замена» ссылается на блоки из [official-blocks.md](official-blocks.md) по их заголовкам.
- Сверено 2026-11-09.

## Каталог

Капс внутри официального блока, вставленного дословно, не трогать | Текущие модели; отдельно установлено для Opus 4.5, 4.6 |

Шаги задачи, где важны порядок и полнота результата, остаются нумерованным списком — это не план мышления | Текущие модели |

| Явные инструкции перепроверки | `double-check your answer`, `re-verify before responding`, `include a final verification step`, `use a subagent to verify`, «перепроверь ответ» | Opus 5 проверяет свою работу сам, такие инструкции вызывают избыточную проверку. Их удаляют, а не переписывают | Удалить | Opus 5; для Opus 5.5 — паттерн Opus 5 как отправная точка. Для остальных моделей самопроверка по-прежнему советуется — расхождение в [models.md](models.md) |
| Подстёгивание «не ленись» | `keep going`, `loop until done`, `don't be lazy`, `don't stop until`, «не останавливайся», «доведи до конца любой ценой» | Текущие модели обычно и без напоминаний доводят согласованную задачу до конца, а такие строки скорее вызывают лишнюю работу, чем лечат остановку. Модели 4.6 проактивнее и могут срабатывать избыточно на инструкции, нужные прежним моделям | Дать проверку, которую надо пройти. Для агентов без присмотра — блоки «Автономная работа» (Fable 5.1), «Постоянная инструкция о конце хода» (Opus 5.5), «Доводить работу и не добавлять лишнего» (Sonnet 5.5, Haiku 5.5) по условию блока | Текущие модели |
| Перетриггер инструментов | `If in doubt, use`, `Default to using`, `always use the`, «если сомневаешься, используй» | Инструкции вида `If in doubt, use [tool]` вызывают избыточное срабатывание | «Use [tool] when it would enhance your understanding of the problem.» — сказать, когда инструмент применяется | Opus 4.6; общий принцип для текущих моделей |

| Принудительные статусы | `After every 3 tool calls, summarize progress`, «каждые N шагов пиши статус» | Модели дают регулярные сообщения сами, такой каркас стоит попробовать убрать | Удалить; если формат сообщений не подходит — описать, как они должны выглядеть, с примерами | Sonnet 5 (для Sonnet 5.5 — отправная точка), Opus 5.5 |
| Отговаривание от инструментов | `only use tools when strictly necessary`, `minimize tool calls`, «используй инструменты только при крайней необходимости» | Такие формулировки убирают первыми, если модель отвечает из знаний обучения там, где поиск поймал бы изменения | Удалить; блок «Поиск в чате и исследованиях» | Sonnet 5.5 |

| Общие дизайнерские указания | `avoid a generic AI look`, `make it clean and minimal`, `don't use that color`, «сделай стильно», «без типичного вида ИИ» | На Opus 5.5 такое указание в основном меняет один дефолтный стиль на другой. | Общая инструкция искать всегда | `search for any present-day factual question, regardless of how confident you are`, «ищи на любой вопрос о текущем» | Модель искала в половине промптов, где поиск не нужен, без прироста верных ответов | Блок «Дата и поиск» | Haiku 5.5 |
| Правило «не думай» | `do not think`, `don't reason`, `no thinking`, `answer without thinking`, «не рассуждай» | На Opus 5 правило «не думай» усиливает утечку внутренних тегов в ответ.
