# Grok: параметры запроса, связанные с текстом промпта

## Назначение

Справочник параметров запроса к моделям Grok через API xAI, которые официальные материалы связывают с текстом промпта: текст заменяет параметр, параметр определяет, куда попадает текст, сколько он действует и что модель видит из прежних ходов, или значение параметра оставляет текст без результата. Остальные параметры (цены, порог дорогого тарифа, окна контекста, таймауты, отложенные запросы, режим WebSocket, `tool_choice`, `parallel_tool_calls`, предел числа инструментов, размер блока кеша) сюда не входят.

Значения сверены 2026-11-13.

## Поверхности

| Поверхность | Что это | Где различия |
|---|---|---|
| Responses API | Основной интерфейс | Разделы ниже |
| Chat Completions | Устарел; не передаёт зашифрованное рассуждение; результаты через него занижают возможности рассуждающих моделей, особенно на нескольких ходах и с вызовами инструментов | [legacy-patterns.md](legacy-patterns.md), строка «Chat Completions вместо Responses API» |
| Grok Build | Агентная среда xAI для программирования | [grok-build-artifacts.md](grok-build-artifacts.md) |
| Приложение Grok | Скилл его не описывает | — |

Для Grok 4.7 источники расходятся: одна позиция — модель работает только через Responses API; другая — её можно вызывать и через стандартные эндпоинты chat и completions.

## Системный промпт и `instructions`

- Системный промпт — сообщение с ролью `system` во вводе или параметр `instructions` в Responses API.
- `instructions` нельзя использовать вместе с `previous_response_id`: тогда действует системный промпт предыдущего сообщения.
- При сжатии контекста `instructions` отбрасывается (раздел «Сжатие контекста»).
- Порядок ролей `system`, `user`, `assistant` свободный: системное сообщение можно поставить в любом месте беседы.

## `reasoning.effort`

Уровень рассуждения: `reasoning.effort` в Responses API, `reasoning_effort` в Chat Completions. Допустимые значения и значение по умолчанию зависят от модели; метод `GET /v1/models` возвращает их для каждой модели в полях `capabilities.reasoning_effort` и `default_reasoning_effort`.

| Модель | Уровни | По умолчанию |
|---|---|---|
| Grok 4.7 | `low`, `medium`, `high`, `xhigh` | `high` |
| Grok 4.6 | `low`, `medium`, `high`, `xhigh` | `high` |
| Grok 4.5 | источники расходятся: одна позиция — `xhigh` не поддерживается, и запрос с ним обрабатывается как `high`; другая — `low`, `medium`, `high`, `xhigh`; третья — `low`, `medium`, `high` | `high` |
| Grok 4.3 | источники расходятся: одна позиция — `none`, `low`, `medium`, `high`; другая — `none`, `low`, `medium`, `high`, `xhigh`; третья — те же четыре уровня, что у Grok 4.7 | `low` |
| Grok 4.20, рассуждающий вариант | Рассуждает автоматически. Прежде xAI указывала, что параметр у неё не поддерживается и его указание возвращает ошибку; сейчас xAI не называет её ни среди моделей, поддерживающих параметр, ни среди не поддерживающих | не установлено |
| Grok 4.20, нерассуждающий вариант | Без рассуждения | — |

- У Grok 4.7, 4.6 и 4.5 рассуждение не отключается; без рассуждения работают Grok 4.3 на уровне `none` и нерассуждающий вариант Grok 4.20.
- Назначение уровней: `low` — агентные сценарии, чувствительные к задержке, и простой вызов инструментов; `medium` — сложный анализ данных и рассуждение на длинном контексте; `high` — очень трудные задачи: сложная математика, многошаговая логика, задачи олимпиадного уровня; `xhigh` — самые трудные задачи, где качество ответа важнее скорости.
- Уровень задавать явно в каждом запросе и записывать вместе с каждым результатом.
- Больше рассуждения не всегда лучше: уровень выбирать по оценке на своей задаче; лучший уровень может меняться от прогона к прогону.
- Полное рассуждение возвращается только зашифрованным; сводка рассуждения доступна только у Grok 4.7. Grok 4.7 возвращает зашифрованное рассуждение всегда, даже без запроса.

## История и рассуждение между ходами

- Зашифрованное рассуждение возвращать в API на каждом ходе: модель помнит свои прежние рассуждения, и это резко улучшает качество в многоходовых беседах и агентных циклах.
- Элементы вывода возвращать во вводе следующего запроса ровно в полученном виде.
- Три ошибки, которые теряют рассуждение:
  1. Взять `output_text` и добавить его как обычное сообщение ассистента, выбросив элементы рассуждения и вызовов функций вокруг.
  2. Править, переставлять или фильтровать элементы вывода перед отправкой назад.
  3. Пересобирать беседу между ходами из стенограммы в другом формате, например в массив `messages` Chat Completions.
- В агентном цикле рассуждение приходит в том же массиве вывода, что и вызов функции: добавлять весь массив, затем результаты функций, чтобы модель продолжила со своим планом.

## Параметры сэмплирования

- `temperature` 0.7 и `top_p` 0.95, и далеко от них не уходить: модели Grok плохо отзываются на другие настройки сэмплирования, и качество обычно падает.
- Значение выше предела сэмплируется как предел; предел температуры — 1.
- `presencePenalty`, `frequencyPenalty` и `stop` с рассуждающими моделями дают ошибку.
- `logprobs` и `top_logprobs` у Grok 4.20 и более новых моделей молча игнорируются.

## `max_output_tokens`

- Ставить выше самого длинного ожидаемого ответа или оставлять значение по умолчанию 128 000.
- Рассуждение в этот предел не входит.
- Слишком малое значение обрезает ответ: он приходит со статусом `incomplete`.

## Кеш и порядок частей

- Статичное — системный промпт, примеры, справочные документы — в начало запроса: так образуется стабильный префикс.
- Только дописывать в конец: любое изменение ранних сообщений ломает кеш. Поэтому новые инструкции посреди беседы добавляются новым сообщением в конец, а не правкой ранних сообщений.
- У каждой беседы — свой `prompt_cache_key`.
- Пропуск рассуждения при возврате истории — главная причина промахов кеша у рассуждающих моделей.
- Текущее время и другие изменяемые данные — в начало последнего сообщения пользователя, а не в начало системного промпта.
- Кеш не меняет ответа модели: вывод одинаков, взят ли промпт из кеша или посчитан заново.

## Сжатие контекста

- Элемент сжатия ставится первым, новые ходы — после него: API отбрасывает всё, что стоит до элемента, включая `instructions`. Поэтому системный промпт идёт во вводе после элемента сжатия.
- Сжимаемая беседа должна уже помещаться в контекст.
- Сжатие обещает более сосредоточенные ответы, но не всегда окупается: в замере xAI на короткой беседе с Grok 4.7 оно стоило больше, чем сэкономило, а короткая сводка теряла детали. На других моделях эффект не измерен.

## Структурированный вывод

- При поддерживаемых возможностях схемы ответ гарантированно ей соответствует.
- Аргументы вызовов инструментов всегда строго следуют схеме.
- `not`, `if`/`then`/`else`, `allOf` с несколькими подсхемами и неподдерживаемые значения `format` принимаются, но не гарантируются: если нужно строгое соответствие, вывод проверять.
- `additionalProperties` по умолчанию `false`.
- При заданной схеме промпт не перечисляет обязательные поля ответа ([principles.md](principles.md), раздел «Формат ответа»).
- Значения `description` и имена полей схемы — текст промпта: правила для них — [agents-and-tools.md](agents-and-tools.md), раздел «Описания функций и полей схем».

## Правила модерации `guidelines`

- Поведение по категориям `nsfw`, `violence` и `profanity` задаётся параметром `guidelines`, а не текстом промпта; модель следует правилам, когда пишет ответ, своими словами.
- Единственное поведение — `decline`.
- С мультиагентной моделью и отложенными запросами параметр не работает.

## `max_turns`

- Ограничивает число ходов агента, а не число вызовов инструментов; заменяет ограничение ходов, которое иначе писали бы в тексте промпта.
- Ориентиры xAI: 1–2 хода для быстрых справок, 3–5 для сбалансированного поиска, 10 и больше или без предела — для глубокого.
