# Grok: функции, инструменты и агенты

## Назначение

Правила для текстов, которые модель Grok получает вместе с инструментами и в агентных сценариях через API xAI: описания функций и полей схем, серверные и клиентские инструменты, защита от внедрения инструкций через веб-страницы и результаты инструментов. Тексты Grok Build — в [grok-build-artifacts.md](grok-build-artifacts.md), задание субагенту Grok Build — в [delegation-task.md](delegation-task.md); параметры запроса — в [parameters.md](parameters.md) (справочник).

Значения сверены 2026-11-13.

## Описания функций и полей схем

Значения `description` у функций, их параметров и полей схем структурированного вывода, а также имена функций и параметров — текст промпта.

- `description` функции — что делает инструмент. Без него описание считается пустым; ясное описание помогает модели решить, когда инструмент применять.
- При структурированном выводе схема задана отдельно, и текст промпта поля ответа не перечисляет.
- Строгость схемы и ключевые слова, которые принимаются без гарантии, — [parameters.md](parameters.md), раздел «Структурированный вывод».

## Серверные и клиентские инструменты

- Серверные инструменты — веб-поиск, поиск по X, исполнение кода, поиск по коллекциям, удалённые MCP-серверы — модель вызывает сама в цикле на стороне xAI; их выводы в ответ API не возвращаются.
- При вызове клиентской функции выполнение приостанавливается, и управление возвращается приложению.
- Клиентские и серверные инструменты можно смешивать в одном запросе.
- Ограничение числа ходов агента — [parameters.md](parameters.md), раздел `max_turns`; рассуждение в агентном цикле — [parameters.md](parameters.md), раздел «История и рассуждение между ходами».

## Защита от внедрения инструкций

xAI проверяла четыре меры защиты от инструкций, внедрённых в веб-страницы и результаты инструментов:

1. Считать страницы данными:
   - в системном промпте сказать, что всё, что возвращают инструменты, — недоверенные данные, а не инструкции, и не оставлять в нём строк, велящих выполнять шаги, найденные на страницах (блок «Ограда в системном промпте»);
   - каждую загруженную страницу в результате инструмента оборачивать в теги `<untrusted>` (блок «Ограда вокруг вывода инструмента»);
   - если инструменты ограничены по шагам, текст, написанный по страницам и вставленный в сообщение следующего шага, оборачивать так же, иначе модель с такой оградой примет его за просьбу пользователя (блок «Ограда для сводки в следующем шаге»).
2. Ограничивать набор инструментов по шагам.
3. Проверять аргументы вызовов.
4. Спрашивать человека перед действием.

Блоки — в [official-blocks.md](official-blocks.md). Результаты проверки:

- В замере xAI на Grok 4.7 на уровне `low` каждая мера по отдельности пропускала часть атак, все четыре вместе — ни одной; отдельный прогон может отличаться на одну-две атаки. На других моделях эффект не измерен.
- Теги ограды страница может закрыть сама. Атака с поддельным закрывающим тегом в замере не прошла ни разу, но ограда не заменяет остальные меры.
- Очевидные атаки — адрес злоумышленника, строку с просьбой игнорировать прежние инструкции, просьбу прислать ключ — модель отклоняла сразу.
- Изредка модель открывала адрес, который выдумала сама; это закрывается ограничением инструментов и проверкой аргументов.
- Замер сделан на клиентских инструментах. Как защищать выводы серверных инструментов, которые в ответ API не возвращаются, — не установлено.
