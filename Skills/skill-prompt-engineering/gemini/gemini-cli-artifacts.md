# Gemini: тексты для Gemini CLI

## Назначение

Официальные правила и значения для текстов Gemini CLI: файлов контекста `GEMINI.md`, замены системного промпта файлом `system.md`, навыков (SKILL.md), файлов контекста расширений и определений субагентов. Общие техники текста — в [principles.md](principles.md); задание, которое главный агент передаёт субагенту, — в [delegation-task.md](delegation-task.md).

Значения сверены 2026-11-11; версии Gemini CLI выходят еженедельно — перед опорой на конкретное значение в важном решении перепроверь его.

## Общее для всех артефактов

- Агентная среда Gemini в скилле — только Gemini CLI; другие среды, включая Antigravity CLI, скилл не описывает.
- Gemini CLI не настроен под серию Gemini 4 и следующие выпуски; моделей Gemini 4 в его коде нет. Из покрываемых моделей в коде есть `gemini-3.8-flash`, `gemini-3.5-flash-lite` и `gemini-3.1-flash-lite`; `gemini-3.6-flash` нет.
- Официальных советов о текстах Gemini CLI под Gemini 4 нет — не установлено.
- Встроенный системный промпт CLI задаёт тон по умолчанию: стараться укладываться меньше чем в три строки текста за ответ, не считая вызовов инструментов и кода.

## GEMINI.md

- Назначение: инструкции по проекту, персона, руководство по стилю кода — то, что иначе пришлось бы повторять в каждом промпте.
- Загрузка: глобальный `~/.gemini/GEMINI.md` — умолчания для всех проектов; файлы в рабочих каталогах и их родителях, подъём вверх до каталога с маркером (по умолчанию `.git`); файлы, найденные точно в момент, когда инструмент обращается к файлу или каталогу, — в этом каталоге и его предках до доверенного корня. Содержимое всех найденных файлов склеивается с пометками о происхождении и пути, подаётся частью системного промпта и уходит модели с каждым запросом.
- Приоритет: встроенный промпт объявляет инструкции из `GEMINI.md` основополагающими требованиями с приоритетом над процессами и настройками инструментов по умолчанию. При конфликте: подкаталог важнее корня рабочей области, корень — расширений, расширения — глобального файла. Инструкции переопределяют поведение по умолчанию (стек, стиль, процессы, выбор инструментов), но не основные требования безопасности и целостности агента.
- Импорт: большой файл разбивается на части синтаксисом `@file.md` (относительные и абсолютные пути); глубина импорта по умолчанию — 5 уровней; импорт держать неглубоким, без длинных вложенных цепочек; `@` внутри блоков кода не обрабатывается.
- Имя файла меняется настройкой `context.fileName` (например, список из `AGENTS.md`, `CONTEXT.md`, `GEMINI.md`).
- Один факт живёт ровно в одном файле на всех уровнях, без дублей между уровнями; файлы подкаталогов упоминаются в корневом `GEMINI.md`, чтобы их было видно.
- Текст:
  - сфокусированный, без перегруза: инструкции исполнимые и относятся к работе с кодом;
  - кратко, без исчерпывающей документации; короткие примеры использования инструментов и команд;
  - явный запрет того, чего не делать, часто действеннее расплывчатого позитивного указания;
  - устаревшие правила периодически убирать.
- Числовые пределы длины `GEMINI.md` — не установлено.
- Источники расходятся:
  - в описании поиска файлов: одна позиция — подъём к предкам каталога, к которому обратился инструмент; другая — обход подкаталогов ниже рабочего каталога (по умолчанию до 200 каталогов);
  - в имени команды перечитывания файлов: одна позиция — `/memory reload`, другая — `/memory refresh`.

## Замена системного промпта (`system.md`)

- Переменная `GEMINI_SYSTEM_MD` полностью заменяет встроенный системный промпт своим файлом Markdown — без слияния: ни одна встроенная инструкция не действует, если её не перенести самому.
- Значения: `true` или `1` — читается `./.gemini/system.md`; другой текст — путь к файлу (относительный, абсолютный, с `~`); `false`, `0` или отсутствие переменной — встроенный промпт. Нет файла — ошибка `missing system prompt file '<path>'`.
- Перед заменой выгрузить встроенный промпт и просмотреть обязательные правила безопасности и работы: `GEMINI_WRITE_SYSTEM_MD=1 gemini`.
- Подстановки в своём файле: `${AgentSkills}` — раздел со списком навыков; `${SubAgents}` — раздел со списком субагентов; `${AvailableTools}` — список включённых инструментов; `${<имя_инструмента>_ToolName}` — имя конкретного инструмента.
- Разделение ролей файлов: в `system.md` — непреложные правила работы (безопасность, протоколы инструментов, подтверждения, механика надёжности), минимально, но полно; в `GEMINI.md` — персона, цели, методики, контекст проекта и предметной области.
- Замена промпта убирает и встроенные правила безопасности и работы инструментов, если их не перенести в свой файл.

## Навык (`SKILL.md`)

- Навыки устроены по открытому стандарту Agent Skills. В отличие от `GEMINI.md` — постоянного фона на всю рабочую область — навык даёт экспертизу по требованию.
- Места поиска по возрастанию приоритета: встроенные, из расширений, пользовательские (`~/.gemini/skills/` или `~/.agents/skills/`), рабочей области (`.gemini/skills/` или `.agents/skills/`). Внутри одного уровня `.agents/skills/` важнее `.gemini/skills/`.
- Активация: в начале сессии в системный промпт попадают только имя и описание каждого включённого навыка. Модель вызывает инструмент активации, пользователь подтверждает, тело SKILL.md и структура папки приходят в историю, папка навыка открывается для чтения. На время задачи модели велено ставить процедуры навыка выше своих правил по умолчанию.
- Описание — единственное, что модель знает о навыке до активации:
  - одной строкой;
  - со словами, которые вероятно встретятся в запросах пользователя;
  - с условием срабатывания — когда применять навык;
  - отличимое от описаний других навыков и от общих возможностей модели;
  - всё о том, когда применять, — только в описании: тело грузится уже после срабатывания, раздел «когда применять» в теле бесполезен.
- Размер: метаданные (имя и описание) — около 100 слов, всегда в контексте; тело — источники расходятся: одна позиция — меньше 5 тысяч слов, другая — меньше 500 строк; ресурсы грузятся по требованию.
- В теле — основные процедуры; подробный справочный материал, схемы и примеры — в отдельные файлы на один уровень от SKILL.md. Файлу длиннее 100 строк — оглавление в начале; для файлов больше 10 тысяч слов — шаблоны поиска в SKILL.md.
- Форма: повелительная или инфинитивная; во фронтматтере только имя и описание; в папку навыка не класть README, CHANGELOG и прочую вспомогательную документацию.
- Степени свободы: текстовые инструкции — когда годятся разные подходы; псевдокод или скрипты с параметрами — когда есть предпочтительный шаблон; конкретные скрипты — когда операции хрупкие или последовательность обязательна.
- Добавлять только то, чего модель не знает: окно контекста — общий ресурс. Короткие примеры лучше многословных объяснений.

## Расширение

- Расширение — каталог в `~/.gemini/extensions` с манифестом `gemini-extension.json`. Файл контекста расширения задаёт поле `contextFileName`; если поля нет, а в каталоге расширения есть `GEMINI.md`, грузится он.
- Расширение может нести навыки (`skills/<имя>/SKILL.md`), субагентов (`agents/*.md`; субагенты в расширениях — функция в preview), команды (`commands/*.toml`), хуки (`hooks/hooks.json`) и правила движка политик (`policies/`; разрешения `allow` и режим `yolo` из расширений игнорируются).
- Текст файла контекста расширения:
  - общее назначение расширения и как работать с его инструментами;
  - кратко, ясно и прямо, без исчерпывающей документации;
  - короткие примеры того, как модели пользоваться инструментами и командами.
- Место в приоритете: контекст расширений ниже корня рабочей области и выше глобального файла (раздел «GEMINI.md»).

## Определение субагента (`.gemini/agents/*.md`)

- Файл обязан начинаться с фронтматтера YAML; тело файла становится системным промптом субагента. Места: `.gemini/agents/*.md` — проект, `~/.gemini/agents/*.md` — пользователь.
- Поля:

| Поле | Обязательно | Что задаёт | По умолчанию |
|---|---|---|---|
| `name` | да | Идентификатор и имя инструмента: строчные буквы, цифры, дефис, подчёркивание | — |
| `description` | да | Что делает субагент; видно главному агенту и помогает решить, когда вызывать | — |
| `kind` | нет | `local` или `remote` | `local` |
| `tools` | нет | Список инструментов; маски `*`, `mcp_*`, `mcp_<сервер>_*` | без поля наследуются все инструменты родительской сессии |
| `model` | нет | Модель субагента | `inherit` — модель основной сессии |
| `temperature` | нет | Температура 0.0–2.0; что модели делают с этим параметром — [parameters.md](parameters.md), раздел «Параметры сэмплирования» | `1` |
| `max_turns` | нет | Предел ходов до возврата | `30` |
| `timeout_mins` | нет | Предел времени в минутах | `10` |

- Источники расходятся в имени поля встроенных серверов MCP: одна позиция — `mcpServers`, другая — `mcp_servers` при строгой проверке полей; поле `display_name` есть в схеме кода и отсутствует в таблице документации.
- Описание: область экспертизы, когда вызывать, несколько примеров сценариев. Образец описания:

```text
Git expert agent which should be used for all local and remote git operations.
For example:

- Making commits
- Searching for regressions with bisect
- Interacting with source control and issues providers such as GitHub.
```

- Строение тела в официальных примерах: роль одной фразой, затем фокусы списком, последней строкой — ограничение роли (например, только сообщать о проблеме, не исправляя её).
- Субагент не вызывает других субагентов, даже с маской `*` в инструментах.

## Проверка срабатывания

- `/memory show` показывает полное склеенное содержимое файлов контекста — ровно то, что получает модель; так разбирают, почему агент может игнорировать правило.
- Если субагент не вызывается по описанию — выбрать модель командой `/model` и спросить её, почему по такому промпту и такому описанию она не вызвала субагента.
- `@имя` в начале промпта заставляет CLI добавить системную заметку, подталкивающую главную модель сразу вызвать этого субагента.
- Список навыков в сессии — `/skills list`; перечитать навыки — `/skills reload`.
