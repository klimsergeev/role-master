# Аудит промптов и скиллов на устаревшие приёмы

## Назначение

Процедура поиска в готовых промптах, скиллах, CLAUDE.md, правилах и определениях субагентов приёмов, которые официальная документация называет устаревшими или вредными для текущих моделей Claude. Результат — таблица находок с основанием и заменой.

## Шаг 1. Определить охват

- Перечень файлов или каталогов — абсолютными путями.
- Целевая модель для каждого файла. ЕСЛИ модель не задана → проверять по всем текущим моделям и в каждой находке указывать, к каким моделям она относится.
- Входят ли в задачу правки. ЕСЛИ правки не заказаны → аудит заканчивается отчётом, файлы не меняются.

## Шаг 2. Найти кандидатов поиском

По колонке «Что искать» в [legacy-patterns.md](legacy-patterns.md) выполнить поиск без учёта регистра по всем файлам охвата, например:

```bash
rg -n -i "CRITICAL|IMPORTANT|think step by step|think hard|be thorough|<thinking>|explain your reasoning|double-check|re-verify|keep going|don't be lazy|if in doubt, use|hold all findings|minimize tool calls|only report high-severity|be conservative" "<путь>"
```

Перед поиском посмотреть две-три строки реального текста файлов: шаблон пишется под их язык и формат. Нулевой результат поиска означает только, что шаблон не совпал.

## Шаг 3. Найти то, что поиском не находится

- Чрезмерная предписанность: длинные перечни поведений по именам, микрошаги на каждое действие, списки граничных случаев вместо примеров (строка «Слишком предписывающие скиллы и промпты прежних моделей»).
- Противоречия между инструкциями внутри файла и между файлами одного охвата ([principles.md](principles.md), раздел 14).
- Для артефактов Claude Code — правила формата из [claude-code-artifacts.md](claude-code-artifacts.md): описание архитектуры в CLAUDE.md, длина файлов, длина `description` и `when_to_use`, ссылки на несуществующие файлы.

## Шаг 4. Разобрать каждого кандидата

Открыть место и прочитать его в контексте. Каждого кандидата отнести к одному исходу:

| Исход | Признак | В отчёт |
|---|---|---|
| Находка | Приём из каталога, и целевая модель есть в колонке «Модели» | Да |
| Часть официального блока | Текст совпадает с блоком в [official-blocks.md](official-blocks.md), вставленным дословно (капс в `investigate_before_answering`, `NEVER` в `frontend_aesthetics`) | Нет; блок проверяется на условие применения, а не на капс |
| Цитата или описание приёма | Приём упомянут как пример, запрет или документация, а не как инструкция модели | Нет |
| Другая модель | Строка каталога относится к модели, на которой промпт не работает | Нет; отметить отдельно, если промпт могут перенести |

## Шаг 5. Записать отчёт

| Файл:строка | Приём (строка каталога) | Текст | Основание | Замена | Модели |
|---|---|---|---|---|---|

После таблицы — число находок по строкам каталога и перечень файлов без находок.

## Шаг 6. Внести правки, если они заказаны

- ЕСЛИ правки входят в задачу → внести замены из колонки «Замена» точечно; официальные блоки — дословно из official-blocks.md.
- После правок повторить поиск шага 2 по исправленным файлам и сверить, что изменились ровно места из отчёта.

## Официальная проверка в Claude Code

Страница memory Claude Code: команда `/doctor prompt-audit` ищет «instructions written for older models, references to files or commands that don't exist, and files that contradict each other» (инструкции, написанные для старых моделей, ссылки на несуществующие файлы и команды, противоречащие друг другу файлы) в CLAUDE.md, CLAUDE.local.md, AGENTS.md, правилах, скиллах, командах, субагентах и стилях вывода; требует Claude Code v2.1.283 или новее; файлы не меняет, пока не попросят применить правки. Это отдельный инструмент; процедура этого файла от него не зависит.

## Пример

**Вход:** аудит каталога скиллов на устаревшие приёмы, целевая модель не задана.

**Ход:** поиск шага 2 даёт 14 совпадений. Три — `MUST` внутри вставленного дословно блока `investigate_before_answering` (исход «Часть официального блока»). Одно — строка документации скилла, перечисляющая запрещённые фразы (исход «Цитата»). Десять — находки: шесть «Капс и нагнетание», три «Просьба выписать рассуждение в ответ» (модели Fable 5.1, Opus 5.5, Sonnet 5.5), одна «Подстёгивание „не ленись“». Шаг 3 добавляет одну находку: в CLAUDE.md раздел с деревом каталогов.

**Результат:** таблица из одиннадцати строк и перечень файлов без находок; правки не вносились, потому что не были заказаны.

Пример иллюстративный.
