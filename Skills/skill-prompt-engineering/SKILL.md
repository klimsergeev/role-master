# Prompt Engineering

## Назначение

Скилл задаёт процедуры и официальные значения для текста промптов к текущим моделям Claude: написание, проверка, перенос между версиями, аудит на устаревшие приёмы и отладка на тестах. Применяется к системным промптам приложений и агентов, к CLAUDE.md, правилам `.claude/rules/`, определениям субагентов, SKILL.md и заданиям, которые агент передаёт субагенту.

## Принципы

1. Охват — текст промпта для Fable 5.1, Opus 5.5, Sonnet 5.5 и Haiku 5.5. Параметры запроса к API (effort, режимы мышления, принудительный вызов инструментов, temperature, заданное начало ответа) в скилл не входят.
2. Утверждения о моделях и блоки — официальные значения Anthropic. Приём, измеренный на одной модели, на другой перепроверяется тестами.
3. Официальные блоки Anthropic вставляются дословно, на английском; меняются только плейсхолдеры в скобках.
4. Где источники расходятся, приводятся все позиции; скилл между ними не выбирает.
5. Значения сверены 2026-11-09.

## Таблица маршрутизации

> Читай файлы под задачу, а не скилл целиком. Колонка «Обязательно» — открыть до начала работы. Колонка «Читать, если» — открыть, когда условие выполнено; условие проверяется по задаче, а не по желанию. Файлы с пометкой `(справочник)` устроены как таблицы для точечного поиска — в них допустим поиск нужной строки вместо чтения целиком.

## Рабочий процесс

### Шаг 1: Определить задачу

Найти строку таблицы маршрутизации, которая соответствует запросу. ЕСЛИ запрос включает несколько задач (проверить и затем сравнить на тестах) → выполнить строки по очереди.

### Шаг 2: Открыть файлы

Открыть файлы колонки «Обязательно» и проверить условия колонки «Читать, если»; для каждого выполненного условия открыть указанный файл.

### Шаг 3: Выполнить процедуру

Пройти шаги файла процедуры по порядку.

### Шаг 4: Сверить блоки

ЕСЛИ в результат вставлены официальные блоки → сверить каждый с [official-blocks.md](official-blocks.md) посимвольно, кроме заменённых плейсхолдеров.

### Шаг 5: Результат

Результат — артефакт процедуры: текст промпта, таблица находок с исправленной версией, перечень изменений при переносе, отчёт аудита или результаты прогона тестов.

Отладка на тестах — отдельная процедура скилла ([prompt-debugging.md](prompt-debugging.md)): ею подтверждается, что написанный, исправленный или перенесённый промпт достигает критериев успеха.

## Что НЕ делать

- Не пересказывать официальный блок своими словами и не выдавать пересказ за официальный текст.
- Не добавлять официальный блок, если условие из его строки «Когда» не выполнено.
- Не применять техники, написанные для Claude 3, там, где они расходятся с правилами скилла, а также заданное начало ответа и рассуждение в тегах `<thinking>`: для текущих моделей они не поддерживаются или рискованны.
- Не задавать рамку вызова Agent tool: путь к файлу роли, рабочую директорию, обязательные разделы промпта и pre-flight checklist задаёт скилл skill-agent-orchestration (файл prompt-format.md); этот скилл — о технике текста внутри рамки.

## Примеры

### Пример 1: Типовой сценарий

**Запрос:** «Напиши системный промпт для бота поддержки на Haiku 5.5, у бота есть веб-поиск».

**Маршрут:** строка «Написать новый промпт»: [write-prompt.md](write-prompt.md), [principles.md](principles.md), [models.md](models.md), [official-blocks.md](official-blocks.md), [legacy-patterns.md](legacy-patterns.md); условие колонки «Читать, если» не выполнено — текст не артефакт Claude Code.

**Результат:** системный промпт с ролью в одно предложение, целью, инструкциями и блоками «Дата и поиск» и «Правила системного промпта на весь разговор»; перечень вставленных блоков с местом вставки.

### Пример 2: Перенос скилла со старыми приёмами

**Запрос:** «Перенеси наш SKILL.md, писавшийся под Opus 4.6, на Fable 5.1. В нём „CRITICAL: ALWAYS…“ и просьба объяснять рассуждение в тегах `<thinking>`».

**Маршрут:** строка «Перенести промпт на другую версию модели»: [migrate-prompt.md](migrate-prompt.md), [models.md](models.md), [legacy-patterns.md](legacy-patterns.md), [official-blocks.md](official-blocks.md), [principles.md](principles.md); плюс [claude-code-artifacts.md](claude-code-artifacts.md), потому что переносимый текст — SKILL.md.

**Результат:** новый SKILL.md без капса и без просьбы выписать рассуждение (риск отказа `reasoning_extraction` на Fable 5.1), с проверкой длины `description` и `when_to_use`; перечень удалённого, заменённого и добавленного с основаниями.

### Пример 3: Две задачи в одном запросе

**Запрос:** «Агент-ревьюер на Sonnet 5.5 находит меньше багов, чем раньше. Проверь промпт и сравни старую и новую версию на тестах».

**Маршрут:** сначала строка «Проверить или улучшить готовый промпт»: [review-prompt.md](review-prompt.md), [principles.md](principles.md), [models.md](models.md), [official-blocks.md](official-blocks.md), [legacy-patterns.md](legacy-patterns.md); затем строка «Отладка промпта на тестах»: [prompt-debugging.md](prompt-debugging.md). Условия колонки «Читать, если» не выполнены.

**Результат:** таблица находок (фильтрующие формулировки «only report high-severity issues» заменены блоком «Ревью кода без фильтрации»), исправленный промпт и таблица результатов двух версий на одном наборе задач.
