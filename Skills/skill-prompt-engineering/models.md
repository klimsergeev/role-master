# Текущие модели и текст промпта

## Назначение

Справочник поведения четырёх текущих моделей Claude, которое меняет сам текст промпта, со ссылкой на официальный гайд и на блок в [official-blocks.md](official-blocks.md). Параметры запроса к API (effort, режимы мышления, принудительный вызов инструментов, temperature, префилл) сюда не входят.

Значения сверены с официальными страницами 2026-11-09. Перед опорой на конкретное значение в важном решении открой гайд модели: страницы обновляются.

## Общее для всех четырёх моделей

- Просьба записать рассуждение в ответе может получить отказ категории `reasoning_extraction`. Гайды Fable 5.1, Opus 5.5 и Sonnet 5.5: вместо этого просить короткое объяснение ответа или сводку выполненных действий. Best practices перечисляет Fable 5.1, Fable 5, Opus 5.5, Opus 5 и Sonnet 5.5 как модели, где ручную цепочку рассуждений заменяет встроенное мышление.
- Новая строка в системный промпт — для новых разговоров. Гайд Haiku 5.5: «Add it to new conversations only» (добавляй только в новые разговоры); изменить инструкции посреди разговора — поместить их в новейший ход или добавить системное сообщение в разговор. Гайд Opus 5.5 для своей постоянной инструкции: добавлять в конец системного промпта с первого запроса сессии. Гайд Fable 5.1: изменения инструкций — системным сообщением посреди разговора, а не правкой системного промпта.
- Когда инструмент должен вызываться: страницы what's new Opus 5.5 и Sonnet 5.5 — «To make the model call a tool rather than reply in text, say in the prompt when the tool applies» (чтобы модель вызвала инструмент, а не ответила текстом, скажи в промпте, когда инструмент применяется). Миграция Fable 5.1: когда вызов обязателен, инструкцию ставить в пользовательский ход или в системное сообщение посреди разговора.

## Claude Fable 5.1

Источник раздела — гайд Fable 5.1 и страница what's new Fable 5.1 (https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1), раздел «Changed from Claude Fable 5».

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| Меньше сообщений пользователю между вызовами инструментов | Убрать строки вроде «hold all findings for the final response»; если нужны сообщения — сказать, когда и что в них писать | Прогресс-сообщения; Скрытый вывод команд |
| По одному вызову инструмента за ход в циклах кода и управления компьютером | Короткая подсказка после каждой партии результатов | Пакетные вызовы в агентном цикле |
| Местами более плотная проза: длинные предложения, мало абзацев | Определение витиеватой прозы как антипаттерна | Витиеватая проза |
| Меньше форматирования в чате | Убрать правила против форматирования или заменить правилом, когда форматирование уместно | Форматирование в чате |
| В сводках документов фрагменты источника без пометки цитаты | Один полный пример правильного ответа в системном промпте | Пример цитирования источников |
| Ход кончается до конца работы, вопросы разрешения на уже запрошенное | Два добавления к системному промпту | Автономная работа; Работа как результат |
| Сжатие разговора на стороне клиента теряет ограничения и детали | Явный перечень того, что сохранить | Резюме для компакции |
| Чинит соседний код, расширяет поведение, коммитит лишние тесты | Явно сказать, что оставить в стороне | Правки и тесты только по задаче |
| На низком уровне усилия отвечает по памяти вместо поиска | Узнать имя — не то же, что знать его текущее состояние | Поиск по незнакомым именам |
| Переписывает файл целиком ради мелкой правки | Минимизировать токены правки | Точечные правки файлов |
| На уровнях xhigh и max пишет длинный результат дважды | Заметка в конец пользовательского сообщения | Длинный результат на xhigh и max |

Ложные срабатывания защитных классификаторов (гайд Fable 5.1, раздел Reduce safeguard false positives) — три ситуации, в каждой меняется текст:

- Формулировка «скомпилируется ли»: вместо «Does this program compile without errors?» спрашивать «Are there any bugs in this program?».
- Малоизвестные языки программирования: дать модели контекст о языке, например доступ к его документации.
- Base64 в выводе инструментов: убрать инструменты, возвращающие base64 в контекст.

## Claude Opus 5.5

Источник раздела — гайд Opus 5.5 и страница what's new Opus 5.5 (https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5); строки с пометкой «из гайда Opus 5» — паттерны предшествующего гайда (https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5).

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| Агент без присмотра останавливается на отчёте о прогрессе | Назвать конкретные виды ранних остановок, которых не нужно, и остановки, которые нужны; добавить с первого запроса сессии; не для приложений с человеком по ходу | Постоянная инструкция о конце хода; Напоминание об открытых пунктах |
| Нужны сообщения о ходе работы в предсказуемых точках | Сказать в системном промпте (строка о намерении перед первым вызовом, короткая сводка в конце) | Ритм прогресс-сообщений; Напоминание после тишины |
| В задачах по нескольким приложениям пропускает сведения, на которые запрос не указывает | Одна фраза о широком сборе контекста до действий | Широкий сбор контекста в нескольких приложениях |
| Многоагентная система должна закончить быстрее | Строка о времени, если бюджет времени не предсказать | Время имеет значение |
| В чате ответ начинается медленно из-за долгого обдумывания | Убрать из системного промпта инструкции «думай тщательно перед ответом»; при перепроверке прежних ответов — две фразы в конец промпта | Не возвращаться к прежним ответам |
| Выполняет инструкции из вставленного пользователем текста | Пометить вставленный текст тегами с идентификатором и добавить заметку | Вставленный текст |
| Шаблонный фронтенд без указаний | Назвать конкретные паттерны, которых избегать, и дополнять перечень итерациями | Конкретные запреты стиля |
| Промпт писался под Opus 5 с выключенным мышлением | Убрать инструкции, заменявшие мышление записью рассуждения в ответе; убрать правило «не думай»; перепроверить смягчающий блок | Промпты под отключённое мышление |
| Точнее читает графики, схемы и скриншоты без инструментов | Перепроверить, нужны ли ещё обходные приёмы в промпте, сделанные для зрения прежних моделей | — |
| Длинные ответы пользователю (из гайда Opus 5) | Явная инструкция краткости; effort длину видимого ответа надёжно не меняет | Краткость ответа; Напоминание о краткости в длинном промпте |
| Длинные документы, записанные на диск (из гайда Opus 5) | Калибровка длины документов | Длина письменных документов |
| Избыточная проверка (из гайда Opus 5) | Удалить инструкции проверки: «include a final verification step for any non-trivial task», «use a subagent to verify», «double-check your answer», «re-verify before responding» | — |
| Расширяет объём задачи (из гайда Opus 5) | Явно ограничить объём узкой задачи | Сделать запрошенное в запрошенном объёме |
| Охотно делегирует субагентам (из гайда Opus 5) | Сказать, какие сценарии оправдывают делегирование | Делегирование только крупных задач |
| Объявляет поправки к своим словам (из гайда Opus 5) | Ограничить объявления поправками, которые что-то меняют | Исправления без лишних объявлений |
| Ревью кода по формулировке «only report high-severity issues» или «be conservative» сообщает меньше (из гайда Opus 5) | Просить сообщать всё и фильтровать отдельным проходом | Ревью кода без фильтрации |

## Claude Sonnet 5.5

Источник раздела — гайд Sonnet 5.5 и страница what's new Sonnet 5.5 (https://platform.claude.com/docs/en/models/sonnet-5-5/whats-new-sonnet-5-5); строки с пометкой «из гайда Sonnet 5» — паттерны предшествующего гайда (https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5).

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| На агентных задачах по коду спрашивает до конца работы | Инструкция доводить работу; правила о рискованных действиях остаются своими | Доводить работу и не добавлять лишнего |
| Добавляет незапрошенные тесты, документацию, вспомогательные файлы | Только второй абзац того же блока | Не добавлять лишнего (второй абзац) |
| На уровнях xhigh и max сама запускает раунды ревью | Направить тщательность на саму задачу | Остановка после проверок на xhigh и max |

| JSON-ответ на задачу в несколько шагов — без обдумывания | Строка в конец системного промпта (при адаптивном мышлении) | Продумать перед JSON-ответом |

| Тихие длинные ходы | Убрать «hold all findings for the final response»; при нужде — сказать в системном промпте, когда писать; напоминание харнесса редкое | Напоминание после тишины |
| Принимает настоящее сообщение пользователя посреди хода за инъекцию | Текст пользователя не класть в результат инструмента; отдавать его текстовым блоком пользовательского хода после последнего результата; уведомления харнесса — отдельным системным сообщением, не в одном блоке со словами пользователя; в интерактивных сессиях не добавлять свой отсчёт токенов после результатов инструментов | — |
| На низком уровне усилия сообщает о готовности без проверки | Абзац о реальной проверке | Реальная проверка изменений кода |
| Правила «не думай» в промпте | Убрать: с ними модель чаще выводит внутренние XML-теги в видимый ответ | — |
| Буквально следует инструкциям, не обобщает их сама (из гайда Sonnet 5) | Явно задавать охват: «Apply this formatting to every section, not just the first one» | — |
| Длина ответа подбирается под сложность задачи (из гайда Sonnet 5) | Инструкция краткости; положительные примеры нужной краткости работают лучше запретов | Краткость (Sonnet 5) |
| Каркас принудительных статусов «After every 3 tool calls, summarize progress» (из гайда Sonnet 5) | Попробовать убрать; если нужен — описать вид сообщений и дать примеры | — |
| Общие дизайнерские указания переводят на другую фиксированную палитру (из гайда Sonnet 5) | Конкретная спецификация или четыре направления на выбор | Четыре визуальных направления; Эстетика фронтенда (короткая) |
| Интерактивные продукты для кода (из гайда Sonnet 5) | Задача, намерение и ограничения — в первом ходе, а не по частям | — |
| Ревью кода (из гайда Sonnet 5) | Сообщать всё, фильтровать отдельно; порог в один проход — конкретный | Ревью кода без фильтрации; Порог для ревью в один проход |

Источник раздела — гайд Haiku 5.5 и страница what's new Haiku 5.5 (https://platform.claude.com/docs/en/models/haiku-5-5/whats-new-haiku-5-5).

## Расхождения между официальными источниками по моделям

Каждое расхождение показано обеими позициями; скилл не выбирает между ними.

1. Самопроверка.
   - Best practices, раздел Leverage thinking: «Ask Claude to self-check. Append something like "Before you finish, verify your answer against [test criteria]." This catches errors reliably, especially for coding and math» (попроси Claude проверить себя; это надёжно ловит ошибки, особенно в коде и математике).
   - Гайд Opus 5, раздел Task scope and over-verification: «Claude Opus 5 verifies its own work without being told to… remove them: instructions like these cause over-verification» (Opus 5 проверяет свою работу без указания; такие инструкции убрать, они вызывают избыточную проверку). Best practices сам называет Opus 5 исключением.
   - Гайд Fable 5, раздел Recommended scaffolding changes: «Make self-verification explicit in long-run prompts. Separate, fresh-context verifier subagents tend to outperform self-critique» (делай самопроверку явной в промптах длинных прогонов; отдельные субагенты-проверяющие с чистым контекстом обычно лучше самокритики).
   - Блок Гайда Opus 5 о делегировании: «do not use subagents to verify or double-check your own work» (не используй субагентов для проверки своей работы).
2. Многословие.
   - Best practices, раздел Communication style and verbosity: последние модели «Less verbose» (менее многословны).
   - Тот же раздел и Гайд Opus 5: ответы Opus 5 по умолчанию длиннее, чем у прежних Opus; Fable 5.1 — наоборот, пишет меньше сообщений между вызовами инструментов.
3. Форматирование.
   - Best practices даёт блок `avoid_excessive_markdown_and_bullet_points` как общий шаблон.
   - Тот же раздел и Гайд Fable 5.1: на Fable 5.1 такой блок может подавить нужную структуру, его убирают.
4. Снижение мышления текстом.
   - Best practices и Гайд Sonnet 5: «The triggering behavior for adaptive thinking is promptable» (срабатывание адаптивного мышления управляется промптом), блок «Thinking adds latency…».
   - Гайд Sonnet 5.5: «Asking the model in the system prompt to think less doesn't reliably reduce its thinking» (просьба думать меньше надёжно не снижает мышление). Гайд Haiku 5.5: «telling the model in the prompt to answer directly didn't stop it from thinking» (просьба отвечать сразу не остановила обдумывание).
5. Склонность к делегированию.
   - Best practices: у Opus 4.6 «a strong tendency to use subagents» (сильная склонность к субагентам). Гайд Opus 5: «delegates to subagents more readily than prior models» (делегирует охотнее прежних моделей). Гайд Fable 5: «dispatches parallel subagents more readily than prior models» (охотнее запускает параллельных субагентов). Инструкции о делегировании переносятся между версиями только с проверкой.
6. Дефолтный стиль фронтенда.
   - Best practices и блог Anthropic (https://claude.com/blog/improving-frontend-design-through-skills): шрифты Inter, фиолетовые градиенты на белом.
   - Гайд Opus 5.5: дефолтные стили иные, в примере запрета — кремовый фон, курсивные акценты, нумерация «01/02/03», моноширинные подписи, кнопки-таблетки. Общие указания меняют один дефолт на другой.
