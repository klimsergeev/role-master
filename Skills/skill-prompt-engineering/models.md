# Текущие модели и текст промпта

## Назначение

Справочник поведения четырёх текущих моделей Claude, которое меняет сам текст промпта, со ссылкой на блок в [official-blocks.md](official-blocks.md). Параметры запроса к API (effort, режимы мышления, принудительный вызов инструментов, temperature, префилл) сюда не входят.

Значения сверены 2026-11-09. Поведение моделей меняется с обновлениями; перед опорой на конкретное значение в важном решении перепроверь его.

## Текущие модели

Текущие модели: Claude Fable 5.1, Claude Opus 5.5, Claude Sonnet 5.5, Claude Haiku 5.5. Fable 5, Opus 5, Opus 4.8, Opus 4.7, Opus 4.6, Opus 4.5, Sonnet 5, Sonnet 4.6, Haiku 4.5 отнесены к категории legacy: устаревшие, но ещё доступные.

| Модель | ID в Claude API | Промпты предыдущей версии |
|---|---|---|
| Claude Fable 5.1 | `claude-fable-5-1` | Промпты для Fable 5 должны хорошо работать на Fable 5.1 без изменений |
| Claude Opus 5.5 | `claude-opus-5-5` | Промпты для Opus 5 должны хорошо работать без изменений, а паттерны Opus 5 остаются разумной отправной точкой |
| Claude Sonnet 5.5 | `claude-sonnet-5-5` | Промпты для Sonnet 5 должны хорошо работать без изменений, а паттерны Sonnet 5 остаются разумной отправной точкой |
| Claude Haiku 5.5 | `claude-haiku-5-5` | Промпты для Haiku 4.5 должны хорошо работать без изменений |

Порядок чтения: сначала раздел своей модели в этом файле, затем общие техники в [principles.md](principles.md).

## Общее для всех четырёх моделей

- Просьба записать рассуждение в ответе может получить отказ категории `reasoning_extraction`. Для Fable 5.1, Opus 5.5 и Sonnet 5.5 вместо этого просить короткое объяснение ответа или сводку выполненных действий. На Fable 5.1, Fable 5, Opus 5.5, Opus 5 и Sonnet 5.5 ручную цепочку рассуждений заменяет встроенное мышление.
- Новая строка в системный промпт — для новых разговоров. Haiku 5.5: новую строку добавлять только в новые разговоры; изменить инструкции посреди разговора — поместить их в новейший ход или добавить системное сообщение в разговор. Opus 5.5, для своей постоянной инструкции: добавлять в конец системного промпта с первого запроса сессии. Fable 5.1: изменения инструкций — системным сообщением посреди разговора, а не правкой системного промпта.
- Когда инструмент должен вызываться: на Opus 5.5 и Sonnet 5.5, чтобы модель вызвала инструмент, а не ответила текстом, в промпте говорится, когда инструмент применяется. На Fable 5.1, когда вызов обязателен, инструкцию ставить в пользовательский ход или в системное сообщение посреди разговора.

## Claude Fable 5.1

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| Меньше сообщений пользователю между вызовами инструментов | Убрать строки вроде «hold all findings for the final response»; если нужны сообщения — сказать, когда и что в них писать | Прогресс-сообщения; Скрытый вывод команд |
| По одному вызову инструмента за ход в циклах кода и управления компьютером | Короткая подсказка после каждой партии результатов | Пакетные вызовы в агентном цикле |
| Местами более плотная проза: длинные предложения, мало абзацев | Определение витиеватой прозы как антипаттерна | Витиеватая проза |
| Меньше форматирования в чате | Убрать правила против форматирования или заменить правилом, когда форматирование уместно | Форматирование в чате |
| В сводках документов фрагменты источника без пометки цитаты | Один полный пример правильного ответа в системном промпте | Пример цитирования источников |
| Ход кончается до конца работы, вопросы разрешения на уже запрошенное | Два добавления к системному промпту | Автономная работа; Работа как результат |
| Сжатие разговора на стороне клиента теряет ограничения и детали | Явный перечень того, что сохранить | Резюме для компакции |
| Чинит соседний код, расширяет поведение, коммитит лишние тесты | Явно сказать, что оставить в стороне | Правки и тесты только по задаче |
| На низком уровне усилия отвечает по памяти вместо поиска | Узнать имя — не то же, что знать его текущее состояние | Поиск по незнакомым именам |
| Переписывает файл целиком ради мелкой правки | Минимизировать токены правки | Точечные правки файлов |
| На уровнях xhigh и max пишет длинный результат дважды | Заметка в конец пользовательского сообщения | Длинный результат на xhigh и max |

Ложные срабатывания защитных классификаторов — три ситуации, в каждой меняется текст:

- Формулировка «скомпилируется ли»: вместо «Does this program compile without errors?» спрашивать «Are there any bugs in this program?».
- Малоизвестные языки программирования: дать модели контекст о языке, например доступ к его документации.
- Base64 в выводе инструментов: убрать инструменты, возвращающие base64 в контекст.

## Claude Opus 5.5

Строки с пометкой «паттерн Opus 5» измерены на Opus 5 и для Opus 5.5 служат отправной точкой.

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| Агент без присмотра останавливается на отчёте о прогрессе | Назвать конкретные виды ранних остановок, которых не нужно, и остановки, которые нужны; добавить с первого запроса сессии; не для приложений с человеком по ходу | Постоянная инструкция о конце хода; Напоминание об открытых пунктах |
| Нужны сообщения о ходе работы в предсказуемых точках | Сказать в системном промпте (строка о намерении перед первым вызовом, короткая сводка в конце) | Ритм прогресс-сообщений; Напоминание после тишины |
| В задачах по нескольким приложениям пропускает сведения, на которые запрос не указывает | Одна фраза о широком сборе контекста до действий | Широкий сбор контекста в нескольких приложениях |
| Многоагентная система должна закончить быстрее | Строка о времени, если бюджет времени не предсказать | Время имеет значение |
| В чате ответ начинается медленно из-за долгого обдумывания | Убрать из системного промпта инструкции «думай тщательно перед ответом»; при перепроверке прежних ответов — две фразы в конец промпта | Не возвращаться к прежним ответам |
| Выполняет инструкции из вставленного пользователем текста | Пометить вставленный текст тегами с идентификатором и добавить заметку | Вставленный текст |
| Шаблонный фронтенд без указаний | Назвать конкретные паттерны, которых избегать, и дополнять перечень итерациями | Конкретные запреты стиля |
| Промпт писался под Opus 5 с выключенным мышлением | Убрать инструкции, заменявшие мышление записью рассуждения в ответе; убрать правило «не думай»; перепроверить смягчающий блок | Промпты под отключённое мышление |
| Точнее читает графики, схемы и скриншоты без инструментов | Перепроверить, нужны ли ещё обходные приёмы в промпте, сделанные для зрения прежних моделей | — |
| Длинные ответы пользователю (паттерн Opus 5) | Явная инструкция краткости; effort длину видимого ответа надёжно не меняет | Краткость ответа; Напоминание о краткости в длинном промпте |
| Длинные документы, записанные на диск (паттерн Opus 5) | Калибровка длины документов | Длина письменных документов |
| Избыточная проверка (паттерн Opus 5) | Удалить инструкции проверки: «include a final verification step for any non-trivial task», «use a subagent to verify», «double-check your answer», «re-verify before responding» | — |
| Расширяет объём задачи (паттерн Opus 5) | Явно ограничить объём узкой задачи | Сделать запрошенное в запрошенном объёме |
| Охотно делегирует субагентам (паттерн Opus 5) | Сказать, какие сценарии оправдывают делегирование | Делегирование только крупных задач |
| Объявляет поправки к своим словам (паттерн Opus 5) | Ограничить объявления поправками, которые что-то меняют | Исправления без лишних объявлений |
| Ревью кода по формулировке «only report high-severity issues» или «be conservative» сообщает меньше (паттерн Opus 5) | Просить сообщать всё и фильтровать отдельным проходом | Ревью кода без фильтрации |

## Claude Sonnet 5.5

Строки с пометкой «паттерн Sonnet 5» измерены на Sonnet 5 и для Sonnet 5.5 служат отправной точкой.

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| На агентных задачах по коду спрашивает до конца работы | Инструкция доводить работу; правила о рискованных действиях остаются своими | Доводить работу и не добавлять лишнего |
| Добавляет незапрошенные тесты, документацию, вспомогательные файлы | Только второй абзац того же блока | Не добавлять лишнего (второй абзац) |
| На уровнях xhigh и max сама запускает раунды ревью | Направить тщательность на саму задачу | Остановка после проверок на xhigh и max |
| На открытый запрос начинает строить результат вместо идей | Сказать в запросе или системном промпте, что нужны идеи или план | Идеи и план без сборки |
| JSON-ответ на задачу в несколько шагов — без обдумывания | Строка в конец системного промпта (при адаптивном мышлении) | Продумать перед JSON-ответом |
| Отвечает из знаний обучения там, где поиск нашёл бы изменения | Убрать «only use tools when strictly necessary», «minimize tool calls»; добавить инструкцию поиска | Поиск в чате и исследованиях |
| Тихие длинные ходы | Убрать «hold all findings for the final response»; при нужде — сказать в системном промпте, когда писать; напоминание харнесса редкое | Напоминание после тишины |
| Принимает настоящее сообщение пользователя посреди хода за инъекцию | Текст пользователя не класть в результат инструмента; отдавать его текстовым блоком пользовательского хода после последнего результата; уведомления харнесса — отдельным системным сообщением, не в одном блоке со словами пользователя; в интерактивных сессиях не добавлять свой отсчёт токенов после результатов инструментов | — |
| На низком уровне усилия сообщает о готовности без проверки | Абзац о реальной проверке | Реальная проверка изменений кода |
| Правила «не думай» в промпте | Убрать: с ними модель чаще выводит внутренние XML-теги в видимый ответ | — |
| Буквально следует инструкциям, не обобщает их сама (паттерн Sonnet 5) | Явно задавать охват: «Apply this formatting to every section, not just the first one» | — |
| Длина ответа подбирается под сложность задачи (паттерн Sonnet 5) | Инструкция краткости; положительные примеры нужной краткости работают лучше запретов | Краткость (Sonnet 5) |
| Каркас принудительных статусов «After every 3 tool calls, summarize progress» (паттерн Sonnet 5) | Попробовать убрать; если нужен — описать вид сообщений и дать примеры | — |
| Общие дизайнерские указания переводят на другую фиксированную палитру (паттерн Sonnet 5) | Конкретная спецификация или четыре направления на выбор | Четыре визуальных направления; Эстетика фронтенда (короткая) |
| Интерактивные продукты для кода (паттерн Sonnet 5) | Задача, намерение и ограничения — в первом ходе, а не по частям | — |
| Ревью кода (паттерн Sonnet 5) | Сообщать всё, фильтровать отдельно; порог в один проход — конкретный | Ревью кода без фильтрации; Порог для ревью в один проход |

## Claude Haiku 5.5

| Поведение | Что делать в тексте | Блок |
|---|---|---|
| С инструментом поиска опирается на старые знания | Дать сегодняшнюю дату; при длинном системном промпте — подсказку искать после даты. Не ставить общих инструкций вроде «search for any present-day factual question, regardless of how confident you are»: в тестах модель искала в половине промптов, где поиск не нужен, без прироста верных ответов | Дата и поиск |
| При выключенном мышлении и JSON-ответе пропускает нужный вызов инструмента | Строка о порядке: сначала инструмент, потом JSON | JSON-ответ и инструменты |
| С длинным системным промптом кодового агента останавливается раньше | Инструкция доводить работу | Доводить работу и не добавлять лишнего (вариант для Haiku 5.5) |
| Сообщает о готовности кода без проверки | Абзац о реальной проверке | Реальная проверка изменений кода |
| Игнорирует сообщения пользователя посреди хода | Те же правила размещения, что у Sonnet 5.5: не в результате инструмента, отдельным текстовым блоком после последнего результата, уведомления отдельно | — |
| Чат-бот отступает от системного промпта под давлением пользователя | Строка о правилах на весь разговор, вместе с прочими защитами от инъекций | Правила системного промпта на весь разговор |
| Просьба в промпте отвечать сразу | В тестах не остановила обдумывание | — |
| Метки context awareness не вставляются | Блок «Автокомпакция контекста» не опирается здесь на встроенный счётчик контекста | — |

## Расхождения по моделям

Каждое расхождение показано всеми позициями; скилл не выбирает между ними.

1. Самопроверка. Источники расходятся:
   - Одна позиция — просить Claude проверить себя, дописав в промпт строку вроде `Before you finish, verify your answer against [test criteria].`; так ошибки ловятся надёжно, особенно в коде и математике. Opus 5 из этого правила исключён.
   - Другая — Opus 5 проверяет свою работу без указаний, поэтому такие инструкции убирают: они вызывают избыточную проверку.
   - Третья — для Fable 5 в промптах длинных прогонов делать самопроверку явной; отдельные субагенты-проверяющие с чистым контекстом обычно справляются лучше самокритики.
   - Четвёртая — блок о делегировании для Opus 5 («Делегирование только крупных задач» в [official-blocks.md](official-blocks.md)) запрещает использовать субагентов для проверки собственной работы.
2. Многословие. Источники расходятся:
   - Одна позиция — последние модели менее многословны.
   - Другая — ответы Opus 5 по умолчанию длиннее, чем у прежних Opus; Fable 5.1, наоборот, пишет меньше сообщений между вызовами инструментов.
3. Форматирование. Источники расходятся:
   - Одна позиция — блок `avoid_excessive_markdown_and_bullet_points` как общий шаблон.
   - Другая — на Fable 5.1 такой блок может подавить нужную структуру, его убирают.
4. Снижение мышления текстом. Источники расходятся:
   - Одна позиция — срабатывание адаптивного мышления управляется промптом (относится и к Sonnet 5); блок «Ограничение мышления» в [official-blocks.md](official-blocks.md).
   - Другая — на Sonnet 5.5 просьба в системном промпте думать меньше надёжно не снижает мышление; на Haiku 5.5 просьба в промпте отвечать сразу не остановила обдумывание.
5. Склонность к делегированию. Источники расходятся по версиям:
   - Одна позиция — у Opus 4.6 сильная склонность к субагентам.
   - Другая — Opus 5 делегирует субагентам охотнее прежних моделей; Fable 5 охотнее прежних моделей запускает параллельных субагентов.
   - Инструкции о делегировании переносятся между версиями только с проверкой.
6. Дефолтный стиль фронтенда. Источники расходятся:
   - Одна позиция — дефолт: шрифты Inter, фиолетовые градиенты на белом.
   - Другая — у Opus 5.5 дефолтные стили иные, в примере запрета — кремовый фон, курсивные акценты, нумерация «01/02/03», моноширинные подписи, кнопки-таблетки. Общие указания меняют один дефолт на другой.
