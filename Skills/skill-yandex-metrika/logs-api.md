# Logs API

## Назначение

Справочник по Logs API Яндекс Метрики — методы, параметры, жизненный цикл запроса и ограничения. Logs API отдаёт неагрегированные («сырые») данные — по одной строке на визит (`source=visits`) или на просмотр/событие (`source=hits`). Формат ответа — TSV.

## Базовый URL

```
https://api-metrika.yandex.net/management/v1/counter/{counterId}
```

## Методы

### 1. Оценка возможности создания запроса — evaluate

| Параметр | Значение |
|----------|----------|
| **Метод** | GET |
| **URL** | `/logrequests/evaluate` |

**Query-параметры:**

| Параметр | Тип | Обязателен | Описание |
|----------|-----|------------|----------|
| `date1` | string | да | Первый день периода, формат `YYYY-MM-DD` |
| `date2` | string | да | Последний день периода, формат `YYYY-MM-DD` |
| `fields` | string | да | Список полей через запятую |
| `source` | string | да | `hits` или `visits` |

**Ответ (200):**

```json
{
  "log_request_evaluation": {
    "possible": true,
    "max_possible_day_quantity": 60
  }
}
```

- `possible` — возможность создания запроса за указанный период
- `max_possible_day_quantity` — максимальное количество дней в рамках текущей квоты

### 2. Создание запроса логов — createLogRequest

| Параметр | Значение |
|----------|----------|
| **Метод** | POST |
| **URL** | `/logrequests` |

**Query-параметры:**

| Параметр | Тип | Обязателен | Описание |
|----------|-----|------------|----------|
| `date1` | string | да | Первый день, `YYYY-MM-DD` |
| `date2` | string | да | Последний день (**не может быть текущим днём**), `YYYY-MM-DD` |
| `fields` | string | да | Список полей через запятую (без пробелов) |
| `source` | string | да | `hits` или `visits` |
| `attribution` | string | нет | Модель атрибуции (см. ниже) |

**Модели атрибуции (параметр `attribution`):**
- `FIRST` — первое взаимодействие
- `LAST` — последнее взаимодействие
- `LASTSIGN` — последнее значимое взаимодействие
- `LAST_YANDEX_DIRECT_CLICK` — последний клик Директа
- `CROSS_DEVICE_LAST_SIGNIFICANT` — кросс-девайс последнее значимое
- `CROSS_DEVICE_FIRST` — кросс-девайс первое
- `CROSS_DEVICE_LAST_YANDEX_DIRECT_CLICK` — кросс-девайс последний клик Директа
- `CROSS_DEVICE_LAST` — кросс-девайс последнее
- `AUTOMATIC` — автоматическая

**Ответ (200):** объект `log_request` (структуру см. ниже).

**Важно:** Logs API не поддерживает фильтрацию на уровне запроса — фильтровать данные нужно после скачивания.

### 3. Список запросов логов — getLogRequests

| Параметр | Значение |
|----------|----------|
| **Метод** | GET |
| **URL** | `/logrequests` |

**Ответ (200):** массив объектов `log_request` в поле `requests`.

### 4. Информация о запросе — getLogRequest

| Параметр | Значение |
|----------|----------|
| **Метод** | GET |
| **URL** | `/logrequest/{requestId}` |

**Path-параметры:**
- `requestId` (integer) — идентификатор запроса логов

**Ответ (200):** объект `log_request`.

### 5. Загрузка части логов — download

| Параметр | Значение |
|----------|----------|
| **Метод** | GET |
| **URL** | `/logrequest/{requestId}/part/{partNumber}/download` |

**Path-параметры:**
- `requestId` (integer) — идентификатор запроса
- `partNumber` (integer) — номер части (нумерация с 0)

**Ответ (200):** бинарные данные (TSV). Первая строка — заголовки полей.

### 6. Очистка подготовленных логов — clean

| Параметр | Значение |
|----------|----------|
| **Метод** | POST |
| **URL** | `/logrequest/{requestId}/clean` |

**Path-параметры:**
- `requestId` (integer) — идентификатор запроса

**Ответ (200):** объект `log_request` с обновлённым статусом.

### 7. Отмена необработанного запроса — cancel

| Параметр | Значение |
|----------|----------|
| **Метод** | POST |
| **URL** | `/logrequest/{requestId}/cancel` |

**Path-параметры:**
- `requestId` (integer) — идентификатор запроса

**Ответ (200):** объект `log_request` с обновлённым статусом.

## Сводная таблица методов

| Действие | Метод | Путь (после `/counter/{counterId}`) |
|----------|-------|--------------------------------------|
| Оценить возможность | GET | `/logrequests/evaluate` |
| Создать запрос | POST | `/logrequests` |
| Список запросов | GET | `/logrequests` |
| Информация о запросе | GET | `/logrequest/{requestId}` |
| Скачать часть | GET | `/logrequest/{requestId}/part/{partNumber}/download` |
| Очистить лог | POST | `/logrequest/{requestId}/clean` |
| Отменить запрос | POST | `/logrequest/{requestId}/cancel` |

## Структура объекта LogRequest

```json
{
  "log_request": {
    "request_id": 12345,
    "counter_id": 44147844,
    "source": ["visits"],
    "date1": "2026-04-01",
    "date2": "2026-04-30",
    "fields": ["ym:s:visitID", "ym:s:dateTime"],
    "status": "processed",
    "size": 1048576,
    "parts": [
      {"part_number": 0, "size": 524288},
      {"part_number": 1, "size": 524288}
    ],
    "attribution": "LASTSIGN"
  }
}
```

## Статусы запроса

| Статус | Описание |
|--------|----------|
| `created` | Запрос принят, лог готовится |
| `processed` | Лог готов к скачиванию |
| `canceled` | Запрос отменён |
| `cleaned_by_user` | Лог очищен пользователем |
| `cleaned_automatically_as_too_old` | Лог очищен автоматически (устарел) |
| `processing_failed` | Ошибка обработки |
| `awaiting_retry` | Ожидает повторной обработки |

## Ограничения

- `date2` не может быть текущим днём — максимум вчерашний
- Нельзя смешивать поля `ym:s:` (visits) и `ym:pv:` (hits) в одном запросе
- Поля перечисляются через запятую без пробелов
- Фильтрация на уровне запроса не поддерживается
- После скачивания необходимо вызвать `clean` для освобождения квоты
- Максимальный объём ограничен квотой счётчика (проверять через `evaluate`)

## Жизненный цикл

```
evaluate -> create -> poll status -> download parts -> clean
```
