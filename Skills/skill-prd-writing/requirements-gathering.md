# Сбор требований

## Назначение

Процедура интерактивного сбора требований для PRD: анализ входных данных, категории вопросов, правила опроса, формат JTBD/Job Stories для discovery.

## Анализ входных данных

1. Прочитать документ/описание от пользователя
2. Определить, что уже известно:
   - Целевая аудитория (кто, контекст, устройства)
   - Проблема (какую боль закрываем)
   - Бизнес-цели (зачем, метрики успеха)
   - Функциональность (что должно работать)
3. Составить список пробелов -- что нужно уточнить

## Категории вопросов

### О целевой аудитории

- Кто будет использовать? (роль, опыт, контекст)
- Какую задачу пользователь решает?
- В каком контексте использование? (устройство, окружение, частота)

**Примеры формулировок:**
- "Это новые пользователи или опытные?"
- "Мобильное устройство или десктоп?"
- "Как часто -- раз в день или раз в месяц?"

### О бизнес-целях

- Какую проблему решаем этой функциональностью?
- Как поймем, что она успешна? (метрики, качественные показатели)
- Есть ли связь с другими функциями или системами?

**Примеры формулировок:**
- "Зачем пользователю это нужно? Какую боль закрываем?"
- "Как измерим успех -- рост конверсии, снижение нагрузки на поддержку?"
- "Эта функция работает отдельно или связана с [другой]?"

### О функциональности

- Какие основные сценарии использования?
- Есть ли ограничения или зависимости?

### Чего НЕ спрашивать

- Приоритеты и дедлайны (зона продакт-менеджера)
- Детали дизайна интерфейса (зона дизайнера)
- Технические детали реализации (зона разработчиков)

## JTBD / Job Stories для discovery

Когда пользователь не может чётко сформулировать задачу, используй Job Stories для выявления потребности:

**Формат:**
```
Когда [ситуация/контекст],
Я хочу [мотивация/действие],
Чтобы [ожидаемый результат].
```

**Пример:**
```
Когда я добавил товары в избранное и жду скидок,
Я хочу автоматически узнавать о снижении цены,
Чтобы не проверять каждый товар вручную и не упустить выгодное предложение.
```

**Когда применять:**
- Пользователь описывает проблему, а не решение
- Неясно, какой результат ожидается
- Нужно выявить скрытую мотивацию

**Как использовать:** Сформулируй Job Story на основе ответов пользователя и предложи для подтверждения. Это помогает синхронизировать видение задачи.

## Правила опроса

### Приоритет 1 -- Интерактивный опрос (AskUserQuestion)

- Задавай вопросы по одному
- Жди ответа перед следующим вопросом
- Адаптируй вопросы на основе ответов

### Приоритет 2 -- Передача оркестратору (субагент)

Верни результат с секцией:
```
## Вопросы для пользователя
1. [Вопрос 1]
2. [Вопрос 2]
```
Попроси оркестратора задать их через AskUserQuestion.

### Приоритет 3 -- Пакетный опрос (оба недоступны)

- Нумерованный список, один вопрос на пункт
- Без подпунктов и двойных вопросов
- Формат: "Ответь цифрами (1. ..., 2. ..., и т.д.):"

## Правила обработки ответов

- ЕСЛИ пользователь не может ответить на вопрос -> зафиксировать как "Открытый вопрос" в PRD
- ЕСЛИ информация противоречива -> указать противоречие, попросить уточнить
- ЕСЛИ достаточно информации для PRD -> перейти к шагу 3 (проработка сценариев)
