# Сценарии и состояния

## Назначение

Процедура проработки User Stories, Acceptance Criteria, типов сценариев и состояний UI для PRD.

## User Stories

### Формат

```
Как [роль пользователя]
Я хочу [действие]
Чтобы [цель/результат]
```

### Правила

- Одна User Story = одна пользовательская цель
- Нумерация: US-1, US-2, US-3...
- Каждая US имеет Acceptance Criteria

## Acceptance Criteria

### Формат 1: Чеклист (по умолчанию)

```
**Acceptance Criteria:**
- [ ] Критерий 1
- [ ] Критерий 2
- [ ] Критерий 3
```

Когда использовать: большинство случаев, простые проверки.

### Формат 2: Given/When/Then (GWT)

```
Дано: [начальное состояние или контекст]
Когда: [действие пользователя или событие]
Тогда: [ожидаемый результат]
```

Когда использовать:
- Сложные сценарии с несколькими условиями
- Автоматизируемые acceptance criteria
- Команда использует BDD-подход

**Пример GWT:**
```
Дано: пользователь авторизован и находится на странице товара
Когда: нажимает кнопку "В корзину"
Тогда: товар добавляется в корзину, показывается уведомление, счётчик увеличивается на 1

Дано: пользователь не авторизован
Когда: нажимает кнопку "В корзину"
Тогда: открывается окно авторизации с сообщением "Войдите, чтобы добавить товар"
```

### Выбор формата

- ЕСЛИ команда не просит конкретный формат -> чеклист
- ЕСЛИ команда использует BDD -> Given/When/Then
- ЕСЛИ сценарий сложный -> можно комбинировать (чеклист + GWT для ключевых сценариев)

## Типы сценариев

### Happy Path (основной сценарий)

Идеальный путь пользователя без ошибок и препятствий. Всегда прорабатывается первым.

### Alternative Paths (альтернативные сценарии)

Разные способы достижения той же цели. Примеры:
- Авторизация через email / через соцсеть / через телефон
- Поиск товара через каталог / через строку поиска / через QR-код

### Edge Cases (граничные случаи)

Минимальные/максимальные значения, пограничные условия, необычные но возможные ситуации. Примеры:
- Имя из 1 символа или из 255 символов
- 0 товаров в корзине / 999 товаров
- Одновременное действие с двух устройств

### Error Cases (сценарии ошибок)

Что происходит при ошибках, как система восстанавливается, что видит пользователь. Примеры:
- Нет подключения к сети
- Сервер вернул ошибку 500
- Истёк токен авторизации

## Состояния UI

| Состояние | Что описать | Пример |
|---|---|---|
| **Пустое** | Первый запуск, нет данных, очищен контент | "У вас пока нет заказов" + CTA |
| **Загрузка** | Индикатор, скелетон, прогресс | Скелетон карточек товаров |
| **Ошибка** | Сообщение, действия пользователя, повтор | "Не удалось загрузить. Попробовать снова" |
| **Недоступность** | Офлайн, тех. работы, нет прав | "Нет доступа. Обратитесь к администратору" |
| **Успех** | Подтверждение действия, следующий шаг | "Заказ оформлен! Отследить доставку" |

### Правила проработки состояний

- ЕСЛИ не описаны пустые состояния -> проработать для всех интерфейсов
- ЕСЛИ пустое состояние -> всегда предлагать действие (CTA), а не только текст
- ЕСЛИ ошибка -> описать и путь восстановления (повтор, альтернатива, обращение в поддержку)
- ЕСЛИ несколько ролей -> проработать состояния для каждой роли отдельно

## Пример проработки сценариев

**Функциональность:** Добавление товара в корзину

**US-1:** Как покупатель, я хочу добавить товар в корзину, чтобы оформить заказ позже.

| Тип | Сценарий |
|---|---|
| Happy Path | Нажал "В корзину" -> товар добавлен, показан счётчик |
| Alternative | Добавление из списка избранного / из сравнения |
| Edge Case | Товар закончился между открытием страницы и нажатием кнопки |
| Error | Сервер недоступен -- показать "Попробуйте позже", сохранить намерение |
