# Заведение доступа: от нуля до первого вызова

## Назначение

Полная последовательность получения доступа к Wordstat API — организация и облако, платёжный аккаунт, сервисный аккаунт с ролью, API-ключ или IAM-токен, идентификатор каталога, проверочный вызов и формат `.env`.

## Хост и точки входа

```
REST:  https://searchapi.api.cloud.yandex.net
gRPC:  searchapi.api.cloud.yandex.net:443
       сервис yandex.cloud.searchapi.v2.WordstatService
```

Адрес подтверждён публичным реестром эндпоинтов `https://api.cloud.yandex.net/endpoints` (отдаётся без аутентификации, 117 записей): `{"id": "searchapi", "address": "searchapi.api.cloud.yandex.net:443"}`.

Документация: `https://aistudio.yandex.ru/docs/ru/search-api/`. Старый адрес `yandex.cloud/ru/docs/search-api/` отдаёт `301` на `https://aistudio.yandex.ru/docs/ru/` (проверено 25.08.2026).

**Документация AI Studio закрыта SmartCaptcha.** `curl` и обычный fetch по `aistudio.yandex.ru/docs/…` с любым User-Agent приезжают на `/tmgrdfrend/showcaptcha?…` со страницей «Вы не робот?» (перепроверено 25.08.2026); `llms.txt` и `llms-full.txt` у неё отсутствуют (404); актуальных снапшотов в веб-архиве нет. Читать её можно только браузером в пользовательской сессии. Именно поэтому скилл несёт содержание документации, а не ссылки на неё.

**Но капча накрывает не весь `yandex.cloud/ru/docs`.** Смежные разделы платформы читаются обычным `curl` без всякой сессии: `https://yandex.cloud/ru/docs/iam/operations/iam-token/create` и `https://yandex.cloud/ru/docs/resource-manager/operations/folder/get-id` отдали `HTTP 200` и полный HTML со всем текстом (проверено 25.08.2026). Закрыт контур AI Studio, включая всю документацию Search API; разделы IAM и Resource Manager открыты. Различие практическое: процедуры получения IAM-токена и идентификатора каталога агент при необходимости может перечитать в первоисточнике, а страницы Wordstat — нет.

## Полная последовательность заведения доступа

### Шаг 1. Организация и облако

Войти в AI Studio под аккаунтом Яндекс ID. Создать организацию: ввести название, указать название облака. Нажать «Открыть AI Studio». В организации автоматически создаётся каталог с именем `default`.

Ресурсная модель: «AI Studio использует ресурсную модель Yandex Cloud: большинство сервисов хранит ресурсы в каталогах. Каталоги принадлежат облакам, а облака — организациям.»

### Шаг 2. Платёжный аккаунт

«Для работы с AI Studio необходим активный платежный аккаунт, привязанный к вашему облаку. При создании первого платежного аккаунта с привязанной к нему банковской картой вам будет начислен стартовый грант.»

Кнопка «Привязать платежный аккаунт» в правом верхнем углу → создать или выбрать → «Добавить карту» → номер, срок, CVV → «Привязать». Убедиться, что статус аккаунта `ACTIVE` или `TRIAL_ACTIVE`.

### Шаг 3. API-ключ

«Создать API-ключ» в правом верхнем углу интерфейса AI Studio → описание (опционально) → срок действия → «Создать» → сохранить идентификатор и секретный ключ.

Дословное предупреждение документации: «Не передавайте никому свой API-ключ. **После закрытия диалога значение ключа будет недоступно.**»

Требование к правам создающего: «Для создания API-ключа пользователю необходима роль `resource-manager.admin` на каталог, в котором создается API-ключ.»

### Шаг 4. Что создаётся вместе с ключом

«Сервис автоматически создаст сервисный аккаунт с минимально необходимыми ролями и API-ключ для него с областью действия для работы со всеми компонентами и сервисами AI Studio.»

Роли автоматически созданного сервисного аккаунта:

| Роль | Что даёт |
|---|---|
| `ai.editor` | Доступ к Yandex Translate, Yandex Vision OCR, Yandex SpeechKit и Yandex AI Studio |
| `serverless.mcpGateways.invoker` | Доступ к MCP-серверам, в том числе через MCP Hub |
| `serverless.mcpGateways.anonymousInvoker` | Доступ к внешним MCP-серверам |
| `serverless.workflows.executor` | Доступ к выполнению рабочих процессов Yandex Workflows |
| **`search-api.webSearch.user`** | **Доступ к Yandex Search API с использованием API v2 — то, что нужно для Wordstat** |

Областей действия у автоматически созданного ключа десять; к делу относится `yc.search-api.execute` («Доступ к Yandex Search API»). Остальные девять: `yc.ai.imageGeneration.execute`, `yc.ai.languageModels.execute`, `yc.ai.speechkitStt.execute`, `yc.ai.speechkitTts.execute`, `yc.ai.translate.execute`, `yc.ai.vision.execute`, `yc.serverless.mcpGateways.invoke`, `yc.serverless.containers.invoke`, `yc.serverless.functions.invoke`.

### Шаг 5. Минимальный вариант вручную

Если ключ AI Studio не подходит (нужен принцип минимальных привилегий), пошаговые инструкции по Wordstat предписывают: «создайте сервисный аккаунт с ролью `search-api.webSearch.user` и получите для него API-ключ с областью действия `yc.search-api.execute`. Также вы можете использовать IAM-токен как более безопасный способ.» (Формулировка перечитана на странице `operations/wordstat-getdynamics` 25.08.2026 — стоит там дословно.)

Где это делается: интерфейс AI Studio → **Доступ** → вкладка **API-ключи** (создание ключа существующему сервисному аккаунту) и вкладка **Права доступа** → **Изменить роли**.

### Шаг 6. Записать идентификатор каталога

Понадобится в теле запросов — когда именно обязателен, см. следующий раздел. Четыре способа получить значение, все со страницы «Получение идентификатора каталога» (`https://yandex.cloud/ru/docs/resource-manager/operations/folder/get-id`, статья обновлена 26.05.2026, страница открыта `curl` 25.08.2026, HTTP 200):

| Способ | Что делать |
|---|---|
| Дашборд консоли | В консоли управления на панели сверху выбрать каталог. Идентификатор указан сверху, под именем каталога |
| Вкладка «Информация о каталоге» | Справа от названия каталога открыть «Информация о каталоге» → поле «Идентификатор каталога» |
| URL консоли | `https://console.yandex.cloud/folders/<идентификатор_каталога>` |
| CLI | `yc resource-manager folder get <имя_каталога>` — если имя известно; `yc resource-manager folder list` — если нет: список каталогов облака по умолчанию с колонкой `ID` |

### Чего в процедуре нет

Модерации, заявки и чьего-либо одобрения. Последовательность выполняется самостоятельно. Единственный случай обращения в поддержку — увеличение квот ([limits-quotas-pricing.md](limits-quotas-pricing.md)).

## Два способа аутентификации и когда обязателен `folderId`

**Аккаунт на Яндексе или федеративный аккаунт:**

- IAM-токен в заголовке: `Authorization: Bearer <IAM-токен>`
- Роль `search-api.webSearch.user` на каталог
- «Идентификатор каталога **должен** передаваться в теле каждого запроса в поле `folderId` (`folder_id`).»

**Сервисный аккаунт:**

- Либо IAM-токен: `Authorization: Bearer <IAM-токен>`, либо API-ключ: `Authorization: Api-Key <API-ключ>`
- Роль `search-api.webSearch.user` на каталог, в котором аккаунт создан
- «При этом идентификатор каталога **можно не передавать**, Yandex Search API будет работать в каталоге сервисного аккаунта.»

Сводка:

| Кто вызывает | Заголовок | `folderId` в теле |
|---|---|---|
| Пользовательский или федеративный аккаунт | `Authorization: Bearer <IAM-токен>` | обязателен |
| Сервисный аккаунт, свой каталог | `Authorization: Api-Key <ключ>` или `Bearer <IAM-токен>` | не обязателен |
| Сервисный аккаунт, другой каталог | то же | передавать |

### Как получить IAM-токен

Источник — страница «Как получить IAM-токен для аккаунта» (`https://yandex.cloud/ru/docs/iam/operations/iam-token/create`, открыта `curl` 25.08.2026, HTTP 200):

- IAM-токен для аккаунта на Яндексе выдаёт YC CLI. Предварительно CLI нужно установить, инициализировать и аутентифицироваться в нём от имени пользователя.
- Команда: `yc iam create-token`. Результат вида `t1.9euelZrLop7Uz8up********` и есть токен.
- Записать в переменную: `export IAM_TOKEN=$(yc iam create-token)`, передавать заголовком `Authorization: Bearer ${IAM_TOKEN}`.
- Дословно о сроке годности: «Время жизни IAM-токена — не больше 12 часов, но рекомендуется запрашивать его чаще, например каждый час.»

Практическое следствие для прогона по списку фраз, который идёт часами: токен протухнет посреди работы — либо перевыпускать его в цикле, либо работать API-ключом сервисного аккаунта, у которого срока жизни нет ([python-reference.md](python-reference.md)).

Для **сервисного** аккаунта у Yandex Cloud отдельная инструкция «Получение IAM-токена для сервисного аккаунта» — её содержание здесь не пересказывается, потому что мы её не читали; способы смотреть в первоисточнике.

### Регистр названия схемы значения не имеет, дефис обязателен

`Api-Key`, `Api-key` и `api-key` сервис распознаёт одинаково — все три доходят до слоя аутентификации и дают один ответ. А `ApiKey` без дефиса не распознаётся вовсе: ответ будет `IAM token or API key has to be passed in request`, как будто заголовка нет. (Снято живыми вызовами 25.08.2026.) В примерах писать `Api-Key`.

## Роли сервиса: одна действующая и пять устаревших

| Роль | Формулировка документации | Статус |
|---|---|---|
| `search-api.webSearch.user` | «позволяет выполнять поисковые запросы в сервисе Yandex Search API, а также просматривать информацию об облаке, каталоге и квотах» | **действующая, нужна для Wordstat** |
| `search-api.executor` | «устарела и больше не используется» (en: «is no longer available») | устарела |
| `search-api.auditor` | «устарела и не должна использоваться» | устарела |
| `search-api.viewer` | то же | устарела |
| `search-api.editor` | то же | устарела |
| `search-api.admin` | то же | устарела |

Отдельной роли для Wordstat не существует. Устаревшие роли встречаются в живых инструкциях, которые агент найдёт поиском, — следовать им не нужно, действующая роль одна.

Примитивные роли (`auditor`, `viewer`, `editor`, `admin`) существуют, но документация рекомендует их не использовать: «Вместо примитивных ролей мы рекомендуем использовать роли сервисов.»

## Проверка доступа — первый вызов

Самый дешёвый способ убедиться, что доступ работает: `GetRegionsTree` — единственный бесплатный метод во всём прайсе сервиса.

```bash
curl --request POST \
  --header "Authorization: Api-Key $YC_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"folderId":"'"$YC_FOLDER_ID"'"}' \
  https://searchapi.api.cloud.yandex.net/v2/wordstat/getRegionsTree
```

Ожидаемо: HTTP 200 и JSON с корнем `regions`, около 57 КБ. Что означают другие ответы — [errors.md](errors.md).

## Формат `.env` и переменные окружения

Для прямых HTTP-вызовов:

```
YC_API_KEY=
YC_FOLDER_ID=
```

Для Yandex AI Studio SDK набор имён задан самим SDK: `YC_API_KEY`, `YC_IAM_TOKEN`, `YC_TOKEN`, `YC_OAUTH_TOKEN` (любой один) и `YC_FOLDER_ID` ([sdk.md](sdk.md)).

## Логирование данных запроса

Заголовок `x-data-logging-enabled` управляет тем, сохраняет ли Яндекс переданные данные. Рабочая версия: **по умолчанию сервис данные не сохраняет** — так говорит страница диагностики Search API, ближайший по предмету источник: «По умолчанию сервис **не сохраняет** ваши данные, отправленные по API»; значение `true` включает сохранение.

> Два источника Яндекса говорят разное. Страница диагностики Search API: «По умолчанию сервис **не сохраняет** ваши данные, отправленные по API». Страница AI Studio про отключение логирования: «По умолчанию модели сохраняют все данные запросов» — но она про модели, а не про Search API. Что действует именно для Wordstat, не сказано нигде, и снаружи это не наблюдаемо: без явного параметра SDK заголовок вообще не отправляет.
>
> Рабочая версия — первая, как ближайшая по предмету. Практическое следствие: если данные запроса чувствительны, на умолчание не полагайся и передавай `x-data-logging-enabled: false` явно.

В SDK то же выражается параметром `AIStudio(..., enable_server_data_logging=False)`; без явного значения SDK заголовок не отправляет вовсе, то есть умолчание сервиса остаётся в силе.
