# Yandex Wordstat API

Документация Яндекса прочитана 24–25.08.2026; поведение сервиса снято собственными живыми вызовами 25.08.2026. Тарифы, версии пакетов и юридический документ датированы по месту.

## Назначение

Справочник для программного получения статистики поисковых запросов Яндекса через раздел Wordstat в Yandex Search API v2. Покрывает четыре метода в REST- и gRPC-форме, заведение доступа от регистрации до первого вызова, квоты и тарифы, операторы языка запросов, регионы и разбор ошибок.

## Принципы

1. **Скилл описывает одну поверхность** — `searchapi.api.cloud.yandex.net/v2/wordstat/*`. Всё, что называет себя «API Вордстата» по другому адресу или в другом продукте Яндекса, за границей скилла.
2. **Одна фраза — один вызов.** Поле `phrase` скалярное, пакетной обработки нет.
3. **Каждый вызов платный, кроме `GetRegionsTree`.** До прогона по списку считай стоимость и время, показывай пользователю, жди подтверждения.
4. **Связывающая квота — 100 запросов в час,** а не 10 rps. Потолок — 100 фраз в час.
5. **`numPhrases` передавай всегда явно.** Умолчания у поля нет; при его отсутствии вызов отвергается валидацией.
6. **`folderId` обязателен при аутентификации от пользовательского аккаунта** и не обязателен от сервисного, если работа идёт в его собственном каталоге.
7. **`count` и `totalCount` приходят строками, `share` и `affinityIndex` — числами.** Приводить типы на своей стороне.
8. **Ошибки тела видны без ключа:** проверка тела идёт до аутентификации. 400 — тело, 401 — ключ.
9. **`GetDynamics` не смотрит раньше 01.01.2018, а по дням — не дальше 60 суток назад.** Оба потолка отвергаются валидацией с отдельными текстами.
10. **Читай только нужные файлы.** Не загружай скилл целиком.

## Рабочий процесс

**Шаг 1. Выбрать метод по задаче.**

| Что нужно | Метод |
|---|---|
| Частотность фразы, топ похожих формулировок, ассоциации | `GetTop` |
| Как менялся спрос во времени | `GetDynamics` |
| Где спрос выше, индекс аффинитивности | `GetRegionsDistribution` |
| Коды регионов для фильтров и расшифровки ответов | `GetRegionsTree` |

**Шаг 2. Взять учётные данные из окружения** — `YC_API_KEY` (или `YC_IAM_TOKEN`) и `YC_FOLDER_ID` из переменных окружения либо `.env` проекта. Пусто — не заводить файлы за пользователя, а сказать, чего не хватает, и отправить в [auth-and-setup.md](auth-and-setup.md).

**Шаг 3. Посчитать стоимость и время.** Число фраз × тариф метода; число фраз ÷ 100 = часы. Показать пользователю до запуска. Для одиночного вызова шаг пропускается.

**Шаг 4. Собрать и выполнить вызов** по [methods.md](methods.md), для gRPC — [grpc.md](grpc.md).

**Шаг 5. Привести типы в ответе:** `count` и `totalCount` — строки, приводить к int; `share` и `affinityIndex` — числа; `affinityIndex` в шкале около 100, не в долях.

**Шаг 6. При ошибке** — [errors.md](errors.md): по HTTP-коду сразу видно ступень (400 — тело, 401 — ключ, 404 — путь).

## Что НЕ делать

- Не передавать несколько фраз в одном вызове — поле скалярное.
- Не опускать `numPhrases`.
- Не ждать, что `numPhrases` управляет числом ассоциаций — не управляет.
- Не передавать `regions[]` в `GetRegionsDistribution` — у метода такого поля нет, оно будет молча проигнорировано.
- Не путать `region` в запросе `GetRegionsDistribution` (уровень детализации) с `region` в ответе (идентификатор региона).
- Не передавать идентификаторы регионов числами — только строками, иначе 400 на ступени транскодирования.
- Не передавать даты со смещением от UTC: границы недели и месяца сервис считает по UTC, и «понедельник по Москве» будет отвергнут. Только суффикс `Z`.
- Не запрашивать `PERIOD_DAILY` глубже 60 суток и ничего глубже 01.01.2018 — отвергается валидацией.
- Не применять страницу «Коды ошибок» Search API к Wordstat — она про XML-ответы текстового поиска.
- Не запускать прогон по списку фраз без предварительного расчёта стоимости и времени.
- Не хардкодить ключ — только окружение или `.env`.
- Не публиковать и не пересылать тело ответа 401 как есть: сообщение `Unknown api key` содержит первые и последние четыре символа ключа.
- Не полагаться на льготный ночной тариф — у Wordstat его нет.
- Не загружать все файлы скилла сразу.
- Не создавать в проекте пользователя директории и `.env` без просьбы — скилл ничего не заводит сам.

## Примеры

### Пример 1 (типовой): частотность одной фразы в регионе

**Вход:** «Какая частотность у фразы "купить кроссовки" в Москве?»

**Маршрут:** [methods.md](methods.md), при необходимости [regions.md](regions.md) за кодом Москвы `213`.

**Результат:** один вызов `GetTop` с `numPhrases: 1`, `regions: ["213"]`. Стоимость 0,02 ₽. В ответе `totalCount` — общее число запросов, содержащих все введённые слова в любом порядке.

### Пример 2 (типовой): динамика по месяцам

**Вход:** «Сними динамику по месяцам за 2026 год».

**Маршрут:** [methods.md](methods.md) плюс [errors.md](errors.md).

**Результат:** `GetDynamics` с `period: PERIOD_MONTHLY`, `fromDate: 2026-01-01T00:00:00Z`, `toDate` — последний день месяца, иначе `400 The to field value should be the last day of the month`. При месячной детализации из операторов работает только `+`.

### Пример 3 (edge-case): прогон по большому списку фраз

**Вход:** «Прогони 3 000 фраз из файла».

**Маршрут:** [limits-quotas-pricing.md](limits-quotas-pricing.md).

**Результат:** расчёт до запуска — 3 000 вызовов `GetTop` = 60 ₽, но 30 часов при квоте 100 запросов в час. Агент показывает оба числа, предлагает сузить список или разбить на прогоны по суткам и ждёт подтверждения, а не запускает.

### Пример 4 (edge-case): дневная детализация за прошлый год

**Вход:** «Покажи динамику по дням за прошлый год».

**Маршрут:** [methods.md](methods.md) плюс [errors.md](errors.md).

**Результат:** в такой постановке невыполнимо: при `PERIOD_DAILY` `fromDate` должен попадать в последние 60 суток, иначе `400 The from field value is older than 60 days`. Агент не отправляет вызов вслепую, а сразу предлагает два выхода: либо дневная детализация за последние 60 суток, либо год целиком, но с `PERIOD_WEEKLY` или `PERIOD_MONTHLY`.
