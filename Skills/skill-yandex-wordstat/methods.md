# Методы Wordstat в REST-форме

## Назначение

Четыре метода Wordstat в REST-форме: пути, поля запроса с ограничениями, форма ответа и ловушки каждого метода.

gRPC-форма вызова, имена полей в snake_case, proto-типы и примеры `grpcurl` — [grpc.md](grpc.md). Ограничения полей, приведённые здесь, действуют для обоих транспортов и не дублируются там.

## Общая часть

Все четыре метода — `POST`, тело JSON, заголовок `Content-Type: application/json`. Все синхронные: «Wordstat работает только через API в синхронном режиме.» Асинхронного режима у Wordstat нет, хотя у текстового поиска в том же сервисе он есть.

Раздел Wordstat в публичной спецификации Search API появился 27.10.2025 (три метода), `GetRegionsTree` добавлен 01.12.2025, готовность к работе отмечена 22.12.2025 — по истории `wordstat_service.proto`. Это единственная доступная датировка появления функциональности, и она нужна, чтобы понимать: любой сторонний материал старше 2026 года описывает другую поверхность.

### REST-пути

Именование непоследовательно: три пути без префикса `get`, четвёртый с ним.

| Метод | REST-путь |
|---|---|
| `GetTop` | `POST /v2/wordstat/topRequests` |
| `GetDynamics` | `POST /v2/wordstat/dynamics` |
| `GetRegionsDistribution` | `POST /v2/wordstat/regions` |
| `GetRegionsTree` | `POST /v2/wordstat/getRegionsTree` |

Хост — `https://searchapi.api.cloud.yandex.net`. Авторизация и `folderId` — [auth-and-setup.md](auth-and-setup.md).

### Перечисления

```
Device:  DEVICE_ALL | DEVICE_DESKTOP | DEVICE_PHONE | DEVICE_TABLET
Period:  PERIOD_MONTHLY | PERIOD_WEEKLY | PERIOD_DAILY   (только в GetDynamics)
Region:  REGION_ALL | REGION_CITIES | REGION_REGIONS     (только в GetRegionsDistribution)
```

Значения передаются строго этими строками: строчные псевдонимы протокол не принимает — `"period": "daily"` даёт `400` на ступени транскодирования (снято живым вызовом 25.08.2026). Строчные написания, которые встречаются в примерах SDK, — удобство библиотеки, а не протокола ([sdk.md](sdk.md)).

### Типы в ответе

| Поле | Что приходит фактически |
|---|---|
| `count`, `totalCount` | **строка** — `"48885"` |
| `share` | **число** JSON — `0.002010327532236065` |
| `affinityIndex` | **число** JSON в шкале около 100 — `109.33370454329048` |

Это каноническое отображение protobuf в JSON: 64-битные целые сериализуются строками, `double` — числами. Проверено фактическими ответами: в кассетах SDK и в примерах документации `count` всегда в кавычках, `share` и `affinityIndex` — всегда без.

### Типы в запросе

Требования мягче, чем в ответе (снято живыми вызовами 25.08.2026):

- `numPhrases` принимается и числом (`100`), и строкой (`"100"`) — строка действительно разбирается как целое, а не игнорируется: `"2001"` отвергается диапазонной проверкой. Нечисловая строка даёт `400`.
- Имена полей тело принимает и в camelCase, и в snake_case.
- **Идентификаторы регионов — только строки.** `"regions": [213]` числом отвергается на ступени транскодирования.

Рекомендация: писать camelCase и числа — так короче и совпадает с примерами документации.

Имена полей в **сообщениях об ошибках всегда в snake_case**, даже если запрос отправлен по REST в camelCase, — подробности в [errors.md](errors.md).

## `GetTop`

Назначение (дословно): «The method returns the last 30 days data about popular queries containing the specified keyword and queries that are similar to the specified one.»

### Запрос

```json
{
  "phrase": "купить собаку",
  "numPhrases": 100,
  "regions": ["213"],
  "devices": ["DEVICE_ALL"],
  "folderId": "<идентификатор_каталога>"
}
```

| Поле | Тип | Обяз. | Ограничение |
|---|---|---|---|
| `phrase` | string | **да** | не более 400 символов; поддерживает поисковые операторы ([query-language.md](query-language.md)) |
| `numPhrases` | int64 | **да, фактически** | 1…2000 включительно. Умолчания у поля нет: при его отсутствии вызов отвергается с `num_phrases: Value must be in the range of 1 to 2000`. Пошаговая инструкция Яндекса называет умолчание 50 — через API оно не срабатывает, передавайте значение явно |
| `regions[]` | string[] | нет | не более 100 элементов, каждый — строка; по умолчанию учитываются запросы из любого региона |
| `devices[]` | Device[] | нет | **не более 3 элементов** |
| `folderId` | string | зависит от способа аутентификации | не более 50 символов |

### Ответ

```json
{
  "totalCount": "48885",
  "results": [{ "phrase": "купить собаку", "count": "48885" }],
  "associations": [{ "phrase": "сколько стоит пудель", "count": "613" }]
}
```

- `totalCount` — «общее число запросов, которые содержат все введенные слова в любом порядке».
- `results[]` — топ формулировок, содержащих фразу.
- `associations[]` — «Queries that are similar to the specified one», похожие запросы на ту же тему. **Максимум 20** (лимит сервиса, [limits-quotas-pricing.md](limits-quotas-pricing.md)).

### Наблюдаемое поведение, которого нет в документации

Записанная Яндексом кассета SDK, фраза `yandex cloud`, `numPhrases: 10` (пересчитано 25.08.2026): вернулось ровно 10 элементов `results` и **4** элемента `associations`, весь ответ — 852 байта. То есть `numPhrases` число ассоциаций не задаёт, и до лимита 20 они могут не дотягивать. `totalCount` совпал с `count` первой, точной фразы.

- **Не рассчитывай, что длина `results` равна `numPhrases`.** Наблюдение выше — единственное, и оно на узкой фразе; что вернётся, если запросить больше формулировок, чем их существует, и дойдёт ли ответ до потолка 2000, не проверялось. Читай фактическую длину массива, а не подставляй запрошенное число.
- **`associations` может не прийти вовсе.** Приходит ли на редких запросах пустой массив или поле просто отсутствует, не наблюдалось: обращайся через безопасное чтение ключа, а не по индексу.

## `GetDynamics`

Назначение: «The method returns the frequency of queries over time for a given keyword.»

### Запрос

```json
{
  "phrase": "<ключевая_фраза>",
  "period": "PERIOD_WEEKLY",
  "fromDate": "2025-12-01T00:00:00Z",
  "toDate": "2025-12-14T00:00:00Z",
  "regions": ["213"],
  "devices": ["DEVICE_DESKTOP"],
  "folderId": "<идентификатор_каталога>"
}
```

| Поле | Тип | Обяз. | Ограничение |
|---|---|---|---|
| `phrase` | string | **да** | ≤ 400 символов |
| `period` | Period | **да** | `PERIOD_MONTHLY` / `PERIOD_WEEKLY` / `PERIOD_DAILY` |
| `fromDate` | RFC3339 | **да** | см. границы ниже |
| `toDate` | RFC3339 | нет | если передан, должен быть строго больше `fromDate`; см. границы ниже |
| `regions[]` | string[] | нет | ≤ 100 |
| `devices[]` | Device[] | нет | **≤ 3** |
| `folderId` | string | зависит | ≤ 50 |

### Границы периода

Жёсткое правило, ломающее вызовы чаще всего:

| Детализация | `fromDate` | `toDate` |
|---|---|---|
| `PERIOD_WEEKLY` | понедельник | воскресенье |
| `PERIOD_MONTHLY` | первый день месяца | последний день месяца |
| `PERIOD_DAILY` | произвольная дата | произвольная дата |

### Глубина доступной истории

Два жёстких потолка, которых нет ни в справочнике, ни в proto, ни в пошаговой инструкции (все три перечитаны 25.08.2026; потолки установлены живыми вызовами того же дня):

| Ограничение | Действует при | Текст отказа |
|---|---|---|
| `fromDate` не раньше 01.01.2018 | всех трёх детализациях | `The from field value should be after 2018-01-01` |
| `fromDate` не старше 60 суток | только `PERIOD_DAILY` | `The from field value is older than 60 days` |

Шестидесятидневное окно **скользящее и отсчитывается от момента вызова, а не от начала суток**: при замере 24.08.2026 в 21:50 UTC полночь дня «сегодня − 59» проходила, полночь дня «сегодня − 60» уже отвергалась. Практическое правило: при дневной детализации брать `fromDate` не раньше чем «сейчас минус 59 суток».

За период длиннее двух месяцев дневной детализации не существует вовсе — за год спрос снимается только `PERIOD_WEEKLY` или `PERIOD_MONTHLY`.

**Верхней границы длины периода при недельной и месячной детализации не проверяли.** Валидация пропускает `fromDate` от 2018-01-01, но что вернёт сервис на восьмилетнем запросе — не наблюдалось. Прежде чем обещать пользователю всю историю одним вызовом, снимай период частями и сверяй, что данные пришли целиком.

**Даты считаются в UTC.** Формат принимает смещения (`+03:00`) и дробные секунды, но день недели и число месяца сервис определяет по UTC-моменту: `2026-08-03T00:00:00+03:00` — понедельник по Москве и воскресенье по UTC — отвергается как `The from field value should be Monday`. Передавать даты с суффиксом `Z`.

**Обе границы включительны по данным:** диапазон `[2026-05-01, 2026-05-02]` при `PERIOD_DAILY` даёт две точки. При этом `toDate`, равный `fromDate`, отвергается: `The to field value should be more than the from field value`.

Тексты всех отказов и порядок их срабатывания — [errors.md](errors.md).

### Ответ

```json
{ "results": [
    { "date": "2025-12-01T00:00:00Z", "count": "1999", "share": 0.002010327532236065 },
    { "date": "2025-12-08T00:00:00Z", "count": "3095", "share": 0.0031681796592690848 }
]}
```

`share` — «доля числа таких запросов от общего числа запросов к Яндексу».

## `GetRegionsDistribution`

Назначение: «The method returns the distribution of the number of queries containing the given keyword globally by region for the last 30 days.»

### Запрос

```json
{
  "phrase": "<ключевая_фраза>",
  "region": "REGION_CITIES",
  "devices": ["DEVICE_PHONE"],
  "folderId": "<идентификатор_каталога>"
}
```

| Поле | Тип | Обяз. | Ограничение |
|---|---|---|---|
| `phrase` | string | **да** | ≤ 400 символов |
| `region` | Region | нет | уровень детализации: `REGION_ALL` (по умолчанию), `REGION_CITIES`, `REGION_REGIONS` |
| `devices[]` | Device[] | нет | **ограничения на число элементов нет** — в отличие от `GetTop` и `GetDynamics` |
| `folderId` | string | зависит | ≤ 50 |

Отсутствие лимита на `devices[]` — не опечатка документации: четыре элемента прошли валидацию у этого метода, тогда как `GetTop` на тех же четырёх вернул ошибку (снято живым вызовом 25.08.2026).

### Две ловушки

1. **Поля `regions[]` у метода нет.** Фильтровать по конкретным регионам нельзя, есть только уровень детализации. Переданное поле `regions` будет молча проигнорировано транскодером (проверено живым вызовом 25.08.2026: вызов дошёл до аутентификации, ошибки не было).
2. **`region` означает разное в запросе и в ответе.** В запросе это перечисление уровня детализации; в ответе — строковый идентификатор региона.

### Ответ

```json
{ "results": [
    { "region": "2",   "count": "117527", "share": 0.033340221022570879, "affinityIndex": 48.87239354882464 },
    { "region": "213", "count": "286666", "share": 0.03751625685705634,  "affinityIndex": 54.99391465808182 }
]}
```

- `share` — доля запросов с фразой от общего числа запросов **в этом регионе**.
- `affinityIndex` — «отношение доли запросов в регионе к их доле по стране». Шкала около 100: значение 109,33 означает, что доля в регионе выше среднестрановой примерно на 9 %. В документации шкала не оговорена — установлено по фактическим ответам.
- В ответе только идентификаторы регионов, без названий. Расшифровка — через `GetRegionsTree`, см. [regions.md](regions.md).

**Ответ большой.** По опубликованным Яндексом кассетам (пересчитано 25.08.2026): без поля `region`, то есть при `REGION_ALL`, вернулось **806 строк, 77 КБ**; с `REGION_CITIES` и двумя типами устройств — **488 строк, 47 КБ**. Планируя обработку, рассчитывать на сотни строк, а не на десятки, и не пытаться показать ответ целиком.

## `GetRegionsTree`

Назначение (в оригинале с удвоенным словом, так и в proto, и на четырёх страницах справочника): «The method method returns a tree of Wordstat-supported regions.»

### Запрос

```json
{ "folderId": "<идентификатор_каталога>" }
```

Единственное поле, **без ограничения длины** — в отличие от остальных трёх методов, где стоит «не более 50 символов». Проверено: `folder_id` длиной 51 символ у этого метода проходит валидацию, у `GetTop` — нет (снято живым вызовом 25.08.2026).

Ключевую фразу метод не принимает. Тело можно опустить целиком — `POST` без тела и с телом `{}` одинаково проходят разбор (проверено 25.08.2026). Но работает это только при аутентификации сервисным аккаунтом в его собственном каталоге: при IAM-токене пользователя каталог обязателен, и тело нужно ([auth-and-setup.md](auth-and-setup.md)).

### Ответ

```json
{ "regions": [
    { "id": "225", "label": "Россия", "children": [ … ] }
]}
```

`RegionInfo`: `id` — string, `label` — string, `children[]` — вложенные `RegionInfo`. Поле названия называется **`label`**. Структура дерева, его размер и ловушки — [regions.md](regions.md).

**Метод не тарифицируется** — единственная бесплатная позиция во всём прайсе сервиса. Отсюда практический приём: использовать его для проверки доступа и кэшировать дерево локально, а не запрашивать перед каждой расшифровкой.
