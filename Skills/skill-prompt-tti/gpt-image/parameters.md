# GPT Image: параметры

## Назначение

Параметры моделей GPT Image в Image API и в инструменте `image_generation` Responses API: значения, умолчания, порядок настройки `quality` и `complexity`, прозрачность, входные файлы и расхождения.

Состояние на 2026-11-09.

## Таблица параметров

| Параметр | Где | Значения и умолчание | Оговорки |
|---|---|---|---|
| `model` | генерация, правка, инструмент | генерация — модель указывается явно; правка — по умолчанию `gpt-image-2.5-sunburst`; инструмент — по умолчанию `gpt-image-2` | модели — в [models.md](models.md) |
| `prompt` | генерация, правка | до 32 000 символов | — |
| `images` | правка | до 16; элемент — `file_id` или `image_url` (полный URL или data URL в base64, `maxLength: 20971520`) | — |
| `mask` | правка (Image API) | ровно одно из `image_url` или `file_id` | подробности в [editing.md](editing.md) |
| `input_image_mask` | инструмент Responses | `file_id` или `image_url` | маска для локальной правки |
| `markup` | правка (Image API) | прозрачный PNG поверх первого изображения, того же размера после учёта ориентации, с прозрачными пикселями | модели 2.5 и 2.6; не сочетается с `mask` |
| `size` | все | умолчание `auto`; произвольные `WIDTHxHEIGHT` | правила — раздел «Размер» ниже |
| `quality` | все | `low`, `medium`, `high`, `auto` (по умолчанию); `xhigh` и `max` — у моделей 2.5 и 2.6 | раздел «Качество и сложность» |
| `complexity` | все (модели 2.6) | `low`, `medium`, `high`; без параметра обе модели 2.6 используют `high` | вычисления на планирование изображения, независимо от качества отрисовки; в инструменте Responses перекрывает `reasoning.effort` основного запроса, а без параметра наследует поддерживаемое усилие основного запроса или берёт умолчание модели |
| `background` | все | `transparent`, `opaque`, `auto` (по умолчанию) | раздел «Прозрачный фон» |
| `output_format` | все | `png` (по умолчанию), `webp`, `jpeg` | `jpeg` быстрее `png` — выбирать его, если важна задержка; `gif` и `svg` скиллом не покрываются |
| `output_compression` | все | 0–100, по умолчанию 100 | только `jpeg` и `webp` |
| `n` | генерация, правка | 1–10, по умолчанию 1 | — |
| `stream`, `partial_images` | все | `partial_images` 0–3, по умолчанию 0 | частичных изображений может прийти меньше запрошенного, если полное изображение готово быстрее |
| `input_fidelity` | правка, инструмент | для моделей 2 и новее не передаётся | модель автоматически обрабатывает каждое входное изображение с высокой точностью, и API не позволяет это менять |
| `action` | только инструмент Responses | `generate`, `edit`, `auto` (по умолчанию) | принудительный `edit` без изображения в контексте — ошибка |
| `style` | генерация | не поддерживается | устаревший параметр выведенных моделей; стиль описывается в промпте |
| `response_format` | генерация | не поддерживается | модели GPT Image всегда возвращают base64 |
| `revised_prompt` (ответ) | Image API, Responses | Image API — моделями GPT Image не возвращается; Responses — переписанный основной моделью промпт | подробности в [surfaces.md](surfaces.md) |
| `reasoning.summary` | — | у GPT Image 2.6 не поддерживается | — |

`prompt_rewriter` — не параметр запроса: свойства с таким именем нет ни в одной схеме запроса; имя встречается только в оговорке о том, что SVG-генерация его не поддерживает. Что это за механизм — не установлено.

## Размер

- Для `gpt-image-2` и моделей 2.5: произвольные разрешения `WIDTHxHEIGHT`; ширина и высота кратны 16; соотношение сторон от 1:3 до 3:1; разрешения выше `2560x1440` экспериментальны; максимальное — `3840x2160`.
- Для Sunburst и Flare: ни одна сторона не больше 3840 пикселей; общее число пикселей — от 655 360 до 8 294 400 (4K); выше `2560x1440` — экспериментально.
- Рекомендуемые размеры: `1024x1024`, `1536x1024`, `1024x1536`. Пример горизонтального слайда — `1536x864`.
- Источники расходятся о границе 3840: одна позиция — сторона не больше 3840; другая — сторона строго меньше 3840, с советом округлять вниз, например до `3824x2144`.

## Качество и сложность

- `quality` управляет тем, сколько визуальных деталей модель может отрисовать — фактура, мелкие буквы; `complexity` — тем, сколько модель планирует перед отрисовкой.
- Сравнивая уровни сложности, держать `quality` неизменным. ЕСЛИ раскладка верна, а мелкий текст нечитаем -> сравнивать уровни качества при той же сложности.
- Точечную правку одной детали начинать с `complexity` `low`. Высокая сложность может увеличить задержку и внести нежелательные изменения — результаты сравниваются под задачу.
- Для правок рекомендуется низкая сложность и тот уровень качества, который нужен для работы; для сцен с большим числом элементов или ограничений — средняя или высокая сложность.
- `xhigh` и `max` — только когда они закрывают невыполненное требование к качеству в рамках допустимой задержки; более высокое значение не гарантирует лучшего результата для каждого промпта. Одинаковое значение `quality` у разных моделей не означает одинакового качества и времени ответа.
- Миграция на новую модель: первое сравнение — при одинаковых промпте, референсах, размере, качестве и формате, сложность — по умолчанию; дальше менять по одной настройке — либо качество, либо сложность.

## Прозрачный фон

- `background="transparent"` и `output_format` `png` или `webp`; `jpeg` прозрачность не поддерживает. У `gpt-image-2` прозрачный фон — в предварительном режиме.
- Промпт важнее параметра: если промпт описывает фон, сцену или цвет фона, модель может нарисовать его вместо прозрачности. Промпт описывает изолированный объект и явно просит прозрачный фон.
- Нарисованная шахматка — не прозрачность. Для PNG `output_compression` не задаётся.

## Входные файлы

- Каждое изображение правки — `png`, `webp` или `jpg` меньше 50 МБ, до 16 изображений.
- С разметкой первое изображение и слой пометок — каждый не больше 16 777 216 пикселей; файл пометок — до 50 МБ.
- Внутреннее уменьшение входных изображений для `gpt-image-2` и новее не опубликовано — не установлено.

## Расхождения

| Предмет | Одна позиция | Другая позиция |
|---|---|---|
| Предел размера маски | корректный PNG меньше 4 МБ тех же размеров, что `image` | изображение и маска меньше 50 МБ |
| Модели в описании поля `image` правки | перечислены модели GPT Image без 2.6 | перечень моделей поля `model` той же схемы включает 2.6 |
| Граница 3840 | не больше 3840 | строго меньше 3840 |

## Примеры

### Пример 1: инфографика с мелким текстом

**Вход:** «инфографика с подписями, `gpt-image-2.6-sunburst`, текст мелкий».

**Результат:** `size="1536x1024"`, `quality="high"`; `complexity` не задан — умолчание `high`; если раскладка верна, а текст нечитаем, сравнивать `quality` при той же `complexity`.

### Пример 2: `input_fidelity` на модели 2.5

**Вход:** «добавь `input_fidelity: "high"`, чтобы лицо сохранилось».

**Результат:** для моделей 2 и новее `input_fidelity` не передаётся — входные изображения и так обрабатываются с высокой точностью; сохранность лица задаётся текстом промпта (что неизменно) и проверкой результата.
