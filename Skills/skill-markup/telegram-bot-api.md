# Telegram Rich Markdown / Rich HTML (Bot API)

Разметка сообщений, которые **бот отправляет через Bot API**. Богатая: заголовки, списки, таблицы, сноски, формулы, медиа, сворачиваемые блоки.

**Не путать с клиентской разметкой** — [telegram.md](telegram.md) описывает то, что разбирается при наборе сообщения руками в приложении. Там работают шесть последовательностей и нет ни заголовков, ни таблиц, ни ссылок. Ключевое расхождение: `__текст__` в клиенте даёт **курсив**, в Rich Markdown — **жирный**.

**Волатильность:** Rich Messages появились в Bot API 10.1 (11.06.2026), в 10.2 (14.07.2026) добавлено поле `blocks`, класс `InputRichMessageMedia` и поле `media`. Домен меняется крупными блоками — при любом расхождении первоисточник `core.telegram.org/bots/api`. Данные ниже сверены по нему **28.07.2026**.

---

## Как содержимое попадает в сообщение

| Метод | Назначение |
|---|---|
| `sendRichMessage` | Отправить rich-сообщение. Обязательные параметры — `chat_id` и `rich_message` типа `InputRichMessage` |
| `sendRichMessageDraft` | Стримить частичное rich-сообщение (в нём же доступен тег `<tg-thinking>`) |
| `editMessageText` | Параметр `rich_message` — редактирование rich-сообщения |

В объекте `InputRichMessage`: «Exactly one of the fields `html`, `markdown`, or `blocks` must be used» — **ровно одно** поле из трёх.

| Поле | Что кладут |
|---|---|
| `markdown` | Текст в синтаксисе Rich Markdown |
| `html` | Текст в синтаксисе Rich HTML |
| `blocks` | Дерево JSON из объектов `InputRichBlock*` — максимум контроля, но собирать вручную |

Рядом — необязательное поле `media` (список `InputRichMessageMedia`) для медиа, заданных в `markdown`/`html` ссылками `tg://photo?id=`, `tg://video?id=`, `tg://audio?id=`.

**Что выбирать для текста, сгенерированного моделью:** обычно `markdown`. Rich Markdown совместим с GFM, а GFM модель порождает без адаптации — тогда как `blocks` требует сборки JSON-дерева. Это рекомендация по опыту, а не предписание документации.

## Rich Markdown: инлайн-синтаксис

| Синтаксис | Результат |
|---|---|
| `**жирный**` | жирный |
| `__жирный__` | жирный (**не курсив**, в отличие от клиента) |
| `*курсив*` | курсив |
| `_курсив_` | курсив |
| `~~зачёркнутый~~` | зачёркнутый |
| `` `код` `` | моноширинный |
| `==выделенный==` | выделенный (marked) |
| `\|\|спойлер\|\|` | спойлер |
| `$x^2 + y^2$` | формула |

Ссылки и специальные вставки:

```markdown
[inline URL](https://t.me/)
[inline e-mail](mailto:user@example.com)
[inline phone number](tel:+123456789)
[inline mention of a user](tg://user?id=123456789)
![](tg://emoji?id=5368324170671202286)
![22:45 tomorrow](tg://time?unix=1647531900&format=wDT)
```

URL, адреса почты, упоминания, хештеги, кэштеги, команды бота, телефоны и номера карт распознаются автоматически. Отключается флагом `skip_entity_detection`.

## Rich Markdown: блочный синтаксис

````markdown
# Heading 1
###### Heading 6

Paragraph text

```python
print('код с указанием языка')
```

---

- unordered list item
1. ordered list item
- [ ] task list item
- [x] completed task list item

>Block quotation started
>
>The last line of the block quotation

| Header 1 | Header 2 |
|:---------|:--------:|
| left     | center   |

Text with a reference[^id1].

[^id1]: Definition of the first footnote.

$$E = mc^2$$

```math
E = mc^2
```

![](https://telegram.org/example/photo.jpg "Photo caption")
````

Медиа-блок: тип определяется по MIME-типу и URL; необязательный заголовок после URL становится подписью.

## Что задаётся только HTML-тегами

Для форматирования без Markdown-синтаксиса используются теги — их можно вставлять прямо в поле `markdown`:

| Тег | Назначение |
|---|---|
| `<u>`, `<ins>` | подчёркивание |
| `<sub>`, `<sup>` | нижний и верхний индекс |
| `<tg-spoiler>` | спойлер |
| `<a name="chapter-1"></a>` | якорь; ссылка на него — `<a href="#chapter-1">` |
| `<aside>…<cite>Автор</cite></aside>` | выносная цитата |
| `<details open><summary>Заголовок</summary>…</details>` | сворачиваемый блок |
| `<tg-map lat="41.9" long="12.5" zoom="14"/>` | карта |
| `<tg-collage>`, `<tg-slideshow>` | коллаж и слайдшоу из медиа |
| `<tg-emoji emoji-id="…">`, `<tg-time unix="…" format="…">` | кастомное эмодзи, дата-время |
| `<tg-reference name="note-1">` | именованный фрагмент для ссылки |
| `<tg-thinking>` | только в `sendRichMessageDraft` |

## Rich HTML

Альтернативный режим — то же содержимое тегами, в поле `html`. Поддерживаются: `<b>`/`<strong>`, `<i>`/`<em>`, `<u>`/`<ins>`, `<s>`/`<strike>`/`<del>`, `<code>`, `<mark>`, `<sub>`, `<sup>`, `<tg-spoiler>`, `<a>`, `<h1>`…`<h6>`, `<p>`, `<pre>`, `<footer>`, `<hr/>`, `<ul>`/`<ol>`/`<li>` (с атрибутами `start`, `type`, `reversed`, `value`), чекбоксы `<input type="checkbox">`, `<blockquote>`, `<aside>`, `<img>`/`<video>`/`<audio>`, `<figure>`/`<figcaption>`/`<cite>`, `<table>` (с `bordered`, `striped`, `caption`, `colspan`, `rowspan`, `align`, `valign`), `<details>`, `<tg-*>`-теги, `<tg-math>` и `<tg-math-block>`.

Оговорки документации:

- «Only the tags mentioned above are currently supported».
- Поддерживаются все числовые HTML-сущности; из именованных — только `&lt;` `&gt;` `&amp;` `&quot;` `&apos;` `&nbsp;` `&hellip;` `&mdash;` `&ndash;` `&lsquo;` `&rsquo;` `&ldquo;` `&rdquo;`.
- Язык блока кода задаётся вложенными `<pre><code class="language-python">`; для одиночного `<code>` язык указать нельзя.
- Тело `<details>` может содержать rich-содержимое; атрибут `open` разворачивает блок по умолчанию.

## Ограничения парсера

Дословно из документации:

- «Markdown isn't parsed inside block HTML tags other than `<details>`, `<tg-collage>` and `<tg-slideshow>`, therefore only HTML tags can be used there» — внутри остальных блочных тегов Markdown не разбирается, только HTML.
- «Table cells can contain only inline formatting» — ячейки таблиц принимают только инлайн-форматирование.
- «Media can be specified only as a separate block» — медиа задаётся исключительно отдельным блоком.
- «Media blocks support only HTTP and HTTPS URLs» — медиа-блоки принимают только HTTP и HTTPS.
- «Formula source is treated as raw LaTeX» — источник формулы обрабатывается как сырой LaTeX.
- «Rich Markdown is compatible with GitHub Flavored Markdown where possible and can contain arbitrary HTML».

## Лимиты rich-сообщения

| Лимит | Значение |
|---|---|
| Символов (UTF-8), включая alt-текст кастомных эмодзи и источник формул | 32 768 |
| Блоков | 500 |
| Уровней вложенности форматирования и блоков | 16 |
| Медиа-вложений всего (фото, видео, аудио) | 50 |
| Колонок в таблице | 20 |

Блоками считаются в том числе вложенные блоки, элементы списков, элементы нумерованных списков, **строки таблиц**, блоки цитат и блоки `details`.

## Три уровня разметки Telegram — не путать

| | Клиентский ввод | Rich Markdown (Bot API) | MarkdownV2 (Bot API) |
|---|---|---|---|
| Где | набор в приложении | `sendRichMessage` | `sendMessage` с `parse_mode` |
| `__текст__` | курсив | жирный | подчёркивание |
| Заголовки, таблицы, сноски | нет | да | нет |
| Справочник | [telegram.md](telegram.md) | этот файл | не покрыт скиллом |

## Правила

- ЕСЛИ формируешь `InputRichMessage` -> заполняй ровно одно поле из `markdown`, `html`, `blocks`
- ЕСЛИ содержимое генерирует модель -> бери `markdown`: он совместим с GFM, а `blocks` требует ручной сборки JSON-дерева
- ЕСЛИ нужно подчёркивание, индексы, карта, коллаж или сворачиваемый блок -> Markdown-синтаксиса для них нет, используй HTML-теги
- ЕСЛИ нужен Markdown внутри HTML-блока -> он разберётся только в `<details>`, `<tg-collage>` и `<tg-slideshow>`; в остальных блочных тегах пиши только HTML
- ЕСЛИ в ячейке таблицы нужен список, цитата или медиа -> так нельзя, ячейка принимает только инлайн-форматирование
- ЕСЛИ вставляешь медиа -> отдельным блоком и только по HTTP/HTTPS-ссылке; ранее загруженные файлы — через `tg://photo?id=` и поле `media`
- ЕСЛИ отчёт длинный -> считай не только символы: строки таблиц и элементы списков расходуют лимит в 500 блоков
- ЕСЛИ текст переносится из README -> `__` здесь жирный, а в приложении Telegram тот же текст даст курсив
- НИКОГДА не переноси клиентские привычки в Rich Markdown и наоборот — это разные парсеры

## Примеры

### Пример 1: Структурированный отчёт бота

**Запрос:** Бот отправляет недельный отчёт с таблицей, формулой и сноской.

**Маршрут:** поле `markdown` в `InputRichMessage`, метод `sendRichMessage`.

**Результат:**

````markdown
## Отчёт за неделю

Выручка выросла на **12 %**, отток снизился до __2,1 %__.
Главная метрика — удержание на 7-й день[^r7].

| Метрика | План | Факт |
|:--------|-----:|-----:|
| Выручка | 100  | 112  |
| Отток   | 2,5  | 2,1  |

$$R_7 = U_7 / U_0$$

[^r7]: Доля пользователей, вернувшихся на седьмой день.
````

### Пример 2 (edge-case): вёрстка упирается в ограничения парсера

**Запрос:** В ячейку таблицы нужен список, а весь блок — свернуть; внутри — картинка.

**Что нельзя и чем заменить:**

| Замысел | Почему не работает | Решение |
|---|---|---|
| Список внутри ячейки | ячейки принимают только инлайн-форматирование | перечисление через запятую или `<br>`-разделённый текст |
| Картинка внутри ячейки | медиа — только отдельным блоком | вынести медиа-блок под таблицу |
| Markdown внутри `<aside>` | Markdown не разбирается внутри блочных тегов кроме трёх | писать содержимое `<aside>` HTML-тегами |
| Markdown внутри `<details>` | работает — это одно из трёх исключений | оставить как есть |
| Таблица на 400 строк | 500 блоков считаются вместе со строками таблиц | разбить на несколько сообщений |

## Границы проверки

- Все синтаксические факты, цитаты ограничений и числа лимитов сверены по первоисточнику `core.telegram.org/bots/api` (разделы Rich Message Formatting Options, Rich Message Limits, Rich Markdown style, Rich HTML style, `InputRichMessage`, `sendRichMessage`) и по `core.telegram.org/bots/api-changelog` — **28.07.2026**.
- Объекты `RichBlock*` и `InputRichBlock*` намеренно не расписаны: это API-справочник, а не разметка. Полный список — в документации.
- Отрисовка в клиентах не проверялась: сверялась документация, а не фактическое поведение приложений.
- Классический `MarkdownV2` (режим `parse_mode` у `sendMessage`) этим файлом не покрыт.
