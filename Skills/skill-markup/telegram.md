# Telegram: разметка при наборе сообщения в клиенте

Что реально разбирается, когда сообщение набирают руками в приложении Telegram. Набор коротким не кажется, а он именно такой: шесть последовательностей.

**Область:** Telegram Desktop (сборка для Windows, Linux и macOS) и нативный Telegram для macOS. Это **разные приложения на разных кодовых базах**, поэтому условия у них различаются и проверены по отдельности.

**Отсечка:** здесь только клиентский ввод. Разметка, которую бот отправляет через Bot API, — другой слой с другими правилами (заголовки, списки, таблицы, медиа), и в приложении она не вводится. Её справочник — [telegram-bot-api.md](telegram-bot-api.md). Не путать.

**Источник:** исходный код официальных клиентов, ветки по умолчанию на дату исследования. Официальной документации по клиентскому разбору разметки Telegram не публикует. **iOS, Android и веб-клиент не проверялись** — см. «Границы проверки» в конце.

---

## Основная таблица

| Последовательность | Результат | Desktop | Telegram для macOS |
|---|---|:---:|:---:|
| `**текст**` | жирный | да | да |
| `__текст__` | курсив | да | да |
| `~~текст~~` | зачёркнутый | да | да |
| `` `текст` `` | моноширинный | да | да |
| ` ```текст``` ` | блок кода | да | да |
| ` ````текст```` ` | блок кода | нет | да |
| `\|\|текст\|\|` | спойлер | да | да |
| `@123456789 (Имя)` | упоминание по числовому id | не найдено | да |
| `^^текст^^` | подчёркивание | **нет** | не найдено |

Одиночные `*текст*` и `_текст_` в таблице разбираемых последовательностей отсутствуют — работают только парные `**` и `__`.

**Подчёркивание в Desktop:** последовательность `^^` в коде объявлена, но из разбора исключена — рядом стоит комментарий «kTagUnderline is not used for Markdown», строка с подчёркиванием в таблице разбираемых выражений закомментирована. Подчёркивание доступно только через меню и сочетание клавиш.

## Ключевое отличие от Markdown

`__текст__` в клиенте даёт **курсив**. В CommonMark и GFM та же последовательность означает жирный, и в Rich Markdown для ботов ([telegram-bot-api.md](telegram-bot-api.md)) — тоже жирный. Один и тот же текст, перенесённый из README в поле ввода Telegram, поменяет начертание.

## Условия срабатывания: Telegram Desktop

Мало написать правильные символы — вокруг них должно быть правильное окружение.

### Что допустимо непосредственно перед открывающей последовательностью

Базовый набор одинаков для всех типов:

```
пробел  перевод строки  возврат каретки  табуляция
. , : ; < > | ' " [ ] { } ! ? % ^ ( ) - + =
« » “ ” ‘ ’ …
```

Плюс начало текста и служебные символы разбиения абзацев. Каждый тип добавляет к базовому набору свои символы:

| Тип | Дополнительно допустимо перед открывающей |
|---|---|
| Жирный `**` | `` ` `` `~` `/` |
| Курсив `__` | `` ` `` `*` `~` `/` |
| Зачёркнутый `~~` | `` ` `` `*` `~` `/` |
| Моноширинный `` ` `` и блок ` ``` ` | `*` `~` `/` |
| Спойлер `\|\|` | `\|` `*` `~` `/` |

Буква или цифра вплотную перед открывающей последовательностью разбор отменяет: `слово**жирный**` не сработает, `слово **жирный**` сработает.

### Что запрещено сразу после открывающей последовательности

| Тип | Запрещённый следующий символ |
|---|---|
| Жирный | `*` |
| Курсив | `_` |
| Зачёркнутый | `~` |
| Моноширинный | `` ` ``, перевод строки, возврат каретки |
| Блок кода | `` ` `` |
| Спойлер | `\|` |

Поэтому пустая конструкция `****` не превращается ни во что, а `` ` `` с переводом строки сразу за ним не открывает инлайн-код.

### Особенность зачёркивания

У зачёркнутого текста, в отличие от остальных типов, **нет требования к символу после закрывающей последовательности** — соответствующее поле в таблице выражений пустое. Практически `~~` — самая терпимая к окружению последовательность из шести.

### Когда разметка превращается в форматирование

Не в момент набора. Функция мгновенной замены в коде отключена явным образом; найденные последовательности накапливаются и применяются при извлечении текста из поля, то есть **при отправке**.

В поле ввода звёздочки и апострофы видны до последнего — это нормальное поведение, а не признак того, что разметка не распозналась.

## Условия срабатывания: Telegram для macOS

Разбор устроен одним регулярным выражением, условия строже.

**Инлайновые последовательности** (`` ` ``, `**`, `__`, `~~`, `||`):

- перед открывающей — **начало строки или пробел**, и ничего другого;
- после закрывающей — **пробел, конец текста или один из символов** `.` `,` `:` `?` `!` `;`;
- содержимое **не может содержать перевод строки**: многострочный жирный не соберётся, разметка останется текстом.

**Блок кода:**

- принимаются и три, и четыре апострофа: ` ``` ` и ` ```` `;
- содержимое многострочное — единственный тип без запрета на переводы строки;
- **первая строка после открывающих апострофов становится указанием языка**, если в ней нет пробелов и переводов строки; иначе она остаётся частью кода;
- перед открывающими — начало строки, пробел или перевод строки; после закрывающих — пробел, перевод строки, конец текста или `.` `,` `:` `?` `!` `;`.

**Упоминание по идентификатору:** `@123456789 (Отображаемое имя)` — числовой id, необязательные пробелы, имя в круглых скобках. В таблице разметки Desktop аналога не найдено.

**Условие для всех типов:** если внутри найденного фрагмента уже есть форматирование, наложенное раньше, разбор для этого фрагмента отменяется и символы остаются как есть.

## Что разметкой в клиенте получить нельзя

Ни в Desktop, ни в macOS ни одна из этих конструкций не разбирается — останется буквальным текстом:

- заголовки `# Заголовок`
- списки `- пункт`, `1. пункт`, чек-листы `- [ ]`
- цитаты `> текст`
- ссылки `[текст](адрес)`
- таблицы `| столбец |`
- сноски `[^1]`
- формулы `$x^2$`
- сворачиваемые блоки, медиа, карты, коллажи
- подчёркивание

Первые шесть пунктов существуют в серверной разметке для ботов (см. отсечку в начале), но для ввода в приложении не предназначены. В клиенте то же самое доступно только визуальным редактором для подписчиков Telegram Premium.

## Чем добрать недостающее в Desktop

Сочетания клавиш из заголовочного файла поля ввода; на macOS вместо `Ctrl` действует `Cmd`.

| Действие | Сочетание |
|---|---|
| Жирный | стандартное системное для «Bold» |
| Курсив | стандартное системное для «Italic» |
| Подчёркнутый | стандартное системное для «Underline» |
| Зачёркнутый | `Ctrl+Shift+X` |
| Моноширинный | `Ctrl+Shift+M` |
| Цитата | `Ctrl+Shift+.` |
| Спойлер | `Ctrl+Shift+P` |
| Ссылка | `Ctrl+K` |
| Дата и время | `Ctrl+Shift+D` |
| Снять форматирование | `Ctrl+Shift+N` |

Три первых сочетания заданы в коде системными константами, а не литералами, поэтому конкретные клавиши зависят от платформы; обычно это `Ctrl+B`, `Ctrl+I`, `Ctrl+U`.

**Урезанный набор:** в полях заметок доступны только жирный, курсив, подчёркнутый, зачёркнутый, спойлер и снятие форматирования — цитаты, моноширинного, ссылки и даты там нет.

## Правила

- ЕСЛИ перед открывающей последовательностью стоит буква или цифра -> разбор отменяется; поставь пробел или начни строку заново
- ЕСЛИ текст пойдёт в Telegram для macOS -> держи инлайновые фрагменты однострочными и закрывай их перед пробелом, концом текста или `.` `,` `:` `?` `!` `;`
- ЕСЛИ нужен блок кода на обоих клиентах -> используй три апострофа; четыре понимает только Telegram для macOS
- ЕСЛИ нужна таблица -> оформи её блоком кода: синтаксис таблиц клиент не разбирает, а моноширинный шрифт сохранит выравнивание по столбцам
- ЕСЛИ нужны заголовки, списки, цитаты или ссылки -> разметкой их не получить; в Desktop используй сочетания клавиш и меню форматирования
- ЕСЛИ текст переносится из README или другого Markdown -> проверь `__`: в клиенте это курсив, а не жирный
- ВСЕГДА помни, что разметка применяется при отправке, а не при наборе — символы в поле ввода до последнего видны
- НИКОГДА не рассчитывай на `^^текст^^` для подчёркивания — оно не работает ни в одном из проверенных клиентов

## Примеры

### Пример 1: Сообщение, безопасное для обоих клиентов

**Запрос:** Оформить недельный отчёт так, чтобы разметка гарантированно сработала и в Desktop, и в Telegram для macOS.

Каждая конструкция удовлетворяет условиям обоих клиентов: открывающие последовательности стоят после пробела или в начале строки, закрывающие — перед пробелом, точкой или концом строки, инлайновые фрагменты однострочные.

````
**Отчёт за неделю**

Выручка выросла на 12 %, отток снизился до 2,1 %.
Главная метрика — __удержание на 7-й день__.

Сырые цифры до ревизии: ||были завышены на 4 %||.

Формула: `R7 = U7 / U0`

```
Метрика   План    Факт
Выручка   100     112
Отток     2,5     2,1
```

~~Старый прогноз отменён~~
````

Таблица оформлена блоком кода намеренно — настоящий синтаксис таблиц клиент не понимает.

### Пример 2: Разметка не сработала — что чинить

**Запрос:** Пользователь жалуется, что звёздочки остались в отправленном сообщении.

| Что набрано | Почему не сработало | Как починить |
|---|---|---|
| `Итого**42**` | буква вплотную перед открывающей `**` | `Итого **42**` |
| `**Отчёт`<br>`за неделю**` | в Telegram для macOS инлайн не может содержать перевод строки | держать фрагмент в одной строке |
| ` ````код```` ` | четыре апострофа Desktop не разбирает | три апострофа |
| `^^важно^^` | подчёркивание через разметку не задаётся | меню форматирования или системное сочетание для «Underline» |
| `# Заголовок` | заголовки в клиенте не разбираются | `**Заголовок**` отдельной строкой |

## Границы проверки

- Проверены ветки по умолчанию **на дату исследования**; в других сборках набор может отличаться. Конкретная дата в источнике-исследовании не зафиксирована.
- **iOS, Android и веб-клиент не проверялись.** По Android при разборе смежного вопроса сверялся тот же набор из шести последовательностей, но условия окружения для него не выяснялись.
- Принадлежность библиотеки `lib_ui` сборке Telegram Desktop **выведена** из структуры репозиториев, файлом сборки не подтверждена.
- Момент применения разметки установлен только для Desktop. Для macOS соответствующая функция найдена, но точка её вызова не прослежена.
- Поведение при вставке в **визуальный редактор** для Telegram Premium не проверялось.
- Источник — исходный код клиентов (`desktop-app/lib_ui`: `input_field.cpp`, `input_field.h`, `text_entity.cpp`; `overtake/TelegramSwift`: `ChatTextInputAttribute.swift`), а не документация: официального описания клиентского разбора Telegram не публикует.
