# Funnel Analysis

## Назначение

Процедура построения и анализа воронок: определение шагов, расчёт конверсии, диагностика drop-off, приоритизация оптимизаций.

## Построение воронки

### Шаг 1: Определить целевое действие

Целевое действие -- конечный шаг воронки, отражающий бизнес-ценность.

| Тип продукта | Типичное целевое действие |
|---|---|
| E-commerce | Завершённая покупка (purchase) |
| SaaS | Активация (выполнение ключевого действия) |
| Marketplace | Первая транзакция (buyer и seller) |
| Media/Content | Подписка или завершение просмотра |
| Fintech | Одобренная заявка / первая транзакция |

### Шаг 2: Определить шаги воронки

Правила формирования шагов:

- **Линейность** -- каждый шаг предшествует следующему (нет параллельных путей в одной воронке)
- **Полнота** -- между шагами нет скрытых промежуточных действий
- **Измеримость** -- каждый шаг трекается событием в аналитике
- **3-7 шагов** -- меньше 3 = не информативно; больше 7 = сложно анализировать

Шаблон определения шагов:

| # | Шаг | Событие (event) | Условие |
|---|---|---|---|
| 1 | [Название шага] | [event_name] | [Фильтры, если есть] |
| 2 | ... | ... | ... |
| N | Целевое действие | ... | ... |

### Шаг 3: Выбрать параметры

| Параметр | Варианты | Когда использовать |
|---|---|---|
| Окно конверсии | 30 мин, 1 день, 7 дней, 30 дней | Короткое -- для сессионных воронок; длинное -- для lifecycle |
| Тип подсчёта | Уникальные пользователи / Все события | Уникальные -- стандарт; все события -- для повторных действий. Доля уникальных растёт с длиной периода: периоды разной длины сравнивай по средней дневной доле -> [kpi-framework.md](kpi-framework.md) |
| Порядок шагов | Строгий / Нестрогий | Строгий -- для checkout; нестрогий -- для исследовательских сценариев |
| Платформа | Все / Web / iOS / Android | Разбивать по платформе ЕСЛИ UX различается |

## Анализ drop-off

### Метрики воронки

| Метрика | Формула | Что показывает |
|---|---|---|
| Step Conversion Rate | Users_step_N / Users_step_N-1 | Конверсия между соседними шагами |
| Overall Conversion Rate | Users_last_step / Users_first_step | Сквозная конверсия всей воронки |
| Drop-off Rate | 1 - Step Conversion Rate | Доля потерянных пользователей на шаге |
| Drop-off Volume | Users_step_N-1 - Users_step_N | Абсолютное число потерянных |
| Median Time Between Steps | median(time_step_N - time_step_N-1) | Скорость прохождения шага |

### Диагностика drop-off

Для каждого шага с drop-off > 20% (или выше нормы для отрасли):

1. **Где** -- на каком шаге максимальный абсолютный drop-off (не относительный)
2. **Кто** -- какие сегменты отваливаются больше (разрезы: платформа, источник трафика, новые/старые, гео)
3. **Когда** -- есть ли временные паттерны (день недели, время суток, после обновления)
4. **Почему** -- гипотеза о причине:

| Паттерн drop-off | Вероятная причина | Проверка |
|---|---|---|
| Резкий рост drop-off с определённой даты | Баг, изменение UX, технический сбой | Сравнить с датами релизов |
| Drop-off выше на mobile | UX не адаптирован под мобильные | Сравнить воронки по платформам |
| Drop-off выше для нового трафика | Несоответствие ожиданий из рекламы | Сравнить по источникам трафика |
| Drop-off на шаге с формой | Слишком много полей, валидация | Анализ field-level drop-off |
| Drop-off после загрузки страницы | Медленная загрузка | Сравнить время загрузки vs конверсию |
| Одинаковый drop-off по всем сегментам | Системная проблема (цена, ценностное предложение) | Качественное исследование (опросы) |

## Оптимизация конверсии

### Приоритизация

Используй формулу Impact Score для приоритизации шагов оптимизации:

```
Impact Score = Drop-off Volume * Potential Uplift * Ease of Fix
```

| Фактор | Шкала | Описание |
|---|---|---|
| Drop-off Volume | Абсолютное число | Сколько пользователей теряем |
| Potential Uplift | 0.0 - 1.0 | Реалистичный % улучшения (обычно 0.05-0.30) |
| Ease of Fix | 1 (сложно) - 5 (просто) | Усилия на реализацию |

### Формулировка гипотез

Формат гипотезы для оптимизации:

```
ЕСЛИ [изменение],
ТО [метрика шага] вырастет на [ожидаемый %],
ПОТОМУ ЧТО [причина, основанная на данных drop-off].
Проверка: [метод -- A/B-тест, до/после, пилот на сегменте].
```

### Типичные оптимизации по типу шага

| Тип шага | Оптимизации |
|---|---|
| Лендинг -> Действие | Улучшить CTA, сократить текст, добавить social proof |
| Регистрация | Уменьшить число полей, добавить OAuth, отложить необязательные поля |
| Добавление в корзину | Показать цену раньше, добавить сравнение, улучшить фото |
| Оформление заказа | Гостевой checkout, прогресс-бар, сохранение данных, меньше шагов |
| Оплата | Добавить способы оплаты, показать безопасность, упростить форму |
| Onboarding | Сократить шаги, показать ценность раньше, добавить skip |

## Бенчмарки конверсии

Референсные значения для калибровки ожиданий (медианы по индустрии):

| Воронка | Overall CR | Источник вариации |
|---|---|---|
| E-commerce: посещение -> покупка | 1-3% | Трафик, цена, ниша |
| SaaS: посещение -> trial sign-up | 2-7% | B2B vs B2C, цена |
| SaaS: trial -> paid | 10-25% | Модель (freemium vs trial) |
| Mobile app: install -> registration | 30-60% | Обязательность регистрации |
| Mobile app: registration -> activation | 15-40% | Сложность onboarding |
| Checkout: корзина -> оплата | 30-70% | Число шагов, способы оплаты |

**ВАЖНО:** Бенчмарки -- ориентир, не цель. Сравнивай с собственной динамикой, а не с "индустрией".

## Примеры

### Пример 1: E-commerce checkout

**Вход:** Данные о 50 000 пользователей, добавивших товар в корзину за месяц.

**Результат:**
- Воронка: Корзина (50K) -> Оформление (28K, 56%) -> Доставка (22K, 79%) -> Оплата (15K, 68%) -> Подтверждение (13.5K, 90%)
- Overall CR: 27%
- Главный drop-off: Корзина -> Оформление (44%). Причина: обязательная регистрация.
- Рекомендация: гостевой checkout. Impact Score: High.

### Пример 2: Воронка с одинаковым drop-off по всем шагам

**Вход:** Все шаги показывают drop-off 25-30%, нет явного "узкого горлышка".

**Результат:**
- Ровный drop-off указывает на системную проблему (не UX конкретного шага).
- Проверить: ценностное предложение, соответствие трафика продукту, ценообразование.
- Рекомендация: качественное исследование (опросы, интервью) вместо оптимизации отдельных шагов.
