# Молчаливые отказы: ответ успешный, результат неверный

Это ядро скилла. Класс отказов, ради которого он существует: **инструмент отвечает «успешно» и возвращает правдоподобные данные, которые неверны.** Окно «изменено» до размера, которого не приняло; страница «прочитана», но половина её содержимого невидима; журнал сети «пуст», хотя запросы были; значение поля получено, а на деле подменено заглушкой; клик «выполнен» мимо цели.

Ни одно из этих расхождений из схемы инструмента не видно.

Если у вас **видимая ошибка** — текст с описанием сбоя, обрыв связи, отказ инструмента — вам не сюда, а в [troubleshooting.md](troubleshooting.md). Здесь только случаи, когда внешнего признака поломки нет.

## Индекс: симптом → причина → куда идти

| Что вы видите | Что произошло на самом деле | Куда идти |
|---|---|---|
| Инструменты перестали отвечать, ошибки нет, браузер выглядит рабочим | Модальный диалог (`alert`, `confirm`, `prompt`, `beforeunload`, окно печати) остановил цикл событий страницы. Скрипты расширения живут в том же цикле и тоже стоят | [troubleshooting.md](troubleshooting.md) |
| Всё зависло сразу после нажатия на поле выбора файла или кнопку загрузки | Открылось нативное окно выбора файла — тот же блокиратор, агент его не видит и закрыть не может | [tools-act.md](tools-act.md), [troubleshooting.md](troubleshooting.md) |
| Клик «выполнен», ввод «напечатан», страница не изменилась | Координаты устарели: страница прокрутилась или перерисовалась. **Промах по координатам не даёт ошибки** | [tools-act.md](tools-act.md) |
| То же самое внутри `browser_batch` | Координаты в пакете относятся к снимку, сделанному **до** вызова. Снимок внутри того же пакета для расчёта координат непригоден | [tools-session.md](tools-session.md) |
| Элемент отчётливо виден на снимке экрана, но `read_page`, `get_page_text` и `find` его не находят | Элемент лежит в теневом дереве (закрытом **или открытом**) либо в кадре с другого источника. Для трёх инструментов чтения он гарантированно невидим. Повторять поиск и менять формулировку запроса бесполезно | [tools-read.md](tools-read.md) |
| Журнал консоли или сети пуст, «значит событий не было» | Запись начинается **с первого вызова соответствующего инструмента**, а не с загрузки страницы. Сообщения времени загрузки уже потеряны | [tools-debug.md](tools-debug.md) |
| Значение поля в результате `javascript_tool` — строка `[BLOCKED: Sensitive key]` | Имя ключа похоже на чувствительное (`secret`, `token`, `password`, `apiKey`, `authorization` — подстрокой, без учёта регистра). Значение подменено, ошибки нет | [tools-debug.md](tools-debug.md) |
| `resize_window` ответил «успешно» и повторил запрошенные числа, а окно другое | Размер молча подтянут до минимума 500×375. Ошибки при этом не будет | [tools-window-media.md](tools-window-media.md) |
| Окно изменено, а вёрстка «не отзывается»: `innerWidth` и строка `Viewport` прежние | Рабочая вкладка неактивна в своём окне — у невидимой вкладки Chrome не пересчитывает область просмотра | [tools-window-media.md](tools-window-media.md) |
| Контекст быстро кончается на отладке, поломки не видно | Консоль прочитана без фильтра — выдача забила контекст | [tools-debug.md](tools-debug.md) |
| Работа оборвалась, хотя пользователь ничего специально не делал | Нажата кнопка «Cancel» на полосе `'Claude' started debugging this browser` — она отцепляет отладчик | [troubleshooting.md](troubleshooting.md) |
| Инструменты отказывают на одной конкретной вкладке, на остальных всё работает | На этой вкладке открыта панель разработчика: Chrome отцепляет отладчик расширения | [troubleshooting.md](troubleshooting.md) |
| В управляемой организации отказ на части сайтов, списки разрешённых сайтов в продукте ни при чём | Корпоративная политика Chrome `ExtensionSettings` перекрывает даже разрешение `debugger`. Внятного симптома у этого отказа нет | [permissions.md](permissions.md) |

## Как сверять: независимая проверка по классам результата

Общее правило: **сверять результат независимым способом, а не по ответу инструмента.** Это дороже на один вызов и надёжнее на порядок.

| Что проверяем | Чем **нельзя** проверять | Чем проверять |
|---|---|---|
| Размер окна и области просмотра | Ответом `resize_window` — он повторяет запрошенные числа | Строкой `Viewport: ШхВ` в конце вывода `read_page`, либо снимком экрана. Плюс убедиться, что вкладка активна |
| Значение поля формы | Ответом `form_input` — он рапортует об успехе | Чтением `value`, `checked` или значения списка через `javascript_tool`, либо повторным `read_page` |
| Факт клика | Ответом `computer` — «Clicked» приходит и при промахе | Изменением состояния страницы: снимок до и после, чтение целевого текста, `read_page` |
| Отсутствие элемента | Пустым или упавшим `find` | Снимком экрана. Виден на снимке — элемент есть, просто он вне дерева доступности |
| Пустой журнал консоли или сети | Самим фактом пустоты | Убедиться, что инструмент уже вызывался **до** воспроизведения. Пустой журнал читать как «запись, возможно, ещё не включена», а не как «событий не было» |
| Значение, полученное из `javascript_tool` | Правдоподобностью строки | Проверить, что имя поля не похоже на чувствительное; при сомнении вернуть голое выражение или переименовать поле |
| Факт загрузки файла | Строкой `Uploaded 1 file(s) … (0 KB total)` — размер округляется до нуля | Содержимым поля на странице: обработчик `change`, `read_page`, снимок |

**Когда сверка не сошлась — не повторять то же действие.** Два-три неудачных подхода — повод остановиться и спросить пользователя, а не перебирать формулировки. Поводы для остановки, названные встроенным руководством: неожиданная сложность, ошибки инструментов, молчание расширения, элементы не реагируют, страницы не грузятся.
