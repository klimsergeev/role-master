# Чтение страницы: `read_page`, `get_page_text`, `find`

Три инструмента чтения и одно общее свойство, которого нет ни в схемах, ни в документации: **они слепы к теневому дереву и к кадрам с других источников**. Раздел «Чего эти три инструмента не видят» — главное в этом файле.

> Пометки происхождения: **наблюдение** — измерено живым прогоном инструмента; **по схеме** — взято из схемы инструмента и вживую не проверялось. Срез данных — в SKILL.md.

---

## `read_page`

**Назначение.** Получить представление страницы в виде дерева доступности (accessibility tree). Возвращает ссылки-идентификаторы элементов (`ref_1`, `ref_2`, …), которые дальше используются в `computer`, `find`, `form_input`, `file_upload`, `upload_image`.

**Параметры**

| Параметр | Тип | Обязательный | По умолчанию | Что делает |
|---|---|---|---|---|
| `tabId` | number | да | — | Вкладка |
| `filter` | string | нет | все элементы | `"interactive"` — только кнопки, ссылки, поля ввода; `"all"` — все элементы, включая невидимые |
| `depth` | number | нет | **15** | Максимальная глубина обхода |
| `max_chars` | number | нет | **50 000** | Предел вывода в символах |
| `ref_id` | string | нет | — | Прочитать конкретный элемент со всеми потомками |

**Ограничения**

- По умолчанию возвращаются **все элементы, включая невидимые**. Для кликов это лишний шум — брать `filter: "interactive"`.
- При превышении предела вывод обрезается по границе строки с пометкой о полном размере. Лечение по схеме: увеличить `max_chars`, либо уменьшить `depth`, либо сузиться через `ref_id`.
- **Предел в 50 000 символов задан ради контекста модели, а не каналом связи.** Канал в направлении «расширение → Claude Code» имеет потолок 64 МиБ, до него отсюда очень далеко. Практически это значит, что поднимать `max_chars` технически можно смелее, чем кажется: упрётесь в контекст, а не в канал. Слепо поднимать его на большой странице всё равно не стоит — по той же причине, ради контекста.

**Формат вывода** (наблюдение). По одной строке на элемент, идентификатор в квадратных скобках, атрибуты хвостом, и **отдельная последняя строка с размером области просмотра, которой нет в схеме**:

```
link "Learn more" [ref_1] href="https://iana.org/domains/example"

Viewport: 1512x744
```

С `filter: "all"` добавляются неинтерактивные узлы, вложенность передаётся отступом:

```
heading "Example Domain" [ref_2]
generic "This domain is for use in documentation examples without needing permission. Avoid use in operations" [ref_3]
link "Learn more" [ref_1] href="https://iana.org/domains/example"
```

Элементы формы отдаются с типом, значением и раскрытым списком вариантов:

```
textbox "Name field" [ref_6] type="text" placeholder="Name field"
checkbox "on" [ref_7] type="checkbox"
combobox "Beta" [ref_8]
 option "Alpha" value="a"
 option "Beta" (selected) value="b"
```

Строка `Viewport` полезна отдельно: это независимый способ проверить фактический размер области просмотра после `resize_window`.

**Как ведут себя идентификаторы элементов** (наблюдение)

- Нумерация сквозная **в пределах вкладки** и не сбрасывается между вызовами: на одной вкладке выдавались `ref_1`…`ref_13`, у соседней вкладки нумерация своя.
- Повторный `read_page` возвращает **те же** идентификаторы для тех же элементов: за три последовательных вызова `ref_6` оставался тем же полем ввода.
- Динамически добавленные элементы получают следующие свободные номера и появляются в дереве сразу, без перезагрузки страницы.

## `get_page_text`

**Назначение.** Извлечь сырой текст страницы с приоритетом основного содержимого. «Ideal for reading articles, blog posts, or other text-heavy pages. Returns plain text without HTML formatting.»

**Параметры**

| Параметр | Тип | Обязательный |
|---|---|---|
| `tabId` | number | да |

Других параметров нет — ограничить объём вывода нечем.

**Ограничения.** Структуры и идентификаторов элементов не даёт: для взаимодействия не годится, только для чтения.

**Формат вывода** (наблюдение). Начинается тремя служебными строками, о которых схема не говорит:

```
Title: Example Domain
URL: https://example.com/
Source element: <body>
---
Example Domain
...
```

Строка `Source element` показывает, **сработал ли отбор основного содержимого**. На обычной странице там `<body>`; на статье может оказаться более узкий контейнер — и тогда всё, что вне него, в вывод не попало. Это единственный доступный признак того, что текст мог прийти неполным.

## `find`

**Назначение.** Найти элементы описанием на естественном языке — по назначению («search bar», «login button») или по тексту («organic mango product»). Возвращает ссылки-идентификаторы для других инструментов.

**Параметры**

| Параметр | Тип | Обязательный |
|---|---|---|
| `query` | string | да |
| `tabId` | number | да |

**Ограничения**

- В выводе **не более 20 совпадений**; при большем числе приходит уведомление с просьбой уточнить запрос.
- Работает по тому же дереву доступности, что и `read_page`, — значит наследует оба его слепых пятна (см. ниже).

**Формат ответа** (наблюдение) — заголовок с числом, затем строки с идентификатором, ролью и пояснением, почему элемент подошёл:

```
Found 1 matching element

- ref_1: link "Learn more" (link) - This link provides additional information about the domain, matching the query for "more information link"
```

Инструмент сообщает **полное** число совпадений, а не только факт превышения:

```
Found 93 matching elements (showing first 20, use a more specific query to narrow results)
```

Число полезно само по себе: по нему видно, насколько запрос широк.

**Отсутствие совпадений — ошибка, а не пустой список** (наблюдение). Вместе с ней приходит краткий пересказ того, что на странице есть:

```
The query "SECRET_CLOSED_BUTTON" does not match any elements in the accessibility tree. The page contains only a heading ("Example Domain"), a generic text description, and a "Learn more" link.
```

Практическое следствие: `find` без гарантированного совпадения **прерывает `browser_batch`** — см. [tools-session.md](tools-session.md).

## Чего эти три инструмента не видят

**Ни `read_page`, ни `get_page_text`, ни `find` не возвращают содержимое теневого дерева (ни закрытого, ни открытого) и кадров с других источников.** При том что на снимке экрана это содержимое отчётливо видно.

**Как это измерено.** На странице `example.com` созданы четыре объекта: узел с **закрытым** теневым корнем (внутри кнопка и абзац), узел с **открытым** теневым корнем (то же содержимое), встроенный кадр с **другого источника**, и — как **контроль** — обычная кнопка в основном документе. Все четыре отрисованы: прямоугольники ненулевые, содержимое читается через `javascript_tool` и видно на снимке. Контроль нужен, чтобы отделить «инструмент не умеет» от «дерево устарело»: без него отрицательный результат ничего не доказывает.

| Объект | Виден на снимке | `read_page` (`all`, глубина 30) | `get_page_text` | `find` | `javascript_tool` |
|---|---|---|---|---|---|
| Контрольная кнопка в основном документе | да | **да**, сразу | **да** | да | да |
| Открытое теневое дерево | да | **нет** | **нет** | нет | **да**, через `.shadowRoot` |
| Закрытое теневое дерево | да | **нет** | **нет** | нет | **нет**, `.shadowRoot` равен `null` |
| Кадр с другого источника | да | **нет** | **нет** | нет | нет, доступ к документу кадра запрещён |

Контроль отработал безупречно: обычная кнопка, добавленная в тот же момент теми же средствами, появилась в дереве немедленно. Значит дело не в задержке и не в кэше, а в свойстве обхода.

**Почему это важнее, чем кажется.** Слепота к **открытому** теневому дереву — куда более частый случай, чем к закрытому: на нём построены веб-компоненты, элементы дизайн-систем, встроенные проигрыватели. Типовые пострадавшие — платёжные формы, сторонние виджеты, встроенные редакторы.

**Расхождение с манифестом, механизм не установлен.** Манифест расширения объявляет скрипт сборки дерева доступности с `all_frames: true`, то есть он внедряется и во вложенные кадры. Тем не менее возвращаемое дерево содержало только верхний кадр: на странице со встроенным чужим кадром запрос «Learn more link» дал **одно** совпадение, хотя на снимке таких ссылок две. Наблюдение зафиксировано, **причина расхождения не установлена** — гипотез здесь не выдвигается.

**Что при этом работает — снимок экрана.** Содержимое и теневого дерева, и чужого кадра прекрасно видно на снимке. Путь остаётся: смотреть глазами и кликать по координатам.

**Проходит ли ввод в кадр с другого источника — не проверено.** Одна попытка клика по координатам ссылки внутри такого кадра видимого перехода не дала; дальше проверка не велась по правилу об остановке после 2–3 неудач. Одного наблюдения на вывод не хватает, поэтому **утверждать, что ввод в чужой кадр не проходит, оснований нет**. Действие агента: попробовать координаты, предупредить пользователя, что точность здесь ниже обычного, и предложить запасные пути — прямой адрес кадра или ручное действие пользователя.

**Признак для распознавания**

> Если элемент отчётливо виден на снимке экрана, но `read_page` и `find` его не находят — это не сбой и не повод повторять вызов. Почти наверняка элемент лежит в теневом дереве или в кадре с другого источника. Переключайтесь на снимок и координаты и предупредите пользователя, что точность здесь ниже.

Тот же признак в диагностическом индексе — [silent-failures.md](silent-failures.md).
