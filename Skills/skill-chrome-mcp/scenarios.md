# Сценарии: под что годится, рабочие последовательности, чеклист

Claude in Chrome — **мост в веб, у которого нет API, работающий внутри живого профиля пользователя.** Отсюда и его сильные стороны, и его границы.

---

## Приоритет инструментов

Дока Claude Code выстраивает порядок сама, и встроенное руководство повторяет его дословно:

**Специализированный MCP-сервер сервиса → Bash → Claude in Chrome → компьютерное управление (computer use).**

О браузерных инструментах там же: «if the target is a web app and there's no dedicated MCP for it, use the browser tools. DOM-aware, much faster than clicking pixels». И прямое указание на случай отсутствия расширения: «If the Chrome extension isn't connected, ask the user to install it rather than falling through to computer use».

**Чем Claude in Chrome отличается от соседних способов**

| Способ | Как работает | Ключевое отличие |
|---|---|---|
| **Claude in Chrome** | Расширение внутри живого профиля Chrome | Наследует сессии входа пользователя, не требует отдельной авторизации в сервисах. Работает в видимом окне: пользователь наблюдает и может вмешаться |
| **Computer use** | Управление экраном macOS через права «Универсальный доступ» и «Запись экрана» | Шире и медленнее. Нужен для нативных приложений и симуляторов. Только macOS, только Pro и Max, не работает в режиме `-p`. Одна сессия за раз |
| **Сторонние браузерные MCP-серверы** | Отдельный сервер поднимает свой экземпляр браузера через отладочный протокол | Изолированный профиль без пользовательских сессий. Не продукт Anthropic; в этом скилле не разбирается |
| **WebFetch и HTTP-клиенты** | Запрос без браузера | Не выполняет JavaScript, не имеет сессии, отсекается защитой от ботов |

Принципиальная разница Claude in Chrome от всего остального — **общий профиль с пользователем**. Это одновременно главное преимущество (доступ к внутренним панелям, устаревшим системам и порталам поставщиков без API) и главный риск (всё, что видно во вкладке, попадает в контекст модели) — см. [security.md](security.md).

## Под что годится

| Сценарий | Почему подходит | Пример запроса |
|---|---|---|
| **Живая отладка** | Читает консоль, сетевые запросы и состояние DOM, тут же правит код | «Open the dashboard page and check the console for any errors when the page loads» |
| **Проверка вёрстки по макету** | Собрать по макету и сверить в браузере | — |
| **Тестирование веб-приложения** | Валидация форм, визуальные регрессии, пользовательские пути | «I just updated the login form validation. Can you open localhost:3000, try submitting the form with invalid data, and check if the error messages appear correctly?» |
| **Работа в приложениях с авторизацией** | Наследует сессии: Google Docs, Gmail, Notion — без коннекторов | «Draft a project update based on the recent commits and add it to my Google Doc at …» |
| **Извлечение данных** | Собрать структурированные данные со страниц и сохранить локально | «Go to the product listings page and extract the name, price, and availability for each item. Save the results as a CSV file» |
| **Заполнение форм** | Повторяющийся ввод данных из локального файла | «I have a spreadsheet of customer contacts in contacts.csv. For each row, go to the CRM …» |
| **Загрузка файлов** | Приложить локальный файл к форме на странице | «Open the bug tracker …, create a new issue, and attach logs/session.log to it» |
| **Процессы через несколько сайтов** | Работа в нескольких вкладках сразу | «Check my calendar for meetings tomorrow, then for each meeting with an external attendee, look up their company website …» |
| **Запись демонстрации** | GIF с наложениями для документации | «Record a GIF showing how to complete the checkout flow …» |
| **Сайты без API** | Внутренние панели, устаревшие системы, порталы поставщиков | Собрать суммы и даты счетов из нескольких порталов поставщиков и построить таблицу |
| **Сайты с защитой от ботов** | HTTP-клиенты не проходят, живой браузер проходит | «Сайт отдаёт HTTP-клиенту заглушку — открой страницу в Chrome и собери данные оттуда» |

Полезная деталь: «Claude has built-in knowledge of how to navigate popular platforms including Slack, Google Calendar, Gmail, Google Docs, and GitHub. Simple commands like "schedule a meeting" or "update the doc" work without detailed step-by-step instructions.»

## Под что не годится

| Сценарий | Почему |
|---|---|
| Финансовые операции, торговля, переводы | Неснимаемый запрет продукта |
| Регистрация аккаунтов | Неснимаемый запрет |
| Ввод карт и удостоверений | Неснимаемый запрет |
| Обход капчи | Неснимаемый запрет; Claude останавливается и просит человека |
| Необратимое удаление (очистка корзины, удаление писем и файлов) | Неснимаемый запрет |
| Сбор изображений лиц | Неснимаемый запрет |
| Работа с медицинскими и регулируемыми данными | Недоступно организациям под HIPAA, не рекомендуется в остальных случаях |
| Юридические документы и договоры | В списке нерекомендуемого |
| Рабочие аккаунты с чувствительными данными компании | В списке нерекомендуемого |
| Массовый сбор данных с чужих сайтов | Ответственность за соблюдение условий использования, включая ограничения на автоматический доступ, лежит на пользователе |
| Управление нативными приложениями и симуляторами | Не браузер — это задача компьютерного управления |
| Работа в стерильном изолированном окружении | Расширение живёт в профиле пользователя со всеми его сессиями |
| WSL, мобильные устройства | Не поддерживаются |

Перечни запретов и нерекомендуемого — в [permissions.md](permissions.md) и [security.md](security.md).

## Пять рабочих последовательностей

### 1. Старт браузерной сессии

1. `tabs_context_mcp` — проба живости канала. Отказ ровно один: «Browser extension is not connected…» (в [troubleshooting.md](troubleshooting.md)). Любой другой ответ — связь есть, чинить нечего; штатный ответ с группой и «No tab group exists…» — примеры такого ответа, а не полный их перечень. Незнакомый текст ошибки — не выдавать за норму: показать пользователю и идти в [troubleshooting.md](troubleshooting.md).
2. Завести свою вкладку: `tabs_create_mcp` либо `createIfEmpty: true`. Вкладки пользователя не трогать.
3. `navigate` на адрес.
4. Пауза 2–3 секунды на страницах с тяжёлым JavaScript.
5. Чтение: `get_page_text` для текста, `read_page` с `filter: "interactive"` для взаимодействия.

### 2. Восстановление связи

Шесть шагов по порядку, с остановкой на первом, который помог: расширение включено в `chrome://extensions` → `claude --version` → Chrome запущен → `/chrome` → «Reconnect extension» → перезапуск Claude Code и Chrome → проверка файла конфигурации хоста. Подробности и точки принятия решения — в [troubleshooting.md](troubleshooting.md).

### 3. Выбор браузера, когда подключено несколько

1. `list_connected_browsers`.
2. **Обязательный опрос пользователя** через AskUserQuestion: каждый подключённый браузер — отдельным вариантом, подпись = отображаемое имя, в скобках `deviceId`; плюс финальный вариант с точной формулировкой схемы про экран подтверждения. Пропускать браузеры и выбирать самому запрещено.
3. По выбору: конкретный браузер → `select_browser` с его `deviceId`; финальный вариант → `switch_browser`.

Дословное требование схемы — в [tools-browsers-shortcuts.md](tools-browsers-shortcuts.md).

### 4. Отладка по консоли и сети — порядок перевёрнутый

1. **Сначала** вызвать `read_console_messages` и при необходимости `read_network_requests` — запись начинается с первого вызова.
2. Воспроизвести: перезагрузить страницу или выполнить действие.
3. Прочитать журнал: консоль — обязательно с шаблоном, сеть — с подстрокой в `urlPattern`.
4. Сетевые данные снять **до** перехода на другой домен: при смене домена журнал теряется.
5. Исправить код, перезагрузить, перепроверить.

### 5. Загрузка файла

1. Найти элемент `input[type=file]` через `read_page` или `find` — получить `ref`. **По полю файла не кликать.**
2. Проверить: суммарно менее 10 МБ; файл сессии разрешено читать; у файла не несколько жёстких ссылок (иначе скопировать и грузить копию).
3. `file_upload` с абсолютными путями и `ref`.
4. Сверить результат содержимым поля на странице, а не ответом инструмента.

## Чеклист процедурных приёмов

По одной строке на приём; разбор — по ссылке. Приёмы, повторяющие принципы из SKILL.md, сюда не включены.

**Планирование вызовов**

- Предсказуемые на два и более шага действия складывать в `browser_batch`; координаты внутри пакета — только из снимка, сделанного **до** вызова. → [tools-session.md](tools-session.md)
- Не ставить `find` в середину пакета там, где совпадение не гарантировано: отсутствие совпадений — ошибка, и пакет остановится. → [tools-session.md](tools-session.md)

**Чтение**

- Для чтения статьи — `get_page_text`; для взаимодействия — `read_page` или `find`. Это разные задачи. → [tools-read.md](tools-read.md)
- `read_page` брать с `filter: "interactive"`, иначе 50 000 символов уйдут на невидимые элементы. → [tools-read.md](tools-read.md)
- «Не найдено» сверять со снимком экрана: виден на снимке, но не находится — теневое дерево или чужой кадр, повторять поиск бесполезно. → [tools-read.md](tools-read.md)

**Действие**

- Никогда не кликать по полю выбора файла и кнопке загрузки — только `file_upload` с `ref`. → [tools-act.md](tools-act.md)
- Перед кнопкой, способной вызвать диалог, предупредить пользователя: после срабатывания помочь нельзя, только руками. → [troubleshooting.md](troubleshooting.md)
- Снимок для загрузки делать непосредственно перед загрузкой — идентификаторы протухают. → [tools-act.md](tools-act.md)

**Отладка**

- Включать журналы **до** воспроизведения. → [tools-debug.md](tools-debug.md)
- Консоль читать только с фильтром. → [tools-debug.md](tools-debug.md)
- Сетевые запросы снимать до перехода на другой домен. → [tools-debug.md](tools-debug.md)
- В `javascript_tool` не писать `return` на верхнем уровне. → [tools-debug.md](tools-debug.md)
- Не называть поля результата `javascript_tool` словами вроде `token`, `secret`, `password`, `apiKey`, `authorization`. → [tools-debug.md](tools-debug.md)

**Окно и запись**

- После `resize_window` сверять фактический размер и убедиться, что рабочая вкладка активна. → [tools-window-media.md](tools-window-media.md)
- Перед тем как отдать GIF, предупредить, что запись содержит всё видимое, включая данные аккаунтов. → [security.md](security.md)

**Темп**

- Ждать после навигации. Прямого требования в схемах нет; статья справки признаёт «Some sites with heavy JavaScript may require a moment to fully load», но конкретных интервалов не задаёт ни она, ни схемы. Значение по умолчанию в этом скилле — 2–3 секунды после перехода и 1–2 секунды между страницами при пакетной обработке; это отправная точка, а не измеренная величина: готовность страницы сверять чтением, а не таймером, и увеличивать паузу, если содержимое ещё не пришло.
