# Каркас сессии: вкладки, навигация, пакет

Пять инструментов, с которых начинается и которыми держится любая браузерная задача: `tabs_context_mcp`, `tabs_create_mcp`, `tabs_close_mcp`, `navigate`, `browser_batch`.

> Пометки происхождения: **наблюдение** — измерено живым прогоном инструмента; **по схеме** — взято из схемы инструмента и вживую не проверялось. Срез данных — в SKILL.md.

---

## `tabs_context_mcp`

**Назначение.** Получить сведения о текущей группе вкладок MCP, включая идентификаторы всех вкладок внутри группы.

**Параметры**

| Параметр | Тип | Обязательный | По умолчанию | Что делает |
|---|---|---|---|---|
| `createIfEmpty` | boolean | нет | не задан | Создать новую группу вкладок, если её ещё нет. Вместе с группой создаётся новое окно с пустой вкладкой. Если группа уже есть — ни на что не влияет |

**Ограничения**

- Схема требует этот вызов первым: «You must get the context at least once before using other browser automation tools so you know what tabs exist».
- «Each new conversation should create its own new tab (using `tabs_create_mcp`) rather than reusing existing tabs, unless the user explicitly asks to use an existing tab».
- `createIfEmpty: true` — **флаг, меняющий состояние**. В плановом режиме Claude Code он вызовет запрос разрешения, тогда как вызов без него считается читающим. Полный разбор планового режима — в [permissions.md](permissions.md).

**Форматы ответов**

Группы ещё нет, флаг не передан — приходит подсказка, а **не ошибка**:

```
No tab group exists for this session. Use `createIfEmpty: true` to create one.
```

С `createIfEmpty: true` — объект и его человекочитаемый пересказ:

```json
{"availableTabs":[{"tabId":476391300,"title":"New Tab","url":"chrome://newtab/"}],"tabGroupId":1238964494}
```

**Наблюдения живой проверки**

1. Новая группа создаётся **вместе с новым окном**, и первая вкладка в ней — `chrome://newtab/`. Следствие: `navigate` с адресами `chrome://` работать откажется, хотя начальная вкладка группы именно такая — переходить надо на обычный адрес.
2. **Созданное окно может оказаться не на переднем плане, а вкладка группы — неактивной в своём окне.** У неактивной вкладки `document.visibilityState` возвращает `hidden`. Это источник ловушки с `resize_window` — см. [tools-window-media.md](tools-window-media.md).
3. Блок «Tab Context» с текущим перечнем вкладок группы, их адресами и заголовками **дописывается к ответам почти всех инструментов**. Отдельно вызывать `tabs_context_mcp` ради обновления списка обычно не нужно: он приезжает попутно.

## `tabs_create_mcp`

**Назначение.** Создать новую пустую вкладку в группе вкладок MCP.

**Параметры.** Нет.

**Ограничения.** Та же оговорка: сначала `tabs_context_mcp`.

**Формат ответа** (наблюдение):

```
Created new tab. Tab ID: 476391304
```

---

## `tabs_close_mcp`

**Назначение.** Закрыть вкладку группы по идентификатору — прибрать за собой.

**Параметры**

| Параметр | Тип | Обязательный |
|---|---|---|
| `tabId` | integer | да |

**Ограничения**

- Закрыть можно **только вкладки из группы этой сессии**; допустимые идентификаторы брать из `tabs_context_mcp`.
- «If you close the group's last tab, Chrome auto-removes the group — the next `tabs_context_mcp` with `createIfEmpty` starts fresh».
- Начиная с Claude Code 2.1.221 расширение само закрывает открытые им вкладки, когда они больше не нужны.

**Форматы ответов** (наблюдение):

```
Closed tab 476391304. 1 tab(s) remain.
Closed tab 476391300. Group is now empty (auto-removed).
```

## `navigate`

**Назначение.** Перейти по адресу либо вперёд и назад по истории.

**Параметры**

| Параметр | Тип | Обязательный | Что делает |
|---|---|---|---|
| `url` | string | да | Адрес с протоколом или без (по умолчанию подставляется `https://`); либо строка `"back"`, либо `"forward"` |
| `tabId` | number | зависит от случая — см. ниже | Вкладка, в которой выполняется переход |

**Три случая с `tabId`, и путать их нельзя**

1. **Отдельный вызов с адресом** — `tabId` можно опустить. Тогда `tabs_context_mcp{createIfEmpty: true}` вызывается за вас, навигируется первая вкладка группы, а его результат дописывается к выводу этого вызова — список вкладок и идентификаторы приходят сразу.
2. **Внутри `browser_batch`** — `tabId` **обязателен**. Это касается всех инструментов, действующих на страницу.
3. **Для `url: "back"` и `url: "forward"`** — `tabId` **обязателен всегда**.

Явный `tabId` нужен и тогда, когда в группе несколько вкладок и состояние каждой надо сохранить.

**Форматы ответов** (наблюдение) — три случая различимы по тексту:

```
Navigated to https://example.com
Navigated back to https://example.com/
Navigated forward to https://www.iana.org/help/example-domains
```

**Собственный фильтр адресов строже платформы** (наблюдение). Отклоняются не только служебные схемы браузера, но и `about:blank` — одним и тем же текстом:

```
Can't interact with browser-internal or unparseable URLs. Navigate to a web page first.
```

Проверено на `chrome://settings/` и на `about:blank`. Платформа расширений `about:blank` допускает, а инструмент — нет: пустую страницу как площадку для опытов через `navigate` не получить, работать надо на обычном адресе.

Отказ происходит **до** перехода: вкладка осталась на прежнем адресе, состояние не потеряно.

Перечень страниц, где инструменты отказывают в принципе, — в [troubleshooting.md](troubleshooting.md).

## `browser_batch`

**Назначение.** Выполнить последовательность вызовов браузерных инструментов за один обмен с сервером.

**Параметры**

| Параметр | Тип | Обязательный | Что делает |
|---|---|---|---|
| `actions` | массив объектов `{name, input}`, минимум 1 элемент | да | `input` — ровно тот же набор полей, что и при самостоятельном вызове инструмента |

Пример из схемы:

```json
[
  {"name":"computer","input":{"action":"left_click","coordinate":[100,200],"tabId":123}},
  {"name":"computer","input":{"action":"type","text":"hello","tabId":123}},
  {"name":"navigate","input":{"url":"https://example.com","tabId":123}}
]
```

**Ограничения — здесь важна каждая строка**

- Действия выполняются **последовательно, не параллельно**.
- Выполнение **останавливается на первой ошибке**.
- Проверка разрешений идёт **по каждому пункту отдельно**: «if an action navigates to a domain without permission, the next item's check fails and the batch stops».
- Изображения возвращаются вперемежку с прочими результатами.
- **Координаты, записанные в пакет, относятся к снимку, сделанному ДО вызова.** Рассчитать координаты по снимку, снятому внутри того же пакета, нельзя.
- **Пакеты нельзя вкладывать друг в друга.**
- Внутри пакета `tabId` обязателен для всех инструментов, действующих на страницу, включая `navigate`.
- В плановом режиме пакет проходит без подтверждения только если каждое действие внутри — читающее.

Схема рекомендует применять пакеты активно: «Use this tool extensively to quickly execute work whenever you can predict two or more steps ahead — e.g. navigate, click a field, type, press Return, screenshot».

**Наблюдения живой проверки**

**Остановка на первой ошибке подтверждена, и ответ сообщает, сколько шагов осталось невыполненными.** В пакете из трёх действий второе (`find` без совпадений) упало:

```
actions[1] (find) failed: The query "SECRET_CLOSED_BUTTON" does not match any elements in the accessibility tree. … (1 completed, 1 remaining)
```

Нумерация действий в сообщении — **с нуля** (`actions[1]` — второй элемент). Счётчик «выполнено / осталось» позволяет точно понять, до какого места пакет дошёл, и не переделывать сделанное.

**Что считается ошибкой, а что нет — несимметрично.** Пустой результат сам по себе пакет не рвёт: `read_console_messages` и `read_network_requests` без совпадений, а также `shortcuts_list` без ярлыков возвращают штатный ответ, и пакет продолжается. А `find` без совпадений — именно ошибка. Отсюда правило: **`find` в середине пакета — точка отказа**, и ставить его туда, где совпадение не гарантировано, не следует.

**Изображения приходят вперемежку с текстом**, как и обещает схема: в пакете со снимком и увеличением после текстового ответа каждого действия шло его изображение.

**Смешение инструментов в одном пакете работает** — в одном вызове проходили `resize_window`, `javascript_tool`, `read_page`, `computer` и `navigate`. Ограничение только на вложенность самих пакетов.

**Уточнение к предупреждению схемы о координатах.** Промах по устаревшим координатам молча происходит и **вне** пакета — это общее свойство координатных кликов, а не особенность `browser_batch`. Разбор — в [tools-act.md](tools-act.md), признак распознавания — в [silent-failures.md](silent-failures.md).
