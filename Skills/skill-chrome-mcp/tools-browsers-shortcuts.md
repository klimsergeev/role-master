# Браузеры и ярлыки: `list_connected_browsers`, `select_browser`, `switch_browser`, `shortcuts_list`, `shortcuts_execute`

Пять инструментов, три из которых вживую не прогонялись — причины названы по месту и не сводятся к нехватке доступа. Главное в файле: **выбирать браузер за пользователя запрещено схемой инструмента.**

> Пометки происхождения: **наблюдение** — измерено живым прогоном инструмента; **по схеме** — взято из схемы инструмента и вживую не проверялось. Срез данных — в SKILL.md.

---

## `list_connected_browsers`

**Назначение.** Перечислить все браузеры (экземпляры расширения), подключённые к аккаунту.

**Параметры.** Нет.

**Формат ответа** (наблюдение) — массив объектов JSON:

```json
[{"deviceId":"72e165d1-f191-4f5f-ba27-e9a3a44c15a0","name":"Browser 1","osPlatform":"macOS","connectedAt":1787156506327,"isLocal":true}]
```

| Поле | Что это |
|---|---|
| `deviceId` | Идентификатор для `select_browser` |
| `name` | Отображаемое имя. Пока пользователь не назвал браузер сам — `Browser 1` |
| `osPlatform` | Платформа операционной системы |
| `isLocal` | Признак «похоже, это тот же компьютер» |
| `connectedAt` | Момент подключения в миллисекундах эпохи. **В описании схемы этого поля нет** |

**Жёсткое процедурное требование прямо в схеме, и его нельзя игнорировать:**

> «Before any browser action, you MUST call the AskUserQuestion tool with a question listing EVERY connected browser as a separate option (use the display name as the label, and include the deviceId in parentheses), plus one final option labeled exactly: "Open a confirmation screen in every connected Chrome extension and let me select the right one there." Do not skip any connected browser and do not pick one yourself.»

Дальше по выбору пользователя: конкретный браузер → `select_browser` с его `deviceId`; последний вариант → `switch_browser`.

Почему требование про `deviceId` в подписи варианта не формальность: имя по умолчанию у всех браузеров одинаковое (`Browser 1`), и без идентификатора варианты в опросе неразличимы между машинами.

## `select_browser`

**Назначение.** Выбрать конкретный браузер по `deviceId` без рассылки запроса на сопряжение.

**Параметры**

| Параметр | Тип | Обязательный |
|---|---|---|
| `deviceId` | string | да — из `list_connected_browsers` |

**Когда применять.** После того как пользователь выбрал браузер из списка.

**Вживую не запускался.** Подключён был ровно один браузер, а схема прямо запрещает выбирать за пользователя и требует предварительного опроса. Описание — по схеме.

## `switch_browser`

**Назначение.** Разослать запрос на подключение **во все** браузеры с установленным расширением и ждать, пока пользователь нажмёт «Connect» в нужном.

**Параметры.** Нет.

**Ограничения.** Ожидание **до 2 минут**. При подключении пользователь может дать браузеру имя. Схема расставляет приоритет: «Use this when the user wants to pick the browser themselves from inside Chrome rather than choosing from a list; otherwise prefer `select_browser` with a known deviceId».

**Вживую не запускался.** Вызов разослал бы запрос на подключение во все браузеры и ждал бы ответа до двух минут. Описание — по схеме.

## `shortcuts_list`

**Назначение.** Перечислить доступные ярлыки и рабочие процессы (в терминологии продукта shortcuts и workflows взаимозаменяемы). Возвращает команды, описания и признак «это рабочий процесс».

**Параметры**

| Параметр | Тип | Обязательный |
|---|---|---|
| `tabId` | number | да |

**Формат ответа при отсутствии ярлыков** (наблюдение) — объект, а не ошибка:

```json
{"message": "No shortcuts found", "shortcuts": []}
```

Пустой результат штатный и `browser_batch` не прерывает — в отличие от `find`, см. [tools-session.md](tools-session.md).

---

## `shortcuts_execute`

**Назначение.** Выполнить ярлык или рабочий процесс, запустив его в новом окне боковой панели на текущей вкладке.

**Параметры**

| Параметр | Тип | Обязательный | Что это |
|---|---|---|---|
| `tabId` | number | да | Вкладка |
| `command` | string | нет | Имя команды **без ведущей косой черты**: `debug`, `summarize` |
| `shortcutId` | string | нет | Идентификатор ярлыка |

**Ключевое ограничение.** «This starts the execution and returns immediately - it does not wait for completion». Результата вызывающий агент **не получает** — только факт запуска. Запущенная сессия боковой панели агенту не подконтрольна.

**Вживую не запускался.** Инструмент открывает новое окно боковой панели и запускает в нём самостоятельную сессию Claude, которой вызывающий агент не управляет и результата которой не видит; оставлять пользователю неконтролируемую работающую сессию ради проверки неправильно. Описание — по схеме.

**Связь с продуктом.** Ярлыки создаются пользователем в боковой панели (сохранением удачного запроса), вызываются в чате символом `/`, редактируются и удаляются в настройках расширения, и их можно ставить на расписание — ежедневно, еженедельно, ежемесячно, ежегодно. Записанные рабочие процессы доступны **только в классической боковой панели**: «Recording isn't available when the side panel runs as a Cowork session».
