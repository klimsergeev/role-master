# Действие: `computer`, `form_input`, `file_upload`, `upload_image`

Четыре инструмента, которыми агент меняет состояние страницы. Главное правило файла: **если у элемента есть идентификатор — работать по идентификатору, а не по координатам.** Промах по координатам не даёт ошибки.

> Пометки происхождения: **наблюдение** — измерено живым прогоном инструмента; **по схеме** — взято из схемы инструмента и вживую не проверялось. Срез данных — в SKILL.md.

---

## `computer`

Самый насыщенный инструмент: мышь, клавиатура, снимки экрана.

**Обязательные параметры:** `action`, `tabId`.

**Действия**

| Действие | Что делает | Обязательные дополнительные параметры | Прогон |
|---|---|---|---|
| `left_click` | Клик левой кнопкой | `coordinate` или `ref` | наблюдение |
| `right_click` | Клик правой кнопкой, контекстное меню | `coordinate` | по схеме |
| `double_click` | Двойной клик | `coordinate` | по схеме |
| `triple_click` | Тройной клик | `coordinate` | наблюдение |
| `hover` | Навести курсор без клика: подсказки, выпадающие меню, состояния наведения | `coordinate` или `ref` | наблюдение |
| `left_click_drag` | Перетаскивание | `start_coordinate` (начало) и `coordinate` (конец) | по схеме |
| `type` | Напечатать строку | `text` | наблюдение |
| `key` | Нажать клавишу или сочетание | `text` | наблюдение |
| `scroll` | Прокрутка | `coordinate`, `scroll_direction` | наблюдение |
| `scroll_to` | Прокрутить элемент в зону видимости | `ref` | наблюдение |
| `screenshot` | Снимок экрана | — | наблюдение |
| `zoom` | Снимок заданной области для разглядывания мелких деталей | `region` | наблюдение |
| `wait` | Пауза | `duration` | наблюдение |

**Прочие параметры**

| Параметр | Значения | По умолчанию |
|---|---|---|
| `coordinate` | `[x, y]`, пиксели от левого и верхнего края | — |
| `ref` | Идентификатор элемента из `read_page` или `find`. Годится как замена координат для кликов, обязателен для `scroll_to` | — |
| `region` | `[x0, y0, x1, y1]` для `zoom` | — |
| `modifiers` | `"ctrl"`, `"shift"`, `"alt"`, `"cmd"` (или `"meta"`), `"win"` (или `"windows"`); комбинируются через `+` | — |
| `repeat` | Число повторов для `key`, от 1 до 100 | 1 |
| `scroll_amount` | Щелчки колеса, от 1 до 10 | 3 |
| `duration` | Секунды для `wait`, **максимум 10** | — |
| `save_to_disk` | Сохранить снимок на диск, чтобы приложить к сообщению; возвращает путь | — |

**Ограничения из схемы**

- Перед кликом по иконке сначала посмотреть снимок и определить координаты.
- Если клик не сработал даже после ожидания — сдвинуть точку так, чтобы **кончик курсора** визуально попадал на элемент.
- Кликать в центр элемента, а не по краю.
- Клавиши для `key` перечисляются через пробел: `"Backspace Backspace Delete"`. Модификатор платформенный: `cmd` на Mac, `ctrl` на Windows и Linux.
- **Сочетания масштабирования страницы (`cmd+=`, `ctrl+-`, `cmd+0`) не поддерживаются и вернут ошибку.** Для разглядывания мелкого — действие `zoom`.
- `save_to_disk` ставить только тогда, когда снимок действительно надо показать пользователю. До Claude Code 2.1.211 флаг ничего на диск не писал — на старых версиях полагаться на него нельзя. В плановом режиме этот флаг превращает читающий вызов снимка в изменяющий состояние: см. [permissions.md](permissions.md).

### Главное наблюдение: клик по устаревшим координатам не даёт ошибки

`triple_click` по координатам поля ввода, снятым с предыдущего снимка, и следом `type` — оба вызова отчитались об успехе («Triple-clicked at (376, 359)», «Typed "typed via computer"»), но значение поля не изменилось: страница успела прокрутиться, и координаты указывали в пустоту. **Ни одного признака сбоя в ответах не было.**

Тот же ввод через идентификатор элемента отработал с первого раза:

```
[computer:left_click] Clicked on element ref_6
[computer:key] Pressed 1 key: cmd+a
[computer:type] Typed "typed via computer"
```

Отсюда правило сильнее совета схемы «свериться со снимком»: **есть идентификатор — кликать по идентификатору**. Координаты оставить для того, у чего идентификатора нет: рисунки на холсте, содержимое кадров с других источников, произвольные точки.

**Форматы ответов** (наблюдение, дословно):

| Действие | Ответ |
|---|---|
| `screenshot` | `Successfully captured screenshot (1512x723, jpeg) - ID: ss_8005zj64f` |
| `zoom` | `Successfully captured zoomed screenshot of region (300,100) to (700,260) - 800x320 pixels` |
| `hover` | `Hovered over element ref_1` |
| `scroll_to` | `Scrolled to element with reference: ref_9` |
| `scroll` | `Scrolled down by 3 ticks at (700, 400)` |
| `wait` | `Waited for 5 seconds` |
| `key` | `Pressed 1 key: Tab` |
| `type` | `Typed "typed via computer"` |

**Прочие наблюдения**

- **`zoom` увеличивает вдвое.** Запрошенная область 400×160 вернулась изображением 800×320 — ровно двукратно по плотности пикселей того экрана. То есть `zoom` пересобирает область в исходном разрешении, а не растягивает вырезку: для мелкого текста работает по-настоящему.
- **Снимок больше области просмотра.** При области просмотра 1512×723 снимок пришёл размером 1568×764. Отношения по сторонам не совпадают (1568 / 1512 ≈ 1,037; 764 / 723 ≈ 1,057), единого множителя из одного замера не выводится. Практический вывод от этого не меняется: **координаты, снятые линейкой с картинки, не равны координатам для клика** — ещё один довод в пользу идентификаторов.
- **Действия прокрутки возвращают снимок автоматически** — в пакете изображение приходит следом за текстовым ответом, отдельного вызова `screenshot` для этого не нужно.
- **Запрет масштабирования страницы подтверждён дословно.** Вызов `key` с `cmd+=`:

  ```
  "cmd+=" was not pressed: page zoom keyboard shortcuts are not supported. To magnify part of the page for closer inspection, use the zoom action with a region instead.
  ```

- **Идентификаторы снимков живут недолго** — см. `upload_image` ниже.

## `form_input`

**Назначение.** Задать значение элемента формы по идентификатору.

**Параметры** — все три обязательные:

| Параметр | Тип |
|---|---|
| `ref` | string |
| `value` | string, boolean или number |
| `tabId` | number |

**Как выбирать значение** (схема): «For checkboxes use boolean, for selects use option value or text, for other inputs use appropriate string/number».

**Ограничение.** Схема упоминает идентификатор именно из `read_page`, не из `find`. На практике `find` тоже возвращает совместимые ссылки, но формулировка схемы уже — надёжнее пара `read_page` → `form_input`.

**Форматы ответов** (наблюдение). Инструмент возвращает не только новое, но и **прежнее** значение, чего в схеме нет:

```
[form_input] Set text value to "Тестовое значение" (previous: "")
[form_input] Checkbox checked (previous: false)
[form_input] Selected option "Beta" in dropdown (previous: "a")
```

Что подтвердилось: кириллица проходит без искажений; выпадающий список принимает **видимую подпись** варианта («Beta»), а не только значение атрибута («b»); флажок принимает логическое значение. Результат сверен независимо — чтением `value`, `checked` и значения списка через `javascript_tool`, а не по ответу самого инструмента.

**Почему для форм это надёжнее клика с набором текста:** `form_input` задаёт значение напрямую и не зависит ни от прокрутки, ни от координат, ни от того, перекрыт ли элемент.

## `file_upload`

**Назначение.** Загрузить один или несколько файлов в элемент выбора файла на странице.

**Параметры** — все три обязательные:

| Параметр | Тип | Что это |
|---|---|---|
| `paths` | массив строк | Абсолютные пути |
| `ref` | string | Идентификатор элемента `input[type=file]` |
| `tabId` | number | Вкладка |

**Ограничения**

- **Никогда не кликать по кнопке загрузки и по самому полю файла.** Дословно: «Do not click on file upload buttons or file inputs — clicking opens a native file picker dialog that you cannot see or interact with». Нативное окно останавливает всю автоматизацию — механизм разобран в [troubleshooting.md](troubleshooting.md). Вместо клика: найти элемент через `read_page` или `find` и передать его `ref`.
- Суммарный размер файлов за один вызов — **менее 10 МБ**.
- **Годится любой файл, который сессии разрешено читать.** Схема формулирует уже — «only files the user has shared with this session (attachments, the session's outputs/uploads folders, or folders the user has connected)», а «other paths will be rejected». Наблюдение это не подтверждает: файл из временного каталога, которым никто с сессией не «делился», загрузился без возражений. Действующее правило — то, что называет дока Claude Code: что сессия может **прочитать**, то можно и загрузить. Правила разрешений, запрещающие `Read`, блокируют и загрузку.
- **Файлы с несколькими жёсткими ссылками отклоняются** — типичный случай внутри хранилищ пакетных менеджеров вроде `node_modules`. Лечение: скопировать файл и загрузить копию.
- Требуется Claude Code 2.1.211 или новее.

**Дословные тексты ошибок** (наблюдение):

```
Cannot upload "/tmp/big-probe.bin": total upload size would exceed 10 MB. file_upload sends file contents over the browser bridge in a single message; use a smaller file, or split across multiple file_upload calls if the page accepts files one at a time.
```

```
Cannot upload "/tmp/does-not-exist-probe.txt": only files this session is allowed to read can be uploaded. Ask the user to share the file with this session, or to add its folder with `/add-dir`.
```

Первая ошибка сама называет обходной путь — **несколько вызовов подряд, если страница принимает файлы по одному**; вторая подсказывает лечение `/add-dir`. Предел отвергает файл целиком, не обрезая его. Как именно содержимое до 10 МБ проходит через мост — вопрос механизма, и он здесь не разбирается: утверждений об устройстве передачи не делается.

**Успешная загрузка** отчитывается округлённым размером, вплоть до `0 KB` на мелком файле:

```
Uploaded 1 file(s) to file input: upload-probe.txt (0 KB total)
```

Опираться на это число как на проверку не стоит — сверять надо содержимым поля на странице.

## `upload_image`

**Назначение.** Загрузить ранее сделанный снимок экрана или изображение, переданное пользователем, в поле файла либо в область перетаскивания.

**Параметры**

| Параметр | Тип | Обязательный | По умолчанию | Что делает |
|---|---|---|---|---|
| `imageId` | string | да | — | Идентификатор снимка из действия `screenshot` инструмента `computer` либо изображения от пользователя |
| `tabId` | number | да | — | Вкладка |
| `ref` | string | нет | — | Для конкретных элементов, «especially hidden file inputs» |
| `coordinate` | `[x, y]` | нет | — | Перетаскивание в видимое место, «like Google Docs» |
| `filename` | string | нет | `image.png` | Имя файла |

**Ограничение схемы:** «Provide either `ref` or `coordinate`, not both».

**Формат ответа** (наблюдение):

```
[upload_image] Successfully uploaded image "probe-shot.png" (20KB) to file input
```

Обработчик `change` на странице увидел файл: `{"name":"probe-shot.png","size":20650,"type":"image/jpeg"}`.

**Два подводных камня, которых нет в схеме**

1. **Имя файла и тип содержимого расходятся.** Передано `filename: "probe-shot.png"` — страница получила файл с этим именем, но тип содержимого `image/jpeg`, потому что снимки экрана делаются в JPEG. Инструмент не приводит расширение в соответствие с форматом. Сайт, который проверяет совпадение расширения и содержимого, такой файл отклонит. Безопаснее задавать имя с расширением `.jpg` либо не задавать вовсе — но значение по умолчанию `image.png` даёт ту же проблему.
2. **Идентификаторы снимков протухают в пределах сессии.** Попытка загрузить снимок, сделанный несколькими минутами раньше в этой же сессии, отклонена:

   ```
   The requested screenshot is no longer available (it may have expired, or was not taken in this session). Take a new screenshot with the computer tool and retry the upload with its new ID.
   ```

   **Точный срок жизни не измерен:** между снимком и отказом прошло около десяти вызовов инструментов, и выводить из одного наблюдения число минут некорректно. Рабочее правило от этого не зависит: **снимок для загрузки делать непосредственно перед загрузкой**, порядок «снять → сделать что-то ещё → загрузить» ненадёжен.
