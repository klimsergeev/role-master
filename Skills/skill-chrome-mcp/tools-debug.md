# Отладка: `javascript_tool`, `read_console_messages`, `read_network_requests`

Три инструмента отладки и один перевёрнутый порядок работы: **журналы консоли и сети начинают писать с первого вызова соответствующего инструмента, а не с загрузки страницы.** Кто этого не знает, отлаживает по пустому журналу.

> Пометки происхождения: **наблюдение** — измерено живым прогоном инструмента; **по схеме** — взято из схемы инструмента и вживую не проверялось. Срез данных — в SKILL.md.

---

## `javascript_tool`

**Назначение.** Выполнить JavaScript в контексте страницы.

**Параметры** — все три обязательные:

| Параметр | Тип | Значение |
|---|---|---|
| `action` | string | **Должно быть ровно** `'javascript_exec'` |
| `text` | string | Код |
| `tabId` | number | Вкладка |

**Семантика исполнения.** Схема: «Evaluated in the page context with REPL semantics: top-level `await` works, and the result of the last expression is returned automatically — write the expression you want (e.g. `window.myData.value`, or `await fetch(url).then(r=>r.json())`) rather than `return ...`».

То есть **`return` на верхнем уровне писать не надо** — вернётся значение последнего выражения. Это самая частая ошибка при работе с инструментом. Подтверждено наблюдением: `await` на верхнем уровне работает, одиночное выражение возвращается как есть — `document.getElementById('t1').value` вернуло строку `typed via computer` без кавычек и без обёртки в объект.

**Возможности.** Доступ к DOM, объекту `window`, переменным страницы; изменение DOM; вызов функций страницы. Через этот же инструмент читается содержимое **открытого** теневого дерева, недоступное инструментам чтения (см. [tools-read.md](tools-read.md)); закрытое теневое дерево и им не берётся.

**Запрет.** Не вызывать `alert`, `confirm`, `prompt` — диалог остановит всю автоматизацию до ручного вмешательства пользователя, и снять его будет нечем: `javascript_tool` исполняется **внутри** остановленной страницы и потому бесполезен ровно тогда, когда нужен. Механизм — в [troubleshooting.md](troubleshooting.md).

### Наблюдение: скрытая цензура полей результата

**Значения полей возвращаемого объекта заменяются на строку `[BLOCKED: Sensitive key]`, если имя поля похоже на чувствительное.** Отбор идёт по имени ключа, а не по содержимому значения. В схеме об этом нет ни слова.

Проверено намеренно — возвращён объект с заведомо безобидными значениями:

| Имя поля | Что вернулось |
|---|---|
| `secret` | `[BLOCKED: Sensitive key]` |
| `mySecretThing` | `[BLOCKED: Sensitive key]` |
| `password` | `[BLOCKED: Sensitive key]` |
| `token` | `[BLOCKED: Sensitive key]` |
| `apiKey` | `[BLOCKED: Sensitive key]` |
| `authorization` | `[BLOCKED: Sensitive key]` |
| `harmless` | `ggg` — прошло |

Совпадение ищется **внутри** имени и **без учёта регистра**: `mySecretThing` перехвачен так же, как голое `secret`.

Почему это важно, а не курьёз:

- **Отсекается не только опасное.** Поле `token` в разборе разметки, `password` как подпись поля формы, `apiKey` как имя ключа в данных страницы — законные вещи, которые молча превратятся в заглушку.
- **Подмена выглядит как данные.** Возвращается строка, а не ошибка. Код, который дальше сравнивает значение или считает по нему число, получит мусор и не заметит: вместо `true`/`false` приходит текст, и логика проверки ломается бесшумно.
- **Обход тривиален**, когда речь о собственных данных страницы: назвать поле нейтрально (`tok`, `pwdField`, `authHdr`) либо вернуть значение не объектом, а голым выражением — одиночная строка цензуре не подвергается.
- **Это не мера безопасности.** Механизм ловит имя ключа, а не смысл; полагаться на него как на защиту от утечки учётных данных нельзя.

## `read_console_messages`

**Назначение.** Прочитать сообщения консоли (`console.log`, `console.error`, `console.warn` и прочие) из конкретной вкладки.

**Параметры**

| Параметр | Тип | Обязательный | По умолчанию | Что делает |
|---|---|---|---|---|
| `tabId` | number | да | — | Вкладка |
| `pattern` | string | нет | — | **Регулярное выражение** для фильтрации |
| `onlyErrors` | boolean | нет | `false` | Только ошибки и исключения |
| `limit` | number | нет | **100** | Сколько сообщений вернуть |
| `clear` | boolean | нет | `false` | Очистить консоль после чтения |

**Ограничения**

- Возвращаются сообщения **только текущего домена**.
- Схема настаивает заглавными буквами: «IMPORTANT: Always provide a pattern to filter messages - without a pattern, you may get too many irrelevant messages». То же требует дока Claude Code: «Tell Claude what patterns to look for rather than asking for all console output, since logs can be verbose».
- `clear: true` — **флаг, меняющий состояние**: в плановом режиме потребует подтверждения (см. [permissions.md](permissions.md)).

### Наблюдение: запись начинается с первого вызова инструмента

Схема обещает «read browser console messages … from a specific tab», из чего естественно заключить, что журнал ведётся всегда. Он не ведётся. Инструмент сам сообщает об этом, когда возвращать нечего:

```
No console messages found for this tab.

Note: Console tracking starts when this tool is first called. If the page loaded before calling this tool, you may need to refresh the page to capture console messages from page load.
```

**Порядок отладки переворачивается:** не «воспроизвести → прочитать консоль», а **«вызвать `read_console_messages` → воспроизвести или перезагрузить страницу → прочитать»**. Иначе сообщения времени загрузки уже потеряны, а пустой журнал будет выглядеть как «ошибок нет».

**Формат вывода** (наблюдение, пять сообщений разных уровней):

```
Found 5 console messages:

[1] [19:33:23] [LOG]
[ZTEST] plain log 1

[2] [19:33:23] [WARNING]
[ZTEST] warn 1

[3] [19:33:23] [ERROR]
[ZTEST] error 1
```

Уровни отдаются как `LOG`, `WARNING`, `ERROR`, `INFO`, `DEBUG`: `console.warn` даёт `WARNING`, `console.debug` виден и не отбрасывается.

**`onlyErrors: true` отсекает и предупреждения тоже** (наблюдение). Из пяти сообщений вернулось одно, с заголовком `Found 1 error/exception messages:` — `WARNING` под определение не подпадает. Нужны предупреждения — брать их шаблоном, а не этим флагом.

**Журнал привязан к домену и теряется при переходе** (наблюдение). После перехода на другой домен запрос по тому же шаблону вернул «No console messages found for this tab». Это не фильтр по домену поверх общего журнала, а полная потеря прежних записей.

## `read_network_requests`

**Назначение.** Прочитать сетевые запросы вкладки (XHR, Fetch, документы, изображения и прочее).

**Параметры**

| Параметр | Тип | Обязательный | По умолчанию | Что делает |
|---|---|---|---|---|
| `tabId` | number | да | — | Вкладка |
| `urlPattern` | string | нет | — | Фильтр по **подстроке** в адресе, например `/api/`. **Не регулярное выражение** — в отличие от `pattern` у консоли |
| `limit` | number | нет | **100** | Сколько запросов вернуть |
| `clear` | boolean | нет | `false` | Очистить после чтения; **меняет состояние** |

**Ограничение схемы:** «Requests are automatically cleared when the page navigates to a different domain». Снимать данные надо до навигации. Запросы с других источников (cross-origin) при этом видны.

### Наблюдение: слово «all» в схеме неверно

Схема обещает «Returns **all** network requests made by the current page». Фактически первый вызов на уже загруженной странице вернул пусто и сам объяснил почему:

```
No network requests found for this tab.

Note: Network tracking starts when this tool is first called. If the page loaded before calling this tool, you may need to refresh the page or perform actions that trigger network requests.
```

**Журнала за прошлое не существует.** Порядок обязателен: сначала вызвать `read_network_requests`, потом воспроизводить сценарий. После включения два запроса, выполненные со страницы, были записаны и найдены.

**Формат вывода** (наблюдение) — три поля на запрос, ни заголовков, ни тел, ни времени:

```
Found 2 network requests (filtered by URL pattern: "probe"):

1. url: https://example.com/?probe=1
   method: GET
   statusCode: 200

2. url: https://example.com/missing-404-probe
   method: GET
   statusCode: 404
```

Следствие: инструмент годится, чтобы **увидеть факт запроса, его метод и код ответа**. Разобрать тело ответа или заголовки им нельзя — для этого нужен `javascript_tool` с собственным запросом.

**Очистка при смене домена подтверждена** (наблюдение). После перехода на другой домен и возврата запрос по прежнему шаблону вернул «No requests matching "probe" found for this tab» с той же оговоркой про начало записи.
