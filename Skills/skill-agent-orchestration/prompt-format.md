# Формат вызова субагента

## Назначение

Обязательный формат промпта при вызове Agent tool и pre-flight checklist для проверки полноты промпта.

## Шаблон промпта

```markdown
## ВАЖНО: Сначала прочитай свою роль

Прочитай файл роли: `[абсолютный путь к файлу агента]`

---

## Задача: [одно предложение]

**Рабочая директория:** "[абсолютный путь в кавычках]"

**ВАЖНО про bash-команды:** Всегда оборачивай пути с пробелами в двойные кавычки. НЕ используй backslash.

**Разрешения УЖЕ настроены** — не спрашивай.

---

### Контекст
[Только то, что субагент не может узнать сам:
 релевантные файлы, решения пользователя, ограничения из плана]

### Границы
- [Что НЕ делать — 1-3 пункта, конкретных]

### Ожидаемый результат
[Формат выдачи]
```

## Правила заполнения

### Файл роли

- ВСЕГДА абсолютный путь
- Агенты могут быть в `.claude/agents/` (проектные) или `~/.claude/agents/` (глобальные)
- Проверь, где именно находится файл, перед формированием промпта

### Рабочая директория

- ВСЕГДА абсолютный путь в двойных кавычках
- Это единственный инфраструктурный параметр, который меняется от вызова к вызову

### Контекст

Передавай ТОЛЬКО операционный контекст — то, что уникально для этого вызова:

| Передавать | НЕ передавать |
|-----------|---------------|
| Конкретные файлы для работы (пути) | Содержимое файлов (субагент прочитает сам) |
| Результаты предыдущих агентов в цепочке | Компетенции и стиль (уже в роли) |
| Решения пользователя, влияющие на задачу | Правила bash/путей (уже в CLAUDE.md) |
| Текущий branch (если связано с git) | Ограничения роли (уже в файле роли) |
| Ограничения из утверждённого плана | Формат выдачи по умолчанию (уже в роли) |

**Не вкладывай в промпт непроверенные допущения.** Субагент исполняет ровно то, что дано — догадка оркестратора (напр. «вероятный стек — Vue/Nuxt») материализуется в его артефакте как дефект. Передавай в контекст только установленные факты; если факта нет (пустой проект, стек не задан) — так и напиши субагенту («стек не задан — используй минимальный дефолт»), а не подставляй догадку. Чисти допущения ДО делегирования.

**Стартовый промпт должен быть самодостаточным.** Продолжение работы уже запущенного агента (`SendMessage` по ID или имени) — удобство, а не гарантия: вызов может отказать, и агента придётся поднимать заново с нуля. Всё, что субагенту понадобится, кладётся в стартовый промпт или на диск (файл, план), а не досылается по ходу. И тем более намерение «дослать вдогонку» не является поводом заполнить `name` и поднять тиммейта: забытое дешевле дослать перезапуском субагента ([delegation-rules.md](delegation-rules.md)).

**У измеренного факта есть срок годности.** Замер свойства среды или объёма данных («синтетические события не поднимают подсказку», «в логе 29 записей») устаревает вместе с кодом и источником: после правок следующий исполнитель перемеряет и получит другое число. Не переноси прошлый замер в новое задание как аксиому — либо датируй его («по замеру до правки обработчиков»), либо поручи перемерить.

### Границы

- ВСЕГДА минимум 1 пункт "что НЕ делать"
- Включай ограничения из утверждённого плана
- НЕ дублируй ограничения, которые уже есть в роли субагента

## Pre-flight checklist

Проверяй перед КАЖДЫМ вызовом Agent tool:

### Минимальный (обязательный)

1. Указан файл роли субагента (абсолютный путь)?
2. Указана рабочая директория (абсолютный путь в кавычках)?
3. Указано правило про двойные кавычки для путей с пробелами?
4. Указаны границы задачи (минимум 1 пункт "что НЕ делать")?
5. Промпт НЕ содержит действий вне утверждённого плана?
6. Промпт НЕ дублирует то, что уже есть в роли субагента?
7. Промпт НЕ содержит непроверенных допущений (догадок о стеке/окружении) и устаревших замеров, выданных за факт?
8. Параметр `name` НЕ заполнен? Заполнен -> есть ли явное указание пользователя на команду в этой сессии? Нет указания -> убери `name`, иначе вместо субагента поднимется тиммейт (правило и чек — [delegation-rules.md](delegation-rules.md))

### Расширенный (для сложных задач)

8. Указан текущий git branch (если задача связана с git)?
9. Указаны релевантные файлы (пути, не содержимое)?
10. Указан формат ожидаемого результата?
11. Если задача зависит от другого субагента — передан результат (summary, не полный текст)?
12. Если есть решения пользователя — переданы явно?

## Примеры

### Пример 1: Правильный промпт

```markdown
## ВАЖНО: Сначала прочитай свою роль

Прочитай файл роли: `~/.claude/agents/agent-skill-master.md`

---

## Задача: Добавь пример edge-case в скилл skill-markup

**Рабочая директория:** "/Users/sergeiklimenko/Cursor Projects/Role creator"

**ВАЖНО про bash-команды:** Всегда оборачивай пути с пробелами в двойные кавычки. НЕ используй backslash.

**Разрешения УЖЕ настроены** — не спрашивай.

---

### Контекст
Пользователь попросил добавить пример использования таблицы в Confluence с merge ячеек.
Файл скилла: Skills/skill-markup/confluence.md

### Границы
- НЕ трогай другие файлы скилла кроме confluence.md
- НЕ коммить

### Ожидаемый результат
Сообщи, какой пример добавлен и в какой файл.
```

### Пример 2: Плохой промпт (чего избегать)

```markdown
Задача: Добавь пример в скилл markup
Контекст: Нужен пример для Confluence
Результат: Сделай и скажи что сделал
```

**Проблемы:**
- Нет файла роли
- Нет рабочей директории
- Нет правила про кавычки
- Нет границ
- "Контекст" слишком абстрактный
