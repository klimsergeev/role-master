# Правила делегирования

## Назначение

Правила выбора исполнителя: когда делегировать агенту, когда вызвать скилл, когда делать самому.

## Доступные агенты

Агенты проекта находятся в `.claude/agents/`. При первом запуске определи доступных агентов — это избавит от повторных проверок.

## Доступные скиллы

Скиллы публикуются в файловую систему. При первом запуске определи доступные скиллы.

Где искать:
- **Claude Code:** `~/.claude/skills/` (каждый скилл — папка с `SKILL.md`)
- **Cursor:** `~/.cursor/skills/` (аналогичная структура)

## Агент vs Скилл

| Критерий | Агент (Agent tool) | Скилл (Skill tool) |
|----------|-------------------|-------------------|
| Задача требует роли и экспертизы | Да | Нет |
| Задача = стандартная процедура | Нет | Да |
| Нужен справочник/чеклист | Нет | Да |
| Нужна работа с файлами проекта | Да | Нет |
| Пример | "Отрефактори компонент" -> frontend-dev | "Какой синтаксис у формулы в LaTeX?" -> /skill-markup |

## Главное правило

**ЕСЛИ существует специализированный агент для задачи -> ВСЕГДА делегируй ему.**
**ЕСЛИ задача лучше решается скиллом (процедура, справочник) -> вызови скилл через Skill tool.**

Это правило НЕ имеет исключений:
- Не важно, насколько задача кажется "простой"
- Не важно, сколько времени она займёт
- Не важно, что это "всего один Edit"

## Когда делегировать субагенту

| Критерий | Делегируй |
|----------|-----------|
| Есть специализированный агент | skill-master, role-master, qa-engineer, frontend-dev и т.д. |
| Задача в домене агента | Редактирование скилла = skill-master, роли = role-master |
| Задача требует глубокого анализа кода | Чтение > 100 строк |
| Задача изолирована | Не требует твоего контекста |

## Когда делать самому

| Критерий | Делай сам |
|----------|-----------|
| Координация между агентами | Синтез результатов |
| Уточнение требований | Диалог с пользователем |
| Опрос пользователя | Через AskUserQuestion — всегда делай сам |
| Нет подходящего агента | И задача не в домене существующих агентов |
| Чисто информационный запрос | Ответ на вопрос без действий |

**ВНИМАНИЕ:** "Кажется простым" НЕ является критерием для самостоятельного выполнения.

## Инструкции для субагентов по опросу пользователя

1. **Приоритет 1 — AskUserQuestion** (если доступен): задавай по одному, жди ответа
2. **Приоритет 2 — Передача оркестратору** (если AskUserQuestion недоступен): верни результат с секцией `## Вопросы для пользователя`
3. **Приоритет 3 — Пакетный опрос** (крайний случай): нумерованный список, один пункт = один вопрос

## Примеры маршрутизации

| Запрос | Исполнитель | Тип |
|--------|-------------|-----|
| "Поменяй название роли с X на Y" | role-master | Агент |
| "Добавь пример в скилл" | skill-master | Агент |
| "Исправь опечатку в компоненте" | frontend-dev | Агент |
| "Как отформатировать таблицу в Jira?" | /skill-markup | Скилл |
| "Какой у нас сейчас бранч?" | Сам оркестратор | — |
| "Инициализируй git / `.gitignore` / закоммить / запушь" | git-ops | Агент |

**Коммит/пуш — только по явной команде пользователя.** Итеративный цикл «меняем — смотрим» или автономный луп НЕ являются бланковой авторизацией на коммит/пуш. Делегируй git-ops только когда пользователь явно попросил зафиксировать/запушить.
