# Модель контекста субагента

## Назначение

Трёхслойная модель контекста: какие слои информации субагент получает, из каких каналов, и что оркестратор должен передать вручную.

## Три слоя контекста

| Слой | Что содержит | Кто отвечает | Где хранится |
|------|-------------|--------------|-------------|
| **Инфраструктурный** | Формат путей, запрет cd&&, абсолютные пути, git-запреты | CLAUDE.md | Проект |
| **Доменный** | Компетенции, стиль, ограничения роли, скиллы роли | Файл роли + скиллы | agents/ |
| **Операционный** | Текущая задача, branch, файлы, решения пользователя, ограничения из плана | Промпт оркестратора | Agent tool call |

### Принцип непересечения

Оркестратор передаёт в промпте ТОЛЬКО операционный слой. Инфраструктурный слой субагент получает из CLAUDE.md, доменный — из своей роли и скиллов.

- НЕ дублируй в промпте правила путей/bash — это в CLAUDE.md
- НЕ дублируй компетенции и ограничения роли — это в файле роли
- НЕ дублируй справочные данные скиллов — субагент загрузит их сам

**Исключение:** правило про двойные кавычки в путях дублируется в промпте намеренно, потому что это самая частая ошибка.

## Что субагент видит при старте

| Источник | Видит? | Примечание |
|----------|--------|------------|
| CLAUDE.md (все уровни) | Да | Автоматически для кастомных субагентов |
| Свою роль (из agents/) | Да | Если указана в промпте |
| Скиллы из роли | Да | Загружает сам при старте |
| Предзагруженные skills (frontmatter) | Да | Из поля `skills` в определении агента |
| Git status (снимок) | Да | Снимок из родительской сессии |
| Историю разговора родителя | **Нет** | Только через fork |
| Результаты tool calls родителя | **Нет** | — |
| Plan файл оркестратора | **Нет** | Оркестратор должен передать ограничения из плана явно |
| Memory оркестратора | **Нет** | — |

## Каналы доставки контекста

| Канал | Слой | Автоматически? | Что передаёт |
|-------|------|---------------|-------------|
| CLAUDE.md | Инфраструктурный | Да | Правила bash, путей, git, язык |
| Файл роли | Доменный | Да (если указан) | Компетенции, ограничения, формат выдачи |
| Скиллы роли | Доменный | Да (загружает сам) | Справочники, чеклисты, процедуры |
| Промпт оркестратора | Операционный | Нет (вручную) | Задача, файлы, branch, решения, границы |

## Что это значит для оркестратора

1. **Знай содержимое ролей.** Если роль уже содержит рабочую директорию или формат выдачи — не дублируй в промпте
2. **Знай, какие скиллы загружает роль.** Если UX Writer загружает skill-editorial-guidelines — не передавай редполитику в промпте
3. **Передавай только операционный контекст.** Конкретная задача, конкретные файлы, конкретные ограничения из плана
4. **План не виден субагенту.** Если план содержит ограничения ("не трогать файл X") — передай их явно в секции "Границы"

## Примеры

### Пример 1: Минимальный операционный контекст

Задача для skill-master: "Обнови версию в скилле skill-markup"

Что передать:
- Задача (обнови версию)
- Файл (Skills/skill-markup/SKILL.md)
- Границы (не трогай другие скиллы)

Что НЕ передавать (уже есть):
- Как работать со скиллами (в роли skill-master)
- Формат путей (в CLAUDE.md)
- Структура скиллов (в роли + скиллах skill-master)

### Пример 2: Цепочка агентов — передача результата

Задача: qa-engineer нашёл баг, frontend-dev должен исправить.

Что передать frontend-dev:
- Задача (исправь баг)
- Результат qa-engineer: "Файл Button.tsx, строка 42, цвет #ff0000 вместо #007bff" (summary, не полный отчёт)
- Границы (не трогай другие компоненты)

Что НЕ передавать:
- Полный отчёт qa-engineer (избыточно)
- Как работать с Vue/React (в роли frontend-dev)
