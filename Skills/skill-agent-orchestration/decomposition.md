# Паттерны декомпозиции задач

## Назначение

Типовые паттерны разбиения запроса пользователя на атомарные задачи для делегирования субагентам.

## Паттерн 1: Исследование + Исправление + Коммит

Запрос включает поиск проблемы, её решение и фиксацию результата.

```
Запрос: "найди баг с цветами и запушь фикс"

Декомпозиция:
1. [qa-engineer] Найти проблему с цветами
2. [frontend-dev] Исправить найденную проблему (зависит от 1)
3. [git-specialist] Закоммитить и запушить (зависит от 2)
```

**Ключевое:** каждый следующий шаг зависит от результата предыдущего. Передавай summary результата, не полный текст.

## Паттерн 2: Параллельный анализ

Запрос включает несколько независимых проверок.

```
Запрос: "проверь код на баги и стиль"

Декомпозиция (параллельно):
1. [qa-engineer] Проверить на баги
2. [code-reviewer] Проверить стиль
```

**Ключевое:** задачи независимы и не пишут в общий файл — запускай параллельно для экономии времени.

## Паттерн 3: Цепочка обработки

Запрос включает последовательные этапы, где каждый этап — вход для следующего.

```
Запрос: "напиши фичу X и покрой тестами"

Декомпозиция (последовательно):
1. [backend-dev] Реализовать фичу
2. [qa-engineer] Написать тесты (зависит от 1)
```

## Паттерн 4: Мультидоменная задача

Запрос затрагивает несколько доменов одновременно.

```
Запрос: "создай скилл для SEO-аудита"

Декомпозиция:
1. [skill-master] Создать структуру скилла и процедуры
   (skill-master может сам привлечь экспертизу через скиллы)
```

**Ключевое:** не пытайся сам разбить задачу между агентами разных доменов. Делегируй агенту, чей домен ближе всего к задаче. Он сам определит, нужны ли ему справочники.

## Правила декомпозиции

- Каждая задача = один исполнитель
- ЕСЛИ задачи независимы -> параллель
- Независимость включает файлы: задачи независимы, только если ни в один файл не пишут два исполнителя. Общий файл делает задачи зависимыми, даже когда по смыслу они не связаны — например, один план, где у каждого исполнителя свой раздел, или общий раздел вроде «Открытые вопросы»: правки через Edit, легшие одновременно, затирают друг друга
- Пересечение по файлам проверяй при декомпозиции, до запуска: для каждой задачи назови файлы, в которые она пишет, и сверь списки между задачами, которые собираешься запустить параллельно
- ЕСЛИ нескольким исполнителям нужно писать в один файл -> запускай их последовательно, либо каждый пишет в свой файл, а объединяет оркестратор или следующий агент цепочки
- ЕСЛИ задача B зависит от результата задачи A -> последовательность, передай summary A в промпт B
- ЕСЛИ запрос атомарный (один агент, одно действие) -> не декомпозируй, делегируй сразу
- ЕСЛИ неясно, как разбить -> спроси пользователя через AskUserQuestion
