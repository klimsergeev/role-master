# Алгоритм разрешения противоречий

## Назначение

Алгоритм для оркестратора: как действовать, когда субагент сообщает о противоречии между своей ролью и полученным заданием.

## Четыре типа противоречий

| Тип | Описание | Пример |
|-----|----------|--------|
| **Прямое** | Роль запрещает, задание требует | Роль: "НЕ создаю файлы вне /Roles/". Задание: "Создай файл в /Updates/" |
| **Расширение scope** | Задание выходит за компетенции | Роль: "Проверяю тексты". Задание: "Проверь текст и перепиши код компонента" |
| **Контекстное переопределение** | Задание уточняет поведение роли | Роль: "Формат — таблица". Задание: "Дай результат списком" |
| **Неявное** | Неясно, есть ли противоречие | Роль: "Не коммить". Оркестратор не упомянул коммит, но субагент считает нужным |

## Алгоритм для оркестратора

### 1. Прямое противоречие

**Сигнал:** Субагент возвращает: "Моя роль запрещает X. Подтвердите?"

**Действие:**
1. Передать вопрос пользователю через AskUserQuestion
2. ЕСЛИ пользователь подтвердил -> дать субагенту явное разрешение: "Пользователь разрешил. Выполни X"
3. ЕСЛИ пользователь отказал -> скорректировать задачу

### 2. Расширение scope

**Сигнал:** Субагент возвращает: "Я сделал X (мой домен). Y (не мой домен) нужно делегировать другому агенту."

**Действие:**
1. Принять частичный результат
2. Делегировать оставшуюся часть подходящему агенту
3. Синтезировать результаты

### 3. Контекстное переопределение

**Сигнал:** Нет сигнала — субагент выполняет задание, адаптируя формат/тон/стиль.

**Действие:** Никаких — это штатная ситуация, не противоречие.

### 4. Неявное противоречие

**Сигнал:** Субагент следует роли, игнорируя то, что оркестратор не упомянул.

**Действие:** Никаких — субагент поступил правильно. Роль — более надёжный источник, чем возможно неполный промпт.

## Правила для оркестратора

- ЕСЛИ субагент вернул вопрос о противоречии -> НЕ решай сам, передай пользователю
- ЕСЛИ субагент вернул частичный результат с рекомендацией делегировать -> прими и перенаправь
- ЕСЛИ субагент выполнил задачу с адаптацией формата -> это нормально
- НИКОГДА не заставляй субагента нарушать ограничения своей роли без явного разрешения пользователя

## Примеры

### Пример 1: Прямое противоречие

**Задание role-master:** "Создай файл role-seo-writer.md в директории /Updates/"

**Ответ role-master:** "Моя роль ограничивает работу директорией /Roles/. Создание файла в /Updates/ выходит за мои границы. Подтвердите?"

**Действие оркестратора:**
1. AskUserQuestion: "role-master сообщает, что его роль ограничивает работу директорией /Roles/. Вы хотите, чтобы он создал файл в /Updates/?"
2. Если да -> "Пользователь разрешил. Создай файл в /Updates/"
3. Если нет -> скорректировать путь к /Roles/

### Пример 2: Расширение scope

**Задание skill-master:** "Обнови скилл и поправь ошибку в компоненте Button.tsx"

**Ответ skill-master:** "Скилл обновлён. Исправление компонента Button.tsx — не мой домен, нужно делегировать frontend-dev."

**Действие оркестратора:**
1. Принять обновление скилла
2. Делегировать frontend-dev: "Исправь ошибку в Button.tsx"
