# Decision Framework

## Назначение

Матрица принятия решений ship/no-ship/iterate по результатам A/B-теста и шаблон финального отчёта.

## Матрица решений

### Ship

**Все условия** должны быть выполнены:

- Primary metric: статистически значимый (p < 0.05) И положительный
- Effect size >= pre-specified MDE (практически значимый)
- Guardrail-метрики: ни одна не ухудшилась значимо
- SRM не обнаружен
- Тест проработал минимально необходимую длительность
- Power >= 80%

### No-Ship

**Любое из условий:**

- Primary metric: значимо отрицательный (p < 0.05, lift < 0)
- Guardrail-метрика: значимое ухудшение
- SRM обнаружен (тест невалиден -- шипить нечего)
- Критический баг обнаружен в варианте

### Iterate (доработать и перетестировать)

- Primary metric положительный, но guardrail ухудшился -> доработать вариант, защитить guardrail
- Эффект значим в одних сегментах, вреден в других -> рассмотреть сегментный rollout
- Результат близок к значимости (0.05 < p < 0.10) при положительном тренде -> уточнить гипотезу, доработать UX

### Extend (продлить тест)

- Тренд положительный, но power < 80% (не хватает данных)
- Тест не прошёл полный бизнес-цикл (< 7 дней, < 1 недельный цикл)
- Внешний фактор мог исказить данные (праздники, акция) -> продлить на "чистый" период

### Inconclusive (закрыть как неинформативный)

- p >= 0.05, effect size близок к нулю, power >= 80%
- Интерпретация: эффекта, скорее всего, нет (или он меньше MDE)
- Действие: закрыть тест, зафиксировать learning, перейти к следующей гипотезе

## Формат финального отчёта

### Шаблон: Summary Table

```
## Результаты A/B-теста: [Название эксперимента]

**Период:** [дата начала] -- [дата окончания]
**Группы:** Control (N = [число]) vs. Treatment (N = [число])

### Primary Metric: [Название метрики]

| Группа | N | Значение | Lift | 95% CI | P-value |
|---|---|---|---|---|---|
| Control | [N] | [значение] | -- | -- | -- |
| Treatment | [N] | [значение] | [+X%] | [lo%, hi%] | [p] |

### Guardrail Metrics

| Метрика | Control | Treatment | Изменение | P-value | Статус |
|---|---|---|---|---|---|
| [Метрика 1] | [значение] | [значение] | [+/-X%] | [p] | OK / Warning / Blocked |
| [Метрика 2] | [значение] | [значение] | [+/-X%] | [p] | OK / Warning / Blocked |

### Сегментный анализ

| Сегмент | N (C/T) | Lift | 95% CI | P-value | Заметки |
|---|---|---|---|---|---|
| [Сегмент 1] | [N/N] | [+X%] | [lo%, hi%] | [p] | [Заметка] |
| [Сегмент 2] | [N/N] | [+X%] | [lo%, hi%] | [p] | [Заметка] |

### Валидация

- SRM: [Пройден / Обнаружен] (соотношение: [X/Y], ожидалось: [X/Y])
- Длительность: [X дней] (минимум: [Y дней])
- Power: [X%] (для MDE = [Y%])

### Рекомендация

**[Ship / No-ship / Iterate / Extend / Inconclusive]**

[2-3 предложения с обоснованием: что показали данные и почему именно такое решение.]

### Следующие шаги

1. [Конкретное действие 1]
2. [Конкретное действие 2]
```

## Правила заполнения отчёта

1. **Все числа с точностью** -- lift до 1 десятичного знака, p-value до 2-3 значащих цифр
2. **CI обязателен** для primary metric -- без CI отчёт неполный
3. **Guardrails** -- если данных нет, запросить у пользователя, не пропускать
4. **Рекомендация** -- ВСЕГДА одна из пяти категорий (Ship / No-ship / Iterate / Extend / Inconclusive)
5. **Следующие шаги** -- конкретные действия, не "подумать" или "обсудить"
6. **Невалидный тест** -- если SRM обнаружен, отчёт завершается на блоке "Валидация" с пояснением

## Принятие решений при неполных данных

| Ситуация | Действие |
|---|---|
| Нет данных по guardrails | Запросить у пользователя. Не делать вывод "guardrails ОК" по умолчанию |
| Неизвестна длительность теста | Запросить. Не пропускать валидацию |
| Нет pre-registered MDE | Использовать industry benchmark или запросить у пользователя |
| Только bayesian output (% probability) | Конвертировать: >95% ~ p < 0.05, >99% ~ p < 0.01 |
| Несколько primary metrics | Запросить: какая одна primary? Остальные -- secondary |
