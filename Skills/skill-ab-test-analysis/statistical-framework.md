# Statistical Framework

## Назначение

Справочник статистических концепций для анализа A/B-тестов: p-values, confidence intervals, statistical power, effect size, frequentist и bayesian подходы.

## P-Value

**Определение:** вероятность получить результат такой же или более экстремальный, если в действительности эффекта нет (нулевая гипотеза верна).

| P-value | Интерпретация |
|---|---|
| p < 0.01 | Сильное свидетельство против нулевой гипотезы |
| p < 0.05 | Конвенциональный порог значимости |
| 0.05 <= p < 0.10 | Граничная зона, результат не значим по стандартному порогу |
| p >= 0.10 | Нет оснований отклонять нулевую гипотезу |

### Что p-value НЕ означает

- НЕ вероятность того, что нулевая гипотеза верна
- НЕ вероятность того, что вариант лучше контроля
- НЕ мера размера эффекта
- НЕ повод для решения без проверки практической значимости

### Пример интерпретации

> p = 0.03 означает: "Если эффекта на самом деле нет, вероятность увидеть такой или более сильный результат случайно -- 3%". Это НЕ означает: "С вероятностью 97% вариант лучше".

## Confidence Interval (доверительный интервал)

**Определение:** диапазон значений, в который с заданной вероятностью (обычно 95%) попадает истинный размер эффекта.

**Формат отчёта:** "Истинный эффект находится между X% и Y% с 95% уверенностью"

### Правила интерпретации CI

| CI | Интерпретация |
|---|---|
| [+2%, +8%] | Эффект положительный, значимый (не пересекает 0) |
| [-1%, +5%] | Эффект не значим (пересекает 0), но скорее положительный |
| [-6%, -1%] | Эффект отрицательный, значимый (не пересекает 0) |
| [-0.5%, +0.5%] | Эффект практически отсутствует |

**Ключевое правило:** ширина CI показывает точность оценки. Узкий CI [+1%, +3%] -- уверенная оценка. Широкий CI [-2%, +10%] -- мало данных.

## Effect Size (размер эффекта)

**Статистическая значимость != практическая значимость.**

| Ситуация | Пример | Решение |
|---|---|---|
| Значимый + большой эффект | +5% конверсии, p = 0.01 | Ship |
| Значимый + мизерный эффект | +0.01% конверсии, p = 0.04 (при N = 5M) | Не стоит усилий |
| Незначимый + большой эффект | +5% конверсии, p = 0.12 (мало данных) | Продлить тест |
| Незначимый + малый эффект | +0.3% конверсии, p = 0.45 | Закрыть тест |

### Minimum Detectable Effect (MDE)

MDE -- минимальный размер эффекта, который тест способен обнаружить при заданных параметрах.

**Определяется ДО запуска теста:**
- Baseline метрика (текущая конверсия)
- Желаемый MDE (какой lift считаем практически значимым)
- Power (обычно 80%)
- Significance level (обычно 0.05)

ЕСЛИ наблюдаемый lift < MDE -> даже при p < 0.05, результат сомнителен практически.

## Statistical Power

**Определение:** вероятность обнаружить эффект заданного размера, если он реально существует.

| Power | Интерпретация |
|---|---|
| < 50% | Тест почти бесполезен -- монетка |
| 50-79% | Недостаточная мощность, высокий риск пропустить реальный эффект |
| 80% | Конвенциональный стандарт |
| > 90% | Высокая мощность, рекомендуется для критичных тестов |

### Факторы, влияющие на power

| Фактор | Влияние |
|---|---|
| Размер выборки | Больше выборка -> больше power |
| Размер эффекта | Больше эффект -> легче обнаружить |
| Уровень значимости (alpha) | Меньше alpha -> меньше power |
| Вариабельность метрики | Больше дисперсия -> меньше power |

**Практическое правило:** если тест "не значим", проверь power. При power < 80% "незначимый" результат может означать просто нехватку данных.

## Frequentist vs. Bayesian

| Аспект | Frequentist | Bayesian |
|---|---|---|
| Основа | P-value, отвержение нулевой гипотезы | Posterior probability, обновление убеждений |
| Результат | "Значимо / не значимо" (бинарный) | "Вероятность X%, что вариант лучше" |
| Преимущество | Строгий, общепринятый | Интуитивный, допускает раннюю остановку |
| Недостаток | Нельзя "подглядывать" до окончания теста | Зависит от выбора prior |
| Инструменты | Собственные скрипты, Google Optimize* | VWO, Optimizely, Dynamic Yield |

*Google Optimize прекращён, указан для контекста.

### Когда какой подход

- **Frequentist** -- стандарт в академии, подходит для pre-planned тестов с фиксированной длительностью
- **Bayesian** -- удобен для бизнеса (понятная интерпретация), допускает continuous monitoring
- **Sequential testing** -- компромисс: frequentist с коррекцией для промежуточных проверок (alpha spending)

### Правило для агента

ЕСЛИ пользователь не указал подход -> использовать frequentist (p-value, CI) как стандарт.

ЕСЛИ пользователь упоминает "probability of being better" или использует VWO/Optimizely -> переключиться на bayesian интерпретацию.

ЕСЛИ инструмент тестирования неизвестен -> спросить, это влияет на корректную интерпретацию.

## Множественные сравнения

Когда тестируется более одной метрики или более одного варианта, вероятность ложного срабатывания растёт.

### Коррекция Bonferroni

Разделить пороговый alpha на количество сравнений:

| Сравнений | Порог (alpha = 0.05) |
|---|---|
| 1 | 0.05 |
| 2 | 0.025 |
| 3 | 0.017 |
| 5 | 0.01 |
| 10 | 0.005 |

**Правило:** Bonferroni консервативен. Для > 5 сравнений рассмотреть Holm-Bonferroni или FDR (Benjamini-Hochberg).

### Стратегия

1. Определить одну primary metric -- для неё alpha = 0.05
2. Secondary metrics -- информативные, без формального порога
3. Guardrail metrics -- проверяются отдельно на деградацию (one-sided test)
