# Подводные камни и частые ошибки

## Назначение

Универсальные подводные камни при работе с Data API МТС Аналитики. Только проблемы, относящиеся к Data API -- без SPA-internal API специфики.

## 1. Date format -- только ISO datetime

**Проблема:** Параметры `receiveFrom`/`receiveTo`/`occurrenceFrom`/`occurrenceTo` требуют полный ISO 8601 datetime. Формат `2026-04-10` (просто дата) возвращает 400 "Text could not be parsed".

**Решение:** Всегда указывать время и timezone:

```
# Правильно
"receiveFrom": "2026-04-01T00:00:00+03:00"
"receiveTo": "2026-05-01T00:00:00+03:00"

# Неправильно
"receiveFrom": "2026-04-01"
```

**МСК timezone (+3):** Для указания дня D в московском времени через UTC:

```
dateFrom: "D-1T21:00:00Z"     (начало дня D в МСК = 21:00 предыдущего дня UTC)
dateTo:   "DT20:59:59.999Z"   (конец дня D в МСК)
```

## 2. Cooldown между задачами

**Проблема:** После создания одной задачи (`POST /dataexporttasks`) нужно ждать ~10 минут перед созданием следующей. Нарушение вызывает 429 Too Many Requests.

**Решение:** 
- Выдерживать паузу ~10 мин между `POST /dataexporttasks`
- При получении 429 -- exponential backoff: 10s, 20s, 40s, 80s...
- Планировать задачи заранее: один большой период лучше, чем много маленьких

## 3. Concurrency при скачивании (429)

**Проблема:** Параллельное скачивание частей (`GET /dataexporttasks/{id}/parts/{n}`) с concurrency > 3 приводит к 429 от сервера.

**Решение:**
- Максимум 2-3 параллельных запроса на скачивание
- При 429 -- exponential backoff
- Последовательное скачивание стабильнее

## 4. Partial downloads (truncated gz)

**Проблема:** 10-30% параллельных downloads возвращают truncated или JSON-error файлы вместо валидного gz CSV. Файл скачивается без HTTP-ошибки, но содержимое повреждено.

**Решение:** Всегда верифицировать целостность скачанного файла:

```python
import gzip

def verify_gz(path):
    """Проверить что gz-файл целый."""
    try:
        with gzip.open(path, "rt") as f:
            f.read()  # Полное чтение для проверки
        return True
    except Exception:
        return False
```

При ошибке -- retry (до 3 попыток). Не продолжать обработку без верификации.

## 5. RESULT_CLEANED_AS_TOO_OLD

**Проблема:** Результат успешно завершённой задачи (`SUCCESS`) автоматически удаляется через 24 часа. После этого статус меняется на `RESULT_CLEANED_AS_TOO_OLD`, и скачать данные невозможно.

**Решение:**
- Скачивать результат сразу после получения статуса `SUCCESS`
- Не откладывать скачивание "на потом"
- Если результат удалён -- создать новую задачу (с учётом cooldown)

## 6. Comma-separated значения в CD-полях

**Проблема:** Некоторые custom dimension поля (например, `abVariant` / `CDabVariant`) содержат множество значений через запятую: `flag_a,flag_b,flag_c,...`. Точный match (`==`) не работает для поиска конкретного значения.

**Решение:** Использовать substring match:
- В Python при парсинге CSV: `if "target_flag" in row.get("abVariant", "")`
- В API (SPA-internal): оператор `ILIKE` для substring match
- Использовать достаточно уникальную подстроку, чтобы избежать ложных совпадений (например, `my_experiment_2026_03_17` вместо просто `control`)
