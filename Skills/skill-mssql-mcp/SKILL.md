# MSSQL MCP

## Назначение

Канал между Claude Code и Microsoft SQL Server: как поднять MCP-сервер к базе, чем он управляется, как передать секрет, как убедиться, что канал работает, как ограничить запись, если это нужно, и как распознать отказ.

Предмет скилла — канал, а не язык. Диалект T-SQL, системные представления, DMV и ловушки самого языка — в скилле `skill-tsql`.

## Срез данных

| Что | Значение |
|---|---|
| Дата сбора фактуры | 21 августа 2026 |
| Сервер | `aadversteeg/mssqlclient-mcp-server`, версия **0.1.0** (тег от 5 июня 2026), MIT |
| Пакет NuGet | `Ave.McpServer.MsSqlClient` 0.1.0, тип `DotnetTool`, целевая платформа `net10.0` |
| Образ Docker | `aadversteeg/mssqlclient-mcp-server:latest` — та же сборка, что тег `0.1.0` |
| Драйвер внутри сервера | `Microsoft.Data.SqlClient` 6.1.4 |
| Claude Code | 2.1.220 |
| Версия SQL Server | не фиксирована: скилл не привязан к конкретной базе |

**Что проверено, а что нет.** Исходный код сервера версии 0.1.0 прочитан целиком, содержимое пакета NuGet проверено распаковкой, документация Claude Code и Microsoft — по первоисточникам, состояние репозиториев и реестров — обращением к их API.

**Живого прогона сервера не было:** на машине, где писался скилл, не оказалось ни .NET SDK, ни Docker, а устанавливать системные компоненты скилл не вправе. Поэтому ни один факт здесь не подан как измеренный на работающем сервере. Утверждения о поведении опираются на код и документацию и размечены метками провенанса — `[код 0.1.0]`, `[README]`, `[пакет]`, `[док CC]`, `[док MS]`, `[инвентарь]`. Там, где «задано» и «работает» — разные утверждения, это сказано отдельно.

## Принципы

1. **Скилл не делает предположений о правах подключения.** Что учётная запись может делать в базе, определяет её владелец: подключение бывает и читающим, и пишущим. Канал этого не знает и не проверяет. Нужно ограничить запись — механизмы и их цена в [read-only-layers.md](read-only-layers.md); они опциональны и включаются осознанно.

2. **У сервера нет фильтра запросов.** Его слой — гейт регистрации инструментов: он решает, какие операции доступны, но внутрь SQL не смотрит. При включённом `EnableExecuteQuery` любой T-SQL доезжает до СУБД, и дальше всё решают права учётной записи.

3. **Проверяй канал, а не верь конфигурации.** `claude mcp add` пишет настройки без проверки: «saves the configuration without validating credentials». Предстартовой проверки у сервера нет, к базе он подключается только при первом вызове инструмента. Поэтому «канал поднялся» означает «инструмент чтения схемы вернул данные», а не «статус зелёный».

4. **Ошибка приходит как успешный результат.** Все инструменты возвращают текст, и ошибка внутри превращается в такую же строку: на уровне протокола вызов считается успешным. Результат, начинающийся с `Error:` или с `## Error Getting Database Information`, — это отказ, даже если протокол доложил успех.

5. **Короткое значение — повод проверить настройку, а не вывод о данных.** Режут в трёх местах и по-разному: **ячейку** режет сервер (`MaxCellOutputLength`, по умолчанию 40, многоточием — выглядит как данные), **весь ответ** режет Claude Code по токенам, то есть посреди таблицы, **число строк** не режет никто — лимита строк у сервера нет вовсе.

6. **Секрет живёт в `.env`-файле проекта и доезжает до сервера через окружение.** Никогда — открытым текстом в конфигурации Claude Code, в аргументах команды, в тексте запроса, в логах и в чате.

## Рабочий процесс

1. **Получить у владельца базы учётную запись и строку подключения.** Что подключению позволено — его решение, не ваше предположение.
2. **Установить сервер** — .NET tool или Docker, по тому, что фактически есть на машине. [setup.md](setup.md)
3. **Задать настройки:** строка подключения, `Enable*`-флаги под задачу, `MaxCellOutputLength`. Каждый флаг — осознанное решение с названной ценой, а не набор «по умолчанию хорошо». [setup.md](setup.md)
4. **Зарегистрировать сервер в Claude Code** — `claude mcp add`, область `local`. [setup.md](setup.md)
5. **Передать секрет через `.env` проекта**, а в конфигурацию — ссылкой `${VAR}`. [setup.md](setup.md)
6. **Выполнить самопроверку** (ниже).
7. **Работать.** Если результат выглядит странно коротким или оборванным — [limits.md](limits.md).
8. **При отказе** — [failures.md](failures.md).

Необязательный шаг, если запись должна быть закрыта: [read-only-layers.md](read-only-layers.md). Он не входит в основной процесс, потому что нужен не всякому подключению.

## Самопроверка при подключении

Одна, и только одна: убедиться, что сервер зарегистрирован и его инструменты видны в ожидаемом составе.

```bash
claude mcp list        # статус сервера и предупреждения конфигурации
```

Дальше в сессии — `/mcp`: счётчик и состав инструментов. **Состав сверяется с включёнными флагами:** включённый флаг обязан дать свой инструмент, выключенный — не дать. Ожидаемые счётчики для обоих режимов и разбор расхождений — в [setup.md](setup.md).

Никаких дополнительных проверок «перед работой» скилл не вводит: неработающий канал проявится на первом же вызове, а разбор симптома собран в [failures.md](failures.md).

## Что НЕ делать

- **Не включать `Enable*`-флаги сверх необходимого.** Каждый включённый флаг регистрирует инструменты, и обратной проверки за ним нет: сервер не смотрит, что именно вы через них шлёте.
- **Не включать `EnableExecuteStoredProcedure` и `EnableStartStoredProcedure`, если запись должна быть закрыта.** `EXECUTE` — документированный путь в обход запрета записи через цепочку владения.
- **Не полагаться на сервер как на фильтр.** Единственная проверка перед отправкой в СУБД — что строка запроса не пуста.
- **Не считать `ApplicationIntent=ReadOnly` запретом записи** — это маршрутизирующая подсказка Always On, см. [read-only-layers.md](read-only-layers.md).
- **Не оставлять `MaxCellOutputLength` на умолчании, не зная, что оно делает:** 40 символов на ячейку молча портят длинные значения. И не выключать усечение бездумно на широких выборках — весь объём поедет в порог Claude Code. Обе стороны цены названы в [limits.md](limits.md).
- **Не класть пароль в аргументы командной строки.**
- **Не ставить `TrustServerCertificate=True` «чтобы заработало»,** не выяснив, почему не проверяется сертификат. То, что этот параметр стоит во всех примерах строк подключения в README сервера, основанием не является.
- **Не выдавать настройку канала за запрет записи:** выключенный флаг и правило `permissions` ограничивают Claude Code, а не учётную запись. Если запись должна быть невозможна, её закрывает владелец базы правами.
- **Не проверять запрет записи пробными `INSERT`/`UPDATE`/`DELETE`** на базе, назначенной владельцем: у этого сервера такие запросы по построению доезжают до СУБД.
- **Не грузить все файлы скилла сразу.**

## Примеры

### Типовой: подключить базу и прочитать срез

Пользователь: «Подключи нашу базу продаж и покажи, что там за таблицы».

1. Запросить у владельца базы строку подключения и учётную запись; выяснить, читающая она или пишущая. Не предполагать.
2. Проверить машину: `dotnet --list-sdks` и `docker info`. Есть .NET 10 SDK — путь через .NET tool.
3. Положить строку подключения в `.env` проекта, внести её в окружение, зарегистрировать сервер с областью `local`, включив `EnableExecuteQuery` — задача требует произвольных `SELECT`.
4. Самопроверка: `claude mcp list` → `✔ Connected`; `/mcp` → в Database Mode при одном включённом флаге ожидается **7** инструментов. Сошлось — идём дальше.
5. `list_tables` → перечень таблиц. Это и есть настоящая проба канала: до неё сервер к базе не обращался.
6. Срез данных — обычным `SELECT` с ограничением выборки, а не `SELECT *`.

### Edge-case: `✔ Connected`, инструменты есть, а `execute_query` среди них нет

Симптом выглядит как сбой, но это штатное поведение.

Что произошло: `EnableExecuteQuery` не включён, поэтому инструмент не зарегистрирован. Сервер печатает об этом в stderr дословную строку `ExecuteQueryTool registration skipped (EnableExecuteQuery is false)`.

Как отличить от настоящего отказа: посчитать инструменты в `/mcp`. Ровно 6 в Database Mode (или 7 в Server Mode) — гейт работает как задумано, конфигурация доехала. Больше или меньше — конфигурация приехала не та.

Что делать: решить, нужен ли произвольный SQL. Нужен — включить флаг. Не нужен — оставить как есть: это и есть механизм B из [read-only-layers.md](read-only-layers.md) в действии.

Чего не делать: перезапускать сервер, переустанавливать пакет и менять строку подключения. Ни одно из этих действий к причине отношения не имеет.

### Edge-case: значение в ячейке обрывается многоточием

Симптом: в колонке с длинным текстом значения заканчиваются на `...`, и выглядит это так, будто данные в базе такие.

Что произошло: сработало умолчание `MaxCellOutputLength=40`. От значения осталось 37 символов плюс три точки.

Как отличить от обрыва со стороны Claude Code: серверная обрезка **ровная** — все значения в колонке кончаются на одной и той же ширине, а внизу ответа есть строка `Total rows: N`. Обрыв со стороны Claude Code происходит в произвольном месте, и `Total rows:` в ответе не будет вовсе.

Что делать: поднять лимит на конкретный вызов параметром `maxCellOutputLength` — точечно, не выключая обрезку глобально. Почему глобальное выключение не бесплатно — в [limits.md](limits.md).
