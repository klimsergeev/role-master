# Отказы и диагностика: от симптома к причине

Файл устроен от симптома. Каждая запись — что видно, почему так, что делать.

Тексты, набранные `моноширинным` шрифтом и помеченные как дословные, взяты из исходников сервера версии 0.1.0 или из документации Claude Code. Там, где точного текста у нас нет, он не выдуман — описан симптом.

---

## Чем вообще смотреть

Порядок инструментов от дешёвого к дорогому. Каждый следующий имеет смысл, только если предыдущий ничего не объяснил.

| Инструмент | Что показывает |
|---|---|
| `claude mcp list` | Статус каждого сервера и предупреждения конфигурации. При `✘ Failed to connect` к строке приписана деталь отказа |
| `claude mcp get <имя>` | Тот же отказ подробнее, на строке `Issue:` |
| `/mcp` внутри сессии | Счётчик и состав инструментов; помечает серверы, которые заявляют возможность `tools`, но не отдают ни одного |
| `nc -zv <хост> 1433` | Достижим ли порт СУБД вообще, до всякого MCP |
| Ручной запуск сервера в терминале с теми же переменными окружения | Единственный способ увидеть stderr сервера целиком |
| `claude --debug=mcp` | Отладочный вывод по MCP; лог — `~/.claude/debug/<session-id>.txt` |
| `/doctor` | Автоматическая проверка установки, настроек и расширений |
| `claude --safe-mode` | Сессия со всеми настройками выключенными: проверить, что виноват именно MCP-сервер |

Про `--debug`: фильтр привязывается только в форме через знак равенства — «The filter binds only in the `=` form; a space-separated filter enables debug mode without filtering» [док CC].

**Статусы, которые печатает `claude mcp list`** — дословно [док CC]:

| Статус | Что значит |
|---|---|
| `✔ Connected` | Процесс поднялся и ответил на рукопожатие |
| `! Needs authentication` | Требуется аутентификация (для удалённых серверов) |
| `✘ Failed to connect` | Не удалось подключиться; деталь приписана к строке |
| `✘ Connection error` | То же, но детали не будет: «Claude Code appends no detail to a `✘ Connection error` status» |
| ⏸ Pending approval (run **claude** to approve) | Проектный сервер ждёт одобрения |
| `✘ Rejected (see disabledMcpjsonServers in settings)` | Сервер отклонён настройкой |

### Чего эти статусы не значат

Две ловушки, которые стоят потерянного времени.

**`Added …` — это не «работает».** «The `claude mcp add` command saves the configuration without validating credentials» [док CC]. Строка означает ровно одно: конфигурация записана.

**`✔ Connected` — это не «база доступна».** Статус говорит, что процесс сервера запустился и ответил Claude Code. К СУБД сервер при старте не подключается: соединение открывается при первом вызове инструмента [код 0.1.0: соединение создаётся внутри `ExecuteQueryAsync` и подобных]. Пре-флайта у этого сервера нет — ни ключа `--validate`, ни инструмента `test_connection`.

Поэтому «канал поднялся» означает **«первый вызов инструмента чтения схемы вернул данные»**, а не «статус зелёный». В Database Mode это `list_tables`, в Server Mode — `list_databases`.

## Сервер не стартует

### Симптом: сервер сразу в статусе отказа, инструментов нет

Что печатает сам сервер при нормальном старте в stderr [код 0.1.0: `Program.cs`]:

```
Starting MCP MSSQLClient Server...
Database name from connection string: <имя или (not specified)>
Using server mode: <True|False>
EnableExecuteQuery setting: <True|False>
EnableExecuteStoredProcedure setting: <True|False>
EnableStartQuery setting: <True|False>
EnableStartStoredProcedure setting: <True|False>
DefaultCommandTimeoutSeconds: <N>
MaxConcurrentSessions: <N>
Registering MCP tools...
Registered ServerCapabilitiesTool
...
All tools registered. Building MCP server...
```

Этот вывод — самый информативный диагностический артефакт, который есть. Он сразу отвечает на три вопроса: какая база разобрана из строки подключения, в каком режиме работает сервер и какие флаги фактически доехали. Увидеть его можно, запустив сервер руками в терминале с теми же переменными окружения, либо в отладочном логе Claude Code.

| Причина | Как распознать | Что делать |
|---|---|---|
| **Не задана строка подключения** | Сервер печатает дословно `MSSQL_CONNECTIONSTRING is not set in appsettings.json or environment variables.` и **завершается** [код 0.1.0]. MCP-сервер при этом не поднимается вообще | Проверить, что переменная доехала: раскрылась ли `${VAR}`, задана ли она в окружении процесса Claude Code, не потерялась ли при переходе на Docker (`-e`) |
| **Переменная не раскрылась** | `claude mcp list` показывает предупреждение о незаданной переменной; сервер получил литерал `${MSSQL_CONNECTIONSTRING}` | «If a referenced environment variable isn't set and has no default value, the config still loads: Claude Code reports a missing-variable warning for that server in `claude mcp list` output and uses the unexpanded `${VAR}` text as-is» [док CC]. Задать переменную или добавить `:-default` |
| **Нет `dotnet` в `PATH` процесса Claude Code** | Ошибка класса `spawn … ENOENT`. Классика: в терминале `dotnet` есть, а при запуске Claude Code из GUI — нет | Прописать абсолютный путь в `command` либо запускать Claude Code из оболочки, где `PATH` настроен |
| **Нет .NET 10 SDK или он старее** | `dotnet tool exec` не распознан: команда появилась в .NET 10 [README] | `dotnet --list-sdks`; либо глобальная установка, либо путь через Docker |
| **Опечатка в идентификаторе пакета** | `dotnet tool exec` не находит пакет | Идентификатор — `Ave.McpServer.MsSqlClient`; в примерах README пишется строчными: `ave.mcpserver.mssqlclient` |
| **Относительный путь в `command`** | Сервер стартует из одних директорий и не стартует из других | «Relative file paths in `command` or `args` […] resolve against the directory you launched Claude Code from rather than the location of `.mcp.json`» [док CC]. Абсолютный путь |
| **Docker: забыт `-i`** | Контейнер поднимается и немедленно умирает | Транспорт stdio требует открытого stdin. `docker run --rm -i …` |
| **Docker: демон не запущен или образ не скачан** | Ошибка от `docker`, а не от сервера | `docker info`, `docker pull aadversteeg/mssqlclient-mcp-server:latest` |
| **Проектный сервер не одобрен** | Статус ⏸ Pending approval | Запустить `claude` интерактивно и одобрить; сбросить прежние решения — `claude mcp reset-project-choices` |
| **Зарезервированное имя сервера** | `claude mcp add` отвергает имя | Занятые имена: `workspace`, `claude-in-chrome`, `computer-use`, `Claude Preview`, `Claude Browser` [док CC] |

### Симптом: сервер `✔ Connected`, но инструментов ноль

«A server that shows as connected but lists zero tools has started successfully but isn't returning a tool list. Select **Reconnect** from `/mcp`. If the count stays at zero, run `claude --debug=mcp` and read the server's stderr in the debug log at `~/.claude/debug/<session-id>.txt`» [док CC].

Отдельный случай, к нашему серверу не относящийся, но объясняющий класс: инструмент, чья входная схема имеет `anyOf`, `oneOf` или `allOf` в корне, может быть пропущен, «when Claude Code can't produce a schema the API accepts» — при этом остальные инструменты сервера остаются доступны [док CC]. До версии v2.1.195 пропускался любой такой инструмент. У выбранного сервера схем с корневым комбинатором нет.

## Инструменты есть, но не те

Ключевой раздел именно для этого сервера: чаще всего «сломано» оказывается не сломанным, а сконфигурированным иначе, чем предполагалось.

| Симптом | Причина | Что делать |
|---|---|---|
| Нет `execute_query` | Не сбой. `EnableExecuteQuery` не включён — инструмент не регистрируется [код 0.1.0] | Решить, нужен ли он. Если да — включить флаг; таблица в [setup.md](setup.md) |
| Флаг включён, инструмент не появился | Переменная не дошла до процесса сервера | Проверить: ровно два подчёркивания в `DatabaseConfiguration__`, кавычки вокруг значения, `-e` у Docker, значение строкой `"true"`. Строка `EnableExecuteQuery setting: False` в stderr сервера — прямое доказательство, что не дошла |
| `execute_query` есть, хотя флаг не включали | Конфигурация приехала из другого источника | Проверить legacy-имя `EnableExecuteQuery` без префикса — оно переопределяет секцию [код 0.1.0]. Также `appsettings.json` рядом с бинарником и user secrets |
| Имена инструментов с суффиксом `_in_database` | Сервер в Server Mode: в строке подключения нет базы | Строка `Using server mode: True` в stderr подтверждает. Нужен Database Mode — добавить `Database=` |
| Нет `list_databases` | В Database Mode этого инструмента не существует: он регистрируется только в Server Mode [код 0.1.0] | Это норма, а не отказ |
| Нет `get_command_timeout` / `set_command_timeout` | Регистрируются только при включённом `EnableStartQuery` или `EnableStartStoredProcedure` [код 0.1.0] | Здесь README расходится с кодом: он относит их к «Common Tools». Прав код. Менять таймаут на лету без включения сессий нельзя |
| Инструмент виден в `/mcp`, но модель его «не видит» | Правило `deny` с голым именем убирает инструмент из контекста | «A bare tool name […] removes the tool from Claude's context entirely» [док CC]. Проверить `permissions`, см. [read-only-layers.md](read-only-layers.md) |

Способ проверить всю картину разом: сверить счётчик инструментов в `/mcp` с ожидаемым по таблице в [setup.md](setup.md). Расхождение указывает на источник конфигурации точнее, чем чтение файлов.

## Ошибка приходит как успех

**Это свойство сервера, которое обязан знать всякий, кто его использует.**

Все инструменты объявлены как `Task<string>` и возвращают текст. Ошибка внутри перехватывается и превращается в такую же строку результата [код 0.1.0: `ExecuteQueryTool` и остальные]. На уровне протокола MCP вызов считается **успешным**: флага ошибки нет.

Практический вывод: **отказ и валидный результат неразличимы по статусу вызова.** Различать их приходится по тексту.

Дословные формы отказов [код 0.1.0]:

| Текст | Когда |
|---|---|
| `Error: Query cannot be empty` | Пустой запрос в `execute_query` (Database Mode) |
| `Error: Query cannot be empty.` | То же в `execute_query_in_database` — обратите внимание на точку в конце: тексты у двух вариантов различаются |
| `Error: SQL error while executing query: <текст от СУБД>` | Любая ошибка СУБД: синтаксис, отсутствующая таблица, отказ по правам |
| `Error: Total tool timeout of <N>s exceeded after <M>s` | Исчерпан бюджет вызова `TotalToolCallTimeoutSeconds` |
| `Error: Maximum number of concurrent sessions (<N>) reached` | Упёрлись в `MaxConcurrentSessions` при запуске фоновой сессии |
| `Database '<имя>' does not exist or is not online` | Server Mode: указана несуществующая база или база не в состоянии `ONLINE` |

Инструменты чтения схемы форматируют ошибку иначе — не строкой, а блоком Markdown [код 0.1.0: `ExceptionExtensions`]. Структура такая: заголовок второго уровня `## Error Getting Database Information`, ниже сообщение исключения внутри блока кода, ниже заголовок третьего уровня `### Possible Causes` и под ним всегда два пункта:

- `Insufficient permissions to perform the operation`
- `Connection issues with the SQL Server`

Список «Possible Causes» — **шаблонный текст, а не диагноз**. Он печатается всегда, независимо от того, что произошло. Реальная причина — только в блоке с сообщением исключения.

Признак, по которому агент должен распознавать отказ: результат вызова, начинающийся с `Error:` или с `## Error Getting Database Information`, — это отказ, даже если протокол доложил успех. Пустой результат при этом отказом не является: успешный запрос без строк возвращает `Query executed successfully. No results returned.` [код 0.1.0].

## Данные пришли, но обрезаны

| Признак | Кто обрезал | Как отличить |
|---|---|---|
| Значения в колонке заканчиваются на `...`, таблица целая, снизу есть `Total rows: N` | Сервер, `MaxCellOutputLength` | Обрезка ровная: все значения в колонке кончаются на одной и той же ширине. Данные не потеряны — потеряны хвосты значений |
| Ответ обрывается посреди строки таблицы, `Total rows:` нет | Claude Code, порог вывода | Обрыв в произвольном месте, без всякой пометки со стороны сервера |
| Вместо результата — ссылка на файл | Claude Code, persist-to-disk | Результат превысил порог и сохранён на диск |

Первый случай коварнее остальных: обрезанное значение выглядит как настоящее. `2024-01-15T10:23:45.1234567+03:00` при умолчании превращается в строку той же формы, но короче, и отличить её от честного значения по виду нельзя.

Механика обрезки, пороги и что с этим делать — в [limits.md](limits.md).

## Подключиться не удаётся

Порядок диагностики: сначала сеть, потом аутентификация, потом TLS. Обратный порядок приводит к тому, что `TrustServerCertificate=True` ставят на проблему, которая была в файрволе.

**Шаг 0 — достижимость порта, до всякого MCP:**

```bash
nc -zv myhost 1433
```

Порт закрыт — дальше искать нечего: ни строка подключения, ни настройки сервера тут ни при чём.

Дальше — по тексту, который приходит внутри `Error: SQL error while executing query: …` или в блоке `## Error Getting Database Information`. Текст порождает драйвер `Microsoft.Data.SqlClient`, поэтому он одинаков для всех приложений на этом драйвере.

| Тег | Что в тексте | Причина | Что делать |
|---|---|---|---|
| `[auth]` | Отказ входа для указанного пользователя | Неверный логин или пароль; учётной записи нет доступа к базе; в пароле остался перевод строки | Проверить предупреждение `Leading or trailing whitespace in: …` в `claude mcp list` — Claude Code сообщает о таком, но «doesn't trim the whitespace and uses the values exactly as written» [док CC] |
| `[connection]` | Сетевая ошибка, хост не найден, отказ соединения, истечение таймаута соединения | Неверный хост или порт; именованный экземпляр без Browser; из контейнера обращаются к `localhost` | См. раздел о портах в [connection-string.md](connection-string.md). Для Docker: `localhost` внутри контейнера — это контейнер |
| `[certificate]` | Отказ по цепочке сертификата, «certificate chain was issued by an authority that is not trusted» | `Encrypt=True` (умолчание с версии 4.0 драйвера) при непроверяемом сертификате | Развилка: поставить доверенный сертификат / задать `HostNameInCertificate` или `ServerCertificate` / осознанно поставить `TrustServerCertificate=True`. Разбор цены — в [connection-string.md](connection-string.md) |
| `[permission]` | Отказ по правам от СУБД | Учётной записи не хватает прав на объект | Это ответ базы, а не сбой канала. Права меняет владелец базы, см. [read-only-layers.md](read-only-layers.md) |

Отдельный симптом Server Mode: `Database '<имя>' does not exist or is not online`. Сервер проверяет существование базы отдельным запросом к `sys.databases` с условием `state_desc = 'ONLINE'` до переключения контекста [код 0.1.0]. Сообщение появляется и когда база существует, но не в сети, — формулировка объединяет оба случая.

## Зависание и обрыв по времени

Потолков сразу пять, и первым срабатывает самый короткий из применимых.

| Потолок | Значение по умолчанию | Чей | Как выглядит срабатывание |
|---|---|---|---|
| `DefaultCommandTimeoutSeconds` | 30 с | сервер | Текст от драйвера об истечении таймаута внутри `Error: SQL error …` |
| `TotalToolCallTimeoutSeconds` | 120 с | сервер | Дословно `Error: Total tool timeout of 120s exceeded after <M>s` |
| Автоперевод в фон | 2 минуты | Claude Code | Вызов не обрывается, а уходит в фоновую задачу; результат приходит уведомлением |
| Idle-таймаут stdio | 30 минут | Claude Code | Вызов прерывается, если сервер не прислал ни ответа, ни уведомления о прогрессе |
| `timeout` сервера в конфигурации / `MCP_TOOL_TIMEOUT` | ~28 часов, если не задано | Claude Code | Жёсткий предел по календарному времени на вызов |

Как понять, кто сработал: у бюджета вызова есть **собственный дословный текст** с двумя числами; у таймаута команды текст приходит от драйвера; обрывы со стороны Claude Code не приносят текста от сервера вообще.

Тонкость, из-за которой таймаут срабатывает раньше ожидаемого: эффективный таймаут команды считается как минимум из настроенного значения и **остатка** бюджета вызова [код 0.1.0: `GetEffectiveCommandTimeout`]. Второй по счёту тяжёлый запрос в рамках одного вызова получит меньше 30 секунд, потому что часть бюджета уже израсходована.

Подробности потолков со стороны Claude Code и что делать с длинным запросом — в [limits.md](limits.md).

## Фоновые сессии

Актуально, только когда включён `EnableStartQuery` или `EnableStartStoredProcedure`.

| Симптом | Причина | Что делать |
|---|---|---|
| `get_session_results` возвращает часть строк на незавершённой сессии | Накопленный результат сохраняется в сессию каждые 1000 строк [код 0.1.0] | Дождаться `status: completed` в `get_session_status`. Частичный результат — не итог |
| Сессия исчезла | Уборщик удаляет завершённые сессии старше `SessionCleanupIntervalMinutes` (60 мин) [код 0.1.0] | Забирать результат раньше. Ответ на пропавшую сессию — JSON с полем `error: "Session <N> not found"` |
| Все сессии исчезли разом | Процесс сервера перезапустился: сессии живут в памяти и перезапуск не переживают [код 0.1.0] | Запустить заново. Stdio-серверы не переподключаются автоматически, см. ниже |
| `Error: Maximum number of concurrent sessions (10) reached` | Упёрлись в `MaxConcurrentSessions`; считаются только **выполняющиеся** сессии [код 0.1.0] | Дождаться завершения или остановить лишние через `stop_session` |
| Результат сессии выглядит иначе, чем у `execute_query` | Так и есть: сессия отдаёт JSON, внутри которого данные лежат строкой в формате TSV, и обрезка ячеек к ним не применяется [код 0.1.0] | Это не сбой форматирования. Разбор — в [limits.md](limits.md) |
| `maxRows` отрезал не то количество строк | `maxRows` режет текст по переводам строк, а не по записям [код 0.1.0] | Значение с переводом строки внутри сдвигает счёт. Полагаться на точность `maxRows` на таких данных нельзя |

## Процесс сервера упал посреди сессии

Дословно: «Stdio servers are local processes and are not reconnected automatically» [док CC]. Автоматическое переподключение с откатом по экспоненте существует, но только для HTTP и SSE.

Что это значит на практике:

- Упавший процесс нужно поднимать вручную — через **Reconnect** в панели `/mcp` либо перезапуском сессии.
- Все фоновые сессии при этом теряются: они в памяти процесса.
- Открытые транзакции откатываются вместе с закрытием соединений — это поведение СУБД, а не сервера.

## Быстрый маршрут диагностики

1. `claude mcp list` — есть ли сервер и какой статус. Есть предупреждение о переменной или пробелах — начинать с него.
2. Статус не зелёный → `claude mcp get <имя>`, читать строку `Issue:`.
3. Статус зелёный, инструментов нет или не те → сверить состав с таблицей в [setup.md](setup.md); поднять сервер руками в терминале и прочитать его stderr.
4. Инструменты на месте, но вызов возвращает `Error:` → определить класс по тексту: `[auth]`, `[connection]`, `[certificate]`, `[permission]`, таймаут.
5. Класс `[connection]` → `nc -zv <хост> <порт>`, до всякого MCP.
6. Ничего не объяснило → `claude --debug=mcp`, лог `~/.claude/debug/<session-id>.txt`; при подозрении на постороннюю настройку — `claude --safe-mode`.
