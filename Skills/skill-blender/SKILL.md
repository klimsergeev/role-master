# Blender

## Назначение

Работа с Blender через три канала: MCP к открытому Blender, запуск Blender из командной строки, скрипт или аддон, который запускает пользователь. Сцена, Python API, запуск без интерфейса, аддоны, безопасность, подключение по MCP.

## Принципы

1. Сначала осмотр сцены, потом изменения.
2. Одна операция — один шаг с проверкой результата; сложная сцена собирается по шагам.
3. Перед изменением сцены файл сохранён.
4. Код, который модель передаёт Blender, исполняется с правами пользователя в любом канале; меры — в [security.md](security.md).
5. Версии, инструменты и значения по умолчанию в файлах скилла сняты на 2026-11-16. Если установленный Blender или сервер показывает другое, верно показанное.

## Рабочий процесс

### Шаг 1: Выбрать канал

- ЕСЛИ задача — работа с открытой сценой в живой сессии → канал MCP, шаг 2.
- ЕСЛИ задача читает `.blend` без открытого Blender или меняет `.blend`, который не открыт в Blender, и Blender 5.1 или новее → канал MCP с инструментами `*_for_cli` официального сервера (условия — правило о `*_for_cli` в разделе «Условия выбора сервера» [mcp-servers.md](mcp-servers.md)), шаг 2.
- Иначе, ЕСЛИ задача — обработка файлов без интерфейса (рендер, конвертация, пакет файлов, работа с `.blend`) → командная строка, шаг 5.
- ЕСЛИ код запускает сам пользователь (скрипт в текстовом редакторе, аддон, панель) → скрипт или аддон, шаг 6.

### Шаг 2: Подключить MCP

Тип сервера определить по разделу «Условия выбора сервера» в [mcp-servers.md](mcp-servers.md); установленный аддон опознаётся по разделу «Как опознать установленный аддон» там же. Подключить сервер по [mcp-setup.md](mcp-setup.md), пройти «Самопроверку при подключении». Если подключение уже работает, пройти только самопроверку. Затем шаг 3.

### Шаг 3: Осмотреть сцену

ЕСЛИ задача анализирует или меняет сцену → первый вызов чтения сцены по шагу 2 [scene-workflow.md](scene-workflow.md); для работы без открытого Blender — вариант `*_for_cli` на файле оттуда же.

### Шаг 4: Работать со сценой по шагам

ЕСЛИ задача анализирует или меняет сцену → по порядку из [scene-workflow.md](scene-workflow.md): сохранить файл, слой за слоем, проверка после каждого шага; без открытого Blender — по разделу «Без открытого Blender» там же. Затем шаг 7 при ошибке.

### Шаг 5: Командная строка

Собрать команду по [command-line.md](command-line.md).

- ЕСЛИ в команде есть `--python`, `--python-text` или `--python-expr` → поставить перед ним `--python-exit-code 1`, после запуска проверить код выхода и вывод.
- ЕСЛИ скрипта в команде нет → после запуска проверить вывод Blender.
- ЕСЛИ скрипт для команды пишется в этой задаче → функции из [python-api.md](python-api.md).

Затем шаг 7 при ошибке.

### Шаг 6: Скрипт или аддон

Написать код по [python-api.md](python-api.md), выбрать способ запуска, упаковать и проверить по [scripts-and-addons.md](scripts-and-addons.md); расширение проверить `blender --command extension validate`. Затем шаг 7 при ошибке.

### Шаг 7: Разобрать ошибку

- ЕСЛИ ответ инструмента или вывод скрипта содержит трассировку Python или `status="error"` от кода → [python-api.md](python-api.md): `AttributeError` или `TypeError` на имени API — таблица ломающих изменений; `RuntimeError` с `poll() failed` — раздел «Ограничения операторов `bpy.ops`».
- ЕСЛИ нет соединения, вызов MCP висит или инструментов нет → [mcp-troubleshooting.md](mcp-troubleshooting.md).
- ЕСЛИ упал скрипт или запуск из командной строки → сначала вывод Blender по разделу «Вывод и ошибки» в [command-line.md](command-line.md), затем первая ветка этого шага.

## Самопроверка при подключении

Проверка — живыми вызовами, подтверждающими канал; открытый порт 9876 подтверждением не считается.

Claude Code:

1. `claude mcp list` — у сервера Blender статус `✔ Connected`. Статус «⏸ Pending approval» у сервера из `.mcp.json` — сервер проекта не одобрен и не подключается; способ одобрения не установлен, сброс прежних решений — `claude mcp reset-project-choices`.
2. Имена инструментов `mcp__<имя сервера>__*` сверить с перечнем сервера в [mcp-servers.md](mcp-servers.md). Они есть среди инструментов сессии, а при отложенной загрузке — среди отложенных, без схем; пользователь видит тот же состав командой `/mcp`. Имён нет ни там, ни там — перезапустить сессию.
3. Один вызов чтения сцены: `get_objects_summary` у официального сервера, `get_scene_info` у сервера сообщества. Ответ с составом сцены — канал работает. Для работы без открытого Blender — один вызов `get_blendfile_summary_datablocks_for_cli(blend_file)` на нужном файле.

Claude Desktop: инструменты Blender видны в коннекторе, и тот же вызов чтения сцены возвращает состав сцены.

Любой шаг не прошёл — [mcp-troubleshooting.md](mcp-troubleshooting.md).

## Что НЕ делать

- Не собирать сложную сцену одним шагом.
- Не подключать два MCP-клиента к одному Blender одновременно.
- Не подключать сервер не того типа, что установленный аддон.
- Не ставить официальный сервер командой `uvx blender-mcp`: она запускает сервер сообщества (раздел «Устройство канала» в [mcp-servers.md](mcp-servers.md)).
- Не открывать чужой `.blend` с разрешённым автозапуском скриптов и не передавать его в работу без мер из [security.md](security.md).

## Примеры

### Пример 1: Анализ сцены через MCP (типовой)

**Запрос:** «Найди тяжёлые объекты в сцене и предложи оптимизацию».

**Маршрут:** строка «Осмотреть, проанализировать или изменить сцену»: [scene-workflow.md](scene-workflow.md); плюс [mcp-servers.md](mcp-servers.md), потому что работа идёт через MCP; [prompt-catalog.md](prompt-catalog.md), потому что задача — анализ сцены; [python-api.md](python-api.md), потому что для шага пишется код цикла по мешам.

**Результат:** первый вызов — `get_objects_summary` (официальный сервер) или `get_scene_info` (сообщество); затем один вызов `execute_blender_code` с циклом по мешам, который возвращает число полигонов каждого; список, отсортированный по весу, и предложения упростить тяжёлые меши.

### Пример 2: Не подключается (edge-case)

**Запрос:** «Blender MCP не подключается: порт отвечает, а `claude mcp list` пишет `connection timed out after 30000ms`».

**Маршрут:** строка «MCP-подключение не работает»: [mcp-troubleshooting.md](mcp-troubleshooting.md); плюс [mcp-servers.md](mcp-servers.md), потому что тип установленного аддона не определён, и [mcp-setup.md](mcp-setup.md), потому что официальный сервер в этом клиенте ещё не регистрировался.

**Результат:** в Edit → Preferences → Add-ons найдено расширение «MCP» с Maintainer Blender Lab, а зарегистрирован `uvx blender-mcp` — сервер сообщества; регистрация удалена `claude mcp remove blender` и заменена официальным сервером из клона репозитория по сценарию «Claude Code и официальный сервер», сессия перезапущена, самопроверка пройдена. Проверка пути к `uvx` не нужна: она относится только к серверу сообщества.

### Пример 3: Рендер без интерфейса

**Запрос:** «Отрендери кадры 1–100 из `shot.blend` в PNG без открытия Blender».

**Маршрут:** строка «Запустить Blender из командной строки»: [command-line.md](command-line.md); условия колонки «Читать, если» не выполнены — скрипт не пишется, файл свой. Рабочий процесс — шаг 5, шаги сцены не выполняются.

**Результат:** команда `blender -b shot.blend -o //frames/frame_#### -F PNG -s 1 -e 100 -a` с `-a` последним аргументом и указание, где смотреть вывод при ошибке.

### Пример 4: Аддон для пользователя

**Запрос:** «Сделай аддон с панелью, которая случайно расставляет выделенные объекты в пределах куба».

**Маршрут:** строка «Написать скрипт или аддон для Blender»: [python-api.md](python-api.md), [scripts-and-addons.md](scripts-and-addons.md); условие колонки «Читать, если» не выполнено — аддон запускается из интерфейса. Рабочий процесс — шаг 6.

**Результат:** расширение — `blender_manifest.toml` и `__init__.py` в архиве `.zip`, проверка `blender --command extension validate`, инструкция по установке с диска и включению.
