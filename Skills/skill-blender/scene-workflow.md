# Работа со сценой

## Назначение

Порядок осмотра, анализа и изменения сцены Blender по шагам — в любом канале: MCP к открытому Blender, скрипт или запуск из командной строки. Имена MCP-инструментов и их параметры сняты 2026-11-16; полные перечни — в [mcp-servers.md](mcp-servers.md), функции API — в [python-api.md](python-api.md).

## Порядок работы

1. Сохранить файл до первого изменения. Состояние файла: у официального сервера — `get_blendfile_summary_path_info` (`is_saved`, `is_dirty`), в скрипте — `bpy.data.filepath` (пусто — файл ни разу не сохранялся) и `bpy.data.is_dirty`.
   - ЕСЛИ файл ещё ни разу не сохранён (`is_saved=False`, пустой `bpy.data.filepath`) → спросить у пользователя путь и вызвать `bpy.ops.wm.save_as_mainfile(filepath=...)`.
   - Иначе → `bpy.ops.wm.save_mainfile()`.
   - Через MCP сохранение — тот же вызов внутри `execute_blender_code`; в открытом Blender пользователь может нажать Ctrl-S.
2. Осмотреть сцену первым вызовом чтения: официальный сервер — `get_objects_summary`, затем `get_object_detail_summary(name)` по нужным объектам; сервер сообщества — `get_scene_info`, отдающий не все объекты (сколько и как добрать остальные — в его строке в [mcp-servers.md](mcp-servers.md)); без MCP — скрипт по разделу «Чтение сцены» в [python-api.md](python-api.md).
3. Разложить задачу на слои: каркас, материалы, свет, камера. Каждый слой — отдельный шаг.
4. Выполнить один шаг — одну операцию.
5. Проверить результат шага: повторное чтение сцены, снимок вьюпорта (официальный — `get_screenshot_of_area_as_image` с `area_ui_type="VIEW_3D"`, сообщество — `look`) или рендер.
6. ЕСЛИ результат не тот → поправить этот шаг, прежде чем идти к следующему.
7. Повторять шаги 4–6 до конца задачи.

## Без открытого Blender

Работа с `.blend` через официальный сервер без открытого Blender идёт вариантами `*_for_cli` тех же инструментов на файле: чтение — `get_blendfile_summary_*_for_cli(blend_file)`, код — `execute_blender_code_for_cli(blend_file, code)`. Шаги 1, 2 и 5 «Порядка работы» в этом случае выполняются этими вариантами, а снимки недоступны. Изменение файла — только по условиям строки `execute_blender_code_for_cli` в [mcp-servers.md](mcp-servers.md): инструмент сам не сохраняет файл.

## Запрос на шаг

- Координаты, размеры и материалы — числами: `"red metallic sphere at (2, 0, 1) with radius 0.5"` точнее, чем `"add a ball"`.
- Опора на референс: картинка и просьба повторить раскладку (`"recreate similar layout"`) даёт результат ближе к замыслу, чем описание только словами.
- Проверка снимком: `"take a viewport screenshot and tell me if the camera angle looks right"`.
- Одна операция на много объектов — одним шагом: цикл по всем мешам в одном вызове кода, а не вызов на каждый объект.

## Что даёт плохой результат

- Сложная многоступенчатая сцена одним запросом.
- Запрос без направления вроде `"Just make it look good"`: результат получается случайным.
- Точная анатомия, реалистичные пропорции, фотореалистичные материалы: результат — набросок, который дорабатывают руками.
- Простые правки одного объекта (сдвиг, масштаб): руками в Blender быстрее, чем через запрос.

## Длинная сессия

Когда сцена ушла далеко от начала разговора, ранние детали теряются. Новая сессия начинается с вызова чтения сцены и короткого описания цели, а не с пересказа истории.

## Особенности инструментов MCP

- Официальный сервер: инструменты рендера пишут файл не по переданному пути — где он лежит, сказано в их строках в [mcp-servers.md](mcp-servers.md). Инструменты `jump_to_*` меняют выделение, режим и вкладку — для чистого чтения они не подходят.
- Сервер сообщества: `look` по умолчанию снимает с затенением `rendered`; режимы `mode` — `viewport`, `camera`, `angles`, `frames`. У `get_scene_info` сведения о геометрии — группа полей health (`topology`, `weights`), их запрашивают параметром `fields`; поля по умолчанию — в строке инструмента в [mcp-servers.md](mcp-servers.md).
- Код через `execute_blender_code` исполняется с правами пользователя ([security.md](security.md)).
