# Канал MCP: объём ответов и контекст

## Назначение

Справочник механики обмена с Blender по MCP и настроек клиента, от которых зависят обрезанные ответы и тяжесть контекста. Значения Claude Code сняты 2026-11-16.

## Механика обмена

| Свойство канала | Следствие для работы |
|---|---|
| Каждая операция — полный обмен: клиент, MCP-сервер, Blender, ответ, разбор ответа моделью | работа идёт шагами: результат каждого шага виден и проверяется до следующего |
| Снимки приходят изображением PNG и занимают контекст целиком: у официального сервера `get_screenshot_of_area_as_image` и `get_screenshot_of_window_as_image`, у сервера сообщества `look` | снимок — самый тяжёлый ответ; размер ужимается параметром: `size_limit_in_bytes` у официального, `max_size` (по умолчанию 768) у `look` |
| `get_objects_summary` отдаёт всё дерево коллекций сразу; `get_scene_info` — до `limit` объектов, общее число объектов — в строке-заголовке (значения — в строке инструмента в [mcp-servers.md](mcp-servers.md)) | у официального сервера большая сцена приходит одним тяжёлым ответом — сужать через `get_object_detail_summary(name)` по нужным объектам или `execute_blender_code`, который возвращает только нужные поля; у `get_scene_info` остальные объекты добираются параметрами `limit`, `query`, `root`, а поля — `fields` |
| Длинная сессия держит всю историю обмена | ранние детали теряются; порядок новой сессии — раздел «Длинная сессия» в [scene-workflow.md](scene-workflow.md) |

## Лимит вывода MCP в Claude Code

- `MAX_MCP_OUTPUT_TOKENS` — предел токенов в ответе MCP-инструмента; по умолчанию 25000. Claude Code предупреждает, когда ответ больше 10 000 токенов.
- Задаётся в оболочке до запуска Claude Code:

```bash
export MAX_MCP_OUTPUT_TOKENS=50000
claude
```

- ЕСЛИ ответ обрезан, в задаче снимок вьюпорта или сцена на сотни объектов → сначала сузить ответ параметрами из таблицы выше; ЕСЛИ сузить нельзя → перезапустить Claude Code с поднятым `MAX_MCP_OUTPUT_TOKENS`.
- Текстовый результат длиннее 50 000 символов Claude Code сохраняет в файл независимо от этой переменной, если инструмент не помечен особой аннотацией.
- Как задать лимит в Claude Desktop и Cowork, не установлено.

## Отложенная загрузка инструментов в Claude Code

`ENABLE_TOOL_SEARCH` — переменная окружения, задаётся так же, до запуска: `ENABLE_TOOL_SEARCH=<значение> claude`. Без переменной инструменты уже загружаются отложенно; переменная задаётся только для смены этого режима.

| Значение | Поведение |
|---|---|
| не задано или `true` | MCP-инструменты откладываются и подгружаются по запросу |
| `auto` | поиск инструментов включается, когда их определения занимают 10% окна контекста |
| `auto:N` | то же с порогом N% (N от 0 до 100), например `auto:5` |
| `false` | все инструменты загружаются сразу |

- `auto` и `auto:N` переводят отложенную загрузку в режим порога, то есть ослабляют поведение по умолчанию.
- `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` выключает поиск инструментов, и `ENABLE_TOOL_SEARCH` это не переопределяет. На более старых моделях все инструменты загружаются сразу.
- При включённом поиске сервер, закончивший подключаться во время работы, передаёт имена своих инструментов со следующим запросом в том же ходе.
- Задание `ENABLE_TOOL_SEARCH` через блок `env` в `settings.json` не описано.

## Приёмы, облегчающие канал

| Приём | Что даёт |
|---|---|
| Отключить неиспользуемые коннекторы в Claude Desktop (Connectors, переключатель) | каждый подключённый коннектор держит определения своих инструментов в контексте |
| Одна пакетная операция вместо серии: один вызов `execute_blender_code` с циклом по всем мешам | один обмен вместо N — меньше точек отказа и меньше истории |
| Чтение сведений вместо снимка, когда нужна геометрия, а не вид: `get_objects_summary`, `get_object_detail_summary`, `get_screenshot_of_window_as_json`, `get_scene_info` | текст вместо изображения |
